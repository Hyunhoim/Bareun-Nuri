# 첫 고도화용 개발·진단 테스트셋

**시작 URL: http://127.0.0.1:8780/advanced/**

가상의 새빛시 시민소통 포털입니다. 기존 `local-benchmark/`와 별도로 구성했습니다. 공공 사이트를 복제하거나 실제 광고·개인정보를 수집한 자료가 아닙니다. 외부 가입·결제 주소는 없습니다.

## 규모

- 시작 화면 1개 + 하위 페이지 100개 = **상위 탐색 페이지 101개**
- 하위 페이지: 목록 10개 + 게시글 상세 90개
- iframe 문서 16개는 상세 페이지에 종속된 하위 리소스이며 위 100개와 별도로 셉니다.
- **라벨링 요소 300개**: 광고 120개, 정상 180개
- 단일 기법 광고 80개, 복합 기법 광고 40개 → **정답 검출 160건**, 기법별 40건
- 정상: 혼동하기 쉬운 사례 120개 + 일반 정상 사례 60개

| 텍스트 위치 | 전체 | 광고 | 정상 |
|---|---:|---:|---:|
| 제목 | 40 | 16 | 24 |
| 본문 | 80 | 32 | 48 |
| 댓글 | 60 | 24 | 36 |
| 답글 | 40 | 16 | 24 |
| 작성자명 | 20 | 8 | 12 |
| 서명 | 20 | 8 | 12 |
| 링크 문구 | 20 | 8 | 12 |
| 첨부파일 표시명 | 20 | 8 | 12 |

모든 위치에 네 탐지 기법을 포함합니다. 제목은 실제 화면의 제목 요소이며 문서 title 메타데이터 검사는 별도 범위입니다. 링크와 첨부파일은 **표시 텍스트** 검사 대상이며 파일 내용 분석이나 외부 링크 탐색은 포함하지 않습니다.

## 구성 원칙

- 게시판·공지·민원·커뮤니티·생활 안내의 **HTML 구조 5종**. 일부 구조에서는 댓글이 article 밖에 있습니다.
- 상세 페이지당 라벨 요소를 0/1/3/5/9개로 배치합니다(각각 10/15/30/30/5페이지). 라벨이 없는 페이지에도 정상 안내와 탐색 링크가 있습니다.
- 광고/예방·단속 인용 **80쌍**. 40쌍은 주변 문맥을 함께 읽어야 인용임을 알 수 있습니다.
- 일반 문자와 위장 문자의 같은 원문 계열, NFD/호환 자모/부분 자모, span으로 분할된 텍스트, 상위 요소에서 적용되는 스타일과 복합 기법을 포함합니다.
- 긴 정상 본문 안의 광고, 정상 게시글 아래 광고 댓글, 광고 제목과 정상 본문 등 요소 단위 판정을 확인합니다.
- 지연 댓글·답글 **24개**: 150ms 12개, 650ms 12개. iframe 사례 **12개**: 1중 8개, 2중 4개.
- 광고 원문 40계열을 변형해 사용합니다. 300개를 모두 독립적인 새로운 의미의 사례로 해석하지 않습니다. 전체 내용 계열은 정답 파일의 family로 추적합니다.

표시용 ID는 의미 없는 해시입니다. HTML에는 정답 라벨·사례 번호·유형별 클래스·기법 코드가 없습니다. 숨김 스타일 자체는 탐지할 증거이므로 HTML/CSS에 존재합니다. 메뉴·일반 안내 등 라벨링한 300개 외의 기본 텍스트는 정상 내용으로 작성했습니다.

## 실행

Windows, Python 3.10+, Node.js 22.12+/24, Microsoft Edge를 기준으로 합니다. Codex에 설치된 Python이 있으면 실행 스크립트가 먼저 사용합니다.

1. 이 폴더의 `start.cmd`를 실행합니다.
2. 브라우저에서 시작 URL을 확인합니다.
3. 탐지 앱에는 **시작 URL 하나만** 입력합니다. 전체 웹 검사 시 페이지 한도를 150, 후보 한도를 10000으로 설정하세요. 300개는 정답 요소 수이며 수집 후보 수가 아닙니다.

```powershell
# 이 폴더에서 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File run.ps1 serve
powershell.exe -NoProfile -ExecutionPolicy Bypass -File run.ps1 verify

# Agent 수집만 수행하고 정답과 오프라인 비교: 모델 호출 없음
powershell.exe -NoProfile -ExecutionPolicy Bypass -File run.ps1 coverage

# 웹에서 내려받은 결과 채점: 경로는 실제 파일 위치로 변경
powershell.exe -NoProfile -ExecutionPolicy Bypass -File run.ps1 score C:/results/result.json --report C:/results/score.json
```

검증·채점 실행은 최초에 `npm ci`로 Playwright 의존성을 설치합니다. 다른 포트는 `serve --port 8781`, 검증/채점은 `--base http://127.0.0.1:8781`을 사용합니다. 사이트와 채점기는 API 키를 사용하지 않습니다. 웹 앱에서 HCX 모드를 선택하는 작업만 실제 API 비용이 발생합니다.

## 검증과 결과

- `verify`: 실제 링크로 101페이지 도달, 300개 원문/선택자, 은닉 스타일, 지연 댓글/iframe, 비공개 파일 HTTP 차단, 화면 표시 및 채점기 자체 검사.
- `coverage`: 현재 `agent/` 수집기에 URL만 전달한 후, 저장된 수집 결과를 정답과 오프라인 비교합니다. 정확한 정답 요소를 못 모은 경우와 부모·자식 요소로 모은 경우를 구분해 검토해야 합니다. 이 수치는 LLM 재현율이 아닙니다.
- `score`: 기존 채점기를 재사용하여 DOM 요소 단위 TP/FP/FN과 형식 오류, 중복, 원문 불일치를 계산합니다. 위치별·HTML 구조별 지표도 추가합니다.
- 정상 오탐률의 분모는 **라벨링한 정상 180개**입니다. 전체 사이트 텍스트의 정상 비율이나 실제 기관 광고 분포를 뜻하지 않습니다. 전체 FP에는 메뉴 등 라벨 대상 밖에서 발생한 탐지도 포함됩니다.
- `artifacts/`: 검증 보고서, 화면 캡처, 수집 결과. 실행 산출물이므로 Git에서 제외합니다.
- `private/`: 정답·라우팅·채점기 자체 검사 oracle. 서버는 이 경로를 제공하지 않습니다. oracle의 완벽한 점수는 Agent 성능이 아닙니다.

## 평가 분리와 재생성

이 세트는 **개발·진단용 합성 자료**이며 최종 홀드아웃이 아닙니다. 정답은 제작 규칙과 브라우저 사실 검사를 기준으로 작성했으며 독립적인 외부 검수자가 판정한 실제 광고 자료는 아닙니다. 수정·오류 분석에 사용한 후 새 일반화 성능의 근거로 보고하지 마세요. 최종 검증에는 원문 계열과 HTML 구조가 분리된 별도 자료가 필요합니다.

Agent 입력에 `build.py`, `private/`, 정답이나 채점 상세를 제공하지 않습니다. 탐지 입력은 HTTP URL과 수집 증거뿐입니다. 평가 파일이 같은 Git 브랜치에 있다고 입력으로 제공해도 되는 것은 아닙니다.

생성 원본은 `build.py`, 스타일/동작은 `public/assets/`입니다. 수정 후 `run.ps1 build`로 다시 생성하고 **사이트 서버를 재시작한 뒤 verify**를 실행하세요. 공개 파일과 정답을 함께 해시하므로 변경된 세트를 이전 결과와 같은 데이터로 비교하지 않습니다. 동일 소스·시드로 재생성하면 같은 해시가 나옵니다.

공유하는 서버와 DOM 채점 코드는 `../local-benchmark/`에 있으므로 이 폴더만 따로 떼지 말고 `Test_set` 브랜치 전체를 사용하세요.
