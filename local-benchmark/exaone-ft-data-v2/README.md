# EXAONE 게시판 합성 학습 후보 v2

2026-09-29. 사용자 지정 비율의 초도200개를 만들었다. 전부 새로 쓴 합성이며 실제 사람이 작성한 원문, 실제 불법광고 수집본, 사람 검수 완료 정답이 아니다. 공공기관 글의 말투와 구성만 참고했다. 개인정보/실제 연락처/거래 URL을 넣지 않았다.

## 구성

- 실제 권유80(40%), 예방·교육·보도30(15%), 피해 문의·일반 정상·합법권유60(30%), 근거부족30(15%). 피해 문의는2다.
- 도박/불법 성인물/마약류·처방약 불법판매/성매매/기타 불법행위: 상황 계열 각4개, 전체20계열. 범주별40행은 광고와 정상 대조를 합한 수이며 광고만의 수가 아니다. 성인 대상 교육·일반 안마·영화 감상 자체는 불법으로 취급하지 않았다. 성인물 양성은 동의 없는 촬영·유출·합성물 판매로 범위를 명확히 했다.
- 일반표기60, HOMOGLYPH30, JAMO30, TRANSPARENT30, OFFSCREEN30, 복합20. 문자/스타일 변형은 정답 라벨과 독립적으로 분배했다. 복합은 자모+숨김이다.
- 직접 권유, 문맥 의존 CTA, 인용 형식의 실제 모집, 정상 문구에 섞인 광고, 신고를 위한 인용, 피해 문의, 합법적 신청, 다른 작성자의 광고, 목적 미확인 대조를 포함한다.

## 확인한 것

200개 HTML 모두 Playwright/Edge로 렌더링했다. 원문·같은 작성 영역·별도 댓글 보존과 투명도/색/좌표/폰트/표시 상태, 자모·닮은꼴 문자를 확인했다. browser-audit.json 참고. 이것은 직접 DOM 검사이며 운영 collector를 통과한 학습 입력은 아직 아니다. dataset.json의 dom_collected/technique_verified는 운영 수집 검증 미완료를 뜻한다.

기존221개와 원래 대상+문맥의 완전 중복0. 의미 유사도·전과거 학습자료 중복을 모두 검사한 것은 아니다. 최종봉인평가 접근0. 제안정답과 HTML은 분리했고 HTML에는 label/category/kind를 넣지 않았다. id는 위치 식별용 해시다.

## 반드시 남길 한계

- 200행은20개 관련 상황 계열의 대조 확장이다. 독립적인200개 실사용 상황이라고 부르지 않는다. 초기 목표1,000개가 완성된 것이 아니다.
- 불법성 설명이 명시적인 예시가 많다. 완곡한 거래 표현·구어체·오탈자·긴 정상 본문 내 소량 광고·여러 종류의 정상 게시글은 추가 검수가 필요하다.
- HOMOGLYPH는 OPEN/INFO/VIDEO/PHOTO/ROOM/BOOK/JOIN/LIVE/BONUS/CODE 등 링크 라벨 중심이다. 다양한 문장 속 숫자 치환 및 정상 식별번호까지 포괄하지 않는다.
- 제목/댓글/본문 형태를 바꿨지만4가지 HTML 틀만 사용했다. 실제 사이트의 수집 일반화 증명은 아니다.
- 출처는 한국어 공공 게시판의 일반 문의·안내 스타일 참고다. 실제 불법광고 말투를 검증한 출처는 없다. 기관 안내와 개인 말투도 출처에서 구분한다.
- 같은 CTA와 문맥 틀의 반복, 누락 문맥의 보류 라벨 등 지름길 가능성이 있어 검수 전 학습하지 않는다. 모든 행은train_candidate_unreviewed이며 train/val/test 무작위 분할은 하지 않았다. group_id뿐 아니라 공유 템플릿·사이트도 분리해야 한다.

## 파일

- review.md / review-blind.csv: 제안 정답을 숨긴 텍스트 검수. 기존 review.csv는 제안 정답 포함 참고본이므로 최초 검수에는 쓰지 않는다.
- dataset.json: 제안 라벨과 출처·관계·변형 기록. 학습용 messages를 export하지 않았다.
- scenario-bank.json: 새 문구 원본20상황. sources.json: 실제 확인한 공공기관 링크와 참고 범위.
- site/*.html: 정답을 포함하지 않는200개 렌더링 페이지.
- audit.json / browser-audit.json: 비율·중복·브라우저 근거 확인.
- 생성/검사: `local-benchmark/exaone-board-data.py`, `exaone-board-browser-audit.cjs`.

사용한 데이터의 품질을 높이는 다음 단계는 사람의 정답/자연스러움 검수, 운영 수집기 입력 검증, 상황·출처 다양화다. 이를 통과하기 전 GPU 학습하지 않는다. 기존 HCX 운영 변경·유료API·외부 게시·push는 없었다.
