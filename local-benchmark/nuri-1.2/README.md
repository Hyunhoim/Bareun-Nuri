# Nuri 1.2 — 순정 모델 재학습용 합성 자료 v1

**후속 감사 주의:** 이 동결본은 피해문의1000행을1로 배정했지만 기존 개발/검수 계약은2다. 새학습에 그대로 재사용하지 않는다. 입력불변·라벨만 바로잡은 별도본은 `.runtime/nuri-1.2-label-contract-v1/train.json`이다. 기존 결과/해시를 보존하기 위해 원본을 덮어쓰지 않았다. 수정만 적용한250step 비교도 성능개선을 달성하지 못했다. `docs/nuri12-shortcut-report.md` 참고.

새 실험 모델명은 **Nuri 1.2**, 기반은 `klue/roberta-base`다. A/D의 파인튜닝 가중치를 이어받지 않는다. 후속 첫 GPU 학습3에포크와 개발 평가를 완료했으며2에포크 모델을 `.runtime/nuri-1.2-v1/model`에 보존했다. A대체/운영 승격은 미채택이다. `docs/nuri12-training-report.md` 참고. 아래 manifest의 not_trained는 학습 전 동결한 데이터 생성 시점 상태이며 실행 결과는 별도 runtime에 기록했다.

## 구성

|의도 라벨|행 수|비율|
|---|---:|---:|
|0 실제 불법 거래·이용 권유|4,000|40%|
|1 피해 문의·신고·예방/교육 인용|2,000|20%|
|2 일반 정보·합법적 권유·식별번호|3,000|30%|
|3 같은 작성자 근거 부족|1,000|10%|

이 비율은 광고 회복과 정상 보존을 함께 학습하기 위한 출발점이다. 실제 사이트 분포나 검증으로 찾은 최적 비율이 아니다. 피해 문의를 일반 정보와 구분한 것은 기존 4분류 계약을 유지하기 위해서다.

도박/사생활·개인정보 침해/위조·대리 응시/무허가 의약·의료/사기 등5영역의20주제로 구성했다. 각 주제마다 직접 권유, 짧은 문맥 의존 권유, 따옴표 안 실제 판매, 정상 서두와 광고 혼합, 피해 문의, 예방 인용, 광고 옆 정상, 합법적 신청, 관리번호, 근거 부족의10상황을 넣었다. 본문·댓글·제목·링크·작성자 소개라는5요소 역할과 문맥 배치5형식을 사용한다.

**10,000행은 독립적인 실사례10,000개가 아니다.** 20개 주제 원형×10개 담화 상황을 표현·배치·변형으로 확장한1000시나리오 그룹이다. 모두 새 합성이며 실제 공공 게시물 수집이나 사람 정답 검수 완료로 표시하지 않는다. 같은 문장 틀과 명시적 불법 행위 설명을 외우는 위험이 남는다. 초기 추가 학습 실패를 이 자료만으로 해결했다고 주장하지 않는다.

## 표현과 관찰 기법

|표현/표시 조건|행 수|설명|
|---|---:|---|
|일반 표기|4,000|짧고 긴 광고·정상 대조 포함|
|자모|2,000|NFD662, 호환 자모649, 공백 자모689|
|숫자 치환 계열|2,000|거래 대상 단어800, 별칭800, 원래 식별번호 보존 대조400|
|투명 표시|1,000|CSS 근거 메타데이터만 부여|
|화면 밖 배치|1,000|CSS 근거 메타데이터만 부여|

모든 표시 조건에서 라벨 비율40/20/30/10을 유지한다. 표시 조건 자체를 광고 근거로 삼지 않는다. 숫자 치환의800개는 한국어 거래 대상어를 영문 대응 표현으로 만든 뒤 숫자를 적용한 혼합언어 합성이다. 자연 발생 은어 전체를 대표하지 않는다. 식별번호400개는 치환 양성이 아니다.

NFD662개는 기존 입력의 NFC 정규화에서 다시 합쳐진다. 이를662개의 새로운 난해 자모 패턴으로 세지 않는다. CSS 조건은 실제 HTML/브라우저 검증을 거치지 않았으며 **분류모델의 투명·화면 밖 탐지 능력을 증명하지 않는다.** 모델은 텍스트 의도만 학습하고 관찰 기법은 운영 DOM 코드가 담당한다.

## 파일과 학습 계약

- `train.json`:10,000행. 기존 `input.target`, `input.context`, `label`, `id`, `group` 계약.
- `provenance.json`:원문·변형·의도 근거·주제/문장틀/요소 역할·합성 출처·스타일. **모델 입력 금지.** 정답 복원문을 학습 입력에 추가하지 않는다.
- `manifest.json`:수량·분할 방침·파일과 생성 코드 SHA256.
- `audit.json`:GPU·길이·중복·기존 관찰 평가와 근접도 검사 결과.
- `review.csv`:20주제와5표현 조건에 걸친400행 층화 검수 표본. `reviewed_label`, `review_note`가 비어 있으며 검수 완료가 아니다.0/1/2/3을 입력하고 애매한 경우 이유를 남긴다. 일부 검수만으로 전량 검수 완료 표시하지 않는다.

모델 직렬화에는 대상과 문맥만 사용한다. 라벨은 loss 정답으로만 전달하고 id/group/rationale/style/source/topic/raw 복원문은 입력하지 않는다. 동일 원문 그룹을 행 단위로 무작위 분리하지 않는다. **이1만개 전체는 훈련 전용**이다. 새 검증/최종 평가는 별도 작성·검수하며 문장틀·주제·출처 중복을 감사해야 한다. 현재 그룹만 분리해도 같은20주제와10틀이 양쪽에 남기 때문에 독립 평가가 되지 않는다. 기존 봉인 확인 세트는 열지 않았다.

## 감사 결과

- 입력 정확 중복0(모델 NFC 직렬화 후에도0).
- 기존 관찰 자료2,204개(2000+120+44+40)와 정확 입력/원문 대상 중복0. 공백 제거 문자trigram Jaccard 최대.25, .8 이상0. 감사 범위 밖 모든 과거 자료와 중복이 없다고 확장하지 않는다.
- 최대228토큰,512토큰 초과0. 이 결과는 실제 긴 페이지 전체 처리 능력의 평가가 아니다.
- 대상 길이 편향을 발견해 학습 전에 긴 미확정·정상과 짧은 광고·피해 문의를 보완했다. 최종 평균 대상 길이는 광고56.0/피해·인용45.5/일반41.6/미확정43.4자다. 평균 전체 입력127.5/136.1/134.6/138.6토큰. 길이만으로 라벨을 맞힐 가능성을 줄였지만 모든 단서 편향 제거를 보장하지 않는다.
- RTX4060 Laptop GPU,약8GiB VRAM,PyTorch2.6.0+cu124에서 CUDA 텐서 연산 확인. 이후 첫 학습 결과는 위 별도 보고서 참고.

재검사: `.runtime/klue-venv/Scripts/python.exe local-benchmark/nuri12-audit.py`

실제 학습에 앞서 독립 검증 자료와 원본 모델 초기화 경로를 고정한다. 이 자료를 학습한 모델을 이 자료의 다른 배열 순서로 평가해 일반화라고 보고하지 않는다. A·HCX 운영 파일은 변경하지 않았다.
