# 광고 의미 판정 개발 검증셋 v1

학습 자료가 다루는 광고 행위와 정상 문맥의 구분을 **새 문장·상황에서 검사**하기 위한 별도 합성 검증셋이다. 학습 파일은 수정하지 않았다. 같은 assistant가 학습·검증 자료를 작성했으므로 작성자 독립성이나 실제 분포의 대표성을 확보한 최종 홀드아웃으로 소개하지 않는다. 모든 새 라벨은 잠정 라벨이다.

## 구성

| 구간 | 수량 | 사용 |
|---|---:|---|
| 광고 권유 후보 | 20 | 범주별 2개 |
| 정상·비권유 문맥 | 20 | 범주별 2개 |
| 정보 부족·위법성 미확인 | 10 | 범주별 1개. 정상 정답으로 강제 변환하지 않음 |
| 표기 변형 | 40 | 위 확정 라벨 40개의 자모/제로폭 변형, 부모와 같은 그룹 |
| 합계 | 90 | 기본 점수는 원문 50개로 계산. 변형을 독립 의미 사례로 합산하지 않음 |

범주: 도박, 마약, 성매매, 성인 영상 서비스, 유출·불법촬영물 홍보, 불법 의약품, 카드깡, 계좌·인증정보 거래, 불법 사금융, 저작권 침해 홍보.

후기형 모집, 행사 답글 뒤 광고, 정상 연구 참여자 모집, 피해자의 입출금 경험, 제목에만 나온 거래 대상, 모호한 은어, 광고 아래 삭제 요청 댓글, 정상 교육 글 아래 독립 광고 댓글, 신고 증거 보관, 권리자 직접 배포 등을 넣었다. 말투·길이·따옴표·정상적인 서두가 곧 정답이 되지 않도록 양쪽 라벨에 배치했다. 도박 등의 업종을 알더라도 **현재 대상을 게시한 행위**를 읽어야 한다.

실제로 관측한 광고의 유형·문맥 문제에서 설계 동기를 얻었지만, 여기에 수록된 문장과 상황은 모두 새 가상 사례다. 실제 기관 원문, 실제 피해자의 진술, 사람 검수 자료라고 주장하지 않는다. 이번에는 추가 실사이트 수집이나 모델 결과를 보고 사례를 맞추는 작업을 하지 않았다.

## 입력과 정답 분리

- `inputs.jsonl`: 모델에 줄 90개. 각 행은 `id`와 `input.target`, `input.context`만 포함한다.
- `primary-inputs.jsonl`: 기본 의미 검증 50개만 따로 제공한다.
- `labels.jsonl`: 정답 후보, 범주, 근거, 구간, 부모 ID. **모델 입력에 넣지 않는다.**
- `cases.json`: 검수 가능한 기본 시나리오 원본. 역시 모델 입력·학습에 넣지 않는다.
- `overlap-audit.jsonl`: 학습 후보와 가까운 문장의 문자열 유사도 비교 기록.
- `manifest.json`: 자료 해시, 비교한 학습 파일 해시와 표본 한계.
- `usage.json`: 실제 점수 계산의 사용 이력. 생성 당시 모델 실행은 0회다.

라벨은 `1=요청 범주의 실제 이용·구매·알선 권유 후보`, `0=정상/비권유 문맥`, `null=근거 부족`이다. 성인 관련 표현 전체를 양성으로 삼지 않으며, 성인 영상 사이트의 직접 이용 권유는 기존 학습 자료의 사용자 지정 선별 범위를 따른다. 법률 확정 정답은 아니다. 광고 업종 범위가 더 좁은 현재 운영 HCX와 비교하려면 양쪽 판정 범위를 먼저 맞춰야 한다.

ID는 라벨을 포함하지 않는 불투명 해시이며 입력 순서를 고정 무작위로 섞었다. 원문과 표기 변형은 같은 그룹으로 관리한다. 본 검증 폴더를 학습 파일 전체 검색 대상에 포함하지 않는다. 다른 댓글은 별도 작성 단위라고 명시된 경우 그 부모 글의 광고 라벨을 전파하지 않는다.

## 학습 자료 중복 점검

비교 대상은 `synthetic-extension-v2/combined-train-candidates.jsonl` 956개다. 이 프로젝트의 모든 과거 학습 파일이나 외부 사전학습 자료까지 검사한 것은 아니다.

NFKC·대소문자·일부 닮은꼴·공백/문장부호/제로폭 영향을 정리한 전체 입력의 동일 중복은 **0개**다. 대상 문장의 문자 5-gram Jaccard가 높은 상위 3개와, 별도로 Jaccard ≥0.35 또는 짧은 쪽 길이 40 이상에서 포함률 ≥0.65인 모든 비교 후보를 검사했다. 상위 후보 SequenceMatcher 비율 ≥0.70도 경고로 삼았다.

현재 경고 **0개**, 최대 최근접 Jaccard **0.1098**, 검사한 최근접 후보의 최대 SequenceMatcher 비율 **0.4894**다. 이는 문자열 복제 점검 결과일 뿐 **의미·상황·문체가 완전히 독립적이라는 증거는 아니다.** 같은 판정 과제와 작성자를 공유한다. 각 범주에 양성/정상이 두 개씩밖에 없으므로 범주별 성능은 취약점 발견용이며 안정적인 성능 추정치가 아니다. 표본의 양성 비율도 실제 운영 분포를 대표하지 않는다.

## 점수 계산

`semantic-validation.py score`는 90개 모두의 예측을 요구한다. 실패/미판정은 `null`로 기록하고 행을 누락하지 않는다. `primary-inputs.jsonl`만 평가한 결과는 이 통합 채점기로 바로 처리하지 않으며, 전체 실행 시 나머지 표기 변형 예측도 함께 제출한다.

예측 파일 형식:

```json
{"id":"inputs.jsonl의 해당 ID","prediction":1}
```

허용 예측은 정수 `0`, `1`, JSON `null`이다. 중복 ID·모르는 ID·누락·잘못된 예측 형식은 거부한다.

기본 50개에서 확정 라벨 40개의 precision/recall/F1, 정상 오탐, 보류를 오답으로 센 정확도·정상 재현율, 판정 커버리지를 보고한다. 양성 보류는 FN에 포함한다. 정상 보류는 별도 집계하며 정확도·정상 재현율·커버리지에 반영한다. 따라서 F1만 보고 선택하지 않는다.

모호한 10개는 F1에서 제외하고 적절한 보류 비율, 양성 과확정, 정상 과확정을 따로 보고한다. 항상 0/1만 출력하는 이진 분류기도 평가할 수 있으나 모호 자료의 검토 필요성을 어떻게 처리할지는 별도 문제다. 표기 변형 40개는 원문과의 예측 일치율과 **원문·변형 동시 정답률**을 모두 계산해 둘 다 틀린 일치를 성공으로 보지 않는다.

```powershell
& 'C:\Users\alvin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -X utf8 local-benchmark/semantic-validation.py selftest
& 'C:\Users\alvin\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -X utf8 local-benchmark/semantic-validation.py score --predictions <예측파일.jsonl> --run-name <모델과설정이름>
```

검증셋 구조·중복·그룹과 세 개의 별도 계산용 가짜 사례에 대한 채점 연산 점검을 통과했다. 모델 성능을 평가한 결과는 아직 없다. 실제 실행 결과는 날짜별 파일과 `usage.json`에 남는다. 모델 입력이 정답 파일에 접근하지 않도록 평가 작업을 구성해야 한다.

이 자료로 설정·임계값을 고르면 개발 검증으로 계속 기록한다. 실패 문구를 학습에 넣은 뒤 같은 자료를 미사용 평가라고 보고하지 않는다. 실제 평가가 기록된 버전은 build 명령으로 덮어쓰지 못하게 했으며 변경은 명시적인 새 버전에서 관리한다. 운영 일반화와 HCX 대체 여부는 별도의 실제 수집 입력·독립 출처 검증이 필요하다.
