# 숫자 닮은꼴 제한적 HCX 재판정 — 미채택

2026-09-23. **실험용 계약·대조 자료를 구현하고 실제 HCX-007 호출로 비교했으나 두 분할 모두 사전 채택 기준을 실패했다.** 숫자 치환의 누락을 줄이는 대신 실제 식별자의 오탐과 모호 표기의 과도한 확정이 발생했다. 기존 관찰기·의미 판정·웹 worker는 변경하지 않는다.

## 구현과 자료

`agent/experiments/digit-contract.cjs`는 영숫자 토큰에 일반적인 숫자→영문 대응을 적용해 가능한 읽기를 최대 32개 생성한다. 단어 사전이나 B0NUS 예외는 없다. 접두·접미 숫자도 실험 대상에 포함한다. 복원 후보는 가설이며 모델은 원문에서 `substitution / literal / uncertain` 중 하나를 판단한다. 숫자 치환으로 확정할 때만 코드가 선택한 원문 범위에 HOMOGLYPH 근거를 추가한다. 다른 기법을 삭제하거나 광고 의도를 바꾸지 않는다.

`digit-run.cjs`는 기존 HCX 어댑터와 요청 내부 ID 변환을 재사용한다. 모델 입력은 토큰·표시한 원문 문맥·읽기 후보뿐이다. 광고 정답·분할·단어 계열·case_id·스타일·다른 후보의 의미 판정을 넣지 않았다. JSON 계약·원문 범위·ID·응답 완전성 검사를 적용했다. 한국어 조사가 붙어 기존 관찰 힌트의 범위가 영숫자 토큰보다 큰 경우도 API 호출 전 계약 검사에서 처리했다.

`test-set-v2/digit-contrast/`에 브라우저로 읽을 수 있는 합성 게시판 HTML과 오프라인 라벨을 만들었다. 개발용 44개, 평가용 44개 각각 치환 16개·실제 영숫자/식별자 20개·모호 표기 8개다. 각 분할의 22개 조건을 광고/예방 문맥 쌍으로 구성했고, 일부 표기는 단어 용법과 식별자 용법을 모두 넣었다. 두 분할의 단어 계열은 겹치지 않는다.

두 HTML만 허용하는 임시 서버로 수집했으며 88개 원문·위치와 88개 질의 범위를 확인했다. 라벨은 웹 응답이나 추론에 제공하지 않았다. 데이터·라벨·추론 소스를 최초 유료 호출 전에 해시로 고정했다. 개발용 결과를 본 뒤 프롬프트·규칙·라벨을 바꾸지 않고 사전 계획대로 평가용을 한 번 실행했다.

**평가용은 최초 실행 시 미사용 단어 계열이었으나 동일 개발자가 작성한 합성 자료다.** 실제 공공 사이트의 독립 홀드아웃은 아니며, 이제 두 분할 모두 분석한 진단 자료다. 모호 표기의 정답은 제공된 정보만으로 단어 치환과 고유 이름/코드의 구분을 확정할 수 없다는 평가 계약에 따른 것이다. 창작자의 숨은 의도를 모델이 맞히도록 요구한 것이 아니다.

식별자와 스타일화된 이름의 경계에는 해석의 여지가 있다. 이 자료의 literal 정답은 원문에서 실제 규격·고정 번호로 사용하는 역할에 따른 실험 계약이며, 주최 측 비공개 정답과 동일한 경계인지 검증하지 않았다. 그러한 한계와 별개로 IPv6·USB3처럼 숫자가 규격의 일부임을 명시한 사례에서도 오류가 관측됐다.

## 고정 조건과 기준선

HCX-007, thinking none, temperature 0, seed 42, 배치 4, 출력 2,048토큰, 순차 실행을 사용했다. 전체 상한 80번 API 시도·80,000 사용 토큰 및 실행별 1시간 제한을 적용했다. 모든 시도와 사용량을 기록했고 소스 해시가 두 실행 뒤에도 같음을 확인했다.

기존 코드는 이 자료에서 치환 확정 0개였다. 개발용은 미확정 힌트 30개·후보 미선별 14개, 평가용은 미확정 힌트 28개·후보 미선별 16개였다. 특히 숫자가 처음/끝에 있는 표기도 새 실험의 대상으로 포함했으므로 이번 비교에는 후보 범위 확장과 모델 재판정이 함께 들어간다. 이 효과를 프롬프트 하나의 효과라고 주장하지 않는다. 기존 코드가 판단하지 않은 것을 literal 정답이나 검토 성공으로 세지 않았다. 확정 양성 0개인 기준선의 정밀도는 계산 불가다.

## 관측한 오류

- 실제 식별자·규격의 단어화: 개발용에서는 R2D2와 제품 번호 용법의 R1VER가 오탐했다. 평가용에서는 B2C 두 문맥, IPv6, USB3, 관리번호 용법의 PL4NET이 오탐했다. 규격/식별자라는 설명이 원문에 존재했다.
- 모호 표기의 과도한 확정: N0VA, L1NE, F0RM, S0LO 등에서 가능한 읽기를 원래 의도로 단정하거나 고유 이름이라고 추측했다. `uncertain` 선택지가 있어도 이를 거의 사용하지 않았다.
- 선택한 읽기의 오류: R1VER를 RLVER로, B00K5를 BO0K5로 선택한 응답이 있었다. 출력 enum과 원문 범위가 유효하다는 사실만으로 의미적으로 맞는 읽기가 보장되지 않는다. 위 이진 F1은 치환 분류 지표이므로 이 오류까지 해결됐다고 해석하면 안 된다.
- 개발용 일부 응답에는 실제 광고 문장을 예방 교육 자료라고 설명한 오류도 있었다. 후보 간 문맥 혼동 또는 생성 오류의 가능성이 있으나 어느 원인인지 이번 실험만으로 확정하지 않는다.

제공한 문자 대응 후보에 모델이 과도하게 의존했을 가능성이 있지만, 후보를 제공하지 않은 동일 모델 대조군을 실행하지 않았으므로 인과로 단정하지 않는다. 일반적인 숫자 대응표 자체와 모델의 확정 판단을 분리할 필요가 드러났다. 이 결과는 HCX-007의 모든 설정·구조가 실패한다는 증거도 아니다.

모든 호출은 HTTP 200이며 사용량 누락은 없었다. 원화 과금액은 확인하지 않았다. 시간은 해당 재판정 단계이며 브라우저 수집과 전체 Pipeline 실행 시간을 포함하지 않는다.

`npm.cmd test --prefix agent`를 통과했다. 새 검사는 접두·접미 숫자, 원문 범위, 읽기 후보 상한, 라벨 제외, 광고 의도·검토 보존, ID/스키마 검증과 한 번의 형식 재요청을 확인한다. 채점기는 완전 정답과 의도적으로 넣은 오탐·누락·불확실성 손실·쌍 불일치를 구분하는 검사도 통과했다. 코드 계약 검사의 통과와 실제 모델의 의미 판정 실패는 별개다.

사전 기준은 두 분할 각각 재현율 최소 87.5%, 실제 영숫자 오탐 0·literal 확정 20/20, 모호 표기 보존 8/8, 문맥 쌍 불일치 0이었다. **두 분할 모두 실패해 미채택하고 종료했다.** 역순 재실험과 기존 306개 통합 확대의 선행 조건이 충족되지 않아 시행하지 않았다. 따라서 기존 최종 탐지 F1 96.77%를 이번에 갱신하거나 일반화 개선을 주장하지 않는다.

오탐한 식별자 목록을 정상 예외로 추가하거나 B0NUS만 양성 처리하지 않았다. 같은 자료를 보고 프롬프트를 반복 조정하면 과적합할 우려를 사용자에게 보고했다. 실험 코드와 실패 기록은 분리 보존하며 기본 웹 worker와 3단계 관찰기에는 연결하지 않는다. 2단계 의미 오류·3단계 숫자 치환 문제는 남아 있고, 4~5단계·커밋·push는 시행하지 않았다.
