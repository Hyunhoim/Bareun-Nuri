# 숫자·닮은꼴 기법 아키텍처 비교의 최종 결정

2026-09-29. **이번 비교에서는 기존 코드 판정을 유지하고, 시험한 HCX 보조 판정과 특화 분류기는 운영에 채택하지 않는다.** 이는 숫자치환 문제를 해결했다는 뜻이 아니다. 사용자 Goal의 '근거가 부족하면 운영을 변경하지 않는다'와 최초 계획의 '둘 다 실패하면 코드 유지'에 따른 비교 결정이다.

## 비교 결론

| 구조 | 기법 최종96 strict F1 | 주요 반대 근거 | 결정 |
|---|---:|---|---|
| 코드 |40.00%|숫자치환36개 미확정, 명확한 문자12개만 확정|현재 운영 유지, 한계 명시|
| 코드+HCX |84.96/74.77%|정상 표기7/4개 및 모호10/15개 과도확정, 순서 민감성|미채택|
| 코드+최초 특화분류 |98.97%|개발 정상12/24 오확정, 실제 수집 B3T 미확정|미채택|
| 역할 보강 분류 |관찰 최종 정탐47/48|개발 모호12/24 과도확정|미채택|
| 두 분류기 동의 |관찰 최종98.95%|기존 회귀에서 정탐2개 손실, 실제 수집 B3T 미확정|미채택|

숫자치환 집중 자료의 조건부 기법 점수다. 전체4종 또는 실사이트 전체 탐지 점수가 아니다. 정상 표기 오확정≤5%, 모호 위장확정≤10%와 후속 회귀보존 기준은 결과를 보고 완화하지 않았다. 모든 후보가 적어도 하나의 관문을 실패했다. 따라서 운영 승격용25분 실험을 추가할 단계가 아니다.

## 지연과 비용

코드96개 문자관찰25회 재생 중앙값0.000913초(최소0.000715/최대0.003469). 순수 관찰 마이크로 측정으로 파일 읽기·수집은 제외한다. 최초 분류기84개 CPU 약2.05초, HCX84개35.36~36.57초다. 모델 로딩/토큰화와 API대기 포함 범위가 다르므로 동일 종단 비용으로 비교하지 않는다.

전체 실제 API는 기법84호출69,592토큰, 공통 의도16호출47,245토큰, 실제 수집 비교12호출12,135토큰으로 **112호출·129,972확인토큰**이다. 요금계약을 확인하지 않아 원화 비용은 산출하지 않았다. 역할보강/동의/길이진단은 추가API0.

## 긴 입력 추가 감사

실제 수집80구간 중512토큰 초과59개는 모두 본문 자체가 긴5개 요소에서 발생했다. 주변문맥만512초과0, 본문이문맥에그대로중복0, 공백정리만으로복구0이다. 단순중복제거로 해결할 수 없다. 본문 일부만 잘라 분류하면 식별자역할·인용 설명을 잃을 수 있다. 긴입력을 처리하는 새로운 구조는 이번 비교의 검증된 개선안이 아니다.

재현 감사 `node agent/experiments/technique-decision-audit.cjs`, `node agent/experiments/technique-collected-audit.cjs`. 근거 `.runtime/technique-decision-audit.json`, `.runtime/technique-collected-v1/input-length-audit.json` 및 앞선 세 보고서. 기존 관찰 최종은 회귀자료로만 보존한다. 더 높은 합성 점수가 나올 때까지 반복 학습하지 않는다.

후속 연구를 새로 진행한다면 모델 크기보다 긴 본문에서 대상에 속한 근거를 보존하는 입력 구성과 독립적인 식별자/치환 정답 검수를 먼저 다룬다. 이번에는 운영 소스 연결·새배포·push 없이 비교를 종료한다.
