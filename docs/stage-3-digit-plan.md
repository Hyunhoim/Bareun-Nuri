# 3단계 숫자 닮은꼴 재판정 실험 계획

2026-09-23, 데이터 생성·유료 호출 전 등록. 기존 의미 판정과 관찰 코드는 고정한다. 모델이 광고 여부를 다시 판정하지 않는다.

## 가설과 범위

숫자가 문자의 대체 표기인지 실제 숫자를 포함한 식별자/수량인지 원문 의미에서 구분하면, 영숫자 혼합을 모두 확정하거나 모두 미확정으로 남기는 것보다 나을 수 있다. 코드가 제한된 문자 대응 후보를 제공하고 HCX는 `substitution / literal / uncertain`만 반환한다. 복원 후보의 존재를 정답으로 간주하지 않는다.

일반적인 숫자→영문 대응을 이용하며 단어 사전·광고 키워드·B0NUS 예외를 넣지 않는다. 접두·접미 숫자도 포함한 영숫자 토큰을 실험용 미확정 후보로 만들되, 이미 코드가 확정한 HOMOGLYPH 범위는 재판정하지 않는다. 기존 관찰기에서 숫자가 중간에 있는 경우만 미확정으로 기록하던 경계는 이 별도 경로에서 확장한다. 따라서 이번 변경에는 후보 범위 확장과 제한적 모델 재판정이 모두 포함된다.

## 자료와 고정 조건

- 개발용 44개, 미사용 단어 계열 평가용 44개: 각 16개 치환, 20개 실제 영숫자/식별자, 8개 모호 표기. 같은 토큰의 광고/예방 문맥 쌍을 포함한다. 일부 토큰은 단어 용법과 식별자 용법을 모두 만든다.
- 두 분할의 단어 계열은 겹치지 않는다. 개발용과 평가용을 같은 코드가 생성하고 같은 개발자가 라벨링하므로 실제 웹 독립 홀드아웃으로 주장하지 않는다. 모호 표기는 제공된 문맥으로 원래 단어/고유 이름 여부를 결정할 수 없는 자료다.
- 라벨·분할·광고 정답은 추론 입력에서 제외한다. 브라우저 수집 원문·원문 범위·위치만 읽고, 모델에는 요청 내부 ID·토큰 표시 문장·가능한 읽기만 전달한다.
- HCX-007, thinking none, temperature 0, seed 42, 배치 4, 출력 2,048토큰. 순차 실행, 전체 실험 최대 80번 API 시도·80,000 사용 토큰, 각 실행 1시간. 실제 사용량 누락 시 비용 검증 미통과로 처리한다.
- 최초 호출 전에 입력·정답·추론 소스를 해시로 고정한다. 개발용 완료 후 같은 소스로 미사용 분할을 한 번 평가한다. 개발용 의미 성능이 낮더라도 계획한 미사용 분할 한 번까지는 비교하되 결과 사이에 프롬프트·규칙·라벨을 바꾸지 않는다. 형식/실행 결함은 별도 기록하고 실험을 중단한다.

## 사전 채택·종료 기준

1. 두 분할 각각 치환 재현율 최소 87.5%(14/16), 실제 영숫자 20개에서 치환 오탐 0개이며 20개 모두 literal로 확정, 모호 표기 8개 모두 uncertain. 광고/예방 쌍의 분류가 같아야 한다. 미확정을 양성 정답으로 세지 않는다.
2. 광고 여부·의미 검토·이유·위치·다른 기법은 변경하지 않는다. 원문에 없는 읽기, 외부 ID/범위/근거, 누락/중복 응답을 거부한다. 모델의 literal 판정이 기존 확정 기법을 삭제해서는 안 된다.
3. 두 분할 통과 시에만 미사용 분할을 역순 배치로 한 번 더 실행해 판정 불변성을 검사하고 기존 306개 패널에서 숫자 후보만 실제 호출한다. 기존 다른 기법 3종 및 정상 findings 회귀 0, 의미 판정 불변, 최종 기법 누락 감소를 확인한다. 미사용 분할 반복은 새 표본 수에 합산하지 않는다.
4. 분할 관문 실패 또는 예산 초과 시 이 개선안을 미채택하고 실험을 종료한다. 결과를 보고 단어 예외·추가 판정 단계·프롬프트 변경을 덧붙이지 않는다. 통합 확대나 웹 worker 전환을 하지 않는다.

보고는 기법 정밀도·재현율·F1, 실제 영숫자의 오탐/불필요한 보류, 모호 표기의 검토 성공, 문맥 쌍 일관성, 후보 선택 누락, 호출·토큰·시간을 구분한다. 기존 미확정 유지 기준선의 확정 양성 0건은 정밀도 계산 불가로 표기한다. 이는 같은 오류 문구의 해결을 넘어선 한정된 가설 시험이며 일반화 개선은 결과 확인 전 주장하지 않는다.
