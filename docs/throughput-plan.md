# 토큰 절감 × 페이지 분산·동시 판정 실험 (2026-09-25)

운영 act4/FIFO/4개/출력3072를 유지하고 실험 경로에서만 비교한다. 사용자 요청은 두 개선군의 동시 적용 실험이며 운영 자동 승격은 하지 않는다.

## 사전 고정

- A baseline: 현행 입력·3072·순차 판정.
- B tokens: 원문과 완전히 같은 normalized_text만 명시적 참조로 대체, 출력512, 동일 요청 묶음 전체의 보수적 캐시. 대상/문맥/링크/출처/스타일을 삭제하지 않는다.
- C distributed: 현행 입력·3072, 페이지별 FIFO 후보 묶음 최대4개, 페이지 사이 판정 기회 분산, 최대2요청 동시 실행.
- D combined: B+C.
- HCX-007 none/temperature0/seed42, 공통 TPM52000·요청 간격1000ms. 조건끼리는 동시에 실행하지 않으며 직전 사용량 창을 기다린다. 마감 후 신규 전송 금지, 미확인 전송 자동 재호출 금지.

## 진단과 확대

1. API0: 문맥/원문 복원, 캐시 오병합 방지, out-of-order 응답 ID귀속, FIFO URL/전체 후보집합, 중단·재개, 미확인요청 거부 검사.
2. 기존 dev52+이미 관찰한 holdout52에서 네 조건을 실제 호출한다. 분산 조건은 페이지 내부 순서를 유지하고 페이지 경계를 넘는 배치를 만들지 않는다. 기준선과 배치 동료/마지막 잔여 크기가 달라지는 효과는 기록한다. 이 단계는 저장된 선별 근거의 진단이며 실제 탐색 시간 비교가 아니다. 최대160전송/입력추정+출력예약120만토큰/1시간. 결과를 보고 프롬프트/분산 가중치 조정하지 않는다.
3. 후보 전체 의미F1이 기준선보다2%p 넘게 하락하거나 어느 분할이5%p 넘게 하락하면 확대하지 않는다. 정상FP 순증2개 초과, 형식잘림/귀속오류/미확인전송도 중단 사유다. 작은 표본의 변동을 인정하되 이것을 정확도 유지 입증으로 부르지 않는다.
4. D가 통과하면 동일 조건 A/D의 고정 순서 재측정(최대100전송/예약80만)으로 변동을 확인한다. 통과한 D만 부산 복제본 게시판 실제25분/200페이지/300호출/누적후보0/토큰보호100만으로 실행한다. 비교 기준은 원본이 보존된 현행운영 게시판25분 결과이며 동시기 재측정이 아니라는 한계를 명시한다. 필요 시 C만 별도25분 실행할 수 있으나 자동 확대하지 않는다.
5. 실제25분 전체 통제64위치(광고28)를 기준으로 P/R/F1·첫정탐·미발견/대기/미판정/모델FN·호출/토큰/저장종료를 평가한다. 처리량만 늘고 정탐이 늘지 않으면 채택하지 않는다. 운영 승격에는 독립자료와 충분한 회귀를 포함한 후속 근거가 필요하며 이번 관찰자료만으로 일반화 개선을 확정하지 않는다.

## 안전성과 한계

원문·정답·출처는 고정한다. 평가라벨은 입력/캐시/스케줄러에 전달하지 않는다. 동일 문구만으로 캐시하지 않으며 불확실/실패/진행중 결과는 재사용하지 않는다. 페이지 종류/태그/무신호를 정상으로 제외하지 않는다. 수집 범위와 관찰기법은 유지한다. 기존52의 점수와 사후보완64의 점수를 혼합하지 않는다. 새 사이트나 새 독립 홀드아웃을 만든 실험이 아니다. 한도·분모·실험기준을 결과에 맞춰 바꾸지 않는다.
