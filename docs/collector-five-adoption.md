# 동시 5개 수집 운영 채택

2026-09-30 사용자 지시로 운영 worker에 최대5개 동시 수집을 적용했다. 앞선63페이지 비교에서5개는 평균163.6초·평균2.64GiB·최대 관측6.91GiB였으며,25개 대비 메모리 부담을 고려한 사용자 지정 선택이다. 이전 비교는 고정URL 복제본·검사용 저장/해시 포함 수집 실험이며 운영 종단 성능이 아니다. 새25분 HCX 비교나 일반화 관문을 통과한 것으로 기록하지 않는다.

## 적용 범위

- `agent/src/worker.cjs`: `collectionConcurrency:5`를 운영 스케줄에 전달한다. 브라우저 생성 Promise를 공유해 동시에 진입하더라도 작업당 브라우저 한 개를 사용한다. 기존 AntiSpoof 연결과 HCX 설정은 보존했다.
- `agent/src/core/bounded-scan.cjs`: 대기열 앞에서 최대5개를 함께 수집하고 출발 순서대로 검증·디스크 저장한다. 수집 묶음 크기는 미판정8페이지 창의 빈자리, 남은 페이지 예산, 대기URL 수에 제한된다. 항상5개가 실행되는 구조는 아니다. 핵심 함수의 기본값1은 기존 진단 호출 호환용이며 운영 worker는 명시적으로5를 지정한다.
- 페이지별 독립 context, 동일 출처·쿼리·프레임 경계, 후보·관찰 근거 검증은 기존 수집기를 그대로 사용한다. HCX 최대12개 순차 묶음,58k 예약,출력512/none,SRPT8/aging8을 유지한다. 수집과 API 호출을 동시에 실행하는 변경은 아니다.
- 취소·시간 예산 이전에 완료한 페이지는 저장한다. 실패한 페이지는 이슈로 남기고, 취소/마감으로 미완료인 URL은 대기열에 보존한다. 개별 수집 실패가 같은 묶음의 다른 성공 근거를 버리지 않는다.
- 판정용 근거 캐시는 최대2페이지다. 수집 시작 전 캐시를 비우며 동시 수집 중에는 최대5개의 snapshot이 별도로 존재할 수 있다. 기존 Node RSS768MiB 입장 보호는 유지하며, 이는 브라우저를 합친 전체 메모리 상한이 아니다. 이전 무제한 수집 실험의 메모리·속도를 운영값으로 보장하지 않는다.
- 수집 동시성을 실행서명에 포함했다. 옛 코드 또는 다른 동시성의 체크포인트는 자동 이행/재개하지 않는다. 거부 시 기존 결과를 보존하고, 미확인 HCX 요청 자동 재호출도 계속 금지한다. `coverage.json`과 `run.json`에 `collection_concurrency`를 기록한다.

## 검증

API 호출0. 다음 로컬 검증을 완료했다.

1. 운영 핵심 코드13페이지/221후보: 실제 최대 동시5, FIFO 출발/저장 순서, 미판정 창 최대8, 전체 원문·후보 보존을 확인했다. 호출 예산 중단/재개는 연속 실행과 판정 묶음 순서가 같고 완료 페이지를 재수집하지 않았다.
2. 묶음 중간 취소: 이미 완료한2페이지는 저장하고 나머지11URL은 대기열에 보존했다. 재개 후221후보가 모두 복원됐다. 페이지/후보 예산, 시간 예산, 개별 페이지 실패를 확인했다.
3. 실제 worker를 수집기 stub과 실행: 최대 동시5, 브라우저 생성1회,13URL FIFO 순서, 완료 상태와 동시성 메타데이터를 확인했다.
4. 실제 Edge/운영 핵심 코드에서 기존8페이지 회귀 fixture를 동시1과5로 비교해 원문·문맥·스타일·좌표·프레임·관찰 근거가 같았다. 두 조건의 실제 최대 동시 수는 각각1과5였다. 기존 클릭/늦은 댓글 등 수집 한계는 해결됐다고 주장하지 않는다.
5. 기존 bounded worker 검증: 체크포인트 서명/체크섬/미확인 전송 거부, 거부 시 파일 불변, 남은 판정 재개, HCX512/12→1 묶음을 통과했다. 기존 의미 채택 검사도1845대상의 동결 요청 일치와 원문/관찰 보존을 포함해 통과했다.

재현: `node agent/experiments/collector-five-adoption.test.cjs --browser`, `node agent/experiments/bounded-worker.test.cjs`, `node agent/experiments/semantic-adoption.test.cjs`.

검증 기록은 `.runtime/collector-five-adoption-1790730131863/result.json`(worker·예산 포함), `.runtime/collector-five-adoption-1790730039767/result.json`(실제 브라우저), `.runtime/bounded-worker-check-1790730050499/result.json`, `.runtime/semantic-adoption-check-1790730056048/check-result.json`이다. 실제 HCX 판정 품질·25분 처리량·운영 최대 RAM은 이번 채택 검사에서 새로 측정하지 않았다. 병렬 입장으로 페이지 간 판정 순서가 달라질 수 있으므로 짧은 예산에서 검사 대상 구성이 동일하다고 보장하지 않는다.
