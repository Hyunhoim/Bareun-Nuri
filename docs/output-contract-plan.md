# 출력 안내 정리 비교 사전 계획

2026-09-30. 기존 안내의 명백한 모순은 발견하지 못했다. 공식 스키마를 사용하는 상태에서 출력 안내의 명확화가 도움이 되는지 비교한다. 의미 지시/입력/분류 enum은 수정하지 않는다. 짧은 ID는 이번 비교에서 제외한다.

- A: 현재 prompt JSON. B: 기존 Structured Outputs. C: Structured Outputs + 출력 안내 한 문장 교체.
- C 안내: `출력 형식은 API에 지정된 JSON 스키마를 따른다. decisions에 입력 node_id 각각의 publication_act를 기록하고 모든 후보를 빠짐없이 포함한다. JSON 외 설명이나 코드 블록은 출력하지 않는다.`
- 기존 완료 묶음 중 해시순12개 + 나머지의 모델 입력 문자수 최단3/최장3개. 실패160번째 요청은 제외하고 재전송하지 않는다. 후보 수·길이 범위와 지정 정답 개수를 보고한다. 기존 자료이므로 회귀 진단이며 독립 평가가 아니다.
- 순서 A-B-C-C-B-A, 각18묶음, 최대108호출·750,000확인토큰·30분 안전상한. none/seed42/온도0/출력512/58kTPM 동일. 한 요청이라도 실패하면 자동 재호출 없이 중단하고 확보된 자료만 보고한다.
- 확대 기준: C 형식 오류0, A 대비 합산 F1 하락1%p 이내, 각 반복 기존TP손실1/새FP1 이하, 중앙 서비스지연 증가20% 이내. B와도 비교해 안내 변경의 효과를 구분한다. 확대 통과는 운영 채택이 아니며 동일25분 조건의 종단 검증이 필요하다. 미달이면 추가 유료 확대 없이 종료한다.
- 라벨별 오류 문구를 보고 안내를 다시 고치는 반복 최적화는 하지 않는다. 이미 관찰한 자료 반복 사용의 과적합 위험이 있으므로 점수 상승을 일반화 개선으로 확정하지 않는다.
