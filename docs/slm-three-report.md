# 한국어 SLM 3종 — 추가 학습 없는 CPU 판정 비교

2026-09-29. **세 모델 다운로드와 비교 완료. 모두 운영 미채택이며 HCX 운영 코드는 변경하지 않았다.** 최종 집계는 `comparison-v4`만 사용한다.

## 조건과 평가 범위

- Ryzen 7 8845HS, RAM 약 32GB. CPU 8스레드, GPU offload 0, llama.cpp b11217. 모델별 순차 실행.
- Q4_K_M GGUF 추론 가중치. EXAONE/Bllossom은 개발팀 배포본, Kanana는 mradermacher 커뮤니티 변환본. 원본 BF16이나 학습용 체크포인트를 설치한 것은 아니다.
- 공통 한국어 분류 지시문, 모델별 공식 Jinja 템플릿, 단일 대상, context 4096, temperature 0/seed 42, 비추론, 출력 상한 32. GBNF로 JSON 라벨 0~3만 허용한다.
- 개발 자료 204개: 광고 64, 예방·교육 인용 38, 일반 정상 65, 근거 부족 37. 광고 이진 F1은 확정된 167개로 계산한다. 근거 부족 37개는 별도 집계한다.
- 추가 실제 정상 17개는 사용자 검수를 마친 3개 페이지의 요소다. 광고 사례가 없어 오탐 수만 보고한다. 1/2 세부 라벨 정답으로는 사용하지 않는다.
- 각 모델 221개 본 측정 + 고정 12개 반복 + 형식 확인용 정상 문장 1개. 스모크는 점수에서 제외한다. 캐시 재사용은 없다.
- 이미 관찰한 개발 자료를 이용한 진단이다. 봉인된 최종 평가에는 접근하지 않았다. 크롤링·DOM 기법 검증·25분 종단 평가가 아니다.

### 관찰한 병목

- **EXAONE:** 광고 64개 중 62개를 찾지만 정상 103개 중 79개를 오탐한다. 예방 인용 38개 중 36개가 광고로 분류됐다. A의 기존 정탐 2개를 잃고 누락 15개를 회복했지만, 오탐 증가 때문에 F1 우위가 없다. 빠른 속도와 높은 재현율을 정상 문맥 이해 능력으로 해석하면 안 된다.
- **Kanana:** 수정된 연결에서도 개발 204개와 실제 정상 17개를 모두 광고로 분류했다. 이는 전체 광고 예측이라는 퇴행적 결과이며 재현율 100%가 실용적 장점은 아니다. 현 변환본·프롬프트·제약 출력 조합은 부적합하다. 원본 모델 자체의 한계로 단정하려면 미양자화/다른 변환본 및 자유 출력 대조가 추가로 필요하다.
- **Bllossom:** 오탐은 7개로 가장 적지만 광고 32개를 놓친다. 누락은 일반 정상 15개, 예방 인용 3개, 근거 부족 14개로 나뉜다. 앞뒤 문맥이 사설 슬롯 모집이라고 명확히 밝혀도 짧은 대상 권유를 정상으로 판단하는 사례가 남았다. ownership44 F1 36.36%로 귀속 문맥 처리의 편차가 크다. A의 정탐 20개를 잃고 누락 3개를 회복했다.
- 근거 부족 37개의 광고 확정은 EXAONE 19, Kanana 37, Bllossom 1개다. 올바른 보류는 각각 0, 0, 4개다. Bllossom도 나머지 대부분을 정상으로 확정하므로 불확실성 처리가 해결된 것은 아니다.

## 판단

**이번 조건의 F1 순위는 Bllossom > EXAONE > Kanana지만, 운영 교체는 모두 보류한다.** Bllossom은 정상 구별의 일부 장점이 있으나 재현율 50%와 귀속 문맥 실패가 커 HCX 대체 근거가 없다. EXAONE의 높은 재현율은 큰 오탐과 함께 발생했다. Kanana는 현재 조합에서 유효한 분류기로 작동하지 않았다.

이 결과만으로 추가 파인튜닝 성공 가능성이나 HCX 대비 우월성을 주장하지 않는다. HCX를 동일 입력으로 새로 호출하지 않았고, 대회 4종 관찰 기법의 수집·위치 판정까지 평가한 결과도 아니다. 후속 검증을 한다면 학습 규모 확대보다 모델별 입력/라벨 계약과 자유 출력 대조를 먼저 확인할 가치가 있다.
