# 깊은 영역 발견 실패 원인 진단

2026-09-23. **이번 정적 합성 자료에서는 링크 수집 누락보다 경유 페이지의 선택 지연이 원인이다.** 50요청에서 FIFO·Bandit 모두 깊은 광고 주소를 아직 발견하지 못했다. 해당 주소가 이미 대기열에 들어와 있는데 검사하지 않은 상황과 구분한다. 경유 주소는 대기열에 정상 등록되어 있었다.

운영 정책·판정기·테스트 사이트는 수정하지 않았다. 원본 120회 순서 재현과 보상 제거 30회를 오프라인 실행했으며 HCX·외부 서비스 호출은 0회다. 계획: `navigation-depth-diagnostic-plan.md`.

## 검증과 범위

- 기존 6개 사이트 × 5링크 순서 × 4정책 = 120회 전체 요청/방문/보상/그룹 기록이 저장 결과와 일치했다. CPU 시간 필드는 비교하지 않았다.
- 원본 manifest 959개 파일의 해시를 실행 전후 확인했다.
- 786개 HTML의 실제 anchor href 2,430개와 저장 스냅샷의 링크 순서가 모두 일치했다. 전체 정적 그래프가 진입점에서 연결되고 전체 실행에서 모든 페이지를 방문했다.
- Bandit은 별도 추적 계산으로 각 요청의 UCB 점수, 동점 시 먼저 등록한 URL 선택, 매 5번째 FIFO 선택이 실제 기록과 일치함을 검증했다.
- 그래프 전체·정답은 사후 진단에만 사용했다. 기본 스케줄러에는 요청한 페이지 관측치만 전달했다.
- 이는 이전에 관찰한 합성 자료의 회귀·원인 진단이다. 실제 기관의 동적 링크·폼·인증·iframe 수집 능력, LLM 정확도와 종단 지연을 새로 검증한 것이 아니다.

## 1. 누락 단계 분해

50요청 시점의 깊은 영역 광고 상태. 분할별 광고 24위치(3사이트 × 8위치)를 링크 순서 5회로 반복한 **120개 관측**이다. 독립 광고 120개가 아니다.

| 분할 | 정책 | 방문 완료 | 주소 발견 후 대기 | 주소 자체 미발견 |
|---|---|---:|---:|---:|
| 개발 | FIFO | 0 | 0 | 120 |
| 개발 | 기존 우선순위 | 10 | 30 | 80 |
| 개발 | 하이브리드 | 17 | 25 | 78 |
| 개발 | Bandit | 0 | 0 | 120 |
| 확인 | FIFO | 0 | 0 | 120 |
| 확인 | 기존 우선순위 | 0 | 0 | 120 |
| 확인 | 하이브리드 | 0 | 4 | 116 |
| 확인 | Bandit | 0 | 0 | 120 |

FIFO·Bandit의 미발견은 링크가 없거나 잘못 파싱된 결과가 아니다. 해당 링크를 담은 중간 페이지를 아직 방문하지 않은 결과다. 각 대상의 실제 최초 발견 부모 경로에서 첫 미방문 페이지는 이미 알려진 대기 URL이었다. 확인 사이트에는 교차 링크가 있으므로 기록한 최초 발견 경로를 유일한 경로로 해석하면 안 된다.

## 2. FIFO: 얕은 영역의 폭 때문에 생긴 구조적 지연

시작 페이지를 깊이 0으로 정의한다. 개발 사이트의 깊은 광고는 최단 거리 5~7, 확인 사이트는 6~8이다. 확인은 긴 안내 경로 외에 교차 링크 지름길도 있어 생성기에 적힌 안내 단계 수만으로 거리를 세지 않았다.

- 개발: 깊이 0~4에 1 + 8 + 32 + 32 + 26 = **99페이지**. FIFO가 깊이 5의 첫 페이지를 요청할 수 있는 시점은 최소 **100번째**다.
- 확인: 깊이 0~5에 1 + 4 + 8 + 32 + 32 + 28 = **105페이지**. 깊이 6은 최소 **106번째**다.

즉 이 자료에서 50요청 FIFO의 깊은 광고 도달 0은 필연적이다. 단순한 처리 속도나 HCX 판정 문제로 설명할 수 없다. 페이지 요청 수 예산을 기준으로 한 결과이며 실제 시간 예산 효과와 구분한다.

| 분할 | FIFO 첫 깊은 광고 평균 요청 | Bandit 첫 깊은 광고 평균 요청 |
|---|---:|---:|
| 개발 | 101.07 (100~103) | 98.13 (96~102) |
| 확인 | 107.53 (106~110) | 104.80 (101~109) |

Bandit은 평균적으로 조금 먼저 도달했으나 깊은 경로를 조기에 여는 수준은 아니었다.

## 3. Bandit: 그룹 선택과 경로 진행은 다르다

실험 구현은 DOM 태그 경로로 링크를 묶는다. 안내 링크·목록 이동·교차 연결은 대부분 `html>body>main>nav>a|0`이라는 **동일한 그룹**이다.

같은 그룹의 대기 URL은 UCB 점수가 같고, 동점에서는 먼저 발견한 URL을 선택한다. 안내 페이지를 방문해 다음 안내 링크가 생겨도 그룹 대기열 뒤로 들어간다. 따라서 한 경로를 연속해서 진행하기보다 다른 목록 이동 링크들까지 먼저 처리한다. 매 5번째 FIFO도 가장 오래된 대기 URL을 고르는 장치이며, 특정 경로를 연속 진행하도록 보장하지 않는다.

보상이 상세 본문 도달에 주어지므로 안내 그룹이 다른 그룹보다 덜 선택되는 구간도 관찰했다. 개발의 첫 50요청 동안 15회 실행을 합산하면 안내 그룹 선택 197회 중 150회가 고정 FIFO 슬롯이고 UCB 선택은 47회였다. 확인에서는 275회 중 FIFO 150회, UCB 125회였다. 다만 이것만을 단독 원인으로 확정하지 않았다.

### 실제 한 경로의 방문 순서

개발 `dev-101`, seed 0에서 같은 광고까지 도달한 요청 번호:

| 경로 | FIFO | Bandit | 하이브리드 |
|---|---:|---:|---:|
| 메인 | 1 | 1 | 1 |
| 안내 1 | 6 | 20 | 6 |
| 안내 2 | 30 | 50 | 12 |
| 안내 3 | 62 | 85 | 22 |
| 게시판 목록 | 90 | 98 | 31 |
| 광고 글 | 102 | 102 | 43 |

Bandit은 안내 2를 방문한 50번째에 안내 3 주소를 정상 발견했지만, 그 시점 동일 그룹 대기 8개 중 마지막이었다. 안내 3 방문은 85번째였다. 50번째 직전 안내 그룹 UCB는 0.810, 대기 중 두 본문 그룹은 1.701과 1.755였다. 이 요청은 강제 FIFO 슬롯으로 안내 2를 골랐다.

이 예는 인과 경로를 설명하는 진단 사례이지 하이브리드 채택 근거가 아니다. 기존 전체 평가에서 하이브리드는 다른 영역의 도달 감소와 사전 관문 실패가 있었다.

## 4. 보상만 제거해도 해결되는가

사이트·링크·DOM 그룹·정책을 고정하고 스케줄러에 주는 `detail`만 모두 false로 바꿔 모든 보상을 0으로 만들었다. 30회 모두 전체 방문 집합을 보존했다. 보상 때문에 생긴 선택 효과를 분리하는 대조이며 보상 0을 새 정책으로 권장하는 실험이 아니다.

| 분할 | 원래 첫 깊은 광고 평균 요청 | 보상 0 평균 요청 | 두 조건의 50요청 깊은 광고 |
|---|---:|---:|---:|
| 개발 | 98.13 | 98.47 | 모두 0 |
| 확인 | 104.80 | 104.53 | 모두 0 |

모든 광고 기준 50요청 평균 도달 개수는 개발 8.53→8.47, 확인 7.67→7.67이다. 보상을 없애도 깊은 경로 지연은 남았다. **본문 보상만 탓하고 보상 수치만 조정하는 접근은 근거가 약하다.** 그룹 구분과 그룹 내부 동점 선택, 페이지 연결 구조가 함께 관여한다. 각각의 기여도를 완전히 분리하는 추가 실험은 하지 않았다.

## 판단과 다음 검증 방향

확인된 것은 (1) 정적 링크 보존, (2) FIFO의 깊이별 전체 처리 때문에 발생하는 예산 초과, (3) Bandit의 같은 그룹 내부 FIFO 처리와 중간 경로 지연, (4) 보상 제거만으로 해결되지 않음이다. 숨겨진 광고를 읽고도 놓치는 LLM 오류를 이번 원인으로 판단하지 않는다.

다음 개선 후보를 검토한다면 **작은 요청 몫으로 선택한 경로를 제한된 횟수 연속 탐색하고, 나머지는 기존 탐색에 남기는 방식**을 독립 비교할 가치가 있다. 모든 경로를 깊이 우선으로 바꾸거나 안내 문구에 점수를 더 주는 수정은 이번에 시행하지 않았다. 연속 진행은 잘못된 가지에 예산을 쓸 수 있으므로 전체 광고 도달률·기존 양성 손실·영역 편중·중복/순환을 함께 검증해야 한다. 아직 효과를 확인한 구조는 아니다.

**과적합 주의:** 각 분할의 3사이트는 깊이별 페이지 수가 동일하며 같은 생성 규칙을 공유한다. seed 변형과 문구·링크 순서 차이를 독립적인 실사이트 다양성으로 해석하면 안 된다. 깊이 5/6, 특정 안내 문구, 특정 DOM 그룹에 전용 가산점을 주면 이 자료에 맞춘 개선이 될 수 있다. 다음 개선 실험은 사전 기준과 다른 폭·깊이·교차 링크·정상 막다른 경로를 가진 별도 구조가 필요하다.

실제 탐지 F1과 일반화 성능 개선은 이번에 주장하지 않는다. 정책 수정이 없어 기존 탐지 동작을 변경하지 않았으며 추가 API 비용은 없다. 원래 2·3단계의 미해결 판정 문제는 그대로 남는다.
