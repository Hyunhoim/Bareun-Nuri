# 1순위 문맥 귀속 재검증 계획 — 2026-09-25

운영 FIFO/브라우저 재사용/HCX-007 none/최대16개 순차 배치를 고정한다. 기존76개는 회귀용이다. 동일 예방 문구에 반복 조정하지 않는다. 추가 유료 실행 전 이 계획과 소스/자료 해시를 고정한다.

## 가설과 변경

가설: 주변 문맥을 나열하는 대신 판정 대상·DOM 문맥 경계·앞뒤 원문·인용 여부·잘림 여부를 구분하면 근거 귀속이 개선된다. DOM 경계는 동일 작성자를 입증하지 않으므로 소유권을 확정하거나 광고/정상을 코드로 추정하지 않는다.

A는 현재 운영 최초 입력, B는 같은 입력에 간결한 구조 문맥 필드를 추가한다. 프롬프트/출력/원문/순서/모델은 동일하다. 기존 필드를 삭제하거나 새 데이터에 맞춰 임계값을 조정하지 않는다. 생성된 관계 설명은 구조의 뜻만 명시하며 광고 의도 결론을 넣지 않는다.

두 번째 요인은 기존 독립 관찰 모듈의 오프라인 통합이다. A와 B 양쪽에 똑같이 적용한 A+관찰/B+관찰을 비교하여 의미 변경과 기법 변경을 구분한다. 이는 LLM에서 기법 출력을 제거한 의미 전용 모델 실험은 아니다. 관찰된 사실로 광고 의도를 변경하지 않으며 미확정/부분 위치는 별도 기록한다. 새 관찰 알고리즘이나 숫자 치환 예외를 추가하지 않는다.

## 자료

새 로컬 HTML 개발32개/확인32개: 정상 예방 인용, 예방 문구 옆 실제 광고, 다른 댓글의 예방 설명 옆 광고, 다른 댓글의 광고 옆 정상 글, 문맥으로만 의미가 드러나는 링크, 근거 부족 링크, 직접 광고, 정상 안내의8상황 × 문자 닮은꼴/자모/투명/화면 밖4기법. 제목·본문·링크·댓글 등 요소와 조상/인라인 구조를 바꾼다. 개발/확인은 문구와 템플릿을 분리하고 전부 실행 전 확정한다. 같은 제작자의 합성 확인 자료이므로 완전 독립 실사이트 홀드아웃으로 주장하지 않는다. 정답은 HTML/LLM 입력에 넣지 않는다.

새64개는 모든 대상에 의미/관찰 기법/검토 정답을 기록한다. 불확실4개씩은 정상으로 간주하지 않고 별도 평가한다. 기존76개의 기법 라벨은48개만 있으므로 분모를 혼용하지 않는다. 새 확인 자료의 수집 위치·원문 검증은 허용하되 모델 결과를 보기 전 후보 소스를 고정한다.

## 실행 및 사전 관문

1. 실제 브라우저로 두 세트를 수집·저장하고 원문/selector/관찰 근거를 확인한다. 수집에서 누락되면 판정 오류와 구분하고 자동으로 새 추출 규칙을 덧붙이지 않는다.
2. 회귀76+개발32에서 A1→B→A2를 실제 호출한다. 입력 동일성/원본 요청·응답/usage를 저장한다. 관찰 통합은 추가 API 없이 별도 계산한다.
3. B가 각 자료에서 공통 기준선 정탐 손실0, FP 증가0, 의미F1 비감소, 정상 검토 전환 증가0, 근거 부족 검토 정확도 비감소를 충족해야 확인32로 진행한다. 회귀/개발 합산 FP 또는 FN 최소1건 감소가 필요하다. 호출 증가0, 토큰·지연은 느린 기준선 대비20% 이내다. 의미 관문에서 실패하면 종료하고 미사용 확인 자료는 남긴다.
4. 확인32는 B→A1→A2 순서로 동일 기준을 적용한다. B 단독 또는 B+관찰의 기법 정답/요소×기법 F1은 각 자료에서 기준선보다 낮으면 안 된다. 숫자 미확정·범위 누락을 정상으로 숨기지 않는다. 새 관찰 근거가 없는 과거 대상은 미검증으로 남겨 전체 통합 채택하지 않는다.
5. 모두 통과한 경우에만 소스 고정/별도 실행 계획 후 동일25분 FIFO 종단 비교로 진행한다. 첫 구간 전체 정답 기준 정탐 보존·FP 비증가·정탐 증가, 자원 보호/재개를 확인한 뒤 채택한다. 진단 점수만으로 운영에 반영하지 않는다.

최초 유료 상한40시도/예약 포함550,000토큰/1시간, 자동 전송·형식 재시도 없음. 중단/미응답은 원본을 보존하고 무조건 재실행하지 않는다. 관문 실패 후 같은 자료로 새 프롬프트·규칙 조정은 하지 않는다. 회귀·독립 확인·기법·검토·비용/지연을 분리 보고한다.
