# Structured Outputs 출력 안내 정리 실험

2026-09-30. **출력 안내 정리안은 미채택, 현재 운영 유지.**

## 실험

사전 계획 `output-contract-plan.md`를 고정한 뒤 A-B-C-C-B-A로 실행했다. A는 현재 prompt JSON, B는 기존 Structured Outputs, C는 Structured Outputs의 출력 안내만 정리한 조건이다. 기본 의미 지시·후보 입력·분류 기준·API 스키마는 B/C 사이 동일함을 실제 요청으로 검증했다. 기존 안내에 명백한 모순이 있다는 증거는 없으며, 이번 비교는 명확화 가설의 검증이었다.

C에서 기존 출력 안내를 다음 문장으로 교체했다.

> 출력 형식은 API에 지정된 JSON 스키마를 따른다. decisions에 입력 node_id 각각의 publication_act를 기록하고 모든 후보를 빠짐없이 포함한다. JSON 외 설명이나 코드 블록은 출력하지 않는다.

기존 Phase1 완료 묶음의 해시순12개와 나머지 모델 입력 중 최단3/최장3개를 선택했다. 18묶음·158후보이며, 지정 정답76개(광고36/정상40)만 의미 F1 계산에 사용했다. 미라벨82개를 정상으로 계산하지 않았다. 후보 수1/2/3/4/12, 사용자 입력 JSON 길이786~5,701문자였다. 이전 비교의18묶음과 구성이 달라 과거85.58%와 이번81.82%를 운영 성능 하락으로 해석하면 안 된다.

각 조건2회·36요청, 총108요청이다. HCX-007·none·온도0·seed42·출력512·예약58k를 유지했다. 실패160번째 요청은 제외했고 재전송하지 않았다. 자료는 소비된 Phase1 합성 회귀 자료이며 독립 최종 평가나 실제 사이트 전체 성능이 아니다.

### 입력 범위별 진단

아래는 두 반복 합산 TP/FP/FN이다.

| 범위 | A | B/C |
| --- | --- | --- |
| 해시순12묶음 | 62/28/0 | 62/32/0 |
| 최단3묶음 | 4/0/0 | 4/0/0 |
| 최장3묶음 | 6/4/0 | 6/16/0 |

각 회차 추가 오탐8개 중6개는 긴3묶음에서 발생했다. 하지만 긴/짧은 묶음의 내용·라벨 분포도 다르므로 길이가 원인이라는 인과 결론은 아니다. 짧은 묶음의 정답 표본도 매우 작다. 이 실패 문구를 보고 추가 프롬프트 보정은 하지 않았다.

108응답 모두 finish_reason=stop이며 최대 출력350토큰으로 이번에는512 잘림이 없었다. 형식 오류가 모든 조건에서0이므로 희귀 누락을 얼마나 줄이는지는 이번에도 확인하지 못했다. 정상 완료 이력이 있는 입력을 골랐다는 한계도 유지한다.

## 결정과 한계

사전 확대 기준 중 F1 하락1%p 이내·새FP1개 이하·중앙지연20% 이내를 C가 통과하지 못했다. 따라서 추가25분 유료 실행 없이 종료하고 운영 변경은 하지 않았다. 짧은 ID도 이번에 함께 변경하지 않았다. 출력 길이 감소용 별도 가설일 뿐, 이번 오탐 증가를 해결할 근거로 보지 않는다.

관측 결론은 **현재 요청에서 출력 안내를 명확히 하는 작은 수정만으로 Structured Outputs의 정확도·지연 손해가 복구되지 않았다**는 것이다. 모델 내부 원인이나 공식 기능의 일반적 우열을 확정한 결과가 아니다. 이미 본 합성 자료를 반복 조정하면 과적합 위험이 있어 동일 오류에 맞춘 안내 재작성으로 확장하지 않는다. 다음 운영 신뢰성 개선은 원래 응답을 보존하는 요청 단위 격리의 처리량·재개 계약 검증이 더 직접적인 후보다.
