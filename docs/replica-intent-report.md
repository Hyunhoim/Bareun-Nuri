### 쿼리 순서로 발생한 집계 오류

초기 감사는 주입5개를 수집0개로 잘못 집계했다. 원본 정답 경로의 `srchCtgry` 위치와 실제 요청 URL의 쿼리 순서가 달라 원문·selector가 같아도 문자열 키가 달랐기 때문이다. 봉인된 서버는 두 주소 모두 `canonical(cfg.source+req.url)`로 같은 catalog `source_id`에 연결해 정확히 같은 저장 HTML을 제공한다. 이를 확인한 뒤 **해당 로컬 복제본 catalog에 존재하는 동일 서버 경로에 한해서** 평가 키를 연결했다. 쿼리 값과 중복 매개변수 순서는 보존하며 실제 worker URL·정답·응답·판정·HTML을 바꾸지 않았다.

### 동일 대상 판정의 차이와 검토 부담

종단에서 실제 판정한 광고 원문은 `B3T 사설현금도박참여문의`이며 `일반정보`로 처리됐다. 같은 대상은 앞선 개발 role16 패널에서는 `이용권유`였다. 두 실제 요청에서 **node_id를 제외한 initialEvidence 전체와 대상에 귀속된 문맥은 동일**함을 확인했다. 그러나 대상 ID, 동반 배치 후보, 실행 시점이 다르다. 따라서 배치 구성에 민감할 가능성은 있지만 배치 하나만을 원인으로 확정하지 않는다. 비교 요청은 종단155번째와 패널2번째이며 원본 입력 비교는 `.runtime/replica-final-independent-check.json`에 남겼다.

## 최종 판단과 다음 개선 우선순위

**이번 후보는 모두 미채택이며 운영 소스는 변경하지 않았다.** role16의 미사용 확인 점수 상승과 처리량2.30배는 인정한다. 그러나 개발·기존회귀의 판정 손실, 모호 입력 정상 확정, 같은25분의 정탐 순이득0, 토큰2.17배를 종합하면 운영 교체 근거가 부족하다. role4도 확인의 두 번째 순서에서 운영보다 광고2개를 더 놓쳤다. 범주 확대·출력512·보조 읽기·명사형 정의는 일관된 광고 누락 개선을 보여주지 못했다. 실패 문구를 예외 처리하거나 관측한 확인 자료에 맞춰 재조정하지 않고 사전 계획의 두 개발 라운드에서 종료했다.

1. **초기 대형 페이지의 후보 처리 대기:** 가장 큰 종단 병목이다. 후보가 받은 광고28개 중25개는 방문 대기,2개는 수집 후 미판정이었다. 다음에는 FIFO URL 순서를 유지하면서 페이지별 미판정 작업을 어떻게 나누어 진행할지 독립 검증할 가치가 있다. 이는 아직 구현·채택한 정책이 아니며 메뉴·작성자·로그인·무신호 후보를 자동 제외하자는 뜻이 아니다. 모든 대기·완료 판정과 재개 상태를 보존해야 한다.
2. **실제 배치에서의 문맥 적용 안정성:** 저장 패널에서 잡힌 같은 대상이 종단에서 누락됐다. 배치 동료·ID·반복 변동을 각각 통제하고 기존 정탐·정상 인용·미사용 표현을 함께 비교해야 한다. 이번의 단일 원문을 고치기 위한 프롬프트 예외는 추가하지 않는다.
3. **불확실성과 기법 검토:** 모호 입력을 정상으로 확정하는 문제, 숫자 치환 미확정, 복제본 스타일/클리핑 진단은 남는다. 의미 F1 상승이나 보류 수 감소만으로 해결을 주장하지 않는다. 앵커 자체 href 보완은 API0 수집 검사만 수행한 별도 미적용 후보이며 판정 성능 개선으로 채택하지 않았다.

새 확인 자료도 이제 관찰한 자료다. 같은 생성자·제한된 문구군·동결된 실제 DOM이라는 과적합 및 외적 타당성 한계를 유지한다. 원격 사이트 전체 F1, 동적 댓글·로그인·원본 iframe·전체 스타일 동작은 이번 결과로 증명하지 않는다.

운영 `judgment.cjs`/`worker.cjs`가 실행 전 해시와 동일함을 확인했다. 기존 `npm.cmd run test:judgment --prefix agent`, 첫·둘째 실험 계약 selfcheck, 평가기의 로컬 URL 별칭/쿼리 값/중복키 순서/수집후미판정FN 회귀검사를 통과했다. 후보 실제 worker를 사용한 API0 모의 전송 검사에서는 부분 종료→재개와 중단 없는 결과가 같고 완료 판정·최초 시각·구간 결과·미방문 URL을 보존했다. 실제 세25분 실행은 모두30분 안에 저장·종료했고 미확인 전송0이었다. 유료 재개 성능을 추가 측정한 것은 아니다.

평가기와 데이터·별도 실험 실행기 및 보고서를 남겼고, 미채택 운영승격안은 `.runtime/replica-role16-production-proposal`에 미적용 상태로 보관했다. 실험의 모든 원본을 보존했으며 추가 유료 호출·공개 서버·push는 하지 않았다.
