# 탐색 정책·Sitemap 발견 경로 실험 결과

2026-09-23. **두 실험을 완료했고 기본 정책 교체는 보류한다.** 경량 Bandit은 새 6개 사이트의 각 예산에서 사이트별 평균 도달률이 FIFO보다 높아 가장 유망했지만, 개발 분할의 개선 폭이 사전 효과 기준에 못 미쳤다. 영역별 하이브리드와 Sitemap 보강은 회귀도 확인했다. 조건/보상/비율을 결과에 맞춰 조정하지 않았다.

이번 결과는 **광고 위치 도달률**이며 실제 탐지 재현율·정밀도·F1이 아니다. HCX 호출은 0회다. 도달한 광고를 모델이 모두 판정한다고 가정하지 않는다. 후속 실제 LLM 평가 진입 관문이 모두 통과되지 않아 유료 평가로 확대하지 않았다.

## 자료와 조건

- 새로운 개발 사이트 3개 × 127페이지, 확인 사이트 3개 × 135페이지. 총 786페이지, 광고 144개/정상 1,008개 라벨(각 사이트 광고 24개, 정상 168개).
- 기존 혼합 사이트 40+40페이지는 회귀·진단에만 사용했다. 전체 866페이지와 정답 위치/원문 1,272개를 실제 Edge DOM으로 읽어 대응을 확인했다.
- 개발은 8개 메뉴의 목록 구조, 확인은 공유 경유 메뉴·교차 링크·더 깊은 경로다. 새 사이트에 정상 게시판 2개, 이용자 게시판 2개, 안내/공지 각 1개, 깊은 게시판 2개를 배치했다. 제목·본문·공지 댓글·정상 예방 인용과 4종 위장 표현을 포함했다.
- 각 사이트의 원래 링크 순서와 seed 11/23/37/51의 순서 변형을 공통 적용했다. 새 분할별 표의 수치는 3사이트 × 5순서의 평균이다. 반복은 독립 사이트 15개가 아니다.
- 시작 URL을 포함한 20/50/100 문서 요청을 비교했다. Sitemap robots/XML/404도 같은 예산에 포함했다. CSS·이미지 등 브라우저의 모든 하위 요청을 재현한 값은 아니다.
- 정책 160회, Sitemap 보강 120회, 총 280회 오프라인 탐색을 실행했다. FIFO 결과를 Sitemap 대조군으로 재사용했다. 소스·자료 959개를 manifest로 고정한 뒤 조건 사이 수정 없이 실행했다.

## 실험 A: 정책

FIFO와 기존 우선순위는 원래 로직을 유지했다. 하이브리드는 최초 발견 가지별 방문량을 기준으로 3회 집중/1회 발견/1회 FIFO를 순환한다. Bandit은 일반화한 DOM 링크 경로별 UCB와 매 5번째 FIFO를 사용한다. 보상은 구조적으로 상세 본문/댓글이 있고 본문 지문이 새로우면 1이며, 광고 정답·HCX 판정은 사용하지 않는다. 둘 다 페이지를 영구 제외하지 않는다.

| 분할 | 정책 | 20요청 도달률 | 50요청 도달률 | 100요청 도달률 |
|---|---|---:|---:|---:|
| 개발 | FIFO | 9.44% | 31.67% | 68.61% |
| 개발 | 기존 우선순위 | 8.33% | 25.83% | 67.50% |
| 개발 | 영역별 하이브리드 | 8.33% | 30.28% | 67.78% |
| 개발 | 경량 Bandit | **13.06%** | **35.56%** | **70.00%** |
| 확인 | FIFO | 4.72% | 26.39% | 63.06% |
| 확인 | 기존 우선순위 | 7.78% | 30.00% | 63.61% |
| 확인 | 영역별 하이브리드 | 5.56% | 27.22% | 63.06% |
| 확인 | 경량 Bandit | **10.56%** | **31.94%** | **65.56%** |

Bandit의 FIFO 대비 차이는 개발 +3.61/+3.89/+1.39%p, 확인 +5.83/+5.56/+2.50%p다. 새 6개 사이트의 5회 평균은 세 예산 모두 양수였다. 확인용의 첫 광고 도달은 평균 FIFO 19.93번째 요청, Bandit 12.73번째 요청이었다. 개별 실행이 모두 우월하거나 모든 기존 양성을 보존했다는 의미는 아니다.

개발에서 같은 예산의 FIFO가 도달한 광고 중 Bandit이 놓친 위치는 실행당 평균 20/50/100요청에서 0.07/0.13/0.20개였으며 한 실행의 최대 손실은 2개였다. 확인에서는 이 손실이 세 예산 모두 0개였다. 합산 이득과 기존 위치 보존은 구분한다.

사전 관문은 각 분할에서 (1) 20요청 평균 비감소, (2) 세 예산 중 두 지점 이상 평균 +5%p, (3) 어느 사이트/예산에서도 평균 -5%p 초과 회귀 없음이다. Bandit은 **확인 분할 통과, 개발 분할 효과 크기 미통과**다. 이를 효과 없음으로 해석하지 않는다. 관문을 낮춰 채택하거나 결과를 본 뒤 보상을 바꾸지는 않는다.

하이브리드는 개발 50요청에서 -1.39%p, 한 사이트에서는 -5.83%p로 회귀했다. 확인의 초기 이득도 +0.83%p에 그쳤다. 기존 우선순위는 개발 20요청에서 한 사이트 평균 -13.33%p였다. 복잡한 정책이 일관되게 좋아지는 것은 아니었다.

### 어떤 영역에서 달라졌나

50요청의 영역별 광고 위치 도달률:

| 분할 | 정책 | 이용자 게시판 | 일반 안내 | 기관 공지/댓글 | 깊은 게시판 |
|---|---|---:|---:|---:|---:|
| 개발 | FIFO | 41.67% | 56.67% | 50.00% | 0% |
| 개발 | 하이브리드 | 33.33% | 50.00% | 36.67% | 14.17% |
| 개발 | Bandit | 48.33% | 63.33% | 53.33% | 0% |
| 확인 | FIFO | 36.67% | 50.00% | 35.00% | 0% |
| 확인 | 하이브리드 | 32.50% | 56.67% | 41.67% | 0% |
| 확인 | Bandit | 45.00% | 63.33% | 38.33% | 0% |

관측: 개발 하이브리드는 깊은 영역 도달을 늘리는 대신 다른 영역의 도달량이 줄었다. Bandit은 얕은 영역의 도달량을 높였지만 **50요청 내 깊은 영역 문제는 해결하지 못했다.** 확인의 공유 경유 메뉴는 최초 가지 기준 영역 구분과 실제 게시판 영역을 다르게 만들 수 있다. 이는 원인 가설이며 해당 요소만 제거한 별도 실험으로 인과를 입증한 것은 아니다.

보상은 광고가 아니라 문서 구조여서 정상 글이 많은 영역에도 보상을 준다. 제목만 다른 페이지를 본문 지문으로 같게 볼 수도 있다. 현재 결과에 맞춰 보상 조건을 추가하지 않았다.

## 실험 B: Sitemap 보강

FIFO를 유지한 채 시작 페이지 → robots → Sitemap index → URL set 2개를 읽고, HTML 발견 FIFO와 Sitemap FIFO를 1:1 교차 선택했다. 정상적인 Sitemap도 메타데이터 4요청을 소비하므로 20요청에서 검사할 수 있는 페이지는 16개다. 선언이 없는 경우 robots 1요청만 소비한다. URL 확보만으로 방문 완료로 세지 않는다.

표는 같은 분할/예산의 FIFO 대비 도달률 차이(%p)다.

| 분할 | Sitemap 상태 | 20요청 | 50요청 | 100요청 |
|---|---|---:|---:|---:|
| 개발 | 없음 | -1.39 | -0.56 | -1.94 |
| 개발 | 충분함 | -5.28 | -3.33 | +6.39 |
| 개발 | 불완전 | -2.50 | +3.89 | +5.83 |
| 개발 | 오래됨 | -5.28 | -7.22 | -23.06 |
| 확인 | 없음 | -0.56 | -0.28 | -0.56 |
| 확인 | 충분함 | +1.11 | +0.56 | +2.50 |
| 확인 | 불완전 | +1.39 | -0.28 | -2.50 |
| 확인 | 오래됨 | -2.78 | -15.56 | -28.89 |

충분한 목록에서 개발 100요청은 68.61%→75.00%로 올랐지만 20요청은 9.44%→4.17%로 내려갔다. 확인 100요청은 63.06%→65.56%다. 어느 유효 조건도 두 분할의 사전 관문을 함께 통과하지 못했다.

오래된 목록은 100요청 중 평균 404가 개발 30.07회, 확인 31.60회였다. 확인에서 실제 도달한 정상 응답 페이지는 평균 64.4개로 줄었다. 이 조건은 기존 URL 일부와 존재하지 않는 32개 URL을 섞은 의도적인 반례이지 실제 기관 Sitemap의 오류율 추정이 아니다.

**판단:** Sitemap의 잠재적 가치와 현재의 무조건 사전 조회 + 고정 1:1 선택 정책을 구분한다. 이번 정책은 미채택이다. 전체 목록을 무료로 얻거나 404를 예산에서 빼야 좋아지는 것으로 보고하지 않았다. 부산 사이트의 Sitemap 제공 여부나 실제 품질은 이번 실험으로 확인하지 않았다.

## 회귀·안전성·비용

기존 40+40페이지에서 링크 순서 5회 평균 20요청 도달률은 FIFO 23.50%, 기존 우선순위 28.00%, 하이브리드 26.50%, Bandit 24.50%였다. 과거 실제 HCX 점수와 다르며, 프롬프트·모델 성능을 갱신한 것이 아니다. 40페이지 전체 도달은 모두 100%다.

- 기존 FIFO/priority 구현과 **80개 전체 순서 비교 일치**.
- 예산 2/20/50/100에서 중단한 결과가 전체 실행의 동일 요청 접두부와 **224개 비교 일치**. 뒤에 방문할 페이지의 정보로 앞의 순서가 바뀌지 않았다.
- 스케줄러에는 정답 인수가 없다. 읽기 콜백은 요청한 페이지의 관측치만 반환한다. 테스트에서 아직 발견하지 않은 URL 접근을 거부했다.
- URL 중복·범위, Sitemap 외부 호스트, 404 비용, XML 오류/DTD 거부, 임의 id/class의 그룹 특징 유입 방지 검사를 통과했다.
- 280회 모두 끝까지 실행했을 때 정상 페이지 집합이 원래 전체 페이지 집합과 일치했다. 정책별 요청 추적·제외 없는 완료 여부를 저장했다.
- 실제 Edge HTML/XML 자료 준비와 정답 위치 검증 합계 약 **7.20초**. 이후는 메모리 스냅샷 재생이다. 선택 연산 시간은 별도 기록했지만 네트워크·브라우저 실행·HCX를 포함한 종단 지연이 아니다. 실서비스 속도 개선 수치로 사용하지 않는다.
- **추가 LLM 호출 0회, 토큰 0개.** 실제 정밀도·F1, 호출 절감률, 원화 비용 변화는 측정하지 않았다.

최초 기능 검사에서 기본 Playwright Chromium 실행 파일이 없어 실패했다. 기존 프로젝트와 동일한 설치된 Edge 채널로 변경한 후 검사·실험을 실행했다. 사이트나 알고리즘을 성능 결과를 본 뒤 변경하지 않았다.

## 최종 판단과 한계

1. **Bandit:** 이번 후보 중 가장 유망한 관측 결과. 성능 개선 방향은 확인했지만 정해 둔 두 분할 효과 관문 미통과로 기본 적용·유료 확대 보류. FIFO가 더 좋다고 입증된 것은 아니다.
2. **영역별 하이브리드:** 현재 구현은 미채택. 깊은 경로와 다른 영역의 범위 교환이 있고 공유 경유 메뉴에서도 일관된 개선을 확인하지 못했다.
3. **Sitemap 보강 FIFO:** 현재 고정 선택 방식은 미채택. 충분한 목록/큰 예산에서 일부 이득은 있으나 조회 비용·목록 순서·404 위험을 견디지 못했다.

과적합 우려를 실행 전/후 보고했다. 새 개발/확인은 연결 구조를 달리했지만 여전히 같은 제작자·생성기의 합성 자료이며, 반복 DOM은 Bandit에 유리할 수 있다. 3개 사이트의 순서 5회 변형은 실사이트 15개 검증이 아니다. 지금부터 새 확인 분할도 관찰한 진단 자료다. 일반화 개선을 확정하거나 동일 자료에 맞춰 가중치를 조정하지 않는다.

기존 2·3단계의 의도/기법 판정 오류와 운영 worker는 유지했다. 이번에는 탐색 실험 파일과 테스트 사이트·문서만 추가했으며 커밋·push는 하지 않았다.

## 실행·자료

```powershell
node agent/experiments/navigation.test.cjs
node test-set-v4/build.cjs
node agent/experiments/navigation-run.cjs .runtime/navigation-trial-new
```

프로젝트 루트에서 실행한다. 설치된 Edge와 기존 Agent의 Playwright를 사용하며 새 의존성은 없다. 실험 디렉터리는 새 경로여야 한다. 외부 사이트를 접속하거나 API 키를 읽지 않는다. HTML은 브라우저에 로드하고 외부 요청은 차단한다. 현 실행은 서버 HTTP 지연까지 재현하지 않는다.

원본 증거: `.runtime/navigation-trial-v1/manifest.json`, `summary.json`, `metrics.json`, `orders.json`, 각 `*-snapshot.json`, `audit.json`. 감사 스크립트는 `.runtime/navigation-audit.cjs`다. 계획은 `docs/navigation-experiments-plan.md`, 연구 근거는 `docs/crawling-research-2026-09-23.md`에 있다.
