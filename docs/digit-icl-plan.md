# 고정 훈련 예시 ICL 진단 계획

원래 compact S의 SYSTEM·대상 입력·문자 대응 후보·출력 스키마를 유지하고, SYSTEM 끝에 고정 훈련 예시 8개만 추가한다. 중립적인 예시/실제 대상 구분 지시를 함께 붙인다. 실패한 P·M·R·N·mask 지시는 누적하지 않는다. `.runtime/digit-icl-train-v1/training.json`의 순서를 그대로 사용하며 예시 교체·순서 탐색·검색 선택을 하지 않는다. 훈련 정답은 예시에만 포함하고 실제 대상 정답은 요청에서 제외한다. 예시 ID는 모델 입력에서 제거한다. private annotations는 해시로만 봉인하며 요청에 넣지 않는다.

예시는 2개 단어 계열의 순수 치환·혼합 숫자·식별표기·불충분 문맥 각 2개다. 이미 관찰한 v4 전체 48개에 ICL 단일 요청 48회를 실행한다. 기준선은 `.runtime/digit-definition-v4-live-v1`의 두 S 조건이다. 기존 요청·응답·저장 판정과 소스 해시를 재검증하고 재사용하며 동시 재측정으로 표현하지 않는다. 학습 예시는 고정된 훈련 자료이고 v4는 진단 자료로서 새로운 홀드아웃이 아니다.

HCX-007 none, temperature 0, seed 42, 출력 1024, 단일 후보, 58,000 TPM 예약, 1초 간격, 요청 180초 제한을 유지한다. 첫 실행은 48회/최대 60회, 예상 예약 166,057토큰/상한 1,000,000토큰, 조건 10분/전역 1시간, 시작 전 61초 대기를 적용한다. API 오류·잘림·계약 오류의 자동 재호출은 금지한다. 첫 실행 경로는 `.runtime/digit-icl-pilot-v1`이다. API0 dry run은 파일을 만들지 않는다.

첫 진단 관문은 S 대비 strict F1 증가, 정상 FP 증가 없음, 모호 사례 과확정 감소, 혼합 숫자 TP 9/12 이상을 모두 충족하는 것이다. 실험 S의 개별 정탐 손실은 빠짐없이 보고하지만 이 새 진단의 절대 거부 조건은 아니다. 실제 운영 광고 정탐 보존은 후속 운영 채택 검증의 절대 요건이다. 실패한 과거 실험의 기준을 소급 변경하지 않는다.

통과할 때만 동일한 예시·프롬프트·소스·설정으로 역순 48회를 별도 `.runtime/digit-icl-reverse-v1`에서 실행한다. 역순 실행기는 최초 manifest의 모든 해시와 설정 및 관문 통과를 확인한다. 이후에도 유망한 경우에만 별도의 미사용 자료로 확인한다. 실패하면 예시나 순서를 고쳐 재시도하지 않고 이 가설을 종료한다.

비용 증가와 지연을 별도 보고한다. 2개 훈련 계열의 상관성과 합성 문맥의 명시적 식별자·설명 부재 단서에 대한 과적합 위험이 있다. 개선되어도 실제 게시판 문맥이나 사이트 일반화, 광고 의도 정확도, 정확한 단어 복원, 25분 운영 성능으로 확대 해석하지 않는다. compact 출력은 복원 단어를 선택하지 않는다. 운영 코드 변경과 채택은 이 진단에 포함되지 않는다.
