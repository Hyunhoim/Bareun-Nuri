# HCX-007 vs Qwen3.5-2B CPU: 기존 137개 평가

2026-09-28. **현재 운영 HCX 유지. 파인튜닝 전 Qwen으로 전체 판정을 교체할 근거는 없다.** 형식 변환을 허용한 참고 F1도 HCX보다 낮고, CPU 요청 시간은 약 6.1~6.4배 길었다. 운영 코드 변경 없음.

## 조건과 범위

사전 계획 `qwen-hcx-plan.md`에 따라 기존 137개 전체(광고60·정상65·근거부족12)를 같은 입력·문맥·12개 묶음으로 비교했다. 마지막 묶음은 5개다. 정순/역순을 각각 실행했고 두 모델의 실제 system/user 메시지 일치를 검증했다. 근거부족12개는 이진 F1에서 제외하고 별도 보고한다. 137개를 두 번 실행한 것이며 독립274개 표본이 아니다.

- HCX-007 none, temperature0, seed42, 출력512, 순차 요청, 운영58k TPM 제한.
- 공개 Qwen3.5-2B Q4_K_M, 파인튜닝 없음, Ryzen7 8845HS/32GB급 RAM, CPU8스레드, GPU사용0, llama.cpp b11217.
- Qwen 추론off/출력512/순차1슬롯/context16384/cache미사용. 모든 응답 cache_n=0, reasoning 내용0, 출력 잘림0.
- 실행 순서는 HCX정순→Qwen정순→Qwen역순→HCX역순. 모델 요청을 겹쳐 실행하지 않았다. Qwen 프로세스는 HCX역순 동안 유휴 상태로 남아 있다가 마지막에 종료했다.
- HCX24회 신규 호출, Qwen24회 로컬 호출. 과거 HCX 응답을 재사용한 속도 비교가 아니다.

이것은 수집 완료된 저장 후보의 판정 실험이다. 페이지 미방문·수집 누락·25분 예산을 포함한 사이트 전체 F1이 아니다. 기존에 관찰한 회귀 자료이며 `fresh`라는 과거 패널명도 새 홀드아웃을 뜻하지 않는다. 이전153개 실험은 경계16개가 더 있었고 묶음·실제 호출도 달랐으므로 이전93.5%와 그대로 증감 비교하지 않는다.

두 모델 모두 B3T/V1D30의 숫자 치환 기법 미확정은 그대로다. 이번 Qwen은 기존 광고 의도 프롬프트를 받은 모델이며 숫자 치환 전용으로 학습하거나 기법 판정 계약을 새로 추가한 모델이 아니다. 따라서 이 결과를 숫자 치환용 파인튜닝의 효과 검증으로 오인하지 않는다.

Qwen에서 크게 관측된 문제는 예방교육/신고/단속 통계 문구의 오탐, 주변 광고 근거를 날짜·분류·작성자에 옮기는 오탐이다. 예를 들어 단속 통계의 위반 행위 제목, 예방교육의 모집 수법 예시, 광고 옆의 작성 시각을 이용권유로 처리했다. 정상 식별자 처리만의 문제가 아니다.

근거부족12개에서 형식 변환 후 Qwen은 두 순서 모두3개를 광고로 확정하고 명시적 보류는0개였다. HCX는 광고확정0/1개, 명시적 보류1/0개로 이 문제도 완전히 해결하지 못했다.

## 검증과 결정

입력·소스 해시,48개 실제 요청 메시지의 재구성 일치, 원본 응답 재파싱, 모델 판정 ID·중복·enum 검사, 원본 DOM 관찰과 출력 위치 대응을 확인했다. 별도 PowerShell 코드로8개 지표행의 TP/FP/FN·미판정을 재집계했다. 형식 어댑터의 잘못된 enum/ID/중복 거부도 확인했다. 로컬 서버 종료 및18967포트 종료를 확인했다.

**현재 HCX를 유지한다.** Qwen은 CPU 실행 가능성은 확인했지만 전체 판정 대체 성능·속도는 불리했다. 향후 검토한다면 소수 대상의 좁은 역할에 대한 파인튜닝을 별도 평가해야 한다. 학습하면 이번 차이를 해소한다는 보장은 없으며, 같은 오류 문구를 학습하고 같은 자료로 평가하는 방식은 피해야 한다. 이번에는 모델 튜닝·운영 어댑터 추가·자동 채택 없이 종료했다.
