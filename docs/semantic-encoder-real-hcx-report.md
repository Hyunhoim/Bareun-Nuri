# 실제 문맥에서 HCX와 동결 분류기 비교

2026-09-29. **31개 실제 저장 문맥의 HCX 양순서 비교와 세 분류기의 재추론·원응답 감사를 완료했다. 잘림 없는 공통23개에서도 불일치가 크고 높은 확신의 불일치가 남는다. 사람 정답이 없으므로 실제 정확도/F1이나 분류기 누락 수를 확정하지 않는다.** 운영 HCX 유지, Goal 미완료다.

## 같은 입력과 다른 판정

이전 예측 접근 전에 고정한 검수31개를 그대로 사용했다. 세 분류기 모두2개 token-limit/6개 collection-context-truncated, 합계8개를 보류한다. 원래/역순 HCX는 각각31개 전체를 받았으며 주 비교는 공통23개다. HCX4분류의0을 광고,1/2를 비광고,3을 보류로 매핑했다. HCX는 두 순서 모두 보류0개를 출력했지만 이를 근거 충분성의 증명으로 취급하지 않는다.

| 모델 | HCX 원래 순서와 이진 일치 | HCX 역순과 이진 일치 | 원래 순서에서 분류기 비광고/HCX 광고 | 분류기 광고/HCX 비광고 |
|---|---:|---:|---:|---:|
|KLUE|16/23|15/23|7|0|
|Kc|12/23|11/23|11|0|
|Ko|13/23|12/23|9|1|

이 표는 정답률이 아니다. HCX를 정답으로 간주하지 않아 precision/recall/F1/TP/FP/FN을 산출하지 않았다. 같은31개를 두 번 판정했으므로62개 독립 표본도 아니다. 원래/역순의4분류 변화는2/31, 광고/비광고 변화는1/31이다. 어느 순서가 맞는지 아직 확정할 수 없다.

고정.2~.8 진단 보류를 적용해도 원래 순서의23개 중 확정 판정은 KLUE23/Kc21/Ko19개이고, 그 안의 HCX 불일치는7/9/7개다. **모델 확신이 높으면 안전하다는 가정이 이번 비교에서 뒷받침되지 않는다.** KLUE가 이번 일치율이 가장 높다는 이유로 동결 후보를 새로 선택하거나 HCX 대체 대상으로 승격하지 않았다.

같은31개를 새 CPU 프로세스에서 재추론한 결과는 이전2003개에 포함된 각 모델의 hard 판정과 모두 같았다. 이번 불일치를 INT8 변환이나 이전 추론 파일 오류로 돌릴 근거는 없다. 이번에는 원본 PyTorch FP32를 사용했다.

## 관측된 입력 분포 차이

불일치 원문에는 링크 목록, 문자 그대로의 HTML anchor, 일반 문장 뒤의 링크 유도, 영문 문단과 링크의 혼합, soft-hyphen 삽입 등이 있다. 특정 출처·문구를 예외 처리하거나 이번 검수 자료를 훈련으로 옮기지 않는다. 영어 학습처럼 보이는 문구와 불명확한 링크/주변 작성자명만 있는 경우는 대상 귀속·연결 목적 자체가 검수 대상이다. HCX 광고 판정이 모두 옳다고 보지 않는다.

| 관찰 속성 | 증강 전 훈련210 | 실제31 | 실제 공통23 |
|---|---:|---:|---:|
|대상 문구 길이 중앙값|53자|173자|203자|
|문자 그대로의 `<a` 태그|0|7|7|
|URL 문자열3회 이상|0|10|9|
|soft-hyphen 포함|0|1|1|
|`앞 문맥:` 수집기 표기|51|31|23|

URL 수는 `https?://` 문자열 등장 횟수이며 독립 링크 수가 아니다. 훈련210도 독립 출처210개가 아니고97광고/113정상의 증강 전 행이다. 표는 사후 입력 분포 진단이며 이 속성이 오류를 일으킨다는 인과 증명이 아니다. 합성 학습 형식과 실수집 표현 차이에 따른 일반화/선택 과적합 우려를 사용자에게 보고했다. 같은 자료에 맞춘 HTML 제거·특정 URL 치환·임계값 조정은 실행하지 않았다.

다음 개발 우선순위는 이 평가 자료와 출처/캠페인이 분리된 실제 학습 문맥에서 원문·링크 표기·일반 문장과 권유의 혼합을 보존하고, 같은 형식의 정상 사례도 검수하는 것이다. 평가 실패 문장을 변형해 훈련하는 방식으로 대체하지 않는다. 더 많은 synthetic 행이나 더 큰 모델만으로 해결될 것이라 단정하지 않는다.

## 시간·사용량

| 대상31개 처리 | 초 |
|---|---:|
|KLUE CPU FP32|6.35|
|Kc CPU FP32|6.70|
|Ko CPU FP32|6.91|
|HCX 원래 순서|11.82|

CPU는8threads/batch8/워밍업 뒤 추론만, HCX는순차12묶음/none/출력512의 네트워크·예약대기 포함이다. CPU는512토큰 초과2개를 잘라 추론한 뒤 보류하므로 HCX의31개 전체 입력 처리와 완전히 동등한 처리량 비교가 아니다. CPU/HCX의 시간 비율을 운영 가속률로 사용하지 않는다. 페이지 경계를 넘는 표집과4분류 프롬프트이며 실제 운영의 페이지별 판정/25분 종단 검증도 아니다.

총6회, 입력24,442+출력1,228=**25,670확인토큰**. 추정 상한38,945토큰/실험 상한50,000토큰, 전체상한600초 안에서23.49초에 종료했다. 오류·미확인응답·자동재시도0이다. 원화 청구액은 가격표/청구서를 확인하지 않아 산출하지 않았다.

## 감사 및 남은 범위

`local-benchmark/semantic-encoder-real-hcx.cjs`의 dry run으로6회/38,945예약토큰과 스키마 거부를 확인한 뒤 live1회 실행했다. `semantic-encoder-real-compare.py`의 감사에서6요청/6원응답/62판정을 재생하고 동일 target/context·원응답·저장라벨·사용량·가중치/입력 해시를 확인했다. 사람 검수HTML은 변경하지 않았다.

HCX 원응답6개는 완전 JSON을 코드펜스로 감쌌다. 실행 당시 해시를 고정한 현재 운영 parser가 이를 허용했다. 최초 Python 감사의 일반 json.loads는 이를 거부했으므로 운영 parser를 재사용하는 오프라인 감사로 수정했다. 추가 API나 운영 parser 변경은 없다. 추론 당시 Python 원본은 `inference-source.py`로 보존하고 새 감사 코드와 해시를 구분했다. 사람 정답/AI 정답 파일을 만들지 않았으며 감사 실패를 API 실패로 바꾸어 기록하지 않았다.

근거: `.runtime/semantic-encoder-real-hcx-v1/manifest.json`, `comparison.json`, `audit.json`, `distribution-audit.json`, 원응답6개 및각모델예측. 신규 가중치 학습/임계값 조정/운영 변경0이다. 검수31개는 이제 모델 비교에 사용한 관찰 자료이며 새로운 독립 최종평가로 소개하지 않는다. 사람 검수로 정답을 보완하더라도 미사용 최종셋이 되는 것은 아니다.

실제 사람 정답, 도박 외 실제 양성 유형의 폭, 출처/캠페인 독립성, 전체 사이트 recall,25분 종단 성능은 아직 부족하다. 현재 자료로 HCX 대체가 달성됐다고 주장하지 않는다.
