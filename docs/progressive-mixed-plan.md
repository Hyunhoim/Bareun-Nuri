# 점진 실행과 혼합 사이트 비교: 사전 계획

2026-09-23. 운영 worker/프롬프트/판정 계약/배치 16을 고정한다. opt-in 실험 경로에서 구현하며 검증 전 기본 웹 실행을 교체하지 않는다. 기존 2·3단계 오류와 4·5단계 미채택을 유지한다.

## 1. 실행 구조 관문

페이지 단위 수집과 전역 후보 순서의 16개 배치 판정을 교차 실행한다. 페이지별로 잔여 배치를 임의 마감하지 않는다. 탐색 종료 때만 마지막 짧은 배치를 판정한다. 원자적 checkpoint를 권위 원본으로 사용하고 결과는 재생성 가능하게 한다.

완료/부분 완료/실패, 방문·대기·제외 URL, 후보·판정·중단 이유, 누적 호출/활성 실행 시간을 저장한다. 페이지/호출/시간 예산은 누적 한도이며 재개 시 증가시킬 수 있다. 완료 판정은 재호출하지 않는다. 응답 여부가 불명확한 in-flight 판정은 자동 재실행하지 않고 실패로 남긴다. 프로세스 동시 실행을 잠금으로 막고 입력·소스·모델 설정이 바뀐 재개를 거부한다. 미검사 대상을 정상 처리하지 않는다.

짧은 문서의 동일 입력·전역 배치에 대해 기존 일괄 처리와 점진 처리·중단/재개의 요청 body 및 결정적 테스트 응답/최종 findings 일치를 검증한다. 실제 LLM 반복의 응답 동일성을 보장한다는 의미가 아니다. 페이지/호출/시간 중단, 실패 전 결과 보존, 미확정 요청, 원문·위치 귀속을 검사한다.

## 2. 긴 본문: 별도 공통 처리

기존 짧은 후보는 변경하지 않는다. 12,000자를 넘는 후보만 원문 offset과 원래 node_id/selector를 보존하는 최대 6,000 UTF-16 단위 창으로 나누고 약 400단위 겹침을 둔다. surrogate를 절단하지 않는다. 각 창의 원문·정규화·signals를 계산하며 주변 및 본문 시작/끝 발췌를 참고로 전달한다. 출력은 원래 요소 단위로 재결합한다. 창 중 확정 광고가 있으면 해당 기법을 합치고, 확정 광고 없이 불확실 창이 있으면 검토로 남긴다. 이 OR 통합은 문맥 밖 인용에서 오탐 위험이 있으므로 독립 안전 검사와 실제 결과에서 명시한다. 복원/분할을 광고 증거로 간주하지 않는다.

공통 처리의 구조적 보존을 검증한 뒤 세 전략에 동일 적용한다. 사이트별 예외 금지. 의미 판정 개선으로 간주하지 않는다.

## 3. 비교 사이트와 고정 정책

개발 40페이지, 최종 확인 40페이지를 별도 경로·문구·배치·마크업으로 생성한다. 같은 제작자의 합성 자료이며 독립 실사이트 일반화 증거는 아니다. 개발 실행 후 정책을 조정하지 않고 최종 확인을 실행한다. 정답 파일은 서버에서 제공하지 않으며 Agent/LLM에 전달하지 않는다.

메인/중간 메뉴/목록/페이지 이동/깊은 불투명 경로, 이용자 게시판의 광고·정상, 정상 전용 게시판, 일반 안내·관리자 공지의 광고, 관리자 공지에 달린 이용자 댓글, 제목/본문/댓글, 긴 본문·인라인 분할을 포함한다. 광고 위치·라벨을 경로명이나 DOM data 속성에 넣지 않는다.

- FIFO: 최초 발견 순서.
- 우선순위: 기존 priority.cjs의 점수와 매 4번째 oldest 정책 그대로. 재조정하지 않는다.
- 게시판 필터: 우선순위와 같은 선택 순서. 방문한 페이지에서 사용자 참여 안내/작성·댓글 기능이 보이면 user, 관리자 전용 안내가 명확하면 admin, 나머지는 unknown. unknown은 유지한다. admin 목록의 내용 링크(tbody/article 범위)는 후속 상세 탐색에서 제외하고 이유를 기록한다. 관리자 게시글의 댓글은 상세 방문 전에 알 수 없으므로 잘못 제외할 수 있다. 이 위험을 측정하며 숨기지 않는다. 메뉴·중간 경유 링크는 유지한다.

필터 분류는 정답·ID·사이트별 클래스·불법광고 키워드를 사용하지 않는다. 네비게이션 발견과 광고 판정을 분리하되, 선택된 페이지의 텍스트 요소를 메뉴/제목이라는 이유로 일괄 제거하지 않는다.

## 4. 실제 비교와 예산

각 분할·전략에서 최대 20페이지, 누적 API 요청 12회(수정/재시도 포함), 활성 시간 600초. 공통 HCX-007/temperature0/thinking none/seed42/maxTokens3072/배치16/순차 실행. 6개 조건은 한 번씩만 실행한다. 전체 상한 96회·900,000 토큰이며 소스/데이터/설정을 첫 호출 전에 고정한다. 비용 확인이 불가능하면 0으로 계산하지 않고 보수적 예약량 또는 중단을 사용한다.

전체 라벨 분모로 의미 TP/FP/FN/F1/정밀도·재현율을 계산한다. 미방문·미판정·검토 양성은 FN이다. 라벨 밖 양성은 별도로 전수 검토 대상으로 보고하며 그 상태에서 전체 정밀도를 확정하지 않는다. 요소×기법 최종 출력, 유형/위치별 누락, 발견/검사/제외 범위, 호출·토큰·실측 시간도 분리한다. mock 응답은 기능 테스트에만 쓴다.

실험 채택 관문: 먼저 모든 실행·재개 안전성 검사 통과. 전략 변경은 두 분할 모두 기존 확정 양성을 보존하고 FP가 증가하지 않으면서 토큰 또는 시간 10% 이상 절감하거나, 같은 예산에서 재현율 +5%p 이상 및 정밀도 비감소일 때만 후속 반복 평가 후보로 선정한다. 단회·합성 결과로 운영 채택이나 일반화 개선을 확정하지 않는다. 미통과이면 정책 조정 없이 종료하고 기록한다.
