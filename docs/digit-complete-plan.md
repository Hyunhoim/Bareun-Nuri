# 완전 복원 후보만 제공하는 숫자 치환 비교

2026-09-26. 운영 변경 없이 실험한다. 기존 112개 자료는 이미 관찰한 회귀 자료이며 새 홀드아웃이 아니다. 특정 실패 단어를 위한 예외는 추가하지 않는다.

가설: 부분 복원 후보가 선택 부담과 불완전 읽기를 유발한다. D는 기존 모든 부분/완전 읽기 조합, F는 서버가 모든 숫자를 대응 문자로 바꾼 완전 읽기만 제공한다. 1→i/l 등 복수 대응은 남기며, 최대64개 초과는 미확정 후보로 표시한다. 원문 유지 선택은 두 조건 모두 별도로 존재한다. 원문/문맥/ID, 프롬프트, 출력, 묶음 구성, 후처리는 동일하다. 표준명이나 숫자가 원래 의미를 가진 경우까지 완전 복원할 위험을 함께 측정한다. 결과에 맞춰 수정하지 않는다.

HCX007 none/temperature0/seed42/배치4/출력1024/58k/순차실행. 개발 및 기존 평가 분할 각각 D/F 원래 순서, F/D 역순의8조건·112요청을 실행한다. 각 조건 전61초 창 분리, 조건10분/전체1시간, 최대160요청·예약80만토큰. 자동 재시도와 형식 복구는 없다. 미확인 응답/429/소스 변경은 전체 종료한다. HTTP200 형식 실패는 조건 실패로 보존한다. 이미 관찰한 자료이므로 두 분할 모두 회귀이며 두 순서는 동료 변경 없이 묶음 내 순서와 요청 순서만 바꾼다.

사전 판단: 후속 검증 후보로 권하려면 두 분할 평균 기법 F1 및 3분류 macro-F1이 D보다 낮지 않고, 완전 복원 재현율이 적어도 한 분할에서 개선되어야 한다. 정상 확정 오탐과 근거 부족 과도 확정은 증가하지 않아야 한다. 양쪽 순서 손익/기존 정탐 손실/시간/토큰도 별도 보고한다. 실패하면 미채택 후 종료한다. 관문 통과도 바로 운영 채택은 아니며 독립 자료와 실제 운영12배치·25분 조건 검증이 남는다. 추가 프롬프트 튜닝·유료 확대·파인튜닝·push는 이번 범위에 없다.

실제 요청을 사전 추정 body와 대조하고, 소스/입력/정답/계약을 해시로 봉인한다. 정답은 실행기 입력에 포함하지 않는다. 기존 별도 계산기로 점수를 산출하고 혼동행렬 기반 F1과 토큰·ID·후처리를 재검증한다.
