# 숫자 치환 대안 비교 — 두 안 모두 미채택

2026-09-23. **1순위 복원 후보 제거와 2순위 개별 요청 모두 기본 구현에 적용하지 않는다.** 1순위는 출력 계약을 통과하지 못했고, 2순위는 완주한 개발용 분할에서 정상 식별자 오탐이 증가했다. 기본 의미 판정·관찰기·웹 worker는 변경하지 않았다.

## 비교 범위와 계획 보완

기존 dev 44개와 evaluation 44개를 진단 자료로 사용했다. 각각 치환 16개, 실제 식별자 20개, 모호 표기 8개이며 광고/예방 22쌍이다. 이미 분석한 동일 작성자 합성 자료이므로 새로운 홀드아웃이 아니다. 라벨은 채점에만 사용했다.

최초 계획은 `stage-3-digit-ablation-plan.md`다. HCX-007, thinking none, temperature 0, seed 42, 최대 출력 2,048토큰으로 고정했다. 후보 목록이 없는 조건에서도 복원을 출력할 수 있도록 세 조건에 같은 자유 문자열 reading 계약을 사용했다. 이 안에서 후보 목록 제공 여부와 배치 크기만 각각 비교했다. 소스·입력·라벨은 호출 전에 해시로 고정했다.

그러나 자유 출력 대조군 자체가 계약 오류로 완주하지 못했다. 이 상태에서 개별 요청의 효과를 판단하면 새로운 출력 계약의 실패와 혼동된다. 이를 사용자에게 보고한 뒤, `stage-3-digit-batch-plan.md`를 추가로 고정하고 **2순위는 기존 enum 계약을 그대로 사용해 배치 4 대 1을 재확인**했다. 최초 계획부터 이 보완이 정해져 있었던 것으로 주장하지 않는다. 기존 결과를 덮어쓰거나 실패 단어용 프롬프트를 추가하지 않았다.

관문은 분할별 TP >= 14/16, 실제 식별자 literal 20/20 및 FP 0, 모호 표기 uncertain 8/8, 쌍 분류 불일치 0, 치환 확정의 잘못된 복원 0, 대조군에서 탐지한 치환 유지였다. 결과를 보고 기준을 낮추지 않았다.

## 1순위: 후보 목록 제거

| 자유 출력 조건 | dev 유효 저장 판정 | evaluation 유효 저장 판정 | 결과 |
|---|---:|---:|---|
| 후보 제공 / 배치 4 대조군 | 40/44 | 24/44 | 계약 오류 중단 |
| 후보 제거 / 배치 4 | 8/44 | 8/44 | 계약 오류 중단 |
| 후보 제공 / 개별 요청 | 24/44 | 26/44 | 계약 오류 중단 |

숫자 치환을 확정하려면 원문의 영문자를 유지하며 지원하는 숫자→문자 대응으로 복원해야 한다. 후보 제거 조건에서는 `R2D2 → R2-D2`처럼 구두점을 삽입하거나 `S0LO → SOLE`처럼 기존 영문자까지 바꾸는 응답이 나왔고, 1회 재요청에도 해결되지 않았다. 대조군에서는 `B2B`·`B2C`를 치환이라고 하면서 복원 문자열도 원문과 동일하게 반환했다.

따라서 **현재 구현한 후보 제거+자유 출력 방식은 미채택**이다. 목록이 없어도 근거 없는 복원이 발생한 사실은 확인했으나, 양쪽 모두 완주하지 못해 목록 제거의 순수한 정확도 효과나 후보 편향의 인과를 입증하지는 못했다. 부분 성공 사례만으로 전체 F1을 계산하지 않았다. 제한적 재요청 이후 검증 기준을 완화하거나 실패를 정상/미확정 정답으로 바꾸지 않았다.

## 2순위: 기존 enum 계약에서 배치 크기만 비교

완료된 dev 44개에 대한 비교다. F1·정밀도는 **치환 16개와 실제 식별자 20개로 구성된 기법 분류 지표**이며, 모호 표기 8개는 별도 보류 계약으로 평가했다. 광고 의도 F1이나 전체 사이트 탐지 F1이 아니다.

| 항목 | 후보 제공 / 배치 4 | 후보 제공 / 개별 요청 |
|---|---:|---:|
| TP / FP / FN | 16 / 2 / 0 | 16 / 7 / 0 |
| 정밀도 | 88.89% | **69.57%** |
| 재현율 | 100% | 100% |
| 기법 F1 | 94.12% | **82.05%** |
| 모호 표기 보류 | 1/8 | **0/8** |
| 광고/예방 쌍 분류 불일치 | 4/22 | 3/22 |
| 치환 확정 중 잘못된 복원 | 1건 | 2건 |
| 실제 호출 시도 | 11회 | 45회(429 1회 포함) |
| 확인된 사용 토큰 | 14,937 | 27,791 + 429 사용량 미제공 |
| 실행 구간 경과 시간 | 47.16초 | 165.68초* |

*개별 요청의 dev 결과는 중단 전 19개와 이후 나머지 25개를 합친 것이다. 동일 후보를 다시 호출하지 않았으며 44개 ID·순서·완전성을 검증했다. 시간은 두 실행 구간의 합으로 429 재시도 대기를 포함하고, 수동 복구 중간 공백은 제외했다. 약 3.51배라는 값은 이 실행 조건에서의 관측치이며 순수 모델 지연이나 안정된 처리량 비교가 아니다. 서버 사용 한도도 영향을 주었다.

기존 치환 양성 16개는 유지했지만 `MP3`, `2026Q`, `RX7800`, 식별번호 용법의 `R1VER` 등에서 오탐이 발생했다. 모호 표현은 모두 치환으로 확정했다. 쌍 불일치가 한 건 줄었다는 사실만으로 안정성이 개선됐다고 할 수 없다. 잘못된 판정으로 양쪽이 일치하는 경우도 있기 때문이다.

evaluation 44개에서는 대조군이 TP 16 / FP 5 / FN 0, 정밀도 76.19%, F1 86.49%, 모호 표기 보류 0/8로 완주했다. 개별 요청은 **20/44개의 유효 판정을 저장한 뒤**, `X509`에 `classification=substitution`과 `reading=none`을 함께 반환했다. 한 번의 재요청에서도 모순이 남아 종료했다. 해당 분할의 개별 요청 전체 F1·정밀도는 보고하지 않는다.

**2순위도 미채택**이다. dev에서 이미 정상 오탐·불확실성·복원 정확도가 기준에 미달했고, 다른 분할은 계약 안정성까지 실패했다. 이것은 배치 문맥 혼동이 없다는 증거가 아니며, 현재 계약에서 단독 호출만으로 문제가 해결되지 않았다는 결과다.

## 실행기 중단과 비용 기록

enum 개별 요청 중 HTTP 429가 발생했고 기본 어댑터의 재시도는 성공했다. 다만 실험 실행기가 거절된 요청의 usage 부재까지 무조건 오류로 취급해 dev 19개 저장 후 멈췄다. 이 실행기 문제는 모델의 판정 오류와 구분했다.

원본 실행 기록과 고정된 추론 코드는 보존하고 `.runtime/stage3-digit-ablation/recovery-run.cjs`에서 예산 계산만 보완했다. **확인된 429에 한해 기록된 요청 예약량을 예산에 반영**하고, HTTP 200 등 다른 요청의 사용량 누락은 계속 차단했다. 429를 실제 0토큰 과금이라고 가정하지 않았다. 재개 시 입력·프롬프트·모델·배치·출력 한도는 그대로였으며 19개 성공 응답을 재사용했다. 이후 evaluation의 계약 오류는 복구 대상이 아니므로 추가 시도하지 않았다.

| 전체 실험 비용 항목 | 값 |
|---|---:|
| 실제 API 시도(자유 출력 실패·대조군·재시도 포함) | **172회** |
| 응답에서 확인한 사용 토큰 합계 | **140,846** |
| 사용량 미제공 | HTTP 429 2회 |
| 429 예약량까지 포함한 예산 계산량 | **147,128** |
| 실행 구간 경과 시간 합계 | **744.55초** |

예약량은 실제 과금 토큰이 아니다. 원화 과금액은 확인하지 않았다. 최초 전체 상한 220회·250,000토큰의 예산 계산 범위를 넘지 않았다. 경과 시간은 실험 추론 구간 합이며 문서 작성·수동 복구 공백·사이트 수집 시간은 포함하지 않는다.

## 채택 판단과 검증 한계

- 두 개선안을 기본 Pipeline·관찰기·worker에 연결하지 않는다. 검증된 기본 경로에도 알려진 누락이 남아 있다는 기존 상태를 유지한다.
- 정상 식별자의 기법 오탐 증가를 실제 웹 광고 오탐 증가로 바꾸어 해석하지 않는다. 의미 판정과 기본 실행 파일은 변경하지 않았다.
- 같은 88개에서 프롬프트·단어 예외를 반복 조정하면 과적합 우려가 있다. 여기서 종료하고 추가 튜닝·새 평가·역순 반복·306개 통합 확대를 하지 않았다.
- 독립 평가에서 일반화 성능이 개선됐다고 주장할 근거는 없다. 기존 최종 탐지 F1 96.77%도 이번 실험에서 재측정하거나 갱신하지 않았다.
- 결과는 설정별 제한된 진단이며 HCX-007 전체나 모든 개별 호출 구조의 성능 한계로 일반화하지 않는다.

`npm.cmd test --prefix agent`를 통과했다. 새 검사는 후보 유무 조건의 동일 SYSTEM/schema, 입력 목록만 제거, 복원 대응 검증, 1회 복구, ID·광고 의도 보존을 확인한다. 429 예산 보완은 실제 토큰 합산·확인된 429 예약량·다른 사용량 누락 차단의 자체 검사를 통과했다. 완료된 결과의 위치·원문·다른 관찰 기법 불변과 모든 고정 manifest를 재검증했다. 기본 소스는 그대로이며 추가 API 호출이나 커밋·push는 하지 않는다.
