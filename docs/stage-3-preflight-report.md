# 3단계 진입 전 점검: 미통과

검증일: 2026-09-22. 사용자가 지정한 조건에 따라 사전 점검을 실행했다. **새 문맥 의존 사례에서 광고 8개가 누락되어 3단계 구현은 시작하지 않았다.** 앞선 `stage-2-generalization-report.md`의 진입 판단은 기존 회귀 범위에서의 판단이며 이번 결과로 보류한다. 기존 결과가 잘못 계산되었다거나 코드를 수정해 성능이 떨어졌다는 의미가 아니다.

## 방법

- 새로운 합성 문구·HTML 조합 28개: 광고 12, 정상 16. 개별 문서 28개와 진입 페이지 1개를 실제 브라우저로 수집했다. 전체 수집 후보 140개 중 사전에 지정한 대상 28개를 모델에 전달했다.
- 링크·버튼·제목·본문, article·댓글 역할·표 셀·사용자 정의 요소의 네 가지 배치를 포함했다. 주변 설명이 실제 수집되었는지, 대상 원문과 위치가 유지됐는지 먼저 확인했다.
- 문맥 의존 표현 8개를 불법 서비스/공공 서비스 문맥에 각각 배치했다(16개). 직접 광고 4개, 동일 광고를 교육 인용한 정상 4개, 이웃에 광고가 있는 정상 작성 정보 4개도 포함했다.
- 첫 API 호출 전에 정답·입력·판정 소스 5개 파일의 SHA-256을 저장했다. 정답과 `case_id`는 모델 입력에 넣지 않았다. 판정기·프롬프트는 수정하지 않았다.
- 최초 실행과 순서 변경 실행 모두 모든 판정 단계를 실제 HCX-007로 호출했다. 저장 응답을 재사용하지 않았다. 순서 변경으로 배치 구성도 달라졌다.
- 조건: HCX-007, temperature 0, seed 42, reasoning none, 최대 출력 3,072토큰, 배치 최대 16, 순차 호출. 기존 실험 도구의 총 호출 300회·1시간 제한을 사용했다. 실제 요청 로그의 설정을 확인했다.

이 자료는 첫 실행 시 새로 작성한 합성 검증 자료였으나 지금은 실패를 분석한 진단·회귀 자료다. 실제 공공 사이트 홀드아웃이 아니며 사이트 전체 정확도를 대표하지 않는다. 이번 검사는 광고 의도·문맥 경계를 평가하며 4종 기법 정확도 평가가 아니다.

## 결과

| 항목 | 최초 실행 | 순서·배치 구성 변경 |
|---|---:|---:|
| TP / FP / FN | 4 / 0 / 8 | 4 / 0 / 8 |
| 정밀도 | 100% | 100% |
| 재현율 | 33.33% | 33.33% |
| 의미 판정 F1 | 50% | 50% |
| 검토 보류 | 0 | 0 |
| 호출 | 5 | 5 |
| 토큰 | 9,687 | 9,553 |
| 모델 실행 경과 시간 | 35.92초 | 33.22초 |

최종 광고/검토 판정은 두 실행에서 모두 동일했다. 직접 광고 4개는 탐지했고 정상 16개는 오탐하지 않았다. 문맥 의존 광고 8개는 전부 누락됐다. 이번 실제 호출 합계는 10회, 19,240토큰, 두 실행 시간 합계 69.14초다. 수집·코드 점검 시간은 모델 실행 시간과 별개이며 원화 과금액은 확인하지 않았다.

## 확인된 원인과 아직 관찰되지 않은 위험

예를 들어 대상 `여기에서 시작하세요.` 앞에 `사설 현금 베팅방 신규 회원을 받습니다. 아래 버튼은 해당 베팅방 접속 창구입니다.`가 실제로 수집돼 있다. 정상 대조군에는 같은 대상 문구 앞에 평생교육원 수강 접수 설명을 배치했다.

실제 실패 경로:

1. `target-contract.cjs`는 대상 문구만 읽고 불법 서비스 권유 여부를 잠정 분류한다.
2. 문맥 의존 광고 8개를 모두 `ordinary`로 반환했다. 표면 문구만으로는 서비스 성격을 특정할 수 없기 때문이다.
3. `contextualize.cjs`의 `serviceCandidates()`는 광고 또는 검토 후보만 통과시킨다. 8개는 보류 없이 정상 종료됐다.

필요한 문맥이 수집됐는데 판정에 사용되지 않았으므로 이번 누락의 직접 원인은 수집 범위 부족이 아니라 **독립 문구 판정을 후속 검증의 제외 조건으로 사용한 것**이다. 불법성을 알 수 없다는 사실과 이용 유도 자체가 없다는 사실을 분리해야 한다.

별도로 `applyServiceContext()`는 최초 `is_violation`과 불법 서비스 확인의 AND로 최종 광고 여부를 계산한다. 따라서 초기 불확실을 서비스 근거로 해소하는 경로도 검토해야 한다. 이는 코드에서 확인한 제약이며 이번 8건은 모두 ordinary였으므로 이번 표본에서 불확실 경로의 실제 누락을 관찰했다고 보고하지 않는다.

3단계의 스타일·위치 관찰만 추가해도 이 의미 판정 누락은 해결되지 않는다. 다음 2단계 수정에서는 문구 자체의 발화 행위와 서비스 성격을 분리하고, 연결 근거가 있는 문맥 의존 후보를 후속 판단에서 배제하지 않는 계약을 비교해야 한다. 모든 정상 후보의 일괄 재호출, 특정 표현 사전, 제목·작성자 일괄 제외를 해법으로 확정하지 않는다. 인접 광고를 정상 문구에 옮기는 오탐과 기존 광고 재현율을 함께 검사해야 한다.

## 출력 계약 점검

기존 `outputResult()`를 네 가지 합성 결정으로 검사했고 모두 통과했다. 이 검사는 모델 정확도 측정과 분리한다.

| 입력 상태 | 확인한 현재 동작 |
|---|---|
| 광고, 4종 기법 없음 | `is_violation=true`를 유지한 diagnostics로 보존. 정상으로 바꾸거나 기법을 만들어내지 않음 |
| 정상, 관찰 기법 있음 | 최종 광고 findings 없음 |
| 광고, 기법 2개 | 같은 URL·위치·원문에 기법별 findings 2개 |
| 판정 불확실 | diagnostics에 검토 상태 유지 |

원본 모집요강 HWPX를 다시 확인했다. 필수 검출 단위는 URL + location + technique이고, 4종 필수 기법 외 추가 제안에는 ETC 및 extra_finding 경로가 따로 있다. 이번 작업에서 추가 제안 출력을 도입하지 않았다. 따라서 일반 표기 광고는 의미 판정/진단에서 보존하고 필수 4종 기법 F1과 구분한다. diagnostics에 남는 일반 광고가 있다는 사실을 UI와 운영 지표에서 정상 0건으로 해석하면 안 된다.

## 변경·검증 범위와 재현

추가 파일은 `agent/experiments/preflight.cjs`와 이 보고서다. 현재 상태를 AGENTS.md와 이전 보고서에 덧붙였다. Agent 판정기·수집기·웹 worker·백엔드·프런트엔드는 수정하지 않았다. 기존 `npm.cmd test --prefix agent` 전체 검사는 통과했다. 3단계 구현·기본 경로 전환·커밋·push는 하지 않았다.

```powershell
# 최초 한 번만 생성. 기존 입력/실행 디렉터리는 덮어쓰지 않는다.
node agent/experiments/preflight.cjs prepare
# 아래 두 명령은 실제 유료 HCX 호출이다.
node agent/experiments/run.cjs isolated .runtime/stage3-preflight/evidence.json .runtime/stage3-preflight/original
node agent/experiments/run.cjs isolated .runtime/stage3-preflight/reordered-evidence.json .runtime/stage3-preflight/reordered
# 채점/출력 계약 검사는 네트워크 호출이 없다.
node agent/experiments/preflight.cjs score .runtime/stage3-preflight/original
node agent/experiments/preflight.cjs score .runtime/stage3-preflight/reordered
node agent/experiments/preflight.cjs output-check
```

이미 실행 자료가 있으면 API 재실행에는 새로운 결과 디렉터리를 사용한다. `.runtime/stage3-preflight/`의 `seal.json`, `collection.json`, `labels.json`, 두 실행의 `analysis.json` 및 요청·응답 로그, `output-contract-check.json`, `acceptance.json`에 근거를 보존했다. API 키는 로그나 문서에 기록하지 않았다.
