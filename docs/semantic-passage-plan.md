# 두 번째 원인 가설 비교 — 첫 선별 중 고정

첫 비교의 초기 응답에서 문맥 지침/압축만으로 인용 오탐이 줄지 않았고, 예시는 실제 광고까지 인용으로 만들었다. 결과별 예시를 더 넣는 대신 질문 자체를 '대상의 게시 행위'로 명시하고, DOM 순서 원문을 실제 문장 하나로 전달하는 다른 계약을 개발 진단 자료에서 한 번 비교한다.

`semantic-passage.cjs`는 별도 짧은 시스템 지침, 한국어 게시 행위 enum, 원문 순서 passage를 한 묶음으로 변경한다. 효과가 있어도 어느 개별 변경의 기여인지는 확정하지 않는다. enum과 기존 verdict의 대응은 사전에 고정하며 코드가 문장을 읽어 정답을 덮어쓰지 않는다. 출처 검증은 유지한다.

- 첫 선별 완료 후 같은64개에서 O/게시행위 배치16/게시행위 배치4를 비교한다. 최대24요청/400,000예약토큰/1시간. 동일 공유48kTPM·2병렬·none/temp0/seed42/출력3072.
- 첫 선별 후보와 합쳐 개발 F1 우선으로 1개 선택한다. 1%p 이내는 호출·토큰·단순성을 우선한다. 새80개는 아직 판정하거나 후보 조정에 사용하지 않는다.
- 새80개에서 정순·고정섞기 두 번과 기존76개 회귀를 수행한다. 앞선 `semantic-search-plan.md`의 F1 중심 기준은 유지한다. 새 자료 결과를 본 뒤 이 계약을 수정하지 않는다.
- 원문·경계·라벨은 모델 입력에 새 정답을 주입하는 데 쓰지 않는다. 출처 ID가 맞아도 의미 귀속은 틀릴 수 있으며 별도로 보고한다.
