## 0순위: 시간·저장·재개

- 웹 기본 검사 구간1500초, 누적 후보 상한0(제한 없음). 25분 이후 새 수집·판정 요청은 시작하지 않으며 전송 중 작업에는 최대210초 정리 시간을 준다. 브라우저 종료 대기는 최대30초이고 백엔드는 구간 시작부터 설정 시간+300초에 worker를 종료하는 보호 장치를 둔다.
- 기존 core 체크포인트를 사용한다. 결과·미판정 후보·FIFO 대기 순서·중복 상태를 보존하고 웹의 ‘이어서 검사 / 여기서 종료’를 연결했다. 첫 구간 결과를 별도 보관·다운로드하며 최초 시작 이후 경과, 구간 실행, 누적 실행, 사용자 대기를 구분한다.
- 전송 전 대기와 전송 후 미확인을 구분했다. 전송 실패를 추측해 자동 재호출하던 경로를 제거했다. 명시적429 거절만 제한 내 재시도하며, 전송됐거나 응답 후 판정 확정이 안 된 요청은 재개를 막는다.
- 누적 후보 제한 해제가 무제한 자원을 뜻하지는 않는다. 구간당 기본200페이지/300호출, 페이지당 추출10,000개, 다음 페이지 수집 전 worker RSS768MiB 보호 중단은 별도다. RSS에는 브라우저의 별도 프로세스가 포함되지 않는다. 전체 체크포인트를 메모리에서 직렬화하는 구조는 그대로이며 저장 구조 개선은 이번 범위가 아니다.

중간 검증에서 웹 재개 시 최초 시작 시각이 새 시각으로 바뀌는 오류를 발견해 worker가 백엔드의 최초 시작 시각을 유지하도록 수정했고 재검증을 통과했다. 기존 소스 버전으로 만든 작업은 체크포인트 코드 서명 검사로 재개가 거절될 수 있다. 새 버전에서 생성한 작업의 재개를 검증했으며 과거 작업을 임의로 호환 처리하지 않는다.

장시간 검사 프로세스는 최초 시작 시각 수정 전에 시작했다. 해당 검사는 `firstStartedAt`을 전달하지 않아 수정된 분기를 사용하지 않는다. 수정 후 버전은 짧은 worker 검사와 웹 최초 시각/재개 보존 검사로 별도 검증했다. 판정기·core 시간 제어 코드는 장시간 검사 중 바꾸지 않았다.

## 1순위: 수집 근거의 판정 입력 전달

관측한 병목은 `context_evidence`와 조상 스타일이 수집돼도 운영 최초 판정 입력에는 포함되지 않는다는 점이다. 필드를 더 보내면 정확도가 오른다는 가설만 시험했으며 프롬프트·모델·원문·순서·최대 배치는 고정했다. 기존 관찰 자료76개(광고36/정상40), 기법 라벨48개를 기본A1→문맥→스타일→기본A2로 실행했다. 기법 정답 일치는 광고 여부와 별도로 비교했다.

두 개선안 모두 기존 공통 정탐 광고35개를 유지했다. 기본 두 회차의 요청 body5개는 각각 동일했고76개 판정 signature 변화도0건이었다. 이는 이번 두 반복에서의 관측이며 일반적인 결정성을 보장하지 않는다.

- **문맥 추가: 미채택.** 의미 판정의 누락1개와 정상 오탐4개를 줄였지만 기법 정답이42→30개로 감소했고 요소×기법 F1도 하락했다. 의미 점수만 보고 채택하지 않는다.
- **스타일 추가: 미채택.** 의미·기법 점수는 개선됐지만 토큰+114.81%, 지연+35.66%로 사전20% 상한을 넘었다. 정상 오탐4개는 정상 확정이 아니라 검토 상태로 바뀌었다. 검토 부담을 해결한 것으로 해석하지 않는다.

총20회 요청·20회 응답, 확인 사용량177,984토큰이다. 예약 기준273,863토큰으로32시도/400,000토큰 상한 안에서 종료했다. 실행 후 별도 집계로 지표·전환·원본 body를 확인했다. 사전 진단 관문에서 실패했으므로 새 자료와25분 유료 비교로 확대하지 않았다. 같은 문구에 맞춘 추가 프롬프트 조정이나 예외 규칙도 추가하지 않았다.

**일반화 성능 개선은 미확인이다.** 이번 자료는 기존 회귀·진단 자료이며 독립 홀드아웃이 아니다. 관측한 이득을 새로운 사이트에 일반화할 근거가 부족하고, 반복 조정하면 과적합 위험이 있다. 수집 근거 전달 병목을 해결했다고 선언하지 않으며 두 추가 필드는 실험 파일에만 둔다.
