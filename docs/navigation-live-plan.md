# 탐색 정책 실제 판정 및 경로 연속 탐색 계획

2026-09-23. 사용자 승인: 탐색 정책만 교체해 실제 판정 비교 → 깊은 경로 연속 탐색 독립 검증 → 채택 판단. 운영 기본값은 판단 전 변경하지 않는다.

## 고정 조건과 단계

1. A: FIFO와 기존 Bandit을 비교한다. 기존 v4 개발/확인에서 사전 고정한 첫 사이트 dev-101, confirmation-201, 원래 링크 순서(seed 0), 시작점 포함 50페이지다. 소표본 진단이며 새 홀드아웃이 아니다. 선택 순서는 dev FIFO→Bandit, confirmation Bandit→FIFO로 교차한다.
2. B: A 완료 후 Bandit에 제한된 경로 연속 탐색만 더한다. 매 10회 중 첫 슬롯은 가장 오래된 content_scope=false 대기 URL(없으면 기존 선택), 다음 2슬롯은 직전 경유 페이지가 detail=false이고 새로 발견한 URL이 있으면 그중 첫 URL을 연속 선택한다. 연속 경로가 끝나면 원래 Bandit으로 복귀한다. 기존 매 5번째 FIFO, 보상·그룹은 유지한다. 최대 3/10 슬롯만 관여하며 특정 깊이·문구·라벨은 사용하지 않는다. 10/3은 결과에 맞춰 조정하지 않는다.
3. B는 기존 6사이트 × 5순서에서 전체 집합·예산 접두부·기존 순서를 검사하고, 별도 구조 대조(폭/깊이/정상 막다른 길/순환/교차 연결)로 독립 안전성을 확인한다. 동일한 두 사이트 50페이지에 실제 HCX 판정도 수행해 A의 Bandit과 비교한다. A가 실패해도 B는 독립 연구 후보로 검증하며 운영 채택하지 않는다.

## 입력·호출과 측정

- 운영 collect와 현재 Pipeline createSession/outputResult를 재사용한다. 제목·메뉴·정상 후보를 제외하지 않는다. 원래 DOM/문맥/위치/배치 내 순서를 보존하며 배치 16, HCX-007, temperature 0, reasoning none, seed 42, max output 3072, TPM 52000, 순차 호출을 고정한다. 요청 초과만 기존 fitBatch로 줄인다.
- 정적 사이트를 loopback으로 제공하고 운영 수집기로 각 사이트 전체 증거를 먼저 수집해 고정한다. 정책은 방문한 페이지의 관측치만 받으며, 정답은 모든 실행 종료 후 채점에만 사용한다. 실제 LLM 판정은 조건마다 새 호출한다. 동일 후보라도 정책별 배치 이웃이 달라지는 효과는 실제 변경 효과에 포함하며 모델 변동과 분리 입증한 것으로 주장하지 않는다.
- 수집 캐시는 양 조건에 동일하게 사용한다. 실제 수집 시간과 각 조건의 판정 시간을 따로 기록하며, 캐시 기반 실행을 실사이트 종단 지연으로 보고하지 않는다. 전체 수집 비용은 운영 때 그대로 발생하는 비용으로 해석하지 않는다.
- 정책별 50페이지의 마지막 잔여 배치도 판정한다. 미방문 광고는 FN에 포함한다. 의미 F1/정밀도/재현율, 요소×기법 최종 F1, 깊은 영역, 기존 양성 손실, 관찰 밖 양성, 호출·토큰·시간을 기록한다. 정답 외 양성은 자동으로 제외하지 않고 별도 검토하며 보수적 FP 지표도 함께 계산한다.
- 실행당 최대 40 API 시도·900초, 전체 최대 220시도·1,800,000토큰(usage 없는 오류는 요청 예약량으로 집계). 형식/429/통신 재시도도 예산에 포함한다. 원화 요금은 임의 추정하지 않는다. 키·인증 헤더는 로그에 기록하지 않는다. 실행 실패/부분 판정은 완전 비교와 분리하고, 무확인 재시도로 유료 호출을 반복하지 않는다.

## 사전 판단 기준과 종료

- 두 자료에서 의미 F1과 최종 기법 F1 모두 비감소, 합산 최종 F1 +2%p 이상, 자료별 정밀도 하락 2%p 이내, FP 증가 최대 1개, 기준 조건의 정탐 위치 손실 0개, 합산 토큰·판정시간 각각 15% 이내 증가를 조건부 채택 기준으로 둔다. 정답 외 양성이 있으면 보수적 지표도 통과해야 한다.
- B는 위 조건에 더해 기존 6사이트의 깊은 광고 도달이 분할별 비감소, 두 분할 중 적어도 하나에서 50페이지 깊은 광고 +5%p, 전체 광고 도달의 사이트별 평균 하락 5%p 이하를 요구한다.
- 동작 계약 실패·유료 예산 초과·API 키 실패는 실제 비교를 중단하고 이유를 보고한다. 기준을 못 채우면 효과와 손해를 그대로 보고하며, 가중치 재조정 또는 새 개선안 연쇄 실행을 하지 않는다. 정책을 통과한 것으로 포장하기 위한 사후 기준 변경은 없다.
- 두 사이트 단회 판정이므로 통과해도 최종 제출 기본값 확정은 별도 구조/실사이트 및 모델 반복 검증이 필요하다. 소규모 이득만으로 과거 미통과를 덮지 않는다.
