## 측정 범위와 남은 누락

실제 공공기관 DOM을 동결한 기존 복제본의 지정64위치(광고28/정상32/모호4)를 평가했다. 실사이트 전체 정밀도나 새 홀드아웃 성능이 아니다. 미방문·미판정 광고를 모두 FN으로 포함한다. 미판정 정상은 확정 정상 판정으로 주장하지 않는다. 지정 위치는 수집39→64, 판정13→42이며 정상 전체를 끝까지 검사한 실험이 아니다.

누락 원인은 미방문9→0, 수집 후 미판정11→7, 판정 오류3→6이다. 오류3개 증가는 이전 정탐의 회귀가 아니라 새로 판정한 광고에서 드러난 누락이다. 기존3개 누락은 해소하지 못했다. 남은13개 중7개는 판정 기회 부족,6개는 의미 판정 실패다. 입력/후보 처리량과 자모·문맥 해석 병목은 남는다.

정답 위치 외 양성은3→7개다. 원문·귀속 문맥 수동 검토 결과 광고를 포함한 중복 상위 요소4개와 실제 권유 설명 문단3개였으며 통제64의 TP에 추가하지 않았다. 이는 독립 블라인드 검토가 아니다. 사이트 전체 정답을 새로 만들었다고 주장하지 않는다.

## 2. 입력 표현 실험

기존 실제300요청/1186작업에서 원문과 동일한 정규화 입력 절감 여지는 후보 JSON 문자의 약6.85%였다. 문구 삭제·문맥 축약·후보 제외 대신 반복 JSON 키를 별칭으로 표현하는 가역 방식 하나를 고정했다. 모든 ID와 텍스트·문맥·링크·귀속 값은 유지한다. 역변환 후 원래 JSON과 완전 일치를1186작업 및 비교168개에서 확인했다.

후보 JSON 문자만 보면20.24% 감소하지만 대응표 프롬프트와 기존 출력 스키마를 포함한 요청 예약 추정 감소는 약5.32%다. 실제 입력 토큰과 F1·오탐·누락을 A-B-B-A로 비교했다. 168개는 이전에 관찰한 합성64와 복제본 개발/확인104이며 새로운 홀드아웃이 아니다. 각 요청4개, 출력512, 동일 모델 설정, 순차 실행, 조건 사이61초 대기를 유지한다. 종단 실험과 API를 동시에 호출하지 않는다.

## 연결·재개 검증과 추가로 발견한 저장 충돌

- 실제 저장462요청/1828작업을 API0으로 연속 재생하고,300회에서 중단 후 재개한 결과와 비교했다. 요청별 원문 입력·배치 순서·판정·전체 근거·방문/대기 URL이 완전히 같고 중복 대상0이다. `.runtime/call-budget-replay-v1/result.json`.
- 의미 계약·기법 통합·장문 구간 통합·미확인 요청 재시도 거부 검사 통과: `.runtime/semantic-adoption-check-1790340851289/check-result.json`.
- 실제 worker 및 Spring API에서600 허용/0·601 거부, 불변 이전 구간, 재개 시 완료 판정 보존 통과: `.runtime/bounded-worker-check-1790341321294/result.json`.
- 프런트 타입 검사/빌드, 백엔드 전체 컴파일·패키징 통과. 제한 환경 JDK의 의존 JAR 실경로 AccessDenied는 승인된 동일 오프라인 빌드에서 정상 컴파일로 확인했다.
- 실제 브라우저 Mock: UI 기본600 및 요청 전달, Spring→Node 실행, 취소, 페이지/시간 부분 완료, API/화면 재개, 첫 구간 다운로드 보존, 서버 재시작, 모바일 표시 통과. `.runtime/verification-1790341331138/report.json`. 유료 호출0.

웹 검증에서 Windows 결과 파일 잠금 충돌을 발견했다. Agent가 result/coverage 파일을 원자 교체하는 동안 백엔드가 같은 파일을 읽어 EPERM/IOException으로 실패할 수 있었다. 최초 실패 기록은 `.runtime/verification-1790340881482`, 재현은 `.runtime/verification-1790341090219`에 보존했다. 단순 Java NIO 읽기로 바꾸는 대안도 파일을 연 동안 교체를 막아 해결하지 못했으며 채택하지 않았다.

최소 수정으로 `Jobs.get`이 현재 실행 중인 작업의 가변 산출물을 읽지 않도록 했다. 진행 수치는 Agent 이벤트로 계속 갱신하고, 완료/부분 완료 후 결과와 coverage를 읽는다. 중간 저장 자체·모델 입력·원래 판정·재개 계약은 바꾸지 않았다. 실행 중 결과 목록의 실시간 미리보기는 제공하지 않으며, 저장 종료 후 결과를 안내한다. 실행 중 깨진 임시 결과를 만들어도 GET이 파일을 읽지 않는 회귀 검사를 추가했고, 수정 후 웹 전체 검증을 통과했다. 예외 원인은 서버 로그에 남기고 사용자에게는 기존 오류 계약을 유지한다.

실험 중 운영 수집기/판정기/스케줄러의 원문 처리 코드는 변경하지 않았다. 백엔드 읽기 경계 수정은 종단 측정 후 웹 검증에서 추가한 안정성 수정이며, 정확도 상승의 원인으로 섞어 설명하지 않는다. Git push나 추가 유료 실험은 하지 않았다.
