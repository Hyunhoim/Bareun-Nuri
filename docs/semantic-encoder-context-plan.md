# 문맥 절단으로 생긴 입력 충돌의 단일 요인 후속

2026-09-29. 최초9조건 학습 중 토큰 입력 감사에서 발견했으며 HCX 회귀 예측을 보기 전에 고정한다.

관측: 단순 오른쪽256절단에서 같은 토큰에 광고/정상 라벨이 함께 붙는 그룹이 KLUE43(195행), Kc12(50행), Ko46(209행)이다. 512에서는 세모델 모두0. 이는 원래 반대 문맥이 잘려 사라지는 입력 결함이다. 작은 개발셋 F1 상승으로 정당화하지 않는다. 원자료 라벨을 모델에 맞추거나 충돌 행을 임의 삭제하지 않는다.

가설: 동일256상한 안에서 대상·문맥 두 부분에 예산을 배분하면 입력 상충을 줄이고 문맥 의도 판정을 보존한다. 전체 토큰이256이하면 기존 입력과 완전 동일하다. 초과일 때 기존 token offset으로 경계를 나누고 문맥에 최대96토큰을 우선 배정한다. 나머지를 대상에 쓰고 대상이 짧으면 남은 예산을 문맥에 돌린다. 앞부분만 보존하므로 긴 각 부분의 뒤 근거 손실은 여전히 가능하다. 원문 저장은 바꾸지 않는다.

조건은 세모델 각1개, freeze8/lr1e-5/FP32/3epoch/seed42/같은956행·가중치·선택 기준 그대로. 단순256과 비교해 바뀌는 것은 입력 토큰 배분뿐이다. 실험 전 세모델의 반대 라벨 토큰 충돌0, 모든 입력길이<=256, 짧은 입력 토큰 완전 일치, 두 부분의 비어 있지 않은 보존을 검사한다. 실패하면 학습하지 않는다. 총학습 상한은 최초9+추가3=12조건이다.

256 원조건은 입력결함 진단으로 보존하고 후속 대체 후보 선택에서 제외한다. HCX 비교 전에 모델별로 512/freeze8,512/full,문맥배분256/freeze8 중 기존 rank로 하나를 고정한다. 동률 순서는 위 순서다. 이 변경은 모델의 회귀 점수를 본 뒤 하는 선택이 아니라 입력 계약 결함을 확인한 조정이며 최초256점수도 빠짐없이 보고한다. 최초 개발 점수 관문은 낮추지 않는다.

신규 최종셋을 만들거나 실패 문구를 훈련에 추가하지 않는다. 검증40변형은 토큰이 원문과 같아서 새로운 난독 표현 일반화의 근거가 되지 않는다는 발견도 함께 기록한다. 이번 후속 역시 개발 실험이며 운영 변경/API 호출0이다.
