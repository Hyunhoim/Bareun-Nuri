# 새 실제 수집 입력의 동결 모델 진단

2026-09-29. 이전12조건은 실험 완료이며 새 학습/임계값 조정을 하지 않는다. 이번 목적은 실제 입력 결손·길이·의미 판단·CPU 자원을 구분하는 것이다.

검색으로 찾은7기관 도메인 페이지를 운영 collector로 읽기 전용 수집한다. 농사로의 정상 본문/광고성 댓글, 대학 게시판3종 광고 의심 글, 관공서 예방/교육/보도3종을 대상으로 한다. 검색 기반 의도 표집이며 실제 출현 비율·전체 사이트 재현율은 추정하지 않는다. 대학은 공공기관으로 일괄 간주하지 않는다. 검색 snippet만으로 라벨을 붙이지 않는다.

페이지별1회,60초/최대10000후보,동일출처 네트워크 경계,외부 광고 링크 미방문,게시/로그인/다운로드 실행 없음. 실패·누락·원문·문맥 귀속·URL·위치·시점·코드 해시를 보존한다. 운영 worker와 같은 allowLongText/allowEmpty/observeTechniques 옵션을 사용하되25분 탐색 종단은 아니다.

훈련 도메인·정규화 동일 입력·원문 유사 캠페인을 감사한다. 새 출처가 곧 독립 사람 정답을 뜻하지 않는다. 모델 예측을 보기 전에 본문/댓글의 대표 문맥을 선택해 블라인드 검수 자료를 고정한다. 새 라벨은 미검수 또는 assistant 잠정으로 명시하며 사람 정답이라고 보고하지 않는다. 긴 입력과 광고 인접 정상 댓글도 남긴다.

동결 후보3개를 각각 별도 CPU 프로세스에서 로딩한다. CPU8threads/FP32/batch8,512한도,워밍업·토큰화·모델순수추론·로딩·프로세스RSS를 분리한다. 전체 대상에 대한 raw binary 예측은 진단으로 저장하되, tokenizer512 초과 또는 collector 문맥 잘림은 확정 판정으로 채택하지 않고 NEEDS_REVIEW로 표시한다. 긴 입력을 빼고 전체 성능을 잘 나왔다고 보고하지 않는다. 확률 보류는 이전의 .2~.8 고정 진단만 병기한다.

이번에는 신규 HCX API0. 사람 검수 준비와 실제 수집·CPU 검증을 먼저 한다. 사람 정답이 부족하면 전체 precision/recall/F1이나 HCX 대체 성공을 산출하지 않는다. 검수된 후 같은 고정 입력을 HCX와 비교할 별도 호출 예산을 기록한다. 운영 변경0이다.
