# JAMO/HOMOGLYPH 순정 모델 비교

2026-09-30. **이번 비교 사이클은 완료했다. KcELECTRA를 후속 연구 후보로 보존하지만 운영 미채택이며 Goal은 미달/active다.** 새 봉인860개는 J F1 100%, H F1 90.12%이나 단일치환·역할 도전만 보면 H74.47%이고 기존 숫자회귀 정탐7개 손실도 남았다. 좋은 합산 점수만으로 일반화 성공을 선언하지 않는다. 운영은 변경하지 않았다.

## 설계

`dual-technique-plan.md` 사전 계획. 공개 사전학습 KLUE RoBERTa-base 및 KcELECTRA-base-v2022에서 새6출력층으로 시작했다. 각각 JAMO/HOMOGLYPH의 present/absent/uncertain을 별도로 학습하며 동시에 두 기법이 존재할 수 있다. 광고 의도는 학습하지 않는다. Unicode16 대응과 기존 `canine-technique.py` 보조근거 생성기를 재사용했다. 원문/표기 위치는 보존한다.

기본864행(24어휘그룹), 추가831행(16그룹), 개발624행(12그룹), 봉인확인624행(12그룹). 같은 한글/영문 어휘와 문자 변형을 여러 문맥으로 교차한 합성자료다. 행 수를 독립 의미 사례 수로 해석하면 안 된다. 기본/추가/개발/확인의 어휘그룹·표기 문자열 직접 중복0, 기존 기법 자료와 직접 표기 중복0을 검사했다. 서로 다른 문장 틀을 사용했지만 같은 작성자·공통 변형 알고리즘의 한계가 있다. 실제 게시글이나 사람 검수 자료가 아니다.

추가 감사에서 기존 숫자 회귀의 `silver` 계열과 초기 기본 학습의 어휘계열 중첩1개를 발견했다. 직접 평가문장/표기 중복은0이지만 이 계열은 독립 어휘 평가가 아니다. 후속 학습에서는 관찰 자료의 어휘계열 전체를 조회해 겹치는 그룹을 제외했다. 초기 체크포인트가 이미 학습한 사실까지 지워진 것은 아니다.

기본 자료도 자모 단독·닮은꼴 단독·복합·일반 표기·식별자·근거 부족을 포함한다. 추가는 부분/공백/zero-width/한글-다른문자 혼용 및 전각을 보강했다. 예방 인용이나 교육 문맥의 실제 분해/치환은 관찰 양성이다. 글 자체의 불법광고 양성이 아니다. 서로 다른 작성자의 실제 DOM 귀속 자료는 이번 생성셋에 포함하지 못했으며 별도 검증이 필요하다.

## 과적합 우려

정상 식별자가 주로 영문-숫자 형식이고 불충분 문맥에는 짧은 대상이 많다. 형식이 정답의 지름길이 될 위험을 개발 단계에서 보고했다. 추가 모델의100%는 이 한계를 해소했다는 증거가 아니다. 기존 문맥 대조 자료에서 정탐·정상·보류를 별도 확인한다. 이미 사용한 기존 최종 자료는 회귀로 취급한다.

## 최초 회귀 실패 및 밀도 진단

기존112개의 KLUE+Unicode 정탐48중30개 손실. 각각56개인 두 판넬의 H F1은100→55.56%,100→44.44%. 한글48은72.73→61.11%로 내려가고 기존 정탐5개 손실이다. 기존96개 개발/과거96개최종에서 저장 HCX+코드확정 보존 결합 F1은37.50/66.67%로, 새 개발100%와 전혀 다르다. 후보를 회귀 결과로 교체하거나 과거 실패 문장을 학습하지 않았다.

새 개발12어휘의 동일4문맥에서 숫자만 전부/하나 치환한96개 대조는 기존 `kc-continue`가 dense48/48, sparse27/48만 확정했다. 이는 밀도 민감성을 직접 보여주지만 과거 모든 누락의 단일 원인을 증명하지 않는다.

`dual-technique-followup-plan.md`에 따라 위치·개수·대소문자와 표기 역할을 보강한968행을 생성했다. 개발300/추가 봉인236이며 기존 final624는 수정하지 않았다. 과거 관찰어휘 중첩 그룹 제외 후 실제 학습 행수는 started.json으로 관리한다. 추가 최종도 같은 생성자의 합성 도전자료이며 외부 독립 검수라고 주장하지 않는다.

후속 실제 학습은 총2603행(기존자료+보강, `리본/silver` 그룹 제외)이고2epoch 중2를 선택했다. 기본 개발 평균F1 99.90%, 보강 개발H70.69%다. 최초 후보의 동일 보강개발H39.47%보다는 개선됐지만 치환을 uncertain으로 남기는 문제가 컸다. 정확히 같은 평가 문장/표기를 학습하지 않았으며 모델은 초기 silver 계열 학습 이력을 상속한다.

## 임계값 진단과 최종 동결

`dual-technique-calibration-plan.md`에서 사전 고정한 t=.05/.10/.20/.30을 개발에서만 비교했다. H present 확률이t이상이면 승격하고 기존 present/J 판정은 유지한다. 기존 개발과 보강 개발의 평균F1 개선>=2%p, 정상오확정증가<=3, 모호오확정증가<=3 조건에서.20을 선택했다. 보강 개발H70.69→77.73%, 두패널 평균85.29→88.81%, 정상FP1유지·모호FP0→1이다. 더 낮은 임계값의 높은F1을 택하지 않은 이유는 모호 오확정 증가다. 확률이 실제 정확도로 보정됐다는 뜻이 아니다.

동결 모델 `.runtime/dual-technique-v1/kc-density-role/model`, 가중치 해시는 frozen.json, 판정 계약은 `calibration-selection.json`과 `calibrated-selection.json`이다. 모델 argmax만 실행하면 아래 결과와 다르다. 임계값은 모든 대상에 공통이며 단어/ID/URL 예외는 없다.

## 기존 성능 및 실제 수집 진단

- 기존112 숫자회귀: KLUE+Unicode48TP/0FP/0FN → 새41TP/4FP/7FN, H F1100→88.17%. FP4는 정상3+모호1이다. 초기 Kc후보18TP에서 후속40TP/임계값41TP로 회복했지만7개 손실은 남는다.
- 한글48: 기존16TP/12FP/0FN(F172.73%) → 새16TP/18FP/0FN(F164.00%). 새FP18은 정상12+모호6이다. 논쟁적인 토ㅌ0/O 정답 한계도 유지한다. 경계16개만 보면 H 오확정8→4이나 전체성과로 대체하지 않는다. J정답이 명시된10개(8양성+2음성)는 양쪽모두맞혔다.
- 실제 저장 HCX 의도와 코드확정H를 보존한 과거192회귀: 기존48TP/0FP/0FN(F1100%) → 새41TP/13FP/7FN(F180.39%). 두96개 F1은82.61/78.57%다. HCX가광고로판정한뒤에도 기법회귀가남는다. 새API/웹실행이아니다.
- 저장 수집80개: 기존KLUE+Unicode20처리/60보호, 새21처리/59보호. 미라벨을정상으로집계하지 않는다. 정답이있는 B3T는양쪽미확정, V1D30는양쪽확정으로2개중1개이며 새로운해결은없다. 원문수집잘림/512초과를모델에억지로잘라넣지않았다. tokenizer의긴입력경고는길이감사중발생했으며초과입력을모델에전달한것이아니다.

## 결정과 다음 병목

**KcELECTRA를 후속 연구 후보로 보존, 기존 운영 HCX+코드 유지.** 새 합성 변형 범위에서는 기존 특화 분류기보다 개선됐지만 기존 정탐/정상표기 보존 Goal은 아직 달성하지 못했다. 낮은 임계값이나 추가 epoch를 계속 시도해 성공으로 만들지 않았다. JAMO는 코드만으로도 대부분 검증되므로 모델단일화 자체를운영이득으로주장하지않는다.

다음은 새 모델 추가보다 (1) 단일치환의 위치·길이·문맥에 대한 오류원인 분리, (2) 실제 원래 식별값인지 확인할 수 있는 표기 역할의 독립 검수, (3) 생성 틀 의존성 진단이 우선이다. 판정 대상에 속하지 않는 설명/다른 작성자 문맥, 긴수집입력의일반화는 미검증이다. 새최종자료를연속생성·소비하는방식으로Goal을추구하지않는다.
