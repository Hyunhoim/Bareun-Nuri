# 근거 선택 계약·의미 전용 판정 비교 — 2026-09-25

사전 계획은 `intent-contract-plan.md`다. 실제 실행은 `.runtime/intent-contract-1790271759072`, 실험 코드는 `agent/experiments/intent-contract.cjs`와 `intent-contract-run.cjs`에 분리했다. 운영 worker/판정기/수집기는 변경하지 않았다.

## 다른 원인 가설

이전 실험에서 수집·전달된 예방 설명을 판정에 적용하지 못했고, 정상 판정이 기법 출력을 지우는 회귀가 있었다. 빈 자유 설명을 기존 검증기가 검토로 전환하는 문제도 확인됐다. 이번에는 특정 문구의 프롬프트를 보완하는 대신 출력의 근거 연결과 판정 책임을 바꾼다.

HCX 공식 지원 목록에 없는 string minLength를 지원한다고 가정하지 않았다. Context7에 해당 HTTP API의 직접 문서가 없어 [공식 Structured Outputs 문서](https://api.ncloud-docs.com/docs/en/clovastudio-chatcompletionsv3-so)를 확인했다. 지원되는 enum과 배열 minItems를 사용하며, 소스 ID·중복·판정/유형 모순을 로컬에서도 검증한다.

| 조건 | 입력 | LLM 출력 책임 |
|---|---|---|
| O1/O2 | 운영 입력 | 기존 광고 의도+기법+자유 설명 |
| J | 운영 필드 보존+대상/문맥 출처 ID | 기존 공동 판정 유지 |
| E | J와 동일 | 공동 판정+근거 유형/실제 근거 ID 선택 |
| S | E와 동일 | 광고 의도+근거 선택, 기법은 별도 코드 관찰 |

E/S의 표시 이유는 모델이 선택한 유형과 실제 참조 원문으로 만든다. 자유 설명을 모델이 생성한 것처럼 표시하지 않는다. 빈 기존 응답에 사후로 임의 문구를 넣는 방식도 아니다. 유효한 출처를 골랐다는 사실만으로 근거 타당성이나 광고 판정 정답을 인정하지 않는다.

문맥 설명이 필요한 예방 인용·연결 링크는 실제 해당 설명을 선택해야 한다. 대상 원문 자체가 근거인 경우는 대상 t를 선택해야 한다. 근거 유형은 정답 의도와 일치해야 하며, 근거 부족은 명시적 uncertain이어야 근거 선택 적합 정답으로 인정한다. 이 정답은 평가기에만 있으며 입력에는 전달하지 않는다.

## 평가 범위

이전 개발32+확인32는 이미 결과를 본 **진단64**다. 각각 광고16/정상12/근거 부족4이며 기법4종·원문·브라우저 관찰을 보존했다. O1→J→E→S→O2로 고정하고 동일 원문·순서·16개 배치를 사용한다. J→E는 근거 출력 계약, E→S는 기법 생성 책임을 바꾸는 비교다. 여러 구성 요소가 포함된 계약 변경의 효과이며 개별 필드 이름의 인과 효과로 주장하지 않는다.

두32개 각각 의미/기법/정상 검토/기존 정탐 보존·근거 부족·실질 근거 선택·토큰/지연의 사전 관문을 적용한다. E/S 중 통과한 하나만 기존76 회귀를 다시 검사한다. 이후 새 미사용 확인 자료와25분 검증을 통과해야 운영 채택할 수 있다. 진단 실패 시 추가 조정 없이 종료한다.

실행 중 소스·입력·정답을 해시로 고정했다. 실행 후 별도 코드로 의미/기법/최종 지표·근거 선택·불확실 판정·원본 요청/응답/사용량을 재집계했다. O1/O2의 요청 body는 동일했고, J/E/S의 user 입력도 동일했다. 기준선 판정 signature 변화는0/64다. 감사 결과는 `independent-audit.json`, 실행 소스는 `source-archive`에 보존했다.
