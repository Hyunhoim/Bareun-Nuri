# Phase1 저장 입력 — 동결 광고 의도 분류기 비교

2026-09-30. **분류기 중 KcELECTRA full이 가장 좋았지만 동일 판정 위치의 HCX보다 낮았다.** 새 학습·임계값 조정·API 호출·운영 변경 없이 종료했다. 이 문서의 F1은 광고 의도이며 기법 결합 F1과 구분한다.

## 조건과 공통 위치 결과

Phase1 운영 실행에서 저장한5,070수집 후보 모두를 CPU8threads/batch8/FP32로 추론했다. 기존 모델 가중치·토크나이저·argmax4분류를 고정했다. 대상은 운영 자모 복원 보조 읽기, 문맥은 기존 `klue-context.cjs` 직렬화 및NFC다. 모델에 정답·URL·사례ID를 넣지 않았다. 모든 예측을 저장한 뒤 채점했다.

주비교는 HCX도 마지막 재판정까지 완료했던 같은 지정2,119위치(광고1,064·정상1,055)다. 아직 HCX가 판정하지 못한 곳을 분류기만 맞혀 얻는 효과를 이 표에서 제외했다.

## 남은 차이

- **Kc의 문맥별 장단점:** 피해 문의 오탐22개로 HCX81개보다 적지만, 운영 문의 오탐151개로 HCX18개보다 많았다. 어느 모델도 모든 정상 문맥에서 우세하지 않다.
- **D의 보수화:** 삭제 요청 오탐1·운영 문의0으로 억제했지만 피해 문의140오탐 및 광고 누락194개가 남는다. 과거 D의 특정 문맥 강점이 현재 분포 전체로 확장되지 않았다.
- **공공웹 참고 보강240개:** HCX F199.58%, Nuri48.65%, D57.14%, Kc70.94%. Kc는 광고120개 중83개 정탐·37누락·정상31오탐이다. 이 구간은24시나리오 파생 합성이며 실사이트 대표 표본은 아니지만, Kc의 전체점수만 보고 이 차이를 숨길 수 없다.
- **문맥 표현의 차이:** 동일한 저장 근거를 사용했지만 HCX는원문 passage/링크/경계·인용 정보/12묶음이고, 분류기는기존 학습 호환 target/context 직렬화다. 특히 링크·명시적 scope메타데이터가 동일하게 전달되는 비교가 아니다. 모델 용량·사전학습만의 인과효과나 분류모델의 보편적 한계라고 단정하지 않는다. CPU batch8은8독립 입력의 벡터 연산이며 HCX12후보 공유 프롬프트와 역할이 다르다.

## 판단과 한계

사전의 공통 위치 F1개선 기준은 모두 미달이므로 **HCX 운영 유지, 즉시 대체 미채택**이다. 속도는 충분히 매력적이며, 향후 처리량과 정확도의 교환을 별도 목표로 비교한다면 Kc가 세 분류기 중 우선 후보다. 그러나 실제25분 비교나 문맥 입력 보존을 검증하지 않고 이번 CPU시간만으로 교체하지 않는다. 이번 평가 문장을 학습시키거나 같은 평가에서 임계값을 골라 점수를 올리지 않는다.

기존A8000 및D보강 원본과 정확한 대상/전체입력 중복은0이었다. 의미·문장틀·생성자 중복까지 없다는 증명은 아니다. Phase1은 이미 관찰한 합성 회귀 자료이며 독립 최종 평가가 아니다. 모델/입력/원래 운영 체크포인트 해시 불변,3모델×5070ID 완전성·클래스 유효성·HCX대비 증감 일치와 채점 기본 검사 통과.
