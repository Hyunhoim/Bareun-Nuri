# 같은 어휘·문맥 생략 대조 자료 검수

2026-09-28. 이번 범위는 자료 구성과 실제 수집 입력의 정답 근거 감사다. 모델 재학습·모델 비교·운영 승격을 하지 않는다. 기존 실패 평가2,000개는 변경하지 않는다.

## 사전 계약

- 12개 대상 문구마다 실제 권유 / 피해 문의 / 교육 인용 / 정상 서비스 / 문맥 없음 / 다른 작성자의 권유 / 다른 작성자의 피해 문의 7조건을 만든다.
- 같은 그룹에서는 대상 문구를 그대로 유지한다. 명시적 서비스와 게시 행위를 대상 소유 문맥에서 판단한다. 피해 문의 안의 권유를 게시자 자신의 권유로 간주하지 않는다.
- 문맥 없음은 ‘정보가 부족하다’는 인위적인 설명을 넣지 않고 실제로 문맥을 삭제한다. 생략된 목적어나 서비스 이름을 비공개 시나리오에서 추측해 정답을 확정하지 않는다.
- 다른 작성자의 권유/피해 문의는 대상의 정답을 바꾸지 않는다. 문맥 없음과 모델 입력이 동일한지 확인한다.
- 자료별 원문, 소유 문맥, 배제된 문맥, 제안 정답, 판단 근거를 기록한다. 자동 검사는 문맥 전달과 정답 계약의 일관성을 확인하며 의미 정답의 독립 검수를 대신하지 않는다.
- 8개 원문 계열은 학습 후보, 4개는 개발 후보로 분리한다. 동일 대상의 모든 변형은 같은 분할에 둔다. 두 분할 모두 같은 작성자의 합성이며 최종 평가용이 아니다.
- 원문 보존, 소유 문맥 전량 전달, 다른 작성자 문맥 제외, 문맥 없음/외부 문맥 조건의 입력 동등성 중 하나라도 실패하면 학습 사용을 보류한다.

## 검수 판단과 한계

불법성이 명시된 서비스의 권유와 정상 서비스 권유를 함께 둬 ‘연락·입금·신청’만으로 광고 라벨을 정하지 않는다. 도박과 비동의 성인 사생활 자료의 판매는 합성 사례의 서비스 정의이며 실재 사이트·피해자 자료를 사용하지 않았다.

라벨은 0=위반 권유, 1=교육 인용, 2=정상/피해 문의, 3=근거 부족이다. 피해 문의도 인용을 포함할 수 있으므로 인용 형식보다 게시 목적을 우선한다. 어느 정상 목적이 우세한지 불명확하면 확정 라벨 대신 검토 대상으로 남긴다.

12개 문구는 반복 변형168개와 같지 않다. 서로 다른 서비스에 같은 짧은 안내문이 사용될 수 있도록 만든 통제 진단이다. 긴 글·비명시적 피해 호소·진짜 권유를 피해 문의처럼 꾸민 글·한 게시글의 혼합 의도까지 대표하지 않는다. 전후 문맥이 매우 명시적이며 합성 문법 의존 우려가 있으므로 바로 대규모 학습 자료로 확대하지 않는다.

제안 정답은 에이전트 검수 초안이며 사람 검수 완료가 아니다. `training_ready=false`로 유지한다. 다음 학습 전에 검수자는 모델 예측 없이 대상과 소유 문맥만 보고 서비스, 게시 목적, 근거 문장을 각각 판단해야 한다. 근거가 없거나 복수 의도가 충돌하면 보류한다. 처음 작성한 비공개 라벨은 검수 근거로 사용하지 않는다.

## 구체적인 정답 기준 예

공통 대상: “새 방으로 옮겼어요. 들어오실 분 쪽지 남기면 초대해드립니다.”

|대상에 속한 문맥|제안 정답|근거|
|작성자가 현금 판돈을 거는 사설 축구 도박방을 관리하며 참가자를 받는다고 설명|위반 권유|서비스의 성격과 작성자 자신의 모집 행위가 모두 있음|
|도박방 운영자가 반복해 보낸 메시지를 피해자가 인용하며 차단·상담을 요청|정상/피해 문의|권유의 발화자는 운영자이고 현재 글의 게시자는 피해를 호소함|
|미디어 수업에서 참여 유도 동사를 분석할 예문이라고 설명|교육 인용|권유가 과제의 분석 대상임|
|주민센터의 무료 독서 모임 대화방 이전 안내|정상|구체적인 서비스는 도박이 아님|
|관련 문맥 없음|근거 부족|초대는 보이지만 불법 서비스의 권유인지 알 수 없음|
|별도 작성자의 댓글에 도박방 모집 또는 피해 상담이 있음|근거 부족|다른 글의 서비스와 목적을 대상에게 옮길 수 없음|

보류는 정상 확정과 다르다. 향후 학습/평가에서도 보류율과 보류 오용을 별도로 보고하며 불법광고 정답을 모두 정상으로 치환하지 않는다. 현재 학습 후보8계열과 개발 후보4계열은 문구가 다르지만 관계 구조는 같은 통제 실험이므로 구조 일반화까지 입증하지 못한다.

문맥 없음/다른 댓글 조건의 모델 입력은 의도적으로 동일해야 한다. 이 반복들은 수집 귀속 검사에 필요하지만, 학습 시 그대로 중복 투입하면 보류를 과하게 학습할 수 있다. 학습으로 전환할 때 동일 입력을 중복 제거하고 원문 계열별 가중치를 검토해야 한다. 이번에는 학습하지 않으므로 자료의 대조 관계를 유지한 채 모두 보관한다.

## 완료 결과

실제 Playwright 수집기와 실험용 scoped 문맥 어댑터를 사용했다. 12계열×7조건×2배치=168개 원문 보존, 소유 문맥96건 전달, 다른 작성자 문맥48건 배제, 문맥 없음/다른 작성자 조건 입력 동등성48비교를 모두 통과했다. 배치는 article 안 선행 설명과 role=comment 안 후행 설명이다. 전후 방향과 태그를 함께 바꿨으므로 각 요인의 단독 효과 실험은 아니다.

중복 제거 후 실제 입력108개(학습 후보72/개발 후보36), 분할 간 동일 입력0, 같은 입력의 상충 정답0이다. 기존 KLUE 토크나이저의 실제 입력 형식으로 최대72토큰이며512토큰 잘림0이다. 기존 평가 원문과 정확히 동일한 대상 문구0이다. 근접 의미 중복/템플릿 유사성을 완전히 제거했다는 주장은 하지 않는다.

이번에는 문자 위장·스타일 변형을 추가하지 않고 문맥 귀속과 정답 명확성만 분리했다. 4종 기법의 성능 검증, 모델 정확도 개선, HCX 대체 가능성을 입증한 실험은 아니다. 모델 추론/학습/유료 API0, 운영 변경0이다.
