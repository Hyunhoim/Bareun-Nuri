# 서버 완전 복원 후보 비교

2026-09-26. 8조건·112회 실제 호출을 완료했고 별도 계산기 대조를 통과했다. **부분 복원 개선은 확인했으나 운영 채택은 보류한다.**

## 변경과 범위

원문·문맥·위치를 유지하고 서버가 모든 숫자를 대응 문자로 바꾼 읽기를 LLM에 제공하는 구조를 시험했다. 기존 D는 부분 복원을 포함한 모든 후보를, 새 F는 완전 복원 후보만 제공한다. `1→i/l`처럼 여러 대응은 유지한다. 예를 들어 `j4ckp0t`는 F에서 `jackpot` 하나가 되며 `A4→AA`도 생성된다. 후자는 복원 가능성이 실제 치환을 뜻하지 않는 대조 사례다. 원문 유지/근거 부족 판단은 LLM이 계속 담당한다.

일반 문자 대응은 기존 코드를 재사용했고 특정 단어·ID·정답 예외는 추가하지 않았다. 후보 상한64개 초과는 전체를 미확정으로 표시하며 임의 앞부분만 남기지 않는다. 입력 보존·복수 대응·상한 초과·정답 필드 제외 검사를 통과했다. 112사례의 제공 후보는 총238→141개이며 치환 정답48개 모두 완전 읽기를 포함했다.

기존 개발56/평가56개는 이미 결과를 본 **회귀·진단 자료**다. 새 홀드아웃이 아니다. 같은 토큰의 네 상충 문맥은 여전히 같은 요청에 들어간다. 이번에는 후보 제공 방식만 바꾸므로 문맥 간섭을 해소했다고 미리 주장하지 않는다.

## 공통 설정과 판단

HCX007 none/temperature0/seed42/배치4/출력1024/58k/순차실행. D의 프롬프트와 원문·문맥·ID·분류·출력 형식·후처리는 동일하다. 각 분할에서 D/F 원래 순서와 F/D 역순, 총8조건112요청이다. 조건 전61초 창 분리를 적용했다. 기존 광고 운영12배치·출력512·FIFO·25분 설정은 변경하지 않았다.

기법 F1은 치환/정상 표기에서 계산하며, 근거 부족은 3분류 macro-F1과 과도 확정 수로 함께 본다. 정확한 전체 복원 재현율을 따로 측정한다. 두 분할 평균 F1·macro-F1이 하락하지 않고 정상 오탐·근거 부족 과도 확정이 늘지 않으며, 적어도 한 분할의 전체 복원 재현율이 개선될 때 후속 검증 후보로 권한다. 통과하더라도 독립 자료·운영 묶음·25분 종단 검증 전 운영 채택은 아니다. 사전 계획은 `docs/digit-complete-plan.md`에 봉인했다.

## 개선된 부분과 남은 오류

- **부분 복원 2개 해결:** 기존 평가 원래 순서에서 `j4ckp0t`의 광고·예방 대상이 `j4ckpot→jackpot`으로 바뀌었다. 한 단어 계열의 대조 두 사례이며 서로 다른 두 단어의 일반화 증거가 아니다. 두 사례는 D도 이미 치환으로 분류했으므로 기법 정탐 증가는 없다.
- **정상 오탐 4개 해소:** 기존 평가 역순의 같은 묶음 `UTF8·SHA256·HTTP2·PCIe4`가 F에서 모두 정상으로 돌아왔다. 이 중 직접 후보 목록이 바뀐 것은 `SHA256`뿐이며 나머지는 동료 후보가 바뀐 요청에서 판정이 달라졌다. 네 독립 단어에 대한 직접 규칙 효과로 단정하지 않는다.
- **개발 회귀:** 역순의 `B2B`가 정상에서 치환 오탐으로 바뀌었다. 자신의 읽기 후보는 그대로이고 같은 묶음의 다른 후보가 바뀐 경우다. 근거 부족 `90lden`도 미확정에서 치환으로 과도 확정했다.
- **보류 문제 미해결:** 기존 평가 역순의 근거 부족 `w3lc0me`가 새로 과도 확정됐다. 반면 `m3mber`의 과도 확정은 해소됐지만 해당 요청 body는 D/F가 완전히 같았다. 후자의 이득을 완전 복원 규칙의 효과로 계산해서는 안 된다.
- **순서 민감성 유지:** 개발의 분류 변화는 D/F 각13/56, 기존 평가는20/56과16/56이었다. 순서 변경과 모델 변동이 섞인 관측이며, F가 안정성을 해결했다고 확정할 근거는 아니다.

### 동일 요청 변동과의 분리

복수 숫자를 가진 표기에서만 부분 읽기를 제거하므로 실제 후보 입력 변경은112개 중21개다. 각 분할14요청 중4요청이 바뀌었고10요청은 동일했다. 두 분할·두 순서의40쌍 동일 요청에서160개 후보를 비교해 분류 변화1개를 확인했다. 그1개가 위 `m3mber`다. 나머지 변화는 후보 목록을 바꾼 요청에서 발생했지만, 이것만으로 개별 변화의 인과를 확정할 수는 없다.

과거 D와 이번 D의56개 요청 body도 모두 일치했다. 개발 두 조건과 기존 평가 원래 순서는 분류 변화0개였고, 기존 평가 역순에서3개가 달라졌다. 따라서 과거 평가 평균 F1 82.27%를 이번 대조군 점수로 대신 쓰지 않았다. 이번 동시기 비교의 D는78.94%다. 이 변동을 후보 교체 효과와 혼동하지 않는다.

## 지연·사용량 및 검증

D 실제 토큰73,392→F70,681로 **3.69% 감소**했다. 조건 처리 시간 합계는227.76→232.25초로 약1.97% 증가했다. 작은 측정 차이이며 속도 악화를 확정하지 않지만, 유의미한 지연 개선을 보였다고 할 근거도 없다. 총112호출·144,073토큰, 조건 시간 합계460.01초와 별도 창 분리 대기488초다. 원화 비용은 단가를 적용하지 않아 계산하지 않았다.

112개 요청은 모두 HTTP200 및 정상 출력 종료였고, 최대 실제 출력310토큰으로 출력 상한1024의 잘림은 없었다. 자동 재시도·형식 복구는0회다. 원문/ID/요청 body/소스 해시/출력 JSON/후처리 재생/호출 및 토큰 합계를 대조했다. 독립 구현의 계산기로8조건의 혼동행렬·기법 F1·3분류 지표·복원·역할별 지표와 두 순서 요약이 일치했다. API0 자가검사와 모든 새 스크립트 구문검사도 통과했다.

## 채택 판단

**운영 코드는 유지한다.** 서버에서 완전 읽기를 제공하는 방식은 부분 복원 오류를 막는 데 실효가 있었다. 전체 정탐은 보존했고 정상 오탐 순감소도 있어 무의미한 안으로 폐기할 필요는 없다. 다만 개발 분할의 정상 오탐·과도 확정 증가로 사전 후속 권고 기준을 통과하지 못했다.

보류 이유는 작은 F1 차이 하나만이 아니다. 완전 복원 이득은 한 단어 계열의2개 위치에 한정됐고, 정상 판정 변화는 묶음 동료의 영향과 모델 변동을 포함한다. 근거 부족과 치환 누락은 해결되지 않았고 실제 속도 개선도 없다. 모든 자료가 이미 관찰한 합성 진단이며 운영12배치/독립 자료/25분 조건의 효과는 아직 모른다. 현재 결과로 ‘대부분의 숫자 치환을 일반화해 해결한다’고 주장할 수 없다.

이번 개선안에 예외를 덧붙이거나 특정 실패 표기를 맞추지 않고 종료한다. 다음에 추가 검증한다면 이전에 제안한 **동일 토큰의 상충 문맥을 서로 다른 요청으로 분리하는 묶음 구성 비교**를 먼저 수행하는 편이 합리적이다. 복원 규칙 자체의 확장이나 파인튜닝과 동시에 바꾸지 않는다. 이 작업은 이번에 실행하지 않았다.
