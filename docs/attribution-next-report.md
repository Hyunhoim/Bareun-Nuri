# 자모 복원 운영 적용 및 문맥 귀속 후속 비교

2026-09-26. 사전 계획: `docs/attribution-next-plan.md`.

## 결론

**검증된 자동 자모 복원 C는 운영에 적용했다. 후속 E/F/H는 모두 기본 구현에 넣지 않는다.** E는 전체 합산 F1과 기존 복제본에서 유망했지만 새 확인 자료의 광고 재현율이 하락했다. F는 역할 구분의 이득과 실제 권유 인용의 누락이 함께 나타났다. H는 호출을 두 배 쓰면서 전체 F1이 낮아졌다. 성공으로 보이도록 결과를 본 뒤 기준을 바꾸거나 이 세 후보를 결합하지 않았다. 사전 확대 조건이 충족되지 않아 기존104 추가 유료 회귀 및 새25분 종단 실행은 시행하지 않았다.

현재 운영: FIFO → 작업당 브라우저 재사용 → 디스크 근거 저장/SRPT8·aging8 → C 보조 읽기 → HCX-007 none·순차 최대4·출력512. 첫 구간25분/최대600호출과 부분 저장 계약을 유지한다.

## 1. 실제 운영 변경과 검증

- `agent/src/core/jamo-reading.cjs`: 이미 검증한 C를 그대로 승격했다. 현대 자모 사이의 제한된 영폭 문자 제거와 단일 공백 자모열의 보수적 음절 결합을 담당한다. 단어 의미나 광고 의도를 추정하지 않는다.
- `agent/src/core/judgment.cjs`: 모델 입력의 `normalized_text`만 C 결과를 사용한다. 원문, 저장된 DOM·스타일·위치, 관찰 기법, 프롬프트, 판정 출력 계약은 유지한다.
- `agent/src/worker.cjs`: 새 모듈을 코드 서명에 포함한다. 옛 코드 서명의 체크포인트는 자동 재개하지 않으며 기존 결과를 보존한다.
- `semantic-adoption.test.cjs`: 보관된 실험 C와 운영의 전체 요청 일치, 실제 저장 입력1,845개 일치, 원문/관찰 보존을 검증했다. 자모 경계14개/현대 NFD 음절11,172개 및 bounded-worker 중단·재개/미확인 요청/서명 불일치 검사를 통과했다. `agent/test.cjs`도 통과했다. 이 승격 검사는 API0회다.

검사 기록: `.runtime/semantic-adoption-check-1790355171631/check-result.json`, `.runtime/bounded-worker-check-1790355209094/result.json`.

앞선 C의 실제25분 검증은 `docs/jamo-context-report.md`에 있다. 통제64위치 F1은69.77→78.26%, 기존15정탐 보존/3회복이었으나 통제 밖 정상 '작성자' 오탐1개가 추가됐다. 그 정상1개를 사후 포함한 민감도 F1은76.60%였다. 이는 과거 측정이며 이번 승격에서25분을 재호출한 수치가 아니다.

## 3. 정확도 결과

각 자료 열은 두 실행의 F1 산술평균이다. 전체는 TP/FP/FN을 합산한 micro F1이므로 평균 F1과 다르다. 43개 복제본 패널은 이미 판정된 대상을 재구성한 의미 진단이며 전체 사이트/25분 도달 성능이 아니다.

| 조건 | 새 개발 F1 | 새 확인 F1 | 복제본43 F1 | 전체 TP/FP/FN | 전체 정밀도 | 전체 재현율 | 전체 F1 |
|---|---:|---:|---:|---|---:|---:|---:|
| A 운영 C | 89.29% | 90.91% | 92.50% | 77/10/5 | 88.51% | 93.90% | 91.12% |
| E 구조 정보 | 92.62% | 87.86% | 97.56% | 77/5/5 | 93.90% | 93.90% | 93.90% |
| F 역할 출력 | 89.47% | 87.62% | 96.34% | 75/5/7 | 93.75% | 91.46% | 92.59% |

**E의 전체 F1 +2.78%p와 오탐10→5는 실제 이득이다.** 다만 새 확인의 광고는 A가20/20회 맞힌 반면 E는18/20회로 줄었다. F도18/20회였다. 기존 복제본의 개선만으로 일반화를 확정할 수 없다. H의 확인 평균 +0.19%p는 두 회의 FP배분이 달라 생긴 비선형 평균 차이로, 확인 합산 TP20/FP4/FN0은 A와 같다.

## 5. 남은 병목: 관측과 가설

1. **인용 형식의 실제 권유를 예방 인용으로 바꾸는 오류.** 새 확인 E는 실제 투견 참가 초대 인용1회, 판매 물품명1회를 놓쳤고 F는 실제 거래 인용2회를 놓쳤다. 판매·입금 문맥은 실제 입력에 있었다. 수집 누락이 아닌 판정 오류다. 태그/인용 표시를 과도하게 신뢰했다는 설명은 가설이며 확정된 내부 원인이 아니다.
2. **짧은 행동 문구와 표시 라벨의 구별.** E는 기존 '접수 창구'를 두 회 모두 회복하고 한 회 '신청 안내'를 회복했다. 그러나 원래 '작성자'는 이번 A도 두 회 모두 판단불가였으므로 E가 그 오탐을 해결했다고 볼 수 없다. F는 작성자를 정상 처리했지만 다른 인용 광고를 잃었다. H는 작성자 오탐을 한 회 재발시켰다. 단순 단어 제외는 하지 않는다.
3. **배치 축소만으로 불안정성이 해소되지 않음.** H는 기존 C가 회복한 영폭 자모 광고1회를 다시 놓쳤고 '주문서 작성' 광고도 개발 두 회 모두 놓쳤다. 호출량 증가를 정당화할 순이득이 없었다.
4. **대상 링크 자체의 주소 미수집.** `collect.cjs`의 후보 links는 대상의 descendant `a[href]`만 조회하므로 대상 자체가 anchor일 때 자신의 href가 비는 경우가 있다. 페이지 탐색용 전체 링크 목록은 별도 수집되므로 URL 발견 누락과는 다른 문제다. 이번 합성 자료도 실제 계약대로 target anchor의 links를 비웠다. 이 결손이 이번 오판을 유발했다는 인과 검증은 하지 않았다. 추후 수정한다면 수집 근거 보존과 own-link 전달만 독립 비교하는 것이 프롬프트 누적보다 명확하다.
5. **25분 안의 미판정 광고는 별개.** 이번 진단은 저장 근거 판정만 비교했다. 앞선25분 실행의 미판정 광고7개를 해결하거나 시간 예산 내 재현율을 높였다고 주장하지 않는다.

## 6. 일반화 한계와 종료 판단

새 개발/확인은 어휘와 표현이 다르지만 여섯 유형의 문장 설계가 유사하다. 독립적인 실사이트 분포 표본이나 실제 DOM 수집 검증이 아니다. 같은 문구/태그의 정상·광고 대조, 정상 anchor와 광고 span을 포함했어도 합성 설계 편향은 남는다. 정상 메타데이터4개/분할은 소속 문맥 광고3개와 미귀속 주변 광고1개로 구분해야 한다. 정답은 해당 요소 자체의 게시 행위를 기준으로 수동 구성했다.

이미 분석한 복제본43개는 회귀 자료다. 이 자료에서만 좋은 후보를 계속 튜닝하면 과적합 위험이 있다. E/F의 새 확인 성능 저하는 그 우려를 뒷받침하지만, 두 회의 작은 표본만으로 모든 사이트에서 나빠진다고 확정하지도 않는다. 새 확인 자료 역시 이번 선택에 사용했으므로 이후 재실행은 새 홀드아웃이 아니다.

따라서 **운영에는 C만 남기고 E/F/H의 유료 확대를 종료한다.** 다음 가치 있는 가설은 위 자기 링크 근거 결손의 독립 검증이며, 같은 실패 문장에 지시를 더하는 작업은 권하지 않는다.
