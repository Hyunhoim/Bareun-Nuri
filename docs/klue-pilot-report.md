# KLUE RoBERTa-base 파인튜닝·CPU 평가

## 결론

**모델 다운로드, 실제 GPU 파인튜닝, 최종1회 평가, CPU 속도 측정 완료. 운영 미채택, HCX007 유지.** CPU 실행 비용은 낮았지만 최종 광고F1이70.00%로HCX96.97%보다 낮았다. 이 한정 학습 실패를 RoBERTa의 성능 상한으로 해석하지 않는다. 최종 결과에 맞춘 재학습·프롬프트 수정·평가 재실행은 하지 않았다.

## 자료 분리와 평가 계약

사용자 지시대로 훈련384개/검증128개/최종128개를 분리했다. 서비스명·권유표현·인용/예방 설명·정상/불충분 설명의 계열을 나눴으며 같은 대조쌍과 자모·영폭문자 변형을 한 분할에 묶었다. 분할 간 동일 완전 입력0개. 원천그룹은48/16/16개다. 원문과 모델용읽기를 보존하지만 분류기 입력은 정규화된 대상+앞뒤문맥으로 구성한다. NFD 복원 등으로 같은 입력이 되는 변형이 있어 실제 고유 입력은224/80/80개다. 사례 수가 독립 표본 수와 같지 않다.

훈련은 train/validation만 읽었다. 검증 macro4F1 최고, 동률이면검증loss최저인 체크포인트 선택. 모델/전처리/자료hash고정 후 KLUE와HCX가 각1회 최종입력판정. KLUE 예측파일을 저장한 뒤 최종정답을 열었다. `final-started.json` 및 `hcx-final-started.json`은 exclusive생성하며 이미 시작한 최종평가는 재실행하지 않는다. 원응답 재집계는 추론 재실행이 아니다.

기존137개는 학습/검증/최종에 사용하지 않고 알려진 자료 회귀로만 별도 측정했다. 이전 v1초안은 공통 역할표현을 학습 전에 발견해 사용하지 않았고 v2에서분리했다. v1학습/추론0. 최종평가후자료변경0.

**한계:** 모두 같은 작성자의 통제된 합성이고 추상적인 시나리오 구조는공유한다. 모호문구에 설명부족을 명시하고 정상메타데이터에 역할설명을붙인 쉬운단서가있다. 실제 공공사이트 분포나 독립 전문가 주석이 아니다. '훈련·검증·최종 분리'만으로 이런 설계편향은없어지지않는다. 최종결과를 본 지금 자료는다음실험의미사용최종셋으로재사용할수없다.

## 학습

klue/roberta-base revision `02f94ba5e3fcb7e2a58a390b8639b0fac974a8da`를 고정하고 공식 model.safetensors LFS SHA256과다운로드파일일치검증. 원본442635012bytes. 새4분류head와전체본체를 full fine-tuning. RTX4060Laptop8GB, seed42, AdamW2e-5/weight_decay.01/batch8/최대512토큰/4epoch. 30분보호이내22.45초학습, PyTorch할당최대2244461056bytes(약2.09GiB). 모델다운로드·의존성설치·토큰화는학습시간밖이다.

## 최종 평가1회

128개=광고32/예방·보도인용32/일반정보32/근거부족32. 근거부족은광고이진F1분모밖이며macro4와별도오확정으로평가.

|지표|KLUE fine-tuned|HCX007 운영계약|
|---|---:|---:|
|TP/FP/FN|28/20/4|32/2/0|
|정밀도|58.33%|94.12%|
|재현율|87.50%|100%|
|광고F1|70.00%|96.97%|
|4분류macroF1|77.92%|81.70%|
|예방인용→광고|8/32|2/32|
|일반정보→광고|12/32|0/32|
|근거부족→판단불가|32/32|17/32|

HCX는근거부족15개를일반정보로,정상6개를판단불가로분류했다. KLUE의모호100%는명시적설명부족단서에대한결과로실제불확실성보정능력증명이아니다. 정상오탐이더큰핵심미채택원인이다.

HCX는현재SYSTEM/자모C/none/512/최대12순차,11호출/37010토큰/58.21초,전부200/완전출력. KLUE는대상읽기+앞뒤문맥,HCX는원문/정규화/스코프등운영근거를받는다. 같은출처대상과문맥의시스템비교이지만입력표현은완전히동일하지않다. 모델크기만의인과효과로결론내리지않는다. 양쪽크롤러는없다.

## CPU 실행

학습프로세스종료후CPU-only/8threads/float32/batch8,128개모델forward3.660초. 토큰화와모델로드제외,로드0.153초는디스크캐시가있는상태다. HCX통신포함58.21초와의이번관측비는약15.9배이나모든사이트/장비의속도배수나25분종단효과가아니다. HCX호출실행기와CPU측정이일부겹쳤다.

검증32개에서만CPU속도3회반복: batch1 1.173/1.178/1.144초, batch8 .820/.901/.882초. 최종128은1회. 판정시점working set948494336bytes(0.88GiB), private1885822976bytes(1.76GiB), peak private/pagefile2271383552bytes(2.12GiB). 서로더하지않는다. 현재장비에서수집기/백엔드전체를함께운영한메모리측정이아니다. 주최측사양보장아님.

훈련/검증/최종/회귀모두512절단0개. 따라서이번실패는입력길이절단때문이라고볼수없다. 길고복잡한실사이트문맥에대한512토큰제약은미검증으로남는다. 양자화는실행하지않았다.

## 알려진137개 회귀

KLUE TP24/FP6/FN36, 정밀도80%, 재현율40%, 광고F153.33%, CPU3.995초. 모호12는이진점수밖. 회귀정답은광고/정상만있어4분류macro점수는해석하지않는다. HCX의최근같은137개기존평가는약89~91%F1이었으나이번같은시각/입력표현통제비교가아니므로과거값은참고만한다.

검증100%→새최종70%→관찰회귀53.33%는넓은분포에대한일반화부족을보여준다. 원인후보는학습384개의낮은유효다양성,표현/역할설명단서의존,운영입력과분류기표현차이다. 단일실험으로각원인의기여를분리하지않았다. 숫자치환관찰이나DOM기법정확도개선실험이아니다.

## 다음 판단

운영교체/25분유료확대없음. 다음학습을원하면현최종128을회귀로내리고새최종자료를분리해야한다. 실제수집문맥의사람검토라벨,다양한귀속경계,예방설명옆실제광고,정상식별자등학습범위를먼저보강할가치가있다. 같은최종오류를예외처리하거나epoch만늘리는수정은권하지않는다. 이번실험은CPU경량분류기라는방향의실행가능성을확인했으나HCX대체가치는입증하지못했다.
