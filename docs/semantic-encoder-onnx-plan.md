# 동결 분류기 ONNX/INT8 진단 계획

2026-09-29. 실제 입력 검수는 아직 대기 중이다. 앞선 turn은 새 실수집·CPU 측정으로 진행했다. 이번에는 학습이나 의미 판정 조정 없이 배포 형식만 비교한다. 운영 HCX 변경·API 호출은 없다.

- 가설: 동일 가중치의 ONNX FP32 및 MatMul 동적 INT8 변환으로 CPU 지연/파일 크기를 줄일 수 있다. 정확도 보존 여부는 별개로 확인한다.
- 대상: research-candidates.json에 고정된 KLUE/Kc/Ko 각1개. 임계값0.5, NFC, 대상+문맥,512토큰,8threads/batch8을 유지한다. 원문/잘림 보류를 그대로 보존한다.
- 형식: PyTorch2.6 기존 exporter(opset17, dynamic batch/sequence), ONNX1.17, ORT1.23.2 CPU. 양자화는 MatMul 상수 weight QInt8/per_channel 한 조건만 실행한다. 이 조건의 실패를 보고 다른 양자화 설정을 점수에 맞춰 탐색하지 않는다.
- 확인 자료: 기존 개발90, 관찰 HCX 비교204, 관찰2000, 실제 미라벨2003. 기존 자료의 반복 회귀이며 새 독립 최종 평가로 부르지 않는다. 실수집 예측 일치는 정확도 증명이 아니다.
- 보존 관문: FP32는 전 자료 hard 판정 일치 및 저장 확률의 최대 오차1e-4 이하. INT8은 라벨 있는 각 패널에서 원본 정탐 손실0/새 정상오탐0, 미라벨 raw 판정 변경0을 요구한다. 보류 경계 변화도 따로 센다. 실패 시 운영/동등 대체 후보로 채택하지 않는다.
- 속도: 같은2003개 실제 입력, 워밍업 후1회. 원본 PyTorch 측정은 이전 turn이므로 환경/순서 차이 한계를 명시한다. 속도 후보 관문은 이전 원본 대비20% 이상 감소지만 이를 인과적 반복 벤치마크라고 주장하지 않는다. 파일 크기와 프로세스 작업 메모리도 기록한다.
- 각 모델 export/각 실행은 별도 프로세스. 라이브 프로세스만 기다리며 오류는 보존한다. 검증 가능한 입력/가중치/코드/출력 해시, 패널별 판정 변경·정탐 손실을 저장한다. 학습/최종셋 소비/임계값 변경은 없다.

실행 정정(예측 전): KLUE의 symbolic shape inference가 `Min(514, sequence)` broadcast 오류로 중단됐다. 보조 symbolic 단계만 생략하고 ONNX shape inference/checker 및 실제2/17/512길이·1/3/8batch 실행을 유지한다. 양자화·학습·판정 조건은 같고 예측 결과에 따른 변경이 아니다. 최초 설치는 출력 없이 시스템 호출이 누적되어 명시 중단 후 pip legacy-certs(인증서 검증 유지)로 성공했다. 의존성은 별도 폴더에만 설치했다.
