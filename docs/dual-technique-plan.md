# JAMO/HOMOGLYPH 두 기법 학습 비교 — 사전 계획

2026-09-30. 운영 HCX/코드 변경 없이 실험한다. 목표는 순정 KLUE와 KcELECTRA 중 두 기법의 일반화 연구 후보를 찾는 것이며, 점수가 나올 때까지 최종 자료를 다시 만들지 않는다.

## 판정 계약

- 광고 의도와 독립적인 문자 기법 관찰이다. 예방 인용에도 실제 분해/치환이 있으면 기법 양성이다. 광고 문구라고 기법을 양성으로 만들지 않는다.
- 대상 표기와 해당 요소 문맥만 사용한다. 두 기법 각각 present/absent/uncertain 3상태(총6 logits, 두 cross entropy 평균)로 판정한다. 복합 기법을 허용한다. uncertain을 absent로 숨기지 않는다.
- Unicode16 보조 대응은 기존 검증한 표와 함수를 재사용한다. 원문과 원문 위치를 보존하며 정답 복원문, 생성 변형명, 라벨, ID, 어휘 그룹을 모델 입력에 넣지 않는다. NFD 변화 자체를 HOMOGLYPH 양성으로 취급하지 않는다.
- 이번 모델은 주어진 표기 구간을 판정한다. 임의 웹페이지의 후보 발견/기법 위치 추출 성능이나 종단 F1로 보고하지 않는다.

## 자료

1. 새 기본 자료: 일반 한글/영문, 정준·호환 자모, 영문 숫자·키릴 치환, 복합, 정상 규격·식별자, 불충분 문맥을 포함한다. 권유/신고/교육/행정 문맥과 문자 기법을 교차한다.
2. 추가 학습 자료: 별도 어휘와 문장 틀에서 부분 분해, 공백/zero-width 분해, 한글자모·라틴/CJK 혼용, 주변 다른 작성자 표기와 대상 귀속을 포함한다. 기본 자료와 함께 학습한다.
3. 개발 자료와 봉인 확인 자료는 어휘 그룹·문장 틀을 분리한다. 동일 생성자의 통제 합성이라는 한계와 문맥 설명의 지름길 위험을 명시한다. 실제 게시글/독립 사람 검수라고 소개하지 않는다.
4. 기존320/96/96,112,한글48은 학습하지 않는다. 기존 관찰/회귀 자료로만 사용한다. 직접 문장·표기 중복을 검사한다. 기존 어휘의 일부 문자 중첩까지 독립성으로 주장하지 않는다.

## 실행·선택

- GPU RTX4060, FP32, seed42, batch8, AdamW lr2e-5/weight_decay.01, clip1, 전체 학습 3epoch, 후보당 최대30분. 공개 사전학습 체크포인트에서 새6출력 헤드를 초기화한다. 모델별 최적화 탐색을 하지 않는 제한 비교다.
- 개발 두 기법 macro(양성F1 평균), 기법별 최저F1, 정상·불확실 오확정 수, 전체 상태 정확도, 이른 epoch 순으로 checkpoint를 선택한다. 기법별 F1 0.80 이상인 모델을 연구 후속 대상으로 삼고, 둘다 미달이면 원인진단 후 다른 한 요인만 추가 비교한다.
- 1차 유망 모델은 개발 기준으로 선택한다. CPU 지연은 실제 배치8/8threads에서 측정하며 로딩 제외/포함을 구분한다.
- 2차는 선택 checkpoint에서 기본+추가 자료(실제 고유 행 각1회)를 lr1e-5/최대2epoch 추가 학습한다. 대조는 같은 모델의 순정 checkpoint에서 동일 전체 자료를 lr2e-5/최대3epoch 학습한다. 단계별 exposure/업데이트 수 차이도 보고한다.
- 최종 후보는 개발 기준으로 동결한다. 기존 회귀의 정탐 손실/오탐은 안전성 판단에 사용하지만, 이를 보고 다른 후보로 바꿔 승자를 만들지 않는다.
- 새 봉인 확인은 선택 모델과 고정 기준선만1회 실행한다. 개발보다 저하/기존 정탐 손실이 있으면 보고하고 운영승격하지 않는다. 별도 제작자의 자료와25분 종단 검증은 이번 범위 밖이다.
- 유망성은 두 기법 균형, 정상 오확정 억제, 기존 HOMOGLYPH 정탐 보존, 독립 어휘/틀 확인에서의 유지로 판단한다. 하나의 합산 점수만으로 성공 선언하지 않는다. 목표 미달이면 해당 사실과 다음 필요한 근거를 보존한다.

## 예산·검증

최초 최대4학습(2기본+2후속), API0, 운영 변경0, push0. GPU 작업 순차 실행. 해시/라벨 비노출/분할/두 기법 점수 계산/중단 재실행 보호를 자체검사한다. 기존 변경 파일을 덮어쓰지 않는다.
