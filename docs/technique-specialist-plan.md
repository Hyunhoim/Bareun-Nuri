# 숫자·닮은꼴 문자 특화 모델 비교

2026-09-29 사용자 요청. 필터 Goal은 폐기됐으며 이 실험은 후보 제외가 아닌 기법 보완이다. HCX 광고 의도 운영/코드 확정 관찰은 고정, 운영 소스 수정 없음.

## 데이터
순정 KLUE RoBERTa-base에 목적 특화3분류(substitution/literal/uncertain)를 학습한다. 어휘계열별 train/dev/final을 분리하고 분할별 문장 틀을 다르게 작성한다. 동일 토큰의 광고/예방/식별자/정보부족 대조와 숫자 일부 보존·키릴 혼합·전각을 포함한다. 입력은 원문 대상 표시+실제 작성 문맥으로 제한하고 정답 읽기는 입력에 주지 않는다. 동일 생성자 합성이며 독립 사람 검수/실사이트 분포가 아니다.

최종 파일은 최초 생성 시 해시만 봉인하고 checkpoint와 HCX 계약을 고정한 후 한 번 평가한다. 최종은 원래/역순 두 조건을 미리 고정한 한 평가 캠페인이며 순서 차이를 숨기지 않는다. 이전 평가 문장을 학습에 재사용하지 않는다.

## 조건
A 현재 관찰 코드. B 코드 확정은 유지하고 나머지 문자 혼합 후보만 HCX-007 none/temperature0/seed42/묶음4/출력512로3분류. C B와 같은 대상에 특화 분류모델. 세 조건에 동일한 의심표기 입력과 확정 코드 관찰을 제공한다. 실험의 넓은 후보 생성과 기존 미확정 힌트 범위 차이를 별도 기록한다.

분류모델은 새3분류헤드/전체학습3epoch/lr2e-5/배치8/seed42/weight decay .01로 제한하고 개발 macro3 F1로 checkpoint를 고른다. 추론 CPU8threads/batch8. 잘림/형식실패는 미확정으로 기록한다. 원래와 역순 추론은 별도 시간/정확도를 측정한다.

HCX 전체300전송/60만 확인토큰/1시간 상한. 기존 예산·요청기록 사용, 미확인 요청 자동재시도 금지. 키 출력 금지. 최종 의도 고정 비교는 합성 정답 광고 마스크의 조건부 결과와 실제 HCX 의도 고정 결과를 구분한다. 후자가 미실행이면 제출 종단 개선으로 주장하지 않는다.

## 판정
기법3분류 macro F1, 확정 표기 F1, 정보부족의 위장 과도확정, 문자 구간/원문 보존, 정상 표기 오확정, CPU시간/API호출·실토큰을 보고한다. URL·위치·기법 제출 형식으로 별도 집계하되 원래 의미 누락을 가리지 않는다.

후속 운영 검증 후보는 개발/최종에서 코드 대비 strict 기법 F1이 최소3%p 개선하고 정상표기 오확정률≤5%, 정보부족 위장확정률≤10%를 만족해야 한다. 성공을 위해 사후 기준을 낮추지 않는다. 양후보 통과 시 제출 정탐/오확정과 지연을 비교해 선택한다. 최종 운영 승격은25분 종단 비교 후에만 가능하다. 둘다 실패하면 코드 유지·아키텍처 미채택 결론과 남은 병목을 기록한다.
