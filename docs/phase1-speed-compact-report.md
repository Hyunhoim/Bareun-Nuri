# Phase 1 반복 값 참조 압축: API 0 사전 진단

2026-10-01. 운영 변경 없이 최신 Phase 1 저장 요청 516개, 후보 5,070개를 검사했다. 정답을 읽거나 압축 규칙에 사용하지 않았다.

후보의 같은 필드에 완전히 동일한 긴 값(80문자 이상)이 반복되면 공용 `shared_values` 표에 한 번 저장하고 해당 필드에 `shared_ref`를 둔다. 다른 문구를 요약하거나 문맥 일부를 삭제하지 않는다. 필드 이름·값·node_id·후보 순서·대상 및 문맥 귀속·출력 스키마를 모두 보존한다. 표가 짧아져도 추가 읽기 지시문까지 합한 로컬 예약 추정량이 감소하지 않으면 원래 요청을 그대로 사용한다. 이는 사례/정답 기반 분기가 아니라 직렬화 비용 검사다.

전체 요청 문자 3.53%, 로컬 예약 추정 0.96% 감소다. **실제 제공사 입력 토큰 감소율이나 실행시간 감소율은 아니다.** 나머지 294요청은 입력 표현 자체가 그대로다. 역복원 일치는 코드의 정보 보존만 증명하며 HCX가 참조를 원래 문맥과 동등하게 해석한다는 증거는 아니다.

과거 `throughput-report.md`의 normalized_text 동일표시와 출력 상한 동시 변경, `call-input-report.md`의 키별칭 치환, `scoped-input-plan.md`의 unscoped_nearby 삭제와 구분한다. 이번에는 정규화 필드 특례·키 축약·문맥 삭제·출력 상한 변경을 하지 않았다. 긴 동일 필드 값만 공유하므로 후보간 귀속을 잘못 합칠 가능성은 여전히 실제 판정 비교 대상으로 남는다.

**사전 판단:** 참조 해석 부담에 비해 입력 절감 폭이 작다. 이 진단만으로 운영 채택 또는 대규모 유료 확대로 이어갈 근거는 부족하다. 소규모 공통 비교에 포함할 수는 있지만, F1 보존을 확인하더라도 실제 지연 감소가 없으면 미채택이 합리적이다.

**이번 비교의 종료 결정:** 추가 유료 측정 없이 사전 경제성 검토에서 중단하고 미채택한다. 기존 전체 실행의 할당량 대기가 약 6초였으므로 작은 예약량 절감이 지배적인 응답 지연을 해소한다는 근거는 약하다. 변경된 222요청만의 결과를 전체 516요청 효과로 보고하면 안 된다. 0.96%는 지연 개선의 수학적 상한이 아니며 실제 토크나이저와 처리시간의 관계는 미측정이다. 따라서 효과가 없음을 입증했다고 하지 않고, 제한된 실험 자원을 배분할 때 추가 호출을 정당화할 근거가 부족하다고 결론낸다. 의미 F1·실제 토큰·실제 지연은 미측정으로 남긴다.

구현 `local-benchmark/phase1-speed-compact.cjs`의 `transformBody(body)`는 불변 변환 함수다. 실행 `node local-benchmark/phase1-speed-compact.cjs`로 516요청 진단과 자체검사를 재현한다. 결과 `.runtime/phase1-speed-compact-v1/diagnostic.json`에는 요청별 전후 길이/예약 추정/공유필드가 저장된다. singleton·참조 범위 오류·literal 참조구문 충돌·원본 불변·값 차이·전체 역복원 검사를 포함한다. 모델 학습·API 호출·운영 수정·Phase 2 접근은 0이다.
