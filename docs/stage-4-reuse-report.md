# 4단계 독립 검증 — 절감 확인, 판정 보존 실패로 미채택

2026-09-23. **반복 판정 절감 실험을 구현하고 실제 HCX-007 호출로 검증했다. 호출·토큰·시간은 줄었으나 기존 광고 판정과 관찰 기법이 달라져 운영에는 적용하지 않는다.** 병렬화와 5단계로 확대하지 않았다. 기본 worker·판정기·수집기·출력기는 그대로다.

## 남겨 둔 2·3단계 문제

2단계에는 문맥 의존 광고 누락, 예방 인용/근거 귀속, 불확실성과 순서·반복 안정성 문제가 남아 있다. 미채택 contextual/attributed/direct 경로는 사용하지 않았다.

3단계 관찰 모듈은 독립 검증 상태이며 전체 통합은 미채택이다. 숫자 치환의 미확정, 식별자 오탐, 복원·출력 계약 오류도 남아 있다. digit 개선안도 사용하지 않았다. 4단계에서 이를 해결하거나 정상으로 재라벨링하지 않았다.

이번 기준선은 **현재 웹 worker의 기본 createSession → 후보 16개 순차 판정 → outputResult**다. 이전 isolated 저장 의미 판정이나 3단계 저장 응답 통합의 F1 96.77%를 현재 worker 점수로 사용하지 않았다. 이번 숫자들과 그 과거 수치를 직접 비교하면 안 된다.

## 실제 중복률부터 확인

사전 계획 `stage-4-reuse-plan.md`를 고정한 뒤, 저장된 전체 사이트 101페이지·3824개 후보를 읽었다. 후보 ID·URL·선택자 같은 출력 위치를 제외하고 수집된 근거 전체를 비교했다. 원문·정규화문·문맥·링크·프레임·자기/조상 스타일·좌표를 보존하고, 별도 관찰 근거도 위치 식별값을 제외한 내용이 같아야 한다. 알려지지 않은 근거 필드를 임의로 제거하지 않았다.

| 일치 조건 | 중복 후보 수 | 비율 |
|---|---:|---:|
| 원문만 같음 — 재사용 근거로 사용하지 않음 | 3289 | 86.01% |
| 현재 모델 입력만 같음 — 누락된 수집 근거를 무시하므로 미사용 | 2058 | 53.82% |
| 수집 문맥·스타일·별도 관찰 근거까지 같음 | **503** | **13.15%** |

현재 모델 입력에는 수집된 구조화 문맥·조상 스타일의 일부가 전달되지 않는다. 이것을 재사용 키에서도 버려서 중복률을 높이지 않았다. 모델 입력의 개선은 이번 변경 요인이 아니다.

대표 후보를 다시 16개씩 묶으면 전체 요청은 계산상 239→208회로 최대 12.97% 줄일 수 있다. **이는 전체 사이트 실제 호출 결과가 아니라 계획상 상한**이다. 기존 순서와 배치를 통째로 유지하면서 재사용할 수 있는 배치는 0개였다. 306개 선별 패널과 28개 문맥 진단의 보수적 중복은 각각 0개였다.

## 구현과 비교 방식

- `agent/experiments/reuse-audit.cjs`: 읽기 전용 중복률 분석. 실제 llm.cjs의 입력 투영 함수를 사용해 모델 입력 일치와 전체 근거 일치를 분리한다.
- `agent/experiments/reuse.cjs`: 실행 안에서 첫 출현 후보만 대표로 선택하고, 검증된 응답을 원래 후보 ID마다 복제한다. 실행 간 캐시, 유사 문장 병합, 메뉴/제목의 일괄 제외는 없다. 보류 결과도 보존한다.
- `agent/experiments/reuse-run.cjs`: 기본 worker와 같은 판정 계약의 opt-in 실험. 실패/누락을 정상 응답으로 재사용하지 않으며 429 사용량 부재는 예산 예약량으로 별도 처리한다.
- `reuse-audit.test.cjs`, `reuse.test.cjs`: 다른 문맥·스타일·좌표·링크·프레임 등 15가지 차이의 병합 차단, 배열 순서, 관찰 귀속, 원문·위치 매핑, 정상/광고/보류 보존, 응답 누락·원본 변경 거부를 검사한다.

유료 호출 전 `stage-4-reuse-live-plan.md`와 입력·라벨·소스를 고정했다. 전체 스냅샷의 첫 192개, 광고/정상×4기법별 6개씩 48개, 문맥 진단 28개로 총 268개 파일럿을 구성했다. 의미 정답은 76개(광고 36·정상 40), 기법 정답은 그중 48개에 있다. 나머지 192개를 정상 정답으로 가정하지 않았다. 라벨은 모델 입력이나 재사용 키에 넣지 않았다.

HCX-007, thinking none, temperature 0, seed42, 최대 출력 3072토큰, 배치 16, 순차 실행을 고정했다. 원본 A1 → 재사용 B → 원본 반복 A2를 각각 한 번 실제 호출했다. 재사용 B는 20개 중복을 대표에 연결해 248개만 모델에 보냈으며 268개 전체 결과를 복원했다. 기본 경로에는 연결하지 않았다.

## 실제 결과

### 광고 의도: 정답이 있는 76개

보류된 양성은 확정 탐지에서 빠지므로 FN에 포함한다. 이 표는 전체 3824개 사이트 F1이 아니다.

| 항목 | 원본 A1 | 재사용 B | 원본 반복 A2 |
|---|---:|---:|---:|
| TP / FP / FN | 35 / 7 / 1 | **33 / 6 / 3** | 35 / 3 / 1 |
| 정밀도 | 83.33% | 84.62% | 92.11% |
| 재현율 | 97.22% | **91.67%** | 97.22% |
| F1 | 89.74% | **88.00%** | 94.59% |
| 라벨 대상 검토 건수 | 1 | 4 | 1 |

원본 두 실행이 모두 확정한 광고 중 B에서 2개가 확정 탐지에서 빠졌다. “바로 연결”은 광고 판단을 유지했지만 needs_review가 추가됐고, “이용 안내 보기”는 정상으로 바뀌었다. 단순히 기존 양성 수만 비교하지 않고 같은 후보가 유지됐는지도 확인했다.

이 48개의 관찰 기법 FP는 세 조건 모두 0이었다. 최종 출력 FP에는 정상 인용을 광고로 잘못 판정한 의미 오류가 반영된다. **관찰 또는 최종 부분집합의 점수 상승으로 76개 의미 판정의 회귀를 가리지 않았다.** 기법 정답이 없는 28개 문맥 사례의 관찰 정확도를 이 표에 섞지 않았다.

### 판정 안정성과 위치

- A1과 B에서 의미/보류/기법 signature가 바뀐 후보는 **20개**, 이유 문장이 바뀐 후보는 166개였다.
- 바뀐 20개는 모두 재사용으로 응답을 복사한 후보가 아니라 **여전히 모델에 직접 보낸 후보**다. 중복 제거 뒤 배치 이웃이 바뀌었다. 복사된 20개는 A1 대비 signature 변화가 0개였다.
- A1과 A2는 **17개 요청 body가 전부 동일**함을 직접 검증했다. 그런데 signature 5개, 이유 문장 63개가 달라졌다. temperature 0과 고정 seed만으로 응답 동일성이 보장되지 않는다는 관측이다.
- 따라서 B의 변동 전부를 캐시나 배치 변경의 단독 원인으로 단정하지 않는다. 원본 반복 변동도 존재한다. 다만 B는 두 원본 모두 탐지한 광고를 놓쳤고, 사전 판정 보존 관문을 실패했다.
- 세 실행 모두 원래 268개 후보를 정확히 한 번 결과에 포함했다. URL·선택자·원문 귀속을 재계산해 저장 출력과 일치시켰다. 같은 근거의 중복 그룹 내 판정 모순은 각 실행에서 0건이었다.

전체 **50회, 329,237토큰, 802.15초**다. 모든 호출은 HTTP 200이고 사용량 누락·429는 없었다. 실제 요청 수·토큰은 사전 상한 64회·400,000토큰 이내다. 원화 과금액은 확인하지 않았다.

## 판단과 남은 범위

4단계 독립 검증은 **안전한 키의 중복 측정 → 재사용 구현 → 위치/보류 검사 → 실제 원본/재사용/원본 반복 비교**까지 시행했다. 절감 실익은 있지만 기존 양성 보존·판정 안정성 관문은 실패했다. 따라서 실험 경로를 미채택하고 현재 Pipeline을 유지한다. 병렬화와 5단계로 확대하지 않는다.

2·3단계 문제를 해결했다고 주장하지 않는다. 이번에 확인한 주요 제약은 “후보 근거가 같아도, 후보를 묶어 보내는 구성이 바뀌면 나머지 후보의 판정을 그대로 유지한다고 가정할 수 없다”는 점이다. 모델의 자체 변동도 별도 제약으로 남는다.

기존에 사용한 같은 작성자의 합성 자료다. 독립 실사이트 일반화 개선은 검증하지 않았다. 이 268개의 점수에 맞춰 키를 완화하거나 문구 예외·프롬프트·배치 규칙을 조정하는 것은 과적합 우려가 있어 하지 않는다. 실패한 원본이나 좋은 반복 결과만 선택해 기준선을 바꾸지도 않는다.

전체 `npm.cmd test --prefix agent`와 `git diff --check`를 통과했다. 기본 실행 소스와 고정 입력·라벨의 해시, 요청 body 동일성, 라벨 필드 미전달을 검증했다. Graphify는 현재 소스 복사본을 구조적으로 갱신했으며 레거시 ID 경고가 있어 연결은 실제 소스로 다시 확인했다. 실제 API는 실험 대상 호출 외에는 사용하지 않았다. 커밋·push는 하지 않았다.
