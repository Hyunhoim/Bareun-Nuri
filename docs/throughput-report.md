# 토큰 절감 × 페이지 분산·동시 판정 비교 결과

2026-09-25. **두 개선군의 단독·결합 실험을 완료했다. 결합안은 속도가 빨라졌으나 광고 누락이 증가해 미채택하며, 운영 코드는 유지한다.** 사전 계획은 `throughput-plan.md`, 실제 수집 API0 보완 계획은 `throughput-coverage-preflight.md`다.

기존 dev52+이미 관찰한 holdout52의 저장 근거를 모두 판정했다. 각 분할 광고24·정상24·모호4이며 아래 이진 지표는 확정96위치(광고48·정상48)다. 104개의 새 독립 홀드아웃이나 전체 사이트 성능이 아니다. 네 조건 모두 새로 실제 호출했으며 과거 응답을 기준선으로 재사용하지 않았다.

B는 원문과 normalized_text가 완전히 같을 때만 참조표현으로 대체하고, 출력 상한512와 보수적 묶음 캐시를 적용했다. passage/대상/문맥/링크/scope/원본 근거는 보존했다. 다른 중복 문맥 제거·요약·태그 기반 제외는 적용하지 않았다. 모델·판정 범주·배치 최대4개·온도0·seed42·none은 공통이다.

C/D는 페이지 내부 후보 순서를 보존하고 서로 다른 페이지의 묶음을 최대2개 동시 호출한다. 저장 근거가 이미 모두 주어져 있으므로 이 단계는 페이지별 순환 판정과 입력/배치 상호작용 진단이며 URL 탐색 속도나 실제25분 정탐수 측정이 아니다. 개발 자료는10페이지에 걸쳐 있어13→20호출(4개 묶음10개,2개2개,1개8개)이 되었고 확인 자료는1페이지라13호출 그대로이며 동시2의 이득이 없다. 따라서 C/D의 차이를 순수 병렬화 효과로 해석하지 않는다.

조건끼리는 순차 실행하고 최신 전송 뒤61초의 quota washout을 적용했다. 표의 벽시간은 조건 내부 대기를 포함하고 조건 사이washout은 제외한다. 공통52000TPM/1000ms 요청 간격을 유지했다. C 후반·D와 API0 브라우저 점검이 겹쳤으므로 CPU·메모리·디스크 부하의 혼입 가능성이 있다. 정밀한 하드웨어 속도 배수나 일반화된 지연 개선으로 주장하지 않는다.

## 실제 복제본 수집과 판정 차례 점검 — HCX0

`.runtime/throughput-e2e-mock-v1`은 실제 Playwright 수집기·동일FIFO·분산 스케줄러를 사용하되 모든 의미 응답을 일반정보로 만드는 모의 세션이다. 판정 품질을 측정하지 않는다. 최대200페이지/300모의호출/1500초/누적후보0/메모리768MiB를 적용했다.

- 209.47초 뒤 `memory_budget`으로 부분 종료:21페이지·4,307후보 수집,164작업 판정 차례,41모의호출.
- HCX실제호출0·토큰0이며 대기URL439개를 보존했다.
- 독립 위치 감사에서 통제64위치 전체(광고28 포함)를 수집했지만 판정 차례는0개였다. 기존52·보완12 모두 미판정이다. 원래 운영 기준선과 공통 수집한1,139위치의 원문과 URL/ID를 제외한 선택 근거도 모두 보존됐다. 즉 수집 누락 대신 판정 대기로 병목이 이동했다.
- 전체 메모리 보관과 체크포인트 전체 쓰기 구조를 유지한 결과 보호 한도에 걸렸다. checkpoint 약151MB, 수집근거 사본 약110MB였다. 이를 메모리 누수의 확정 증거로 보지 않는다.
- 300호출까지 완주하지 못했으므로 '300호출 안에 광고를 판정할 수 없다'는 증명이 아니다. 무조건 정상인 모의응답의F1=0도 실제모델 성능으로 인용하지 않는다.
- 페이지 분산으로 수집 범위가 넓어져도 미판정 근거의 저장·메모리 부담과 페이지 후반부의 판정 대기가 남는다. 이 병목을 해결했다는 주장은 할 수 없다.

## 구현과 검증

- `agent/experiments/throughput-contract.cjs`: compact 입력, 출력512 설정, 동일 근거4개묶음 재사용 wrapper. 원문/문맥 보존·출처/스타일/순서/설정 차이의 캐시miss·보류/실패 제외·ID귀속 자체검사.
- `agent/experiments/throughput-scan.cjs`: FIFO 수집 후 새페이지1묶음+오래 기다린 기존페이지1묶음, 동시1/2 선택. 단일세션 quota와 AsyncLocalStorage 요청귀속. ID기반 결과/coverage, 미판정·wave계획·다중inflight 저장.
- `agent/experiments/throughput-scan.test.cjs`: FIFO/페이지내순서/최대4·동시성별동일dispatch계획·중간중단재개·앞선응답보존·미확인자동재호출거부·준비상태취소·빈페이지·장문원문통합·페이지/호출예산 검사.
- `agent/experiments/throughput-run.cjs`: 네조건 실제 판정, 요청/응답/배치계획/입력소스봉인/비용 기록.
- `agent/experiments/throughput-audit.cjs`: 독립집계, 미방문/미판정FN, 모호분리, 검증된 로컬쿼리 별칭, 의미/기법 분리.
- `.runtime/throughput-e2e-run.cjs`: 실제collector 연결 실험 harness. `--mock`만 실행했으며 실제HCX25분 경로는 준비만 되어 있다. 운영worker 변경·승격이나 웹연결 완료가 아니다.

기존 `npm.cmd run test:judgment --prefix agent`도 통과했다. 모든실제응답과 저장판정·ID를 독립 대조했고 원본/소스 해시를 보존했다. 자료는 `.runtime/throughput-panel-v1`, 독립감사는 `.runtime/throughput-independent-audit/final-raw.json`과 `mock-coverage.json`이다. 이번 유료실행은118회/162,630토큰이며 예약추정477,053은 과금토큰과 구분한다. 실제요청 미확인0,모의실행inflight도빈객체이며 모든운영소스 해시가 보존됐다.

## 판단

이번 결합안은 운영에 적용하지 않는다. B도 기존정탐2개 손실과 별도종단검증 부재가 있어 운영 승격하지 않는다. C는 호출 증가와 벽시간 악화로 속도 우위가 없다. D의 속도 절감으로 재현율 하락을 가릴 수 없다.

다음 실험을 한다면 프롬프트·후보배치·방문순서를 고정한 출력상한 단독 비교가 가장 작은 변경이다. 페이지 분산은 메모리/저장소로의 미판정 근거 보관과 제한된 활성 페이지 수를 먼저 설계해야 한다. 이는 후속 가설이며 이번에 구현·채택한 개선이 아니다. 공개실사이트 원문 수집·외부공개·push·자동유료확대는 하지 않았다.
