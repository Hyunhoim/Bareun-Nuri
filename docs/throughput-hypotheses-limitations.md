# 처리량 가설 비교의 해석 한계와 P 운영 안전 계약

2026-09-26. 이번 실행은 저장된 137개 관찰 후보에서 판정 요청 처리만 비교하는 제한 진단이다. 새 광고 정답·프롬프트를 수정하지 않으며 API 추가 호출 없이 작성했다.

## 결과 해석의 한계

- A/P/Q/W는 동일 그룹·후보 순서·배치 동료를 유지한다. P는 요청 중첩, Q는 로컬 예약 상한, W는 요청 내 ID 표현만 달라진다. B는 배치 동료와 요청 수가 달라지므로 의미 판정 차이를 단순 속도 개선과 분리해야 한다.
- 137개는 이미 관찰한 문맥 대조·복제본·합성 자료다. 일반 웹사이트의 정상 텍스트 비율, 긴 입력 분포, 작은 배치 잔여 비율을 대표하지 않는다. 두 반복을 독립 274개 표본처럼 계산하면 안 된다.
- 조건 사이 61초 대기는 로컬 61초 예약창과 provider 60초 한도 잔류를 줄인다. 모델 부하, 서버 응답 지연, 백엔드 캐시, 다른 계정 작업의 간섭까지 초기화한다는 뜻은 아니다.
- A/P/Q/W/B/B/W/Q/P/A의 대칭 배치는 시간 추세를 일부 통제하지만, 조건별 두 번만으로 지연 분포·통계적 우위·실사이트 안정성을 확정할 수 없다. 동일 입력 반복에 따른 provider prompt cache 여부와 실제 과금/처리 효과는 관측된 usage·헤더가 명시하지 않는 한 추정하지 않는다. W의 ID 변경, B의 묶음 변경은 캐시 적중 패턴도 바꿀 수 있다.
- 시작 직후 빈 예약창의 짧은 패널은 장시간 quota 정상상태와 다를 수 있다. Q의 속도 이득은 52k 제한에 실제로 걸린 요청 비율에 좌우된다. 짧은 조건에서 대기 감소가 없더라도 장기 효과 없음으로 확정하지 않고, 반대로 초기 burst 이득을 25분 처리량으로 선형 외삽하지 않는다.
- P의 service_sec 합과 queue_sec 합은 요청 간 중첩을 포함한다. 이 합을 벽시간 또는 절감 시간으로 사용하지 않는다. 최초 전송~마지막 응답, 조건 벽시간, 실제 전송 개수와 순서, 각 요청/대기 구간을 구분한다.
- 동일 요청·seed·입력이라도 provider 응답은 달라질 수 있다. 두 A의 판정 변동과 후보 조건의 변동을 함께 보고한다. 저장 판정 보존·역순 응답 귀속 검증은 semantic 재현성 보장이 아니다.
- 수집·탐색·SRPT 순서·디스크 저장·중단 및 재개는 이번 실시간 패널에 포함되지 않는다. 끝까지 판정한 패널 F1은 전체 광고 기준 F1@25분과 다르다. 진단 통과 시에만 동일 25분 조건과 운영 재개 계약을 별도로 검증한다.

## P(동시 2개) 운영 승격에 필요한 최소 안전 계약

현재 bounded-scan은 단일 state.inflight를 전제로 하므로 Promise.all만 추가해서 운영하면 안 된다.

1. 작업 준비 순서 고정: FIFO 수집·기존 배치 동료·페이지 offset을 유지하고, 각 요청에 고유 ID·페이지 ID·정확한 후보 목록·예약 offset을 영속 저장한다. 같은 후보를 두 요청에 동시에 배정하지 않는다.
2. quota 소유자 하나: 두 요청이 하나의 createSession 예약기와 총 호출/토큰/시간 예산을 공유한다. 계정별 독립 limiter 두 개를 만들지 않는다.
3. 요청별 lifecycle: prepared/sent/responded/validated/committed를 구분하고 후보 ID로 응답을 귀속한다. 역순 응답이 다른 요청의 상태·페이지 offset을 덮어쓰지 않아야 한다.
4. 커밋과 재개: 영속 저장된 확정 배치만 한 번 커밋하고, 비순차 완료로 offset 중간에 생긴 공백을 정상 완료로 넘기지 않는다. prepared의 미전송 요청은 재개할 수 있지만 sent/responded의 미확정 요청은 자동 재호출하지 않는다.
5. 한 요청 실패: 아직 전송되지 않은 요청의 새 전송을 막고, 이미 전송한 요청의 응답과 실패는 각각 보존한다. 성공한 형제 요청을 버리거나 전체 실패를 이유로 둘 다 재호출하지 않는다.
6. 25분 경계: 마감 이후 신규 전송을 금지하며 in-flight 회수/정리 시간과 첫 25분 내 완료 판정을 구분한다. 취소된 전송의 과금 여부를 추정해 0으로 처리하지 않는다.
7. 검사: 역순 완료, 한쪽 통신 결과 미확인, 한쪽 형식 오류, quota 대기 중 취소, 저장 전후 강제 종료, 중단·재개를 검증한다. 완료 결과·원문·위치·중복 제거·coverage 보존을 확인한다.

위 사항은 아직 운영에 구현·승격했다는 뜻이 아니다. 이번 실험 runner의 호출별 기록은 진단 자료이며 운영 checkpoint 계약을 대신하지 않는다.
