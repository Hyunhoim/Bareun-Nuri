# 요청 내부 후보 ID 단축: API 0 진단

2026-09-26. 운영 변경 없음. 이 문서는 실제 HCX 정확도·지연 측정 결과가 아니다.

## 가설과 변경 범위

후보의 긴 위치 ID가 입력·JSON Schema의 properties/required·출력에서 반복된다. 요청 내부에서만 a0, a1, a2, a3으로 표현하고 응답을 원래 ID로 복구하면 의미 입력이나 배치 구성을 바꾸지 않고 특히 출력 길이를 줄일 가능성이 있다. 출력 상한512·모델·프롬프트·문맥·원문·링크는 그대로 둔다.

이전 `call-input-report.md`의 실패안은 모든 필드 이름을 축약하고 해석표 지시를 추가했다. 이번 변경은 필드 이름과 지시를 유지하며 불투명한 식별자 값만 바꾼다. 따라서 같은 개선안 재실행은 아니지만, 입력 절감 규모가 작을 수 있다는 기존 결과는 그대로 고려한다.

`agent/experiments/throughput-wire.cjs`의 `createWireSession(config, options)`는 운영 createSession 하나를 재사용한다. 매 decide 호출의 후보 얕은 복사본에서 node_id만 바꾸고, 해당 호출의 지역 변수 매핑으로 결과를 복구한다. 원문 데이터는 수정하지 않는다. 공유 createSession의 호출 예산·직렬 예약 게이트·전송 상태 콜백·응답 형식 검증을 그대로 사용한다. 매핑은 별도 wire_id_mapping 로그로 남긴다.

## 동결된467요청 진단

자료: `.runtime/scale-large-live-v1`의 저장 실제 요청467개/판정작업1845개. 이미 관찰한 회귀 자료다. 원래 응답의 publication_act를 짧은 ID로 바꿔 stub을 통해 실제 createSession에 전달했다. **API 0회이며 새로운 모델 판정이 아니다.**

| 항목 | 원본 | 짧은 ID | 변화 |
|---|---:|---:|---:|
| 전체 요청 JSON 문자 |2,166,192|2,077,440|-4.10%|
| 운영 함수의 요청 예약 토큰 추정 |1,523,949|1,497,052|-1.765%|
| 응답 JSON 문자 |95,629|66,045|-30.94%|

출력 JSON 문자는 실제 출력 토큰 감소율이 아니다. 예약 추정은 운영 추정 공식으로 계산한 입력+고정512 예약이며 제공사 실측 토큰과 다르다. 총 토큰·대기시간·종단 처리량의 개선은 아직 알 수 없다.

## 검증

- 467개 body는 후보 node_id 및 해당 Schema 키/required 외 완전 동일하다. raw text에 같은 문자열이 있어도 치환하지 않는다.
- 복구 후1845개 판정이 기존 응답을 원래 계약으로 검증한 결과와 완전 일치한다.
- 입력 원본 객체를 수정하지 않는다.
- 입력 중복/빈 ID, 출력 unknown/duplicate/missing ID, 잘못된 publication_act를 거부한다.
- 결과 순서 변경에도 ID 기준 복구한다.
- 동일 session의 두 요청을 역순 응답으로 완료하는 병렬 stub 검사에서 호출별 원래 ID 귀속을 보존한다.
- 예산/타임아웃/미확인 요청 처리는 운영 createSession을 재사용하며 여기서 별도 재시도 코드를 추가하지 않는다.

재현: `node agent/experiments/throughput-wire-audit.cjs <새 결과 디렉터리>`.
최초 기록 `.runtime/throughput-wire-v1/audit.json`, 동시 완료 순서 검사 포함 최종 기록 `.runtime/throughput-wire-v2/audit.json`.

## 판단

의미정보를 줄이지 않고 출력 생성을 줄이는 작은 독립 가설로 실제 패널 비교 가치는 있다. 입력 예약 추정 이득1.765%만으로 획기적 처리량 개선이나 운영 채택을 권할 수는 없다. 출력 ID가 달라져 모델 판정이 달라질 가능성이 있으므로 실제 정확도와 출력 토큰/응답 지연을 비교해야 한다. 라벨·case_id별 예외는 없다. 실제 결과에 맞춰 ID 형식이나 프롬프트를 반복 조정하지 않는다.
