# 요청 단위 불완전 응답 격리 — 운영 채택

2026-09-30. 사용자 요청에 따라 사전 계획·오프라인 계약 검사·실제25분 실행·재개 검증 후 **운영에 채택했다.** Structured Outputs는 적용하지 않았다.

## 채택한 동작

HTTP200/정상 종료/완전 JSON에서 요청한 ID 일부만 유효하게 반환된 경우, **해당 요청 묶음 전체**를 미판정으로 격리한다. 원응답·요청ID·미반환ID·검증된 반환 판정을 저장하고 같은 페이지 다음 묶음과 다른 페이지를 계속 처리한다. 반환된11개도 부분 확정하지 않는다. 격리 묶음을 정상으로 채우거나 자동 재호출하지 않는다.

잘린 JSON·중복키·알 수 없는ID·잘못된 값·통신 미확인은 계속 실패 처리한다. 모든 형태의 API 오류를 무시하는 기능이 아니다.

offset은 다음 처리 위치이며 판정 완료 수와 다를 수 있다. 격리된 위치는 coverage에 남고, 페이지 끝까지 시도했어도 격리 항목이 있으면 완전 검사로 표시하지 않는다. 남은 일반 작업의 재개는 가능하지만 격리 묶음은 자동 재판정하지 않는다. 화면에도 이를 안내한다. 코드/저장형식 서명이 달라 과거 코드의 체크포인트는 자동 이행하지 않는다.

## 실제 25분 검증

Phase1 복제 사이트, HCX-007 none/출력512/최대12묶음/58k/순차 판정/FIFO/수집동시5/SRPT8을 유지했다. 원래 실패 체크포인트를 재개하지 않고 새 작업을 실행했다.

희귀 오류의 재발에 의존하지 않도록20번째 정상 응답에서 ID1개를 실험용으로 제거했다. 원래 완전 응답은 `fault.json`에 따로 보존했다. 이 외에 **160·183·202번째 실제 응답에서도 각각12개 중1개 누락이 자연 발생했다.** 모두 격리됐고 각 페이지의 남은 후보까지 진행했다.

기준선은 같은 수집 근거·원응답을 이전 코드에 오프라인 재생했다.20번째 오류에서 중단됨을 확인했고, 이전에 완료한209개 판정은 개선안에서 완전히 보존됐다. 기준선은 별도 유료25분 실행이 아니며, 장애가 없을 때의 속도 비교나 일반적인 F1 상승 폭으로 해석하지 않는다.

| 지표 | 같은 오류를 받은 이전 코드 재생 | 개선안 첫25분 |
| --- | ---: | ---: |
| 저장 판정 수 | 209 | 2,840 |
| 지정 광고 정탐 TP | 38 | 582 |
| 지정 정상 오탐 FP | 15 | 255 |
| 전체 광고 누락 FN | 1,082 | 538 |
| 전체 광고 기준 정밀도 | 71.70% | 69.53% |
| 전체 광고 기준 재현율 | 3.39% | 51.96% |
| 전체 광고 기준 F1 | 6.48% | 59.48% |

전체 정답은2,240위치/광고1,120개이며 미방문·미수집·미판정을 FN에 포함했다. 미라벨 위치의 양성을 정상 오탐으로 계산하지 않았다. 이미 사용한 합성 Phase1 회귀이며 독립 일반화 평가/실제 공공사이트 전체 성능이 아니다.

추가 처리 영역에서 **정탐544개와 오탐240개**가 추가됐다. 공통 완료 판정 변화는0이므로 추가 오탐은 기존 동일 입력의 판정 변경이 아니라 새로 처리한 영역의 의미 오류다. 완료된 지정 위치만의 의미F1은80.67%다. 이 변경은 의미 모델의 정확도 개선이 아니라 오류 때문에 검사 기회가 사라지는 것을 줄인 것이다. 오탐·미방문·의미 누락은 남아 있다.

마감1495.379초의 마지막25분 내 저장 지점은280호출/2,840판정이다. 마감 직후 완료한 마지막 요청까지 포함하면281호출/2,852판정·TP584/FP257/FN536·F1 59.56%이지만, 위 표에는 포함하지 않았다. scanner1500.686초, worker 구간 정리까지1501.528초에 `partial / time_budget`로 종료했다. 재개 후 결과로 첫25분을 대체하지 않았다.

## 남은 손실과 비용

- 총4묶음48개 미판정: 주입1회+자연3회. 실제 미반환은 총4개지만 보수적으로 묶음 전체를 격리했다.
- 격리48개 중 지정 광고15개/정상9개/미라벨24개다. 이15광고는 정상으로 숨기지 않고 FN에 포함했다.
- 종료 시 수집71페이지/3,067후보, 대기URL70개, 수집 후 미판정215개(격리48개 포함). 사이트 전체 검사 완료가 아니다.
- 실제281호출·825,988확인토큰. 요청 후보2,900개의 중복 전송0, 마지막 inflight=null. 계속 검사하므로 조기 실패하는 기준선보다 호출·비용도 증가한다.
- 유효한11개를 부분 확정하거나 격리 묶음을 재판정하는 기능은 채택하지 않았다. 후속 개선은 별도 계약 검증이 필요하다.

## 안전성·승격 검증

오프라인 검사에서 중간/마지막 묶음/모든 묶음 격리, 같은 페이지 계속 처리, 빈 정상 판정 생성0, 기존 정상 결과 불변, 호출 예산 후 재개, 중복 호출0, 파일 변조·서명 변경 거부를 확인했다. 긴 본문의 일부 구간 미판정을 전체 정상으로 합치지 않는다.

실제 실행 체크포인트는 복사본에서 **동일 서명**으로 재개했다. 네트워크를 막고1회 stub 응답만 추가해 기존2,852판정·격리48개 보존, 원본 불변을 확인했다(API0). 이 재개 결과는 성능 집계에 사용하지 않았다.

검증한4소스(`llm.cjs`, `bounded-scan.cjs`, `bounded-scan-store.cjs`, `worker.cjs`)를 그대로 운영 반영했다. 화면에 격리 안내를 추가하고 ‘수집 문제’ 합계 명칭을 ‘검사 문제’로 바꿨다. 승격 후 다음을 통과했다.

- `node local-benchmark/request-quarantine-check.cjs --operating`
- `node agent/experiments/semantic-adoption.test.cjs` — 기존1,845개 입력 일치·의미/기법/자모/재개 계약
- `node agent/experiments/bounded-worker.test.cjs --envelope --backend` — 실제 로컬 백엔드 재개 API·옛서명/미확인 요청 거부·첫 구간 보존(API0)
- `npm.cmd run build`(frontend) — TypeScript/프로덕션 빌드

실험 중 학습·의미 프롬프트 조정·라벨 수정은 없었다. 원래 실패 체크포인트와 실험 자료는 보존했고 push/배포는 하지 않았다.
