# 처리량 가설 독립 병렬 검증 계획

2026-09-26. 사용자 요청: 유망한 여러 처리량 가설을 병렬 시험. 개발·오프라인진단은 병렬, 동일계정 실시간 속도 비교는 조건별 분리한다. 운영 C/FIFO/근거보존은 유지하고 운영파일을 변경하지 않는다. API키는 출력하지 않는다.

## 조건

- A: 운영 C, 후보4개/출력512, 순차, 52kTPM/61초창/최소1초간격.
- P: 같은 배치·요청 그대로 최대 동시2개, 하나의 createSession 예약기 공유.
- Q: A에서 예약 한도만58k. 새 A응답의 실제 헤더가60kTPM/60RPM 이상임을 확인한 경우에만 실행한다. provider limit을 바꾸는 작업이 아니다. 현재1초poll/61초창은 유지한다.
- W: A에서 요청 내 후보ID만 a0..로 바꾸고 응답을 원래ID로 복구한다. 원문/문맥/키/프롬프트 의미/상한은 유지한다.
- B: A에서 배치크기만8개로 변경. 출력512 유지. 원문/문맥은 축약하지 않으며 마지막 잔여 후보도 검사한다. 배치 동료 변경의 의미 회귀를 별도로 평가한다.

P/W/Q의 실제body/대기 비용은 기존467실요청에서 먼저 독립 재생·보존 검사한다. 이 결과는 실제속도/F1이 아니다. 추정토큰 평균 비율을 줄이는 보정은 자료 과적합 위험으로 채택하지 않는다.

## 실제 제한 비교

이미 관찰한 문맥 대조48개+복제본65개+합성문맥24개,137후보 전체를 사용한다. 광고60/정상65/모호12. 정답은 입력에 넣지 않는다. 새 홀드아웃이 아니다. 후보 수집·탐색은 제외한 저장근거 비교다. 그룹 안 순서와 배치 동료는 P/Q/W에서 A와 동일. B만8개 묶음이다.

순서 A/P/Q/W/B/B/W/Q/P/A로 각2회, 매 조건 전61초 계정창 분리. 계정 속도를 왜곡하므로 서로 다른 조건을 동시에 전송하지 않는다. 동시2인 P도 같은 공통 할당량을 공유한다. 단일조건 10분, 전체1시간/최대400실전송/예약120만토큰. 실제 예상316호출이며 실행 전 확인한다. HTTP/형식/귀속 오류나429시 추가발송을 멈추고 이미 전송한 요청을 회수·기록한다. 미확인 자동 재시도/모의 응답 대체 없음.

동일 대상의 의미 TP/FP/FN·F1,기존정탐 손실,모호성 처리,반복변동,실제전송/토큰/서비스/대기/벽시간을 함께 본다. P의 서비스시간 합은 중첩되므로 벽시간과 구분한다. 기법관찰입력은 변경하지 않는다. 이 단계가 수집 포함 전체4종F1 개선이라는 주장은 하지 않는다.

후속25분 검증 추천 관문: 두 회차 평균F1이 A보다 낮지 않음, A의 반복 정탐을 후보가 두 회차 모두 놓치는 위치0, 형식/귀속/통신실패0, 평균 판정벽시간10% 이상 감소. 5~10%면 제한적 이득으로 분리 보고하고 운영채택으로 올리지 않는다. 작은 진단에서의 처리량 상승만으로 자동 운영채택하지 않는다. 전체사이트25분/중단재개 검증은 별도 통과해야 한다.

동일 패널과 같은생성기의 반복이므로 일반화주장은 제한한다. 결과를 본 뒤 프롬프트/배치/판정라벨/성공기준을 튜닝하지 않는다. 선별·중복캐시·수집중첩 등 미채택 변경은 결합하지 않는다.
