# INT8 수치 진단 결과

2026-09-29. 사전 계획 `semantic-int8-numeric-plan.md`에 따른 라벨 없는 진단이다. 세 동결 모델의 원본 FP32를 유지하며 INT8은 계속 미채택이다. 이번 검사는 광고 정확도나 새로운 홀드아웃 평가가 아니다.

## 정수 커널 검사

AMD Ryzen 7 8845HS, ONNX 1.17.0, ORT 1.23.2 CPUExecutionProvider, intra8/inter1 환경에서 극값/난수 입력을 사용했다. 두 행렬 크기, 세 값 분포, 정수 직접/동적 양자화 경로, 최적화 비활성/전체활성의 24조건이다. 정수 출력은 int64 참조와 비교했고 동적 경로는 그래프에 실제 존재하는 FP32 Cast까지 반영했다. 보정 후 24/24 오차0이다. 이 범위에서 U8S8 중간 포화 가설은 지지되지 않았다. 모든 모델 연산의 포화 부재나 실제 실행 ISA를 증명한 것은 아니다.

첫 실행은 22/24였다. 동적 경로의 FP32 출력을 반올림하지 않은 int64와 비교한 시험 구현 오류로, 큰 양수 합에서 1의 차이를 실패로 잘못 집계했다. FP32 참조를 사용한 재실행에서 두 차이가 모두 사라졌다. 최초 `kernels.json`과 `initial-script.py`를 보존하고 `kernels-corrected.json`에 교정 이유와 참조 반올림 크기를 저장했다. 광고 정답이나 결과에 맞춘 허용 오차 변경은 없다.

## 동결 모델 그래프 검사

seed42 난수 token-ID, 배치1/8 × 길이16/64의 네 입력 배열을 사용했다. 배치8의 뒤7행은 후반을 마스킹했다. 각 모델에서 FP32/INT8 × ORT_DISABLE_ALL/ORT_ENABLE_ALL을 비교했다. 각 형식 파일의 SHA-256을 기존 export manifest와 확인했다. 모델 간 어휘 수가 달라 token-ID 배열도 다르므로 모델 간 오차 순위를 의미 성능 순위로 해석하지 않는다.

아래는 raw logit의 최대 절대 차이다.

| 모델 | FP32 최적화 전후 | INT8 최적화 전후 | FP32→INT8 최적화 비활성 | FP32→INT8 최적화 활성 |
|---|---:|---:|---:|---:|
| KLUE | 0.000001371 | 0 | 0.620211 | 0.620210 |
| Kc | 0.000003636 | 0.033165 | 1.406367 | 1.406368 |
| Ko | 0.000001550 | 0.000000596 | 1.629395 | 1.629394 |

Kc에는 최적화 전후 차이가 있으나 최적화를 꺼도 FP32 대비 큰 차이가 남는다. 이번 입력에서 최적화만이 큰 수치 손실을 만든다는 가설은 지지되지 않는다. 최댓값들은 서로 다른 출력에서 나올 수 있어 비율로 원인 기여도를 계산하지 않는다. 무의미 입력이므로 부호/클래스 변화도 광고 정확도로 채점하지 않았다. 네 작은 배열의 일회 실행 시간은 raw 자료에만 보존하며 처리량 벤치마크로 사용하지 않는다.

## 결정과 한계

관측한 것은 양자화 이후의 수치 변화이며, 원인 연산이나 층은 아직 특정하지 못했다. 가중치 양자화 오차, 활성값 범위, 누적 오차 및 특정 연산 민감성을 이번 검사만으로 구분할 수 없다. 사전 계획에 따라 reduce_range/U8U8/제외 층을 새로 탐색하거나 기존 광고 평가 점수에 맞춰 설정을 선택하지 않았다. 원본 FP32 후보와 운영 HCX를 유지한다. INT8 품질이 복구됐다고 주장하지 않는다.

후속 수치 진단을 한다면 고정된 비평가 입력에서 중간 활성값을 비교해 오차가 처음 커지는 연산을 특정하는 것이 먼저다. 실제 HCX 대체의 주요 미완료 항목은 독립적인 실제 광고 문맥과 사람 검수, 근거부족 처리, 운영 시간 조건의 품질 검증이다. 이번 수치 검사가 그 항목을 대신하지 않는다. 추가 학습·재양자화·유료 API·운영 변경은 모두0이다. Goal은 미완료다.
