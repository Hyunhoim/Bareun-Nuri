# FIFO 대안 조사와 실험 후보

조사일: 2026-09-23. 논문 원문·저자 공개 저장소·공식 프로토콜을 확인했다. 구현이나 실제 유료 실험은 수행하지 않았다. 현재 프로젝트 결과는 `progressive-mixed-report.md`를 직접 재확인했다.

## 판단

새로운 탐색 정책으로는 **DOM 링크 구조를 이용하는 Sleeping Bandit의 경량 변형** 한 개를 우선 실험 후보로 선정한다. 별도로 **Sitemap을 이용한 시작 URL 보강**은 낮은 구현 비용으로 검증할 가치가 있다. 후자는 FIFO와 경쟁하는 스케줄러가 아니라 URL 발견 단계의 보완이다. 둘을 처음부터 합치지 않는다.

영역별 하이브리드는 메뉴 영역에 탐색량을 배분한다. Bandit 후보는 서로 다른 페이지에 반복되는 링크의 DOM 위치별로 실제 방문 성과를 학습한다. 서로 다른 가설이며, 복잡한 알고리즘이 무조건 우월하다는 주장이 아니다.

## 확인한 문헌과 범위

### 1. Efficient Crawling for Scalable Web Data Acquisition — EDBT 2026

[학회 논문](https://www.openproceedings.org/2026/conf/edbt/paper-204.pdf), [저자 재현 저장소](https://github.com/AntoineGauquier/efficient_crawler_for_scalable_web_data_acquisition/), [확장판](https://arxiv.org/abs/2602.11874).

SB-CLASSIFIER는 링크의 DOM tag path를 묶고, 보상 평균과 탐색 보너스로 다음 그룹을 선택한다. 정부·통계기관 등을 포함한 18개 사이트, 총 22.2M 페이지를 수집한 평가이며 BFS는 FIFO 큐를 사용한다. Table 2에서 목표 90% 확보까지 수행한 요청 비율은 프랑스 교육부(ed) BFS 94.6% / SB 51.5%, 법무부(ju) 80.8% / 35.8%다. 두 사이트는 완전 수집된 평가 영역이다. 이 수치는 시간·F1·절감률 자체가 아니라 논문이 정의한 요청 비율이다.

적용 한계: 목표는 주로 MIME 유형으로 판별되는 통계 파일이며 광고 의도 판정이 아니다. 수천~대규모 페이지에서의 결과를 현재 20페이지 예산에 옮길 수 없다. 일부 사이트는 부분 수집 범위로 평가했다. 저장소는 코드·재현 자료 제공을 확인했으며 로컬 실행으로 재현하지 않았다.

**선정 이유:** 단일 기관 사이트 안에서 적은 요청으로 목표를 찾는 문제이고, FIFO와 직접 비교했으며 공공기관 구조도 포함한다. 후보 링크에 '게시판' 같은 단어가 없어도 HTML의 반복 위치를 활용할 가능성이 있다.

### 2. Focused Crawling Using Context Graphs — VLDB 2000

[원문](https://www.vldb.org/conf/2000/P527.pdf).

목표 페이지까지 이어지는 여러 단계의 문맥을 학습한다. 논문 모집 공고 탐색에서 예시 10개와 깊이 4의 context graph를 사용했다. BFS보다 우수했고, 일반 focused crawler보다 관련 문서를 평균 50~60% 더 찾았다고 보고한다(§4, Figure 4). 50~60%는 BFS 대비 수치가 아니다.

**현재 보류:** 목표로 이어지는 경로의 학습 자료와 역링크 정보가 필요하다. 원문은 검색엔진 역링크 의존을 한계로 명시한다. 현재 두 합성 사이트는 연결 구조를 공유하므로 이 자료로 경로를 학습하고 같은 계열에서 평가하면 과적합 위험이 크다. 여러 기관의 독립 경로 자료가 확보된 뒤 검토할 후보이며, 기존 메뉴 키워드 규칙을 이 이름으로 바꾸는 것은 재현이 아니다.

### 3. Tree-based Focused Web Crawling with Reinforcement Learning — TRES

[원문](https://arxiv.org/pdf/2112.07620).

스포츠·음식·하드웨어 주제에서 20,000페이지를 수집하고 여러 시작점 실험을 평균했다. Table 3의 높은 harvest rate는 방문 페이지 중 주제 관련 비율이며, 전체 사이트 광고 재현율이 아니다. 관련성 평가에 학습된 BiLSTM을 사용했다. 공공기관 내부의 희소 광고 탐지와 조건이 다르다.

위 EDBT 논문의 다른 과제로 옮긴 평가에서는 TRES의 성능·계산 비용 문제가 보고됐다(§4.5). 이를 원래 주제 탐색 결과의 반증으로 해석하지 않는다. **지금은 보류:** 판정기·학습·탐색의 복잡도를 함께 늘릴 만큼 현재 조건에 직접 맞는 근거가 부족하다.

### 4. ACHE

[공개 구현](https://github.com/ViDA-NYU/ache), [공식 탐색 설정](https://github.com/VIDA-NYU/ache/blob/master/docs/crawling-strategies.rst).

온라인 링크 학습과 soft-focus 모드를 제공한다. soft-focus는 비관련 페이지의 링크를 일괄 버리지 않고 링크 분류기로 순서를 정한다. 이것은 우리 필터의 제외 문제를 피하는 구현 참고가 된다. 다만 문서의 기능 설명 자체가 우리 과제에서 FIFO보다 우수하다는 실험 증거는 아니다. **전체 크롤러 교체는 추천하지 않는다.** 기존 Node 수집기를 유지하고 필요한 아이디어만 독립 비교한다.

### 5. Sitemap 기반 URL 발견

[Sitemaps 프로토콜](https://www.sitemaps.org/protocol.html), [Google 공식 설명](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview).

프로토콜은 XML URL 목록, index, robots.txt의 Sitemap 선언을 지원한다. Google은 크거나 복잡한 사이트의 URL 발견에 도움이 되지만 모든 URL의 수집·색인을 보장하지 않는다고 설명한다. 이 근거는 발견 경로와 제공 기능에 관한 것으로, 광고 재현율 상승의 정량 실험은 아니다.

**조건부 실험 추천:** 같은 허용 범위의 Sitemap이 실제로 제공되고 내부 상세 URL을 담고 있다면, 깊은 메뉴를 거쳐야 발견하던 URL을 먼저 대기열에 등록할 수 있다. 공개 목록에 URL이 있다고 검사를 완료한 것으로 세지 않는다. 누락·오래된 Sitemap을 고려해 기존 링크 탐색을 유지한다. `priority`나 `lastmod`를 광고 위험도로 해석하지 않는다.

## 제안 A: DOM 링크 그룹의 성과를 학습하는 경량 Bandit

원문 SB-CLASSIFIER 전체의 재현이 아니라, 핵심 가설을 우리 과제에서 검증하는 변형이다.

1. 이미 방문한 페이지에서 각 링크의 DOM 경로·역할을 수집한다. 페이지별 임의 ID나 정답 URL을 특징으로 외우지 않도록 일반화된 구조를 사용한다.
2. 구조가 비슷한 링크를 그룹으로 관리한다. 대기 URL이 있는 그룹만 선택 대상이다.
3. 그룹별 방문 성과와 아직 충분히 방문하지 않았다는 불확실성을 함께 고려한다. 선택된 그룹 안의 URL은 최초 발견 순서로 처리해 새 변수를 제한한다.
4. 첫 실험의 보상은 방문해 확인한 서로 다른 상세문서·댓글 영역에 도달했는지로 한정한다. 아직 방문하지 않은 페이지의 정답이나 전체 그래프를 보상에 사용하지 않는다. 추가 HCX 호출로 링크를 채점하지 않는다.
5. 광고 판정·추론 설정은 그대로 유지한다. 정상·공지 링크를 영구 제외하거나 한 번 실패한 그룹을 폐기하지 않는다.

보상은 실제 광고 발견의 대리 지표다. 정상 글이 많은 게시판으로 쏠릴 수 있고, 일반 안내의 광고를 늦게 찾을 수 있다. 게시판 분류 정확도나 후보 수가 늘었다는 이유만으로 채택하지 않는다. 기존 HCX 오탐을 보상으로 사용하면 잘못된 판정이 탐색 편향으로 증폭될 우려가 있어 초기 비교에서는 제외한다.

**구별할 가설:** 같은 DOM 링크 패턴의 방문 성과가 이후 선택에 유용한가? 아직 분류할 수 없는 새 구조에 탐색 기회를 주는 것이 가치가 있는가? 짧은 예산에서는 학습이 늦게 시작되어 FIFO에 못 미칠 수 있다. 20페이지 지점의 실패를 100페이지 이후 성과로 감추지 않는다.

## 제안 B: Sitemap 보강 + 기존 FIFO

1. 시작 URL의 허용 범위 안에서 robots.txt에 선언된 Sitemap 또는 발견된 Sitemap을 제한된 비용으로 읽는다.
2. XML의 URL들을 검증·중복 제거하고, 기존 FIFO와 병행할 발견 목록으로 사용한다. 큰 XML의 파싱·전송·대기열 메모리 비용도 제한·집계한다.
3. URL 발견만 추가하고 광고 판정·수집 내용은 바꾸지 않는다. Sitemap 밖 페이지의 링크 탐색도 유지한다.

Sitemap URL을 기존 큐 뒤에 무조건 붙이면 효과가 없을 수 있고, 반대로 모두 앞에 넣으면 편향이 생긴다. 초기 삽입/교차 선택 규칙은 사전에 하나로 고정한다. 모든 비교군에 같은 사이트/동일한 Sitemap 접근 가능성을 제공하고, 이용 여부가 비교 요인임을 명시한다. robots/Sitemap 요청도 비용에 포함한다. 실제 제공 여부는 아직 부산 사이트에서 확인하지 않았다.

## 권장 실험 설계

- 정책 비교: 기존 FIFO, 기존 우선순위, 제안한 영역별 하이브리드, A를 각각 비교한다. 모든 개선을 한꺼번에 결합하지 않는다.
- 발견 방식 비교: FIFO 대 FIFO+B를 따로 비교한다. Sitemap 없음/불완전/오래됨/충분함 조건을 포함하고 유리한 조건만 보고하지 않는다.
- 기존 40+40페이지는 진단·회귀용이다. 별도 사이트는 연결 구조·DOM 템플릿·링크 표현·광고 분포부터 다르게 한다. 정상 고밀도 게시판, 공지 댓글, 깊은 불투명 경로, 같은 DOM에 정상·광고 혼재를 포함한다.
- 오프라인 탐색에서 정책은 방문한 페이지와 그 링크만 볼 수 있다. 전체 그래프와 정답은 평가기에만 있다. 먼저 20/50/100페이지 예산별 실제 광고 위치 도달률·첫 도달 시점·영역별 누락을 확인한다. 20페이지 단기 성과를 별도로 보고한다.
- 페이지 수 외에 HTTP 수, 총 실행 시간, HTML 파싱/브라우저 비용, 후보 판정 호출·토큰도 확인한다. Sitemap을 무료로 처리하거나 파일 수집 연구의 요청 절감률을 HCX 비용 절감으로 바꾸지 않는다.
- 확정된 페이지별 판정을 재사용하는 비교는 탐색 효과를 분리하는 진단이다. 새 배치에서의 실제 LLM 판정 효과를 검증한 것은 아니다. 후보 정책이 통과한 뒤 새 배치의 실제 전체 정답 F1·정밀도·재현율을 별도 측정한다.
- 여러 시작 링크 순서와 확률 시드를 포함한다. 개발에서 설정을 고정한 후 다른 사이트에서 확인하며, 사이트별 결과와 합산 결과를 모두 보고한다. 특정 예산·사이트를 보고 성공 기준을 다시 정하지 않는다.

현재 추천은 **A의 좁은 독립 실험**, 그리고 Sitemap 제공이 확인되는 경우 **B의 별도 보강 실험**이다. Context Graph와 TRES의 전체 구현은 지금 추가하지 않는다. 연구 근거는 실험 비용을 지출할 이유를 제공하지만, 현 Pipeline보다 낫다는 검증을 대신하지 않는다.
