# 2단계 문맥 판정 개선 및 3단계 진입 검증

검증일: 2026-09-22. **2단계 검증을 통과했으며 3단계 진입이 타당하다고 판단한다.** 아래 수치는 원시 의미 판정이며 대회용 위치 × 기법 F1과 구분한다.

후속 점검(2026-09-22): 새로운 문맥 의존 표현 28개 검사에서 광고 8개가 누락되어 **3단계 진입 판단을 보류했다**. 아래 기존 회귀 결과는 유지되지만 검증 범위 밖의 초기 정상 판정 조기 종료 문제가 확인됐다. 현재 상태와 재현 근거는 [3단계 사전 점검 보고서](stage-3-preflight-report.md)를 우선 참고한다.

## 변경한 구조

기존에 대상 문구, 주변 설명, 광고 의도와 근거 설명을 한 번에 생성하게 했을 때 실제 광고를 인용으로 설명하거나 이웃 광고를 정상 항목에 옮기는 오류가 남았다. 문장을 단독으로 주면 해결되는 누락도 관찰됐다. 단순한 프롬프트 축약·묶음 축소로는 재현성 있게 해결되지 않았다.

이번 실험은 같은 HCX-007을 순차적으로 사용하되 판단 대상을 분리한다.

1. **대상 자체의 이용 유도 판단**: 주변 문구를 빼고 대상 원문·정규화문만 읽는다. 불법 서비스 이용 유도/대상 자체의 인용 설명/일반 정보/불확실을 짧은 이유와 함께 잠정 판정한다. 정상 항목이 이웃 광고를 이유로 광고가 되는 경로를 차단한다. 짧은 문구의 서비스 성격은 이 잠정 판정만으로 확정하지 않는다.
2. **연결된 서비스 확인**: 이용 제안 또는 불확실 대상만 동일 DOM 범위의 근거와 함께 확인한다. 도박·불법 촬영물 등의 서비스인지, 정상 서비스인지, 이용 제안이 없는 문서 정보인지, 근거가 부족한지 구분한다. “계정 만들기” 같은 짧은 문구 자체를 불법으로 취급하지 않는다.
3. **주변 설명의 인용 주장 확인**: 광고로 판단했거나 서비스 성격이 불명확한 대상의 주변 설명을 각각 독립된 전제로 읽는다. “이것은 교육·신고용 인용이다”를 긍정하는지, 부정하는지, 언급하지 않는지 구분한다. 일반적인 경고만으로 실제 광고를 인용 처리하지 않는다.
4. **근거 귀속**: 앞/뒤 참조 표현과 DOM 위치를 결합해 설명을 원래 후보에만 적용한다. 대상 서비스·귀속이 불명확하거나 서로 충돌하면 검토 대상으로 남긴다. 실제 설명 문장은 코드가 입력에서 복사한다.

위 번호는 내부 판정 순서이며, 합의한 고도화 계획의 3단계(관찰 기법 분리)를 완료했다는 뜻이 아니다.

인용 주장 판정은 정순·역순으로 확인한다. 동일한 설명에 상반된 응답이 나오면 해당 설명 하나를 별도로 재판정한다. 이는 한 번의 배치 응답에서 발생한 흔들림을 줄이는 절차이며 정답을 보장하는 투표가 아니다. 독립 문장의 주장만 다시 확인하며 후보 전체의 문맥·스타일 판정을 다른 후보에 재사용하지 않는다.

존재하지 않는 ID, 누락·중복·추가 필드·정의되지 않은 값은 오류다. 첫 단계는 짧은 이유를 필수로 받고 스키마에도 최소 길이 1을 명시한다. 빈 이유는 근거가 있는 판정으로 보정하지 않으며 제한된 형식 재요청 후에도 오류면 실행을 실패로 남긴다. 첫 단계 이유는 모델의 설명이며 별도로 검증된 사실이 아니다. 서비스 확인도 짧은 이유와 범주값을 받고, 인용 주장 검사는 범주값을 받는다. 실제 인용 설명은 입력에서 복사해 결합한다. 서비스 확인이 최초 판단을 뒤집으면 최종 이유도 바꾸며, 최초 이유는 target_judgment에 별도로 보존한다. 서비스 종류가 불명확해도 인용 설명은 확인한다. 명확하게 귀속되는 인용 근거가 있으면 서비스 불확실성만 해소하고, 다른 불확실성은 보류로 남긴다. 후속 검증에 최초 모델의 이유를 입력하지 않는다.

## 검증 범위와 완료 기준

- 고정 회귀 패널: 기존 정답 요소 300개(광고 120 / 정상 180)와 과거 오탐 위치 6개. 기존에 잡던 광고를 잃지 않고 모든 광고 탐지, 정상 오탐 0, 미판정·검토 보류 0을 목표로 한다.
- 동일 306개를 입력 순서만 바꿔 다시 실행한다. 배치 순서 변화에서도 같은 결과인지 확인한다.
- 기존 문맥 변형 32 + 16개, 이번 개발 과정에서 사용한 72 + 32개, 정상/불법 서비스의 동일 짧은 실행 문구 8개를 회귀 검사한다.
- 개발 중 한 차례 코드를 고정한 뒤 새 문구 32개(광고 8 / 정상 24)를 처음 실행했다. 첫 실행은 통과했지만 이후 다른 회귀 사례와 계약 경계 검사로 코드가 수정되어 최종 버전에서는 재검사 자료로 분류한다. 기존 DOM 템플릿을 재사용하므로 독립적인 실제 웹사이트 홀드아웃이 아니다.
- 원문·위치·스타일 수집은 이번 목표 작업에서 변경하지 않는다. 정답은 채점에만 사용한다. 문구·ID·URL·라벨별 탐지 예외는 추가하지 않는다.

원래 사이트의 101개 문서에서 수집한 3,824개 후보 전체에 대해 새 모델을 돌린 결과가 아니다. 판정 개선에 사용한 자료의 통과를 미공개 데이터 일반화 성능으로 보고하지 않는다. 합성 자료에서도 제공된 문맥 범위 안에 필요한 설명이 있는 조건이 중심이다.

모델 조건: HCX-007, temperature 0, reasoning none, seed 42, 요청 출력 한도 3,072토큰, 16개 묶음, 순차 호출, 분당 토큰 예산 52,000, 요청 시간 제한 180초, 실험당 300회·1시간 상한. 여러 역할 사이에도 총 호출 상한을 적용한다. API 제한 재시도를 포함한 실제 경과 시간을 기록한다.

## 관찰한 실패와 수정 근거

- 최초 대상 단독 판정은 광고 120개를 유지했지만 인용된 정상 문구 40개를 광고로 판단했다. 따라서 대상만 읽는 방법을 최종안으로 채택하지 않았다.
- 인용 설명을 추출하는 방식은 기존 패널을 통과했으나 새 문구에서 “인용이 아니라 실제 모집”이라는 부정을 잘못 처리했다. 인용 여부의 논리 관계를 별도로 판정하도록 바꿨다.
- 동일 인용 설명도 묶음 위치에 따라 응답이 달랐다. 정순·역순의 모순을 탐지하고 독립적으로 다시 확인한다.
- 대상만으로 합법성까지 정한 방식은 정상 서비스의 짧은 실행 문구 4개를 오탐했다. 후속 서비스 확인을 추가해 정상/불법 문맥을 구분한다.
- 첫 단계 출력을 범주값만으로 압축한 안은 기존 306개를 정순·순서 변경 모두 통과했지만 추가 72개에서 광고 4개를 누락했다. ID 단순화, 문체 설명 추가, 4개 묶음, 원문 구절 추출만으로도 해결되지 않았다. 이 압축 계약은 폐기하고 짧은 이유를 포함하는 잠정 의도 판정 계약을 재검증했다.
- 방향 참조 처리에서 “위한”을 “위” 참조로 읽는 결함을 발견했다. 지시어와 활용형의 문법 경계를 분리했고 회귀 검사를 추가했다. 특정 광고 문장 예외는 사용하지 않았다.

서비스 종류를 모르는 것과 이용 제안 자체가 없는 것을 구분하지 못해 정상 문서 정보 1개가 검토 대상으로 남았다. 제안없음 상태를 분리했다. 이어 서비스가 없는 신청·구매 문구를 정상으로 추정하는 반례를 확인해, 정상과 불법 모두 구체적인 서비스 근거가 있어야 확정한다는 대칭 조건을 명시했다. 추가 경계 검사 4개에서 정보 부족 2개와 문서 정보 2개를 구분했다.

범주값만 받는 계약과 짧은 이유를 받는 계약은 질문 범위와 라벨도 다르므로 이유 출력 하나의 인과 효과로 해석하지 않는다. 이 과정에서 사용한 72개·32개 추가 세트는 이제 개발/회귀 자료다. 오류를 고친 후의 통과를 최초 홀드아웃 성공으로 바꾸어 보고하지 않는다.

## 최종 결과와 진입 판단

원시 의미 판정: 정답 요소 300개 + 추가 정상 위치 6개. 보류를 임의로 정상에 합치지 않고 별도로 집계했다.

이전 미채택 2단계 실험에서 남았던 광고 누락 4건과 추가 정상 위치 오판 2건도 이 패널에서 해소했다. 특정 실패 위치만 고치지 않고 전체 120개 광고와 정상 186개를 함께 검사했다. 원순서와 순서 변경 실행의 최종 광고·보류 판정은 모두 같다.

별도의 서비스 계약 경계 4개는 정보 부족 2개와 이용 제안이 없는 문서 정보 2개를 구분했다. 정보 부족을 정상으로 확정해 0건을 만든 것이 아니다. 이는 서비스 단계 검사이며 위 의도 F1 표본에 합치지 않는다.

검증 방식: 순서 변경 306개와 추가 32/16/32/32개는 전체 단계를 실제 API로 실행했다. 원순서 306개 및 72/8개는 마지막에 바뀐 서비스 단계만 새로 호출하고, 변경하지 않은 대상·인용 응답은 해당 근거 객체의 동일성을 확인해 재사용했다. 따라서 이 세 묶음에 새 전체 실행 시간이나 0원 비용을 붙이지 않는다. 마지막 통합 코드의 불확실성 해소 분기는 별도 검사했고, 저장된 전체 실행 306개 응답을 재생하여 최종 코드에서도 동일한 결과임을 확인했다. 실제 44개 요청의 프롬프트·모델 설정도 최종 계약과 대조했다.

**3단계 진입 기준은 충족했다.** 기존 광고를 유지하면서 정상 오탐을 줄였고, 기존 실패와 추가 변형·순서 변경에서 회귀가 없었다. 다음은 DOM·스타일 기반 관찰 기법을 연결하고 위치 × 기법 평가 및 웹 경로를 검증하는 단계다. 합성 회귀 자료에서의 성공이며 새로운 실제 사이트에 대한 일반화 성능은 아직 입증하지 않았다.

이번 목표 작업의 전체 실제 진단 로그는 요청 483회, 응답 확인 476회, 확인된 1,185,879토큰이다. 사용량을 확인하지 못한 요청 7회가 있어 총 과금량은 확정하지 않는다. 실패·미채택 안도 포함했고, 네트워크 없는 검사와 저장된 결과 재사용은 중복 계산하지 않았다. 앞선 단계의 136회 진단 로그는 이 합계에 포함하지 않는다.

## 구현·운영 범위

새 구조는 `agent/experiments/`의 `target-contract.cjs`, `service-contract.cjs`, `support-contract.cjs`, `contextualize.cjs`, `run.cjs`에 있다. 새 패키지는 추가하지 않았다. 공통 HCX 전송·스키마·재시도·취소 처리를 재사용한다. `node agent/experiments/run.cjs isolated evidence.json NEW_OUTPUT_DIR`로 실제 유료 API 실험을 실행한다. 기존 출력은 덮어쓰지 않는다.

웹 worker의 기본 판정기는 이번 작업에서 바꾸지 않았다. 새 구조는 아직 관찰 기법 결과를 결합하지 않아 대회용 findings를 생성하지 않는다. 3단계에서 기법 관찰을 연결하고 위치 × 기법 단위와 웹 전체 경로를 검증한 뒤 기본 적용을 판단한다.

`npm.cmd test --prefix agent`는 자모·수집·기존 판정 계약·문맥 범위·서비스 확인·근거 귀속·불확실 처리·상반된 설명 재확인을 통과했다. 별도의 네트워크 없는 실행 검사는 전체 실험 단계, 실패 저장, findings 미출력, 덮어쓰기 거부를 통과했다.

## 남는 한계

방향 표현의 동의어, 여러 문단에 걸친 암묵적 귀속, 범위 밖 설명, 실제 사이트의 혼합 문맥은 추가 검증 대상이다. 정순·역순 확인도 동일하게 틀리는 경우를 검출하지 못한다. 짧은 문구의 서비스 근거가 부족하면 정상으로 확정하지 않고 검토 대상으로 남긴다. 실제 법률 판단 전반이나 모든 광고 업종을 입증한 실험이 아니다.

다중 판정은 호출 수를 늘린다. 순서 검사 축소·반복 판정 재사용·병렬화는 정확도 회귀를 함께 비교해야 하며 이번 작업에서는 적용하지 않았다. 원화 과금액은 실제 청구 정보를 확인하지 않았으므로 추정하지 않는다.
