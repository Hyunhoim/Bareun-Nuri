## 기준선과 변경

기준 자료는 `.runtime/phase1-full-1790774023853`의 실제 516개 요청이다. HCX-007 none / temperature 0 / seed 42 / 출력 512 / 최대 12후보 / 58,000 TPM / 61초 창 / 요청 간격 1초를 유지한다.

1. 요청 본문·배치 구성·발송 순서를 유지하며 동시 요청만 1→2로 비교한다.
2. 의미 판정 완료 응답을 먼저 영구 저장하고, CPU 기법 판정·결과 저장을 다음 API 대기와 중첩할 수 있는지 검증한다. 의미 및 기법 알고리즘은 변경하지 않는다.
3. 동일 문맥 값만 공유표에 저장하고 명시적 참조로 전달한다. 원문·귀속·문맥을 삭제하지 않으며 역변환 일치를 확인한다.

## 진행과 종료

세 오프라인 분석은 병렬로 진행한다. 실제 API 조건은 계정 한도 경쟁을 피하도록 조건별로 실행한다. 시간 재생과 토큰 추정은 실제 속도·F1로 보고하지 않는다.

동시 요청 실제 진단은 전체 요청에서 정답을 보지 않고 균등 추출한 24개에 대해 순차/동시2/동시2/순차 순서로 반복한다. 최대 120회, 확인 사용 토큰 500,000, 실행 20분 안전 상한이다. 입력은 완전히 같고 요청별 UUID·전역 순번·본문 해시 및 원응답을 남긴다. 미확인 요청은 재호출하지 않는다. 정답은 실행 입력에 포함하지 않는다.

실제 진단의 확대 조건은 평균 시간 10% 이상 단축, 각 반복의 F1과 정탐 보존 여부 및 정상 오탐 악화 확인, 불완전 응답 증가 여부다. 작은 표본의 동일 F1만으로 일반화 보존을 확정하지 않는다. 동시 조건에서 반복되는 추가 정탐 손실이나 저장·귀속 오류가 있으면 운영 승격하지 않는다.

25분 운영 승격은 별도 관문이다. 요청별 영구 상태, 응답 역순·부분 응답·중단과 재개·중복 방지 검증이 먼저 필요하다. 미완성 실행 구조에서 API 처리량만 측정하고 운영 채택으로 보고하지 않는다. 미방문·미판정 광고를 FN에 포함한 동일 25분 종단 비교 전에는 현 운영을 유지한다.
