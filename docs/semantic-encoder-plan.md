2026-09-29. 사용자 요청 Goal의 첫 단계. 운영 HCX와 기존 체크포인트는 변경하지 않는다.

## 자료와 해석

- 훈련: `synthetic-extension-v2/combined-train-candidates.jsonl`, 956행. SHA256 `46e86fc999dd351e33b7fd9fd4917218bdf4e8136b8379c096d41bd09125e685`.
- 개발: `semantic-validation-v1` 기본50(광고20/정상20/근거부족10), 표기변형40. 이미 개발용으로 지정했으며 최종 평가가 아니다. 모든 epoch의 사용을 장부에 남긴다.
- 실제 양성은 소수 출처·캠페인에 집중되고, 새 라벨 대부분은 AI 잠정 검수다. 956행을 독립 실제 광고956건으로 해석하지 않는다. 같은 작성자의 합성 개발 성능에는 공통 편향이 남는다.
- 입력은 오직 대상과 문맥. ID·범주·라벨·설명·출처는 입력하지 않는다. NFC만 공통 적용하며 위험 단어 치환이나 정답 복원문을 추가하지 않는다. 훈련 가족당 총 가중치를 같게 하고 전체 평균 가중치를1로 맞춘다. 원자료는 수정하지 않는다.
- 이번 새956행·이진 헤드 실험은 과거 A의8000행·4분류 학습 재현이 아니다. 하위8층과 임베딩 동결, lr1e-5라는 성공했던 최적화 방향만 출발점으로 참고한다.

## 결과를 보기 전에 고정한 비교

각각 KLUE-RoBERTa-base, KcELECTRA-base-v2022, KoELECTRA-base-v3-discriminator를 순정 pretrained에서 시작한다. 기존 로컬 원본 재사용, 새 다운로드는 revision 고정.

1. 기준: 최대512토큰, 임베딩+하위8층 동결.
2. 길이 가설: 최대256토큰만 변경. 짧은 입력의 속도를 유지하면서 긴 문맥 손실이 늘어나는지 확인.
3. 적응 가설: 최대512토큰에서 전체 층 학습만 변경. 작은 자료에 대한 과적합 및 정상 오탐 확인.

총9조건, 조건당 최대3epoch. seed42, FP32, AdamW lr1e-5/weight_decay.01, 유효batch8·micro2, gradient clip1. 전체학습은 GPU 메모리 보호를 위한 activation checkpointing을 적용한다. 각 실행40분 상한, 동시 GPU 학습 금지. 다른 학습이 실행 중이면 준비 후 순차 대기한다. OOM은 실패로 남기고 조용히 설정을 바꾸지 않는다.

공통 직렬화는 기존 `판정대상: ...\n문맥: ...`이다. 오른쪽 토큰 절단을 명시하고 전체 길이·대상 잘림·문맥 완전 소실 건수를 모델/조건별 기록한다. 잘린 입력을 의미 판단 오류와 혼동하지 않는다.

epoch 선택은 기본40개 광고F1와 변형40개 광고F1 중 최솟값 우선, 두 평균 다음, 정상 오탐 적은 순이다. 기본/변형 지표는 합쳐 표본수를 부풀리지 않는다. 범주당 양성2/정상2이므로 범주별 최적화는 하지 않는다. 기본 판정은 p>=.5이며, 별도 고정 .2~.8 보류 진단은 확률 미보정·근거부족 클래스 미학습이라는 한계와 함께 보고한다. 모호한10개를 이진 오답/정답으로 강제하지 않는다.

## 다음 단계로 진행할 기준

합성 개발의 최소F1 .85, 기본 정상FP<=2/20, 표기 일치>=.9를 만족한 모델만 실제 입력·HCX 직접 비교의 우선 후보로 삼는다. 통과하지 못하면 실패로 기록하고 이번 개발셋에 맞춘 추가 반복은 하지 않는다. 이 기준은 운영 대체 기준이 아니다.

선택 체크포인트마다 CPU8threads/FP32/batch8, warmup 후 같은90개3회 추론시간과 로딩·토큰화·RSS를 분리 측정한다. 학습GPU시간으로 CPU 배포 속도를 주장하지 않는다. 확률과 예측, 체크포인트·데이터·코드 해시를 보존한다.

운영 대체 결론에는 추가로 실제 수집 문맥의 독립 검수, 동일 저장 입력의 HCX 비교, 기존 정탐 보존, 정상 오탐·보류 부담, 동일25분 종단 검증이 필요하다. API 비교는 범주 계약 차이를 먼저 정리하고 별도 호출 예산을 기록한 뒤 진행한다. 이번 9조건 학습에는 유료 API를 사용하지 않는다.
