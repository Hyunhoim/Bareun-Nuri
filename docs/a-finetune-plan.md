# A 일반화 파인튜닝 병렬 비교 사전 계약

2026-09-28. A를 연구 개선 출발점으로 고정한다. 사용자 요청의 채택 목표는 새 분류 후보 확보이며 운영 HCX 대체를 자동 승인/검증한 것은 아니다. 기존 평가/오류 원문은 훈련하지 않는다. 새 학습자료 작성과 봉인 확인자료 작성은 서로 다른 에이전트가 수행하며 서로의 자료를 읽지 않는다. 둘 다 합성 자료여서 독립 사람 정답이라고 부르지 않는다.

## 1차 실험

- 새 실제 권유/피해/인용/정상/근거부족 대조자료+기존훈련 리허설. A에서 초기화한 CE, CE+기존행 teacher distillation, 마지막1층+분류기만 학습하는 보수적 CE의3조건.
- seed42, batch8,96step,lr2e-6,AdamW(weight_decay .01). 배치 새4(라벨별1)+기존4, 동일표본·순서. 32/64/96step에서 개발만 평가한다. 기준선도 동일개발로 측정한다.
- CE/KD는 임베딩+하위8층 고정, 보수적 CE는 하위11층 고정. KD는 새 자료에 적용하지 않고 기존4행에만 T2 KL×T²×0.5를 추가한다. teacher logits는 A eval로 사전 계산해CPU 중복상주를 피한다.
- 원래 target/context 계약+NFC를 유지한다. 자모 읽기 개선/제목삭제를 함께 적용하지 않는다. 자료·설정·코드 해시와 스케줄을 보존한다. CPU8threads, 각후보학습20분/전체90분 안전상한. 실행 스레드 병렬화는 메모리·시간 측정 혼선을 피하기 위해 순차일 수 있다. 자료/설계/감사는 병렬이다. API0.

## 평가·선택

새 개발자료와 기존120/44를 개발 패널로 사용한다. 새 개발광고F1이 A보다 높고, 패널평균F1이 A보다 높으며, 기존120/44 각패널F1 하락이2%p 이내인 후보를 우선한다. 새 개발에서 uncertain→ad가 A보다 늘거나 재현율이5%p 넘게 떨어지면 제외한다. 적격 후보 중 패널평균F1→최저F1→낮은step 순으로1개만 선택한다. 개발 적격이 없으면 봉인자료를 열지 않는다. 실패를 성공으로 만들기 위해 기준을 사후 변경하지 않는다.

선택후 기존2,000회귀에서전체F1 비감소·4기법별F1 하락2%p이내·재현율하락2%p이내를 확인한다. 손실개수0을 절대조건으로 하지는 않지만 TP손실/회복·FP교환을 모두 기록한다. 회귀관문을 실패하면 해당후보확인 평가를 열지 않는다. 기존2,000은 새평가가 아니다.

관문통과한 고정후보와 A만 봉인 확인자료에서1회 비교한다. 새 자료에 기법별 표기변형을 적용할 경우 동일 원문계열로 묶어보고, CSS 숨김 두조건의 텍스트가 같음을 명시한다. 분류성능과DOM기법관찰은 다르다. 확인 광고F1 개선·재현율 비감소·4분류 macroF1 비감소 및uncertain→ad 비증가를 연구후보 채택 근거로 한다. 반복표기수를 독립 표본수로 취급하지 않는다.

전체 모델/토큰화/입력 hash·근접중복 감사를 실행 전 수행한다. 사람이 검수하지 않은 새 합성의 정답 우려는 별도 표시하며 라벨수정은 예측전에만 한다. 같은 작성자의 합성 편향은 자료개수를 늘려 해결됐다고 주장하지 않는다. 후보실패시 기존평가점수를보며 학습률을 계속 조정하지 않고 실패원인/추가가능가설/외부검수 필요성을 보고한다. 운영 채택은 동일HCX/25분·재개·DOM통합 검증이 별도로 필요하다.
