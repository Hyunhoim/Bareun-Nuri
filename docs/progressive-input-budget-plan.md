# 장문 요청 크기 후속 검증 계획

2026-09-23. 혼합 사이트의 여섯 유료 조건은 최초 고정 버전 그대로 끝까지 실행한다. 개발 결과를 보고 프롬프트·탐색 점수·필터·데이터를 변경하지 않는다.

별도 로컬 자원 검사에서 기존 부산 사전 점검의 27,816자 본문은 5개 창으로 나눠도 한 요청의 추정 토큰이 84,630이었다. 설정한 TPM 52,000보다 커, 13,300자 수준의 혼합 사이트 장문만 통과했다고 일반적인 장문 처리를 완료했다고 볼 수 없다. 이 문제는 광고 문구와 무관한 요청 용량 계약 문제다.

유료 비교 종료 후, 기존 createSession이 만드는 실제 요청 body를 전송 직전 로컬에서 추정한다. 상한 이내 배치는 그대로 유지하고, 초과 배치만 같은 순서의 가장 긴 접두부로 나눈다. 최대 16개는 유지하되 상한 초과 시 더 작은 배치를 허용한다. 한 후보도 상한을 넘으면 자르거나 정상으로 간주하지 않고 명시적인 실패로 남긴다. 프롬프트·출력 계약·원문을 변경하지 않는다.

검증 기준:

- 요청 추정은 실제 공통 판정기 코드로 생성하며 HTTP 전송은 하지 않는다.
- 원래 정상 크기의 16개 배치, 그리고 여섯 유료 조건의 모든 기존 배치가 유지되는지 저장 입력에서 검증한다. 하나라도 달라지면 과거 정확도 수치를 새 경로 결과로 전용하지 않는다.
- 다양한 길이·한글·자모·surrogate·인용 문구에서 모든 조각의 순서/ID/원문 보존과 입력 상한 준수를 확인한다.
- 중단·재개 및 기본 짧은 문서 회귀 검사를 다시 실행한다.
- 실제 추가 LLM 정확도 호출은 하지 않는다. 큰 입력을 전달할 수 있다는 구조 검증과 긴 인용 문맥의 광고 판정 정확도는 구분한다.

기존 유료 실행의 manifest·소스 사본을 보존한 후 새로운 입력 예산 처리를 연결한다. 실제 웹 worker에는 자동 채택하지 않는다.
