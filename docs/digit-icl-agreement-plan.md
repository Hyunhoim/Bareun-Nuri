# 고정 ICL 후보 읽기 제거와 불일치 보류 진단

ICL은 v6에서 S 대비 숫자 치환을 더 잘 찾았지만 정상 식별자의 S 오판이 남았다. 운영7개에서는 양성2개/정상3개를 맞혔으나 모호2개를 S와 L로 확정하여 기존 연결 관문을 실패했다. 해당 실패 판정은 유지한다. 과거 ICL 없는 N 역시 미채택이었다. 이번 가설은 문맥 활용이 개선된 고정 ICL에서 실제 대상에 제시한 복원 가설이 남은 과확정을 유발하는지 확인하는 별도의 상호작용 진단이다.

A는 이미 전부 감사한 고정 ICL v6 원래/역순 및 운영7 원래/역순의 실제 응답이다. B는 훈련8예시와 순서를 완전히 유지하고 실제 대상의 readings/source_ids/readings_truncated만 제거한다. 관련 두 문장 `제공 readings는 검증된 단어가 아닌 문자 대응 가설이다.`와 `readings_truncated가 true이거나 후보 중 근거 있는 읽기가 없으면 substitution으로 확정하지 않는다.`만 삭제한다. 원토큰·원문·소속 문맥·unchanged·출력 계약은 유지한다. 따라서 입력 제거와 호환 지시 변경의 결합이며 순수 입력 제거로 표현하지 않는다. 예시 교체, 단어 예외, 추가 역할/복원 지시를 넣지 않는다.

C는 A/B 분류가 같으면 유지하고 다르면 uncertain이다. raw 필드는 B 원응답이며 C의 합성 분류와 구분한다. 동일 모델의 합의는 독립 검증이나 참의 증거가 아니다. 두 조건이 같은 오답을 내면 해결되지 않고, 양성 불일치를 보류하여 재현율이 떨어질 수 있다. A/B/C 각각의 점수와 불일치 유형을 공개한다.

이미 관찰한 v6 48개와 운영7개 전체를 각 원래·역순으로 재사용한다. 새 B 호출은48+7+48+7=110회이며 A110응답을 재사용한다. 기존 A의 요청 본문·원응답·저장 판정·소스 해시·독립 감사 완료를 검증한다. A와 B의 시간 차이에 따른 모델 변동을 완전히 통제하지 못한다. v6 출력1024/운영7 출력512로 각각 기존 A와 맞추며 HCX-007 none/temp0/seed42/58k/단일순차/1초간격/요청180초를 유지한다. 호출 보호130회·예약 상한100만·예상370,840예약토큰, 조건10분/전체1시간·조건간61초다. root `.runtime/digit-icl-agreement-v1`, 자동 재호출·기존 경로 덮어쓰기 금지, API0 dry run 쓰기 없음.

새 진단 관문은 각 순서 C가 운영 양성2개와 v6의 ICL 정탐24개를 모두 보존하고, v6 정상의 S 오판이 A보다 엄격히 줄며, v6 모호 과확정이 증가하지 않고, 운영 모호의 S 오판이 증가하지 않는 것이다. 운영 모호의 L/U까지 정답을 요구했던 이전 관문 실패를 이번 기준으로 소급 통과시키지 않는다. 운영7의 정확2U 관문 충족 여부는 별도 계속 보고한다. 새로운 목표는 숫자 기법의 정탐 보존과 오확정 억제이며 이전 실패의 이름만 바꾸는 것이 아니다.

모든 조건 완료 후 감사하며, 실패하면 예시·프롬프트·보류 기준을 이 사례에 맞춰 바꾸지 않는다. 통과해도 관찰한 자료의 진단이며 새 홀드아웃, 실제 광고 정탐 보존, 위치 귀속, 정상 광고 내 식별표기,25분 저장/재개 검증이 필요하다. 운영 사용은 숫자 대상당 두 호출을 요구하므로 신규 B110회만 비용이라고 주장하지 않고 A+B 비용과 시간을 별도 추정한다. 정확 단어 복원은 출력하지 않으며 운영 관찰·코드는 수정하지 않는다.
