# 새 구조 측정 사이트와 네 정책 비교 사전 계획 — 2026-09-24

성능 실행 전 고정한다. 기존 FIFO/문맥 Bandit을 변경하지 않는다. 목적은 동일 문서 요청 예산에서 광고 위치 도달을 비교하는 것이며 LLM 정확도 실험이 아니다. HCX 호출 0, 외부 검색 발굴 및 Firecrawl 미사용. 실제 기관에는 구조 확인을 위한 소수의 읽기 요청만 보낸다.

## 관측과 가설

- 기존 자료에서는 얕은 폭과 경유 선택 지연으로 깊은 주소 발견이 늦었다. 문맥 Bandit은 이미 발견한 광고의 대기를 줄였지만 다른 주소 발견을 늦추고 기존 FIFO 위치를 잃었다.
- 깊이 순환은 발견된 깊이 사이에 기회를 배분한다. 구조 순환은 같은 URL 형식이 대기열을 독점하는 정도를 줄인다. 둘 다 광고 재현율 보장이나 보편적 우월성은 아니다.
- 기존 자료에서 모든 광고가 detail이었다. 새 자료는 정상 상세 글, 비상세 광고, 얕은 광고, 깊은 정상 말단, 특정 템플릿 집중 광고, 여러 템플릿 분산 광고를 함께 포함한다.

## 자료

새 `test-set-v5`에 개발 4개와 확인 4개 사이트를 만든다. 각 120~200개 HTML 페이지를 목표로 하며 공통 예산은 20/50/100 요청, 주요 채택 예산은 50이다. 시작 페이지와 실패 요청도 예산에 포함한다. 브라우저 하위 리소스 요청 수와는 다르다.

실제 부산 시민열린마루의 표/필터/페이지 이동/상세 메타데이터 및 대전 공지의 쿼리형 경로·메뉴 구조를 참고한다. HTML 문법·레이아웃·연결 형태만 재구성하며 로고·게시글·개인정보는 복제하지 않는다. 각 사이트에 서로 다른 폭, 경로 길이, 페이지 이동, 교차 링크를 둔다. 확인 사이트는 다른 경로 형식과 연결 조합을 사용한다. 양쪽 모두 동일 작성자의 합성이므로 실사이트 홀드아웃이라고 주장하지 않는다.

각 사이트는 광고 위치 32개를 기본으로 한다: 얕은 광고 4개, 한 템플릿 집중 광고 12개, 여러 구조 분산 광고 8개, 깊은 영역 광고 8개. 여러 광고가 같은 페이지에 존재할 수 있으며 페이지 수와 위치 수를 구분한다. 정상 대상과 예방 인용도 별도 라벨에 보존한다. 제목·본문·댓글·작성자·서명·링크 문구 및 4종 위장 표현을 포함한다. 정상 상세 글도 충분히 둔다. 깊이는 전체 생성 그래프의 최단 거리로 사후 평가하되 탐색기에는 전달하지 않는다.

정답·시나리오 범주는 private에 둔다. HTML id와 파일명은 정답 여부를 나타내지 않는다. 서버는 public 경로만 허용하고 private와 소스 파일은 제공하지 않는다. 서로 다른 사이트는 별도 포트로 제공하여 동일 출처 계약에서 서로 섞이지 않게 한다. 정답 전체를 브라우저 DOM selector와 대조한다. 공개 사이트에 실제 불법 서비스 주소를 넣지 않는다.

## 고정 정책

1. FIFO: 기존 core의 choose/feedback.
2. 문맥 Bandit: 기존 `frontier-context.cjs` 그대로. 55차원, alpha 0.5, 매5번째 FIFO, 새 detail 본문 보상. 변경/튜닝 없음.
3. 깊이별 순환 FIFO: 처음 발견한 링크 이동 깊이별 큐를 오름차순 순환한다. 빈 깊이는 건너뛰고 큐 안은 발견 순서다. 깊이0은 시작 URL이다. 나중의 지름길로 깊이를 수정하지 않는다. 전체 최단 거리를 미리 사용하지 않는다.
4. URL 구조별 순환 FIFO: origin+pathname+정렬한 쿼리 키/값의 구문 템플릿별 큐를 최초 그룹 발견 순서로 순환한다. 순수 숫자, UUID, 긴 16진수 식별자만 그룹 키에서 치환한다. 실제 URL·중복 키의 쿼리는 변경하지 않는다. 일반 문자열 값은 보존한다. 같은 그룹의 글을 생략하거나 정상으로 간주하지 않는다.

두 순환 정책의 커서는 성공/실패 방문 feedback에서 확정하고 직렬화한다. 기존 네트워크/iframe 경계는 유지한다. 정책별 입력은 방문한 페이지의 실제 DOM에서 추출한 링크/문맥/profile뿐이다. 아직 방문하지 않은 페이지·정답·전체 연결 정보를 정책에 주지 않는다. 고정 점수, LLM 점수, 위험 점수, 추가 FIFO 혼합 비율은 넣지 않는다.

## 평가·회귀·채택

사이트당 링크 순서 20개(seed 0,11,23,37,51,67,79,97,109,127,149,163,181,199,211,229,251,269,283,307)를 공통 적용한다. 8×20×4=640회 전체 순회를 기본으로 한다. seed는 링크 배열만 바꾸며 광고 위치를 바꾸지 않는다. 독립 사이트 160개로 해석하지 않는다.

- 전체 광고 위치를 분모로 reach@20/50/100. 평균, 모집단 표준편차, 관측 최저, 최대, 대응 FIFO 차이와 FIFO 위치 손실을 기록한다.
- 얕은(최단거리≤2)/깊은(≥5), 배치 시나리오, 실제 영역(게시판/안내/공지), 표면(제목/본문/댓글 등), 위장 기법별 도달.
- 누락은 주소 미발견/발견 후 대기로 분리한다. 첫 광고·깊은 광고의 요청 순번, 정상 막다른 경로의 예산 소비도 기록한다.
- 전체 집합·중복 방문0·같은 입력 재현·중간 상태 직렬화 재개·예산 접두부 일치를 검사한다. 실제 core runner로 새 정책의 부분 완료/재개/방문 순서 보존을 별도 확인한다.
- 정책/자료 해시를 점수 계산 전에 고정하고 실행 전후 검증한다. 브라우저 수집 시간과 메모리 정책 실행 시간을 구분한다.

채택 관문은 기존 엄격한 보존 원칙을 유지한다: (a) 모든 사이트·예산의 링크 순서 평균 도달률 FIFO 이상, (b) 주요50요청 모든 실행에서 FIFO 광고 위치 손실0, (c) 개발/확인 각각50요청 평균 +5%p 이상, (d) 사이트별50요청 관측 최저와 깊은 광고 평균 FIFO 이상, (e) 구조·재개 검사 전부 통과. 결과를 보고 완화하지 않는다. 통과한 후보도 운영 종단 F1/시간 검증 전에는 탐색 후속 후보이며, 이번 오프라인 결과만으로 HCX 포함 운영 교체를 확정하지 않는다. 모두 실패하면 최종 기본 정책은 FIFO 유지다.

동일 자료의 비율/그룹 예외/깊이 가산점 튜닝, 실패 후보의 결합 재실험은 하지 않는다. 성능 회귀는 즉시 보고한다. 코드 오류는 점수를 확인하기 전 검사 단계에서 수정하고 이력을 남긴다. 이후 채점 오류가 발견되면 기존 실행을 보존하고 수정 이유와 재집계를 명시한다.
