# 탐색 계약 반영 및 방문 정책 최종 판단

2026-09-23. **동일 출처 전체 경로 + 삽입 프레임 별도 검사 + 점진 판정/부분 결과 저장 구조를 적용하고, 운영 방문 순서는 FIFO를 채택한다.** Bandit과 경로 연속 탐색은 비교 옵션으로 남기며 웹 기본값으로 연결하지 않는다. 특정 사례 전용 예외·프롬프트 튜닝·git push는 하지 않았다.

## 고정 요구사항과 구현

`AGENTS.md`와 `crawl-contract.md`에 계약을 고정했다. 일반 링크는 입력 URL과 동일 출처의 연결된 모든 경로를 대상으로 한다. 게시판 여부나 pathname 첫 구간으로 제외하지 않는다. 외부 일반 링크는 출처·이유를 기록하고 따라가지 않는다. 외부 iframe은 실제 삽입된 문서로서 검사하되 그 사이트의 일반 링크 탐색으로 확장하지 않는다. 댓글, 동일/외부/중첩/srcdoc 프레임의 원문과 상위 페이지·프레임 위치를 보존한다.

- `agent/src/core/collect.cjs`: 기본 경로 `/`, 프레임과 일반 탐색 요청 경계 분리, 수집 문제 기록. 기존 의미 단위 수집·정규화·LLM 프롬프트는 유지한다.
- `frame-access.cjs`: 외부 문서의 HTTP(S)·인증정보·DNS 주소 검사. 로컬 테스트 진입에 한해 loopback 프레임 허용. 프레임 깊이 8/페이지당 50 제한은 미검사로 기록한다. DNS 사전 검사는 별도 네트워크 격리를 대체하지 않는다.
- `scan.cjs`: 기존 progressive 실험의 체크포인트·배치·장문 분할을 재사용해 운영 경로에 반영했다. 배치 16 단위 판정·원자적 저장을 수행하고 페이지 예산 종료 시 잔여 배치도 판정한다. 한도/접근 문제는 부분 완료, 모든 페이지 접근 실패는 실패다. 완료 판정만 result.json에 넣으며 coverage.json에 성공 방문·요청 시도·대기·제외·실패·미판정·미확인 API 요청을 남긴다.
- `frontier.cjs`: FIFO, 과거 UCB Bandit, 최대 3/10 슬롯의 경로 연속 규칙을 공유한다. 두 기존 사이트 50페이지의 6개 방문 순서가 과거 구현과 일치했다. 정책은 순서만 바꾸며 후보를 필터링하지 않는다.
- `worker.cjs`, Spring Boot `Jobs.java`, React 화면: 점진 실행과 부분 완료를 연결했다. 부분 결과 다운로드·검사 범위 상세가 가능하다. 웹 재개 버튼은 미구현이며 동일 설정 core 체크포인트 재개만 검증했다. 미확인 API 요청의 자동 재호출은 거부한다.

동일 정규 URL은 중복 제거하지만 실제 요청 주소는 원래 URL을 보존한다. 게시글/페이지 번호 쿼리는 제거하지 않는다. 페이지 예산은 요청 시도 기준이며 리다이렉트 별칭을 두 페이지로 중복 집계하지 않는다. 아직 발견하지 못한 페이지 수는 unknown이다. 외부 링크 제외 자체는 정한 경계의 정상 동작이고, 검사 대상 문서/리소스 접근 실패는 부분 완료 사유다.

## 검증 자료와 조건

새 혼합 사이트 2개, 27+28=55개 탐색 페이지, 147+150=297개 텍스트 후보를 브라우저로 수집했다. 정답은 사이트당 광고 12·예방 인용 정상 12, 총 48개 위치다. 모든 정답의 원문/위치를 확인했다. 다른 경로의 상세 글·쿼리 게시판·본문/제목·본문 밖 댓글·일반 안내/공지·프레임·순환 링크·깊은 메뉴를 포함한다. 중첩/srcdoc 및 접근 실패·재개는 별도 기능 검사에서 다뤘다.

세 정책을 각 12페이지 예산으로 비교했다. 수집 증거 캐시를 동일하게 사용하고 조건마다 HCX-007을 새 호출했다. 온도 0, seed 42, reasoning none, 배치 16, 출력 3072, 순차 호출과 TPM 52000을 고정했다. 첫 사이트 FIFO→Bandit→경로, 두 번째 경로→Bandit→FIFO 순서다. 미방문 광고도 FN에 포함한다. 표의 시간은 **캐시 기반 정책 실행 + 실제 판정/저장 시간**이며 웹 전체 종단 지연은 아니다. 최초 브라우저 수집은 각각 32.58/34.01초다.

새 자료도 동일 제작자의 합성 자료이고 광고 표현/DOM에 반복이 있다. 과거와 다른 경로·프레임 구조를 검증하지만 실사이트 일반화 또는 독립 홀드아웃 성능으로 해석하지 않는다. 같은 자료에 맞춘 정책 비율·가중치 조정은 하지 않았다.

정답 표시 밖 확정 양성은 없었다. 경로 연속의 의미 오탐 1개는 기법을 반환하지 않아 최종 findings 대신 진단에 남았다. 따라서 최종 기법 FP=0만 보고 광고 의도 오류가 없다고 해석하면 안 된다.

Bandit은 첫 사이트의 FIFO 정탐 2개(일반 안내 본문과 외부 프레임 광고)를 미방문했고 다른 광고 3개를 추가 방문했다. 경로 연속은 FIFO 정탐 중 외부 프레임 광고 1개를 미방문했다. 두 번째 사이트에서는 FIFO 정탐 손실이 없었다. 방문한 정답 광고의 의미 판정은 모두 맞았고, 이번 FN은 모두 미방문이다. 깊은 영역 광고는 세 정책 모두 0개 탐지였다. 프레임 광고는 FIFO 1개, 나머지 0개였으며 프레임 수집 실패가 아니라 상위 페이지 선택 지연이었다.

사전 채택 기준에서 Bandit은 기존 정탐 보존을 실패했다. 경로 연속은 기존 정탐 보존·사이트별 의미 F1 비회귀·정밀도 기준을 실패했다. 합산 이득으로 개별 영역의 회귀를 가리지 않았다.

자료·예산·실행 방식이 달라 두 실험의 점수를 단순 합산하거나 전후 성능 하락으로 해석하지 않는다. 두 비교 모두 Bandit의 평균 이득은 관찰됐지만 기존 영역을 대체하는 손실도 반복됐다. 이전 6사이트 오프라인 실험에서도 경로 연속은 50요청의 깊은 영역 효과 기준을 통과하지 못했다.

**운영 채택: FIFO. 추가 비교 후보: Bandit. 이번 경로 연속안: 미채택.** 이는 FIFO의 보편적 최적성을 입증한 것이 아니라 미리 고정한 정탐 보존 기준에서 대체안이 통과하지 못했다는 결정이다. 같은 사이트에서 비율을 재조정해 채택 근거를 만들지 않는다. 새 계약의 수집/상태 기능과 미채택 방문 정책은 분리한다.

현재 주요 병목은 제한된 예산의 미방문이다. 다만 미해결 의미 판정·기법 오류와 배치 변동도 남아 있으며 이번 간단한 표현에서 방문 광고를 맞혔다고 해결을 주장하지 않는다. 다음 고도화는 이 계약을 기준으로 미방문·수집 누락·판정 오류를 분리해 측정해야 한다.

## 검증·사용량·개발 중 발견 사항

- 실제 29회, 169,657토큰, 모두 HTTP 200. 미확인 유료 요청이나 재실행은 없었다. 원화 비용은 추정하지 않았다.
- 실행 중 18개 소스/증거 해시 고정, 공통 프롬프트·모델 설정 일치. FIFO 대비 공통 후보 입력은 사이트별 Bandit 55/58개, 경로 63/65개가 모두 동일했다. 배치 구성은 정책에 따라 다르므로 판정 차이를 순수 탐색 효과로 분리했다고 주장하지 않는다.
- 기존 Agent 전체 테스트 통과. 새 구조 검사에서 다른 경로·쿼리·본문 밖 댓글·외부/중첩/srcdoc 프레임·순환·예산·부분 저장/재개·실패 페이지/403 프레임·리다이렉트 중복·미확인 API 재호출 거부를 확인했다.
- 최초 fixture 준비에서 숫자로 시작하는 ID의 CSS 이스케이프와 정답 선택자가 맞지 않았다. 평가 전에 fixture ID를 문자로 시작하게 고쳤으며 모델/탐지 규칙은 수정하지 않았다. 해당 실패는 API 호출 전이었다.
- 웹 테스트가 끝 슬래시 요청 주소 오류를 발견했다. 유료 비교 완료/소스 보존 후 실제 요청 주소와 중복 키를 분리하고 리다이렉트 요청 횟수도 바로잡았다. 비교 사이트 URL에는 이 차이가 없었다. 최종 코드에서 저장 응답을 재생해 6조건의 방문 페이지·후보·요청 배치·판정 결과가 모두 동일함을 검증했다. 유료 재측정이 아니라 동등성 검사다.
- React 빌드, 별도 경로 Spring Boot 패키징 성공. 제한 실행/기존 산출물 경로에서 JAR 처리 오류가 있어 격리 빌드로 검증 후 정상 JAR를 `backend/target/public-ad-backend.jar`에 반영했다. 기존 실행 서버는 종료하지 않았다.
- 웹 Mock 검증에서 시작·진행·결과 다운로드, 페이지/시간 한도의 부분 결과, 취소, 동시 실행 제한, 데스크톱/모바일, 재시작 후 이력 보존을 통과했다. 웹 전체 경로의 추가 HCX 호출은 하지 않았고 위 29회는 같은 core 실행기를 직접 이용했다.
