# 핵심 분류만 출력하는 계약의 확인

16개배치 passageJson은 첫16개 분류값 자체가 맞았지만12개에서 evidence_ids=[]를 반환해 엄격한출처선택계약을 실패했다. 이를사후통과시키지않는다. 새로운act조건은 모델에부여한출처번호생성과제를없애고 publication_act만생성하게한다. 입력문맥·분류지침은그대로이고,코드가의미정답을바꾸지않는다.

- 개발64개에 act16과 기존passageJson4를새로실행한다. 최대20요청/350,000예약토큰/1시간. none/temp0/seed42/출력3072. 운영대조는직전같은64개O의응답을사용하며재호출하지않았음을명시한다.
- 엄격한전체nodeID/중복/누락/enum/추가필드/JSON검증을유지한다. 표시이유는분류명+대상원문을코드로만들며모델이선택한근거나자유설명으로표시하지않는다. 수집된전체문맥과원문위치도보존한다.
- 개발F1최대후보1개만선택한다. 차이1%p이내는적은호출/토큰의act16을우선한다. 형식실패응답을집계에서버리거나정상으로보정하지않는다.
- 선택후프롬프트/계약수정없이새80개정순·고정섞기2회,기존76개회귀로검증한다. 실제25분상한FIFO비교와출력·재개검증까지통과해야운영연결한다.
- 4기법은기존코드관찰로별도검증한다. 숫자치환/부분스타일/근거누락은계속미확정으로남겨야하며의미F1로이를해결했다고표현하지않는다.
