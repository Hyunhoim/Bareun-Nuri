# 고정 ICL 대상 후보 제거 B의 새 v7 확인

기존 agreement110 진단 관문을 통과한 이후에만 실행한다. 해당 진단에서 B와 결합C의 S 집합은 같았고 C는 추가 S 오판 제거 없이 L→U 및 두 호출 비용을 늘렸다. 따라서 이번 후보는 **B 단독**이며 합의 보류를 운영 후보에 누적하지 않는다. 원래 ICL A와 고정 target-nohint B의 프롬프트·예시를 수정하지 않는다.

새 자료는 최소18개 단어 계열의48개로 치환18(순수9·혼합9), 정상 식별18, 모호12를 구성한다. 제작자와 별도 검토자가 기존 자료/훈련 예시와의 중복, 정답 근거, 원문/문맥 귀속을 봉인한다. 입력에는 node_id/token/target_text/context만 허용하며 실행기는 정답 파일을 읽지 않고 해시만 검증한다. 별도 independent-seal.json의 passed를 필수로 확인한다.

실제 실행은 A→B→역순B→역순A 각48회/총192회이며 동시기 대조다. 양쪽 출력512를 적용한다. v6의1024에서 변경된 운영 목표 조건이므로 과거 v6 값을 이 비교의 기준선으로 대체하지 않는다. HCX-007 none/temp0/seed42/58k/단일후보/순차/1초간격/요청180초를 유지한다. 호출 보호220, 예약 상한100만, 조건10분/전체1시간, 조건간61초, 오류/미확인 자동 재호출 금지다. `.runtime/digit-icl-v7-live-v1`만 새로 사용하고 dry run은 파일을 만들지 않는다.

실행 전에 동결된 agreement 소스·훈련 예시·개발 관문 및 새 자료의 독립 봉인을 검증한다. 각 A/B 요청은 대상 readings/source_ids/readings_truncated 제거와 사전에 고정된 호환 지시2문장 제거 이외에 동일해야 한다. 전체 네 조건 완료 전에는 정답과 결과를 열어 평가하지 않는다.

각 순서에서 B는 A보다 strict F1이 높고, 정상 식별자 S 오판이 증가하지 않으며, 실제 치환 재현율이 감소하지 않고, 모호 사례의 S 오판이 증가하지 않아야 한다. 모든 조건을 만족해야 이 확인 관문을 통과한다. 개별 정탐 손실과 회복, L/U 혼동, 원래/역순 변동, 입력·출력 토큰과 시간을 별도 보고한다. 숫자 치환 기법 정탐이며 광고 의미 정탐으로 부르지 않는다.

실패하면 이 자료에 맞춰 예시·프롬프트·판정 기준을 바꾸지 않는다. 통과하더라도 새 합성 자료의 검증이며 실제 운영 광고 정탐 보존, 숫자 구간과 광고 행위의 귀속, 장문·기존 기법 보존, 저장/재개 및 동일25분 검증은 별도 필수다. 정확 복원 단어는 여전히 출력하지 않는다. 운영 코드 변경이나 채택은 이번 확인에 포함되지 않는다.
