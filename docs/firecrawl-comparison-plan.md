## 실측 전 예산 보충

원래 아래 설계의1,400페이지분은 계정 잔여량을 넘으므로 **사이트4개×(50페이지 두 반복+100페이지 한 반복)=800페이지분**으로 줄인다.25페이지 조건은 실행하지 않는다. 사전 접속 확인은2페이지 한 번으로 제한한다. 전체 비용 상한900크레딧, 전체1시간은 유지한다. 반복 없는100페이지 결과의 불확실성을 명시한다. 이 수정은 어떤 Firecrawl 탐색 결과도 보기 전에 잔여량만으로 결정했다. 아래 원안의25페이지/두 반복/1,400·1,500크레딧 표기는 이 보충으로 대체한다.

## 대상과 범위

- 비교 대상은 `frontier-context.cjs`의 context-bandit(alpha0.5, 55차원 ridge, 매5회 FIFO, 새로운 상세 본문 보상)이다. 최근 경로 재개 wrapper는 회귀로 미채택이므로 사용하지 않는다. 기존 코드/보상/프롬프트를 조정하지 않는다.
- 상대는 Firecrawl Cloud v2 `/crawl`이다. Map/Search/Agent 엔드포인트는 사용하지 않는다. SDK를 새로 설치하지 않고 Node fetch로 REST를 호출한다.
- 이번 1차 본 비교는 **탐색 성능**이다. 전체 정답 광고 위치 중 방문 페이지에 포함된 비율, 깊은 광고 위치 도달, 기존 위치 손실, 실패/중복 요청, 페이지별 최초 도달 시간, 누적 도달 곡선과 비용을 비교한다. LLM 정밀도/F1을 측정했다고 표시하지 않는다. 후보 선별·4종 기법 판정의 우열은 별도다.
- 기본 FIFO와 운영 코드는 변경하지 않는다. 준비된 실행기는 정적 합성 HTML 탐색용이다. 동적 클릭/iframe 증거 수집을 대신하지 않는다.

## 고정 실행 조건

- 기존 v4 중 dev-101/102 및 confirmation-201/202의127/135페이지 사이트4개, 사이트당 광고24개/깊은 광고8개. 기존에 관찰한 자료이며 새 홀드아웃이 아니다. 제작자·구조 반복과 상세 본문 보상 편향을 보고한다. 실제 공공사이트에는 전체 정답이 없으므로 정확도 분모를 임의 생성하지 않는다.
- 사이트별25/50/100페이지 제한, 두 반복. 조건별 독립 새 작업으로 시작한다. Firecrawl 전체 작업의 앞부분을 작은 예산 실행 결과로 대신하지 않는다. 최초 반복은 사이트·예산 번호 합에 따라 A/B 순서를 교대하고 두 번째는 역순이다. 문맥 모델은 매번 초기화한다.
- Firecrawl 성공 페이지 기준 limit와 Bandit 요청 시도 기준 limit는 의미가 다를 수 있다. 순위 판단은 반환 수뿐 아니라 합성 서버의 문서 요청 기록(실패·반복 포함)을 이용한 동일 요청수 도달 비교와 동일 시간 비교를 병기한다. Firecrawl의 result 배열 순서는 실제 요청 순서가 아니다.
- 두 방식 모두 동시성1. Bandit은 실제 브라우저로 동일 공개 URL에 접속하고 Firecrawl은 원격 서비스에서 접속한다. 네트워크·인프라 차이가 남으므로 시간은 제품 전체 실행 성능이지 순수 알고리즘 속도가 아니다. 로컬 회귀 시간과 비교하지 않는다.
- 조건별600초, 전체1시간. Firecrawl 설정상 최대1,400페이지분 요청(4×175×2); 실제 크레딧은 서비스 응답으로 기록하고 가격은 요금제 확인 없이 원화로 환산하지 않는다. 1,500크레딧 실험 상한을 사용하며 관측되지 않은/진행 중 작업은 예약량으로 포함한다. 상한은 서비스의 원자적 비용 보장이 아니다. 초과/불명확 시 후속 작업 중단. HCX 호출0회.
- `sitemap:skip`, `crawlEntireDomain:true`, 외부 일반 링크/하위도메인 false, 쿼리 보존, `maxConcurrency:1`, 캐시 재사용0, 광고 차단false, 본문만 추출false, rawHtml/links 반환. API가 옵션을 거부하면 동일조건 검증 전 비교 중단; 임의 제거 후 성공으로 처리하지 않는다.
- 출처는 스킴·호스트·포트를 포함해 비교한다. Firecrawl의 내부 링크 범위가 같다고 가정하지 않고 반환 URL·서버 로그로 검사한다. 테스트 서버는 한 사이트의 명시된 HTML만 제공하고 파일시스템 경로를 요청으로 해석하지 않는다. 정답·환경파일·코드·서버 로그는 HTTP로 제공하지 않는다. 공개는 사용자 확인 후 합성 HTML 전용 서비스만 한다.

## 측정과 종료

- 원본 API 상태/결과/오류, job ID, 서버 요청 로그, 선택기 trace, 소스/HTML/정답 해시를 남긴다. 결과 pagination을 끝까지 수집하고 404를 성공 방문으로 세지 않는다. Firecrawl 미방문 대기열과 미발견 목록은 API로 확인되지 않으면 unknown이다.
- 페이지 반환 성공, 서버 요청 도달, 기존 수집기로 근거 추출 성공은 서로 다른 지표다. rawHtml 반환만으로 투명/화면 밖 위치 검증을 완료했다고 표시하지 않는다.
- timeout/오류 시 알려진 작업 ID는 취소를 시도하고 취소 실패를 기록한다. POST 전송 후 응답 불명확이면 새 작업 자동 생성 금지. 계정에서 진행 작업 확인 후 재개한다. 원본 실행 디렉터리는 재사용하지 않는다.
- 탐색 대안 검토 기준: 모든 사이트·사전 예산에서 반복 평균 전체 광고 도달 비감소, 기존 광고 위치 손실0, 깊은 도달 합산+10%p 이상을 적어도 한 예산에서 달성, 범위 계약 위반0. 서비스 지연은 중앙값/p95와 분포를 보고한다(2반복 p95는 신뢰할 추정치가 아님). 시간 증가15% 초과는 도입 비용과 함께 별도 미통과로 보고한다. 비용/재방문 부담이 크면 도달 개선만으로 채택하지 않는다.
- 이 조건을 통과해도 즉시 운영 교체하지 않는다. 공통 브라우저 수집기의 스타일/위치/댓글/iframe 보존 및 최종 판정 비교가 남는다. 재사용 합성 자료만으로 일반화 개선을 확정하지 않는다. 실패 자료에 맞춘 파라미터 조정 없이 계획된 비교로 종료한다.

## 현재 준비물과 실행법

본 비교 전 접속 검증: 첫 연결은 실행 중 빈 next 페이지의 API 동작을 수정하고 취소 확인(0크레딧), 두 번은 Cloudflare가 robots.txt에 Firecrawl Disallow를 추가해 거부(각0). 원인 확인용 `/scrape`로 robots.txt만 읽음(1크레딧, Map/Search 아님). localhost.run으로 임시 제공 경로를 변경한 뒤 Crawl2페이지·Bandit2페이지의 정상 접근을 확인했다(2크레딧). 비교 목적지 HTML/선택기 조건은 변경하지 않았다. robots를 무시하거나 접근 제한을 우회하지 않는다. 이 준비 비용3크레딧은 본 비교와 별도다.

`node agent/experiments/firecrawl-trial.cjs run PUBLIC_ORIGIN NEW_OUTPUT_DIR`가 전체 비교를 조정한다. 로컬18990포트의 합성 서버를 사이트별로 시작/종료하며, 선택된 정책 하나만 실행하고 결과·서버 로그·비용 예약을 저장한다. 정답은 실행 뒤 도달 채점에만 사용한다. 소스/HTML 해시는 실행 전 고정한다. 테스트용 공개 터널은 별도 프로세스로 유지하고 종료 시 함께 닫는다.

1. `agent/.env`에 `FIRECRAWL_API_KEY`를 등록한다. 값은 출력/커밋하지 않는다.
2. 합성 HTML만 임시 공개할지 확인하거나, 사용자가 같은 자료의 공개 주소를 제공한다. 현재 localhost 주소를 Firecrawl Cloud에 보내지 않는다.
3. `node agent/experiments/firecrawl-compare.test.cjs`는 API 계약·안전한 파일 제공·문맥 Bandit의 로컬 동작을 검증한다.
4. `node agent/experiments/firecrawl-compare.cjs preflight`는 키 존재 여부만 표시한다. `bandit URL LIMIT OUT` 및 `firecrawl URL LIMIT OUT`은 **개별 조건 실행기**이며 전체 비용 상한은 위 trial 명령에서 관리한다.

Context7 및 공식 REST 문서를 확인했다. Firecrawl Cloud 버전의 내부 방문 정책은 검증된 Bandit 우위 근거로 공개되어 있다고 가정하지 않는다.
