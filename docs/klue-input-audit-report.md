# 분류모델 입력·정답 감사와 제한 학습 결과

## 입력·정답 감사 — 2026-09-28

원래 2,000개 정답/예측/모델은 보존했다. 원문 전수 일치2,000/2,000, `[object Object]` 손실0, 수집 문맥 잘림0, 이전 추론512토큰 잘림0이다. 기존 입력 최대 문맥44자이며 실제 blockquote/q 대상0개다. 따라서 복잡한 장문 귀속이나 실제 인용 경계의 독립 검증 자료로는 부족하다.

분류모델용 `klue-context.cjs`는 구조화된 문맥 외에 `nearby`도 합친다. 수집기의 `nearby`는 DOM 형제 텍스트이며 같은 게시글/댓글 귀속을 보장하지 않는다. 새 기계적 DOM 검사에서 독립된 댓글 요소4종의 다른 댓글 문구가 모두 입력에 들어왔다. **별도 수정 어댑터 `klue-scoped-context.cjs`는 target을 포함한 scoped units가 있으면 unscoped nearby를 합치지 않는다.** 같은 소유 범위의 문맥은 유지하고 옛 근거 형식에는 기존 fallback을 남긴다. 귀속 근거가 없는 옛 fallback의 안전성을 새로 보장한 것은 아니다.

새 범위 검사8개에서 다른 댓글 혼입4→0, 같은 댓글 근거4/4 보존이다. 최초 검사v1은 서로 다른 article/li 형제를 같은 소유자로 잘못 기대해2개가 실패했다. 해당 결과를 `.runtime/klue-input-audit-v1`에 보존했고, 명시적인 동일 comment owner 안에 설명/대상을 넣은v2를 따로 실행했다. 실패한 실험 결과를 삭제하거나 수집 경계를 무작정 넓히지 않았다.

원래2,000개는 수정 전후 입력 변화0개다. 재추론 없이 동일 입력/모델의 이전 예측을 그대로 재사용한다. **기존 누락143/오탐63개를 이 문맥 결함의 탓으로 설명할 수 없다.** 운영 HCX 수집기/프롬프트/판정부는 바꾸지 않았다. Graphify 구조 그래프와 실제 `ownerFor`/`contextFor`/`initialEvidence`/분류 직렬화 코드를 대조했다. 그래프의 동명 함수 충돌 경고가 있어 소스를 최종 근거로 사용했다.

## 정답 명확성

영문명·충전·복귀·계좌·정산만 있고 서비스 종류가 분명하지 않은12개 광고 원문(48변형)을 검토 대상으로 표시했다. 예: “BET 전에 쓰던 아이디 그대로 복귀 가능합니다. 잔액 옮기실 분 연락 주세요.” 비공개 `scenario_family`를 보면 작성 의도는 도박이지만 실제 모델 입력에서는 이를 충분히 입증하기 어려울 수 있다.

정상으로 뒤집거나 원래 평가에서 빼지 않았다. 나머지488개 원문도 독립 사람 검수 완료라는 뜻은 아니다. 검토 후보는 에이전트의 보수적 의견이며 확정된 오라벨 목록이 아니다. 모델 예측을 읽기 전에 이번 검토 파일을 저장·해시 고정했지만, 이전 턴에 전체 성능과 오류를 이미 관찰한 사람이 수행한 감사이므로 완전한 맹검으로 주장하지 않는다.

| 집계 | 기존 KLUE | 기존 개선 후보 |
|---|---:|---:|
|원래2,000개 F1|87.32%|89.27%|
|검토48개 제외 민감도 F1|87.28%|89.97%|
|민감도 TP/FP/FN|854/151/98|830/63/122|

민감도는 참고값이며 원래 점수를 대체하지 않는다. 정답 모호함을 분리해도 후보의 광고 누락은 남는다. 기존 전체 지표를 좋게 만들기 위한 정답 변경/삭제를 하지 않는다.

## 제한된 학습 비교

새 학습 원문64개를 실제 HTML4가지 배치로 수집한256입력과 기존 훈련자료1,600개를 사용한다. 새 개발검증은 별도 원문32개·64입력이고 학습과 정확한 대상문구 중복0이다. 실제 수집한320개 입력을 사용하며 수작업 설명·정답 복원문을 입력에 추가하지 않는다. 새 자료는 같은 작성자의 합성으로, 과제 의미 범주와 일부 설명 문법이 유사하다. 독립 실사이트/사람검수/새 최종 평가가 아니다. 이 한계를 해소하지 않은 대규모 확대는 하지 않는다.

기존 frozen8 모델에서 상위4층+분류기, lr5e-6, batch8, seed42, 최대2epoch만 비교한다. 새 개발검증 광고F1→macro4→이른epoch로 선택한 뒤 원래2,000개를 회귀 점검한다. 기존 평가 문구는 학습에 넣지 않는다. 기존 리허설 자료는 과거 합성 자료이므로 전체 학습 데이터가 실제 수집 출처라는 주장은 하지 않는다.

GPU 가용성 검사에서 CUDA 장치0개로 시작 전 중단됐다. 가중치 업데이트 전 실패이며 빈 `run` 디렉터리를 보존했다. 동일 학습 설정으로CPU8threads/30분 상한의 `run-cpu` 경로에서 한 번 실행한다. 새 모델의 회귀 판정 역시20분 안전상한이다. GPU 드라이버/시스템 설정을 변경하지 않았다.

추가 한계: 근거 부족 자료 중 일부는 서비스 설명이 없다는 사실을 문장 자체가 직접 설명한다. 모델이 실제 생략·단편 문맥을 추론하기보다 이 표현을 학습할 위험이 있다. 개발검증의 높은 점수는 이러한 설명 문법에 대한 적응과 구분할 수 없다. 원문64개/32개의 HTML 변형을 각각256개/64개의 독립 의미 사례로 해석하지 않는다.

## 학습 결과와 결정

CPU 학습2epoch 약420.67초, 개발검증으로 epoch2를 선택했다. 새 개발검증 광고F1 73.17→100%, 4분류 macroF1 44.11→95.27%다. 근거 부족은 광고F1에서 제외하고 별도 집계하며, 올바른 보류4→16/16, 광고 오판2→0이다. 기존 평가2,000개는 선택이 끝난 뒤 한 번만 추론했다.

| 기존 관찰 평가2,000개 | 이전 분류 후보 | 이번 추가 학습 |
|---|---:|---:|
|정밀도|93.15%|98.76%|
|재현율|85.70%|79.80%|
|광고 F1|89.27%|88.27%|
|TP / FP / FN|857 / 63 / 143|798 / 10 / 202|

기존 정탐76개를 잃고17개를 회복했다. 오탐54개를 해소했지만 새 오탐1개가 생겼다. 도박 피해 문의 오탐21→4/40, 성인영상 피해 문의20→2/40, 결제 문의10→0/40으로 줄었다. 정상 도입부 뒤 광고는 누락26→17/40으로 개선됐지만 전체 광고 누락은 증가했다. 같은 원문의4변형이 포함된 수치이므로 독립 원문 개수로 해석하지 않는다.

**이번 학습 모델은 미채택이다.** 개발검증의 상승이 기존 관찰 평가로 이어지지 않았다. 피해 문의 구별의 개선 가능성은 확인했지만 전체 일반화 개선은 확인하지 못했다. 학습자료 편향·설명 문법 의존·과적합 가능성을 보고하며, 정확한 원인을 한 번의 실험만으로 확정하지 않는다. 실험용 범위 어댑터는 보존하되 기존 모델·운영 HCX는 유지한다. 새 모델은 연구 산출물이며 운영에서 불러오지 않는다.

## 실행 및 감사 기록

추론2,000개 저장 후 집계 코드가 `selection.json`의 확장자를 빠뜨려 실패했다. 학습/예측 원본과 동결 코드를 보존하고 `klue-audit-summarize.cjs`로 저장 예측만 재집계했다. 추가 학습/추론0회다. 정확한 순수 추론 시간은 실패 전 디스크에 저장되지 않아 보고하지 않는다. 과거 약38초와의 속도 개선도 주장하지 않는다.

`klue-audit-learning-check.cjs`가 새 실제DOM 입력320개 재구성, 기존 모델·소스·정답 해시 보존, 예측 ID2,000개, TP/FP/FN/F1 독립 재집계를 통과했다. 이 검사는 구현/수치 감사이며 독립 평가셋 또는 사람 정답 검수라는 뜻은 아니다. 학습/개발검증 토큰 잘림0, 유료 API0, 운영 변경0, push0이다.

주요 산출물:
- `.runtime/klue-input-audit-v2/summary.json`: 입력 및 범위 감사
- `.runtime/klue-label-audit-v1/review.json`: 정답 재검토 원문 목록
- `.runtime/klue-audit-learning-v1/run-cpu/result.json`: 회귀 결과 및 유형별 결과
- `.runtime/klue-audit-learning-v1/run-cpu/changes.json`: 정탐 손실·회복/오탐 변화 위치
- `.runtime/klue-audit-learning-v1/run-cpu/audit.json`: 독립 재집계 확인

다음 작업은 같은2,000개 점수를 보고 반복 학습하는 것이 아니다. 서비스 종류가 드러난 실제 권유와 피해 문의를 동일 어휘의 대조쌍으로 구성하고, 주변 다른 작성자의 말·직접 인용·짧은 생략문을 실제 소유 경계와 함께 검수한다. 모호한 원문은 보류 계약으로 분리하며 강제 이진 정답을 부여하지 않는다. 새 검증 분할도 학습과 다른 문장 문법·원문 계열·사이트 구조로 구성한 뒤 제한된 비교를 시행해야 한다. 기존2,000개는 계속 회귀 자료로만 사용한다.
