# Qwen3.5-2B CPU 속도 측정 결과

2026-09-27. 다운로드·실행·10회 측정 완료. 운영 Agent/HCX 코드 수정 0, 유료 API 호출 0. 파인튜닝은 하지 않았다.

## 설치와 장비

- 모델: Unsloth 배포 `Qwen3.5-2B-Q4_K_M.gguf`, 1,280,835,840바이트(약 1.28GB). Qwen 원본의 제3자 양자화 배포이며 직접 학습한 모델이 아니다.
- 모델 revision: `f6d5376be1edb4d416d56da11e5397a961aca8ae`. SHA-256: `aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`.
- 엔진: 공식 llama.cpp Windows CPU x64 `b11217`, commit `c9064dded`. 다운로드 ZIP SHA-256 검증 통과.
- 장비: AMD Ryzen 7 8845HS, 논리 스레드 16, 물리 메모리 33,602,785,280바이트(32GB급). 실험에서는 8 CPU 스레드 사용.
- CPU 전용 빌드의 `--list-devices`: Available devices (none). `--device none`, GPU layers 0, KV/연산 GPU offload 비활성. RTX 4060과 내장 GPU 사용 안 함.
- 파일은 `.runtime/qwen-cpu/`에 보관하며 Git 제외를 확인했다. 전역 설치·운영 연결 없음.

## 방법

기존 137개 저장 후보에서 직렬화 입력 길이에 따라 단일 후보 3개와 기존 12개 묶음 2개를 선택했다. 원문·문맥을 잘라내지 않고 현재 HCX 요청 생성기가 만든 system/user 메시지를 그대로 사용했다. 짧음/중간/최장은 해당 저장 자료 내 기준이다. 후보는 바꾸지 않고 실행 순서를 뒤집어 각 조건 2회 측정했다.

추론 off, temperature 0, seed 42, 출력 상한 512, context 16,384, 실행 슬롯 1. 모든 응답 cache_n=0, reasoning 내용 0, 종료 사유 stop. 모델은 메모리에 상주하되 요청 간 프롬프트 캐시는 재사용하지 않았다. 프로세스 시작은 별도 약 3.11초였다.

## 실측

| 조건 | 입력 토큰 | 출력 토큰 | 1회차 | 2회차 | 평균 |
|---|---:|---:|---:|---:|---:|
| 단일 짧은 후보 | 616 | 31 | 4.23초 | 4.50초 | **4.36초** |
| 단일 중간 후보 | 656 | 29 | 4.34초 | 4.66초 | **4.50초** |
| 단일 긴 후보 | 988 | 32 | 6.08초 | 5.59초 | **5.84초** |
| 12개 중간 묶음 | 3,539 | 289 | 31.23초 | 30.60초 | **30.91초** |
| 12개 긴 묶음 | 3,882 | 295 | 34.17초 | 34.02초 | **34.09초** |

- 입력 처리 약 171~222 tokens/s, 출력 생성 약 24~30 tokens/s.
- 긴 12개 묶음의 입력 처리 약 22.1~22.6초, 출력 약 11.4~12.0초. 출력 축소만으로 입력 읽기 비용은 없어지지 않는다.
- 최대 프로세스 working set **2,261,995,520바이트 ≈ 2.11GiB**. 최대 private bytes 약 1.33GiB. 두 값을 더하지 않는다.
- 요청 시간 합 159.43초. 시작·메모리 조회·종료 포함 전체 168.70초.

RAM 수치는 모델 서버만의 사용량이다. 브라우저·백엔드·Node·OS까지 포함한 총 메모리나 최소 배포 RAM 사양이 아니다. 앱 전체 동시 실행 부하·전원 모드·발열 통제는 하지 않았다. 주최측의 미상 CPU 성능을 재현하지 않았다.

## 출력 형식과 해석

단일 후보 6/6회는 현재 운영 출력 계약을 통과했다. 12개 묶음 4/4회는 유효 JSON이었지만 각 node_id 값이 `{"publication_act":"이용권유"}` 객체 대신 `"이용권유"` 문자열로 나와 계약을 실패했다. 토큰 상한 잘림은 없었다. 사후 자동 수선이나 재호출은 하지 않았다.

따라서 위 12개 처리 시간은 **응답 생성 시간**이며 성공적으로 검증된 광고 판정 처리량이 아니다. 의미 정답·기법 정답을 평가하지 않았고 F1을 산출하지 않았다. 실험 대상 전체를 판정한 것도 아니며, 속도만 보고 HCX 대체·파인튜닝 효과·25분 완주를 주장하지 않는다.

**판단:** 이 장비에서 2B 4비트 모델은 GPU 없이 정상 실행 가능하고 메모리 부담도 확인 가능한 수준이다. 제한된 의심 후보의 보조 판정기를 연구할 하드웨어 근거는 생겼다. 다만 현재 운영의 전체 판정을 대체할 속도·정확도 근거는 없다. 다음 단계는 모델 크기를 늘리는 것보다 좁은 역할의 출력 계약·파인튜닝 효과를 별도 평가하는 것이다.
