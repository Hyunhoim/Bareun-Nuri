# 문자 근거·문맥 분리의 적용 가능 범위

2026-09-30. 기존 Graphify 그래프의 queries/createAntiSpoof/worker 경로를 조회했고 수정시각과 실제소스로 확인했다. 현재 queries가 표기원문과전체대상·주변문맥을 생성하고 infer.py가 Unicode문자열근거를붙여같은512토큰한도에넣는다. 서비스교체는별도실험이며운영변경은없다.

검증표현은 문맥채널의 원문·대상마커·주변문맥을 그대로 보존하고, 문자채널에는 각 위치의 Unicode 정수 코드포인트와 표준표 대응을 배열로 저장한다. 원문을 재구성하고 대응값을 대조하는 assert를 실행했다. 기존155문자probe의 정수표현은 모두 구별됐다. **이를 처리하는 학습된 모델은 아직 없으며** 토큰과 문자배열길이를 합쳐 동일단위 비용처럼 비교하지 않는다.

## 구조 판단

KcELECTRA의 문맥 경로와 작은 문자 근거 경로를 결합하는 격리실험에는 근거가 있다. 새 경로는 표기·대응의 실제 코드포인트를 받아 tokenizer의UNK손실을우회하고, 최종두기법은문맥과합쳐판단하는 가설이다. 숫자/자모가있다는이유만으로H또는광고를확정하지않는다. 실제CPU비용과학습가능성은미확인이다.

기존 학습표기는짧고live는최대124문자라서새경로의장문외삽을따로검증해야한다. 먼저동일학습자료·고정개발검증으로효과를확인하고기존정탐보존/정상·보류/CPU/HCX고정연결을거쳐야한다. 개발성공만으로승격하지않으며과거최종860은재사용하지않는다. 아직새모델학습없음/추가API0/운영0,Goal active.
