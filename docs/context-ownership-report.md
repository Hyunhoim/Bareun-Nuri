# 1순위 문맥 귀속 개선 실험 — 2026-09-25

사전 기준은 `context-ownership-plan.md`에 고정했다. 실험 코드는 `agent/experiments/context-ownership.cjs`, 새 HTML 자료 생성·수집 코드는 `context-ownership-site.cjs`다. 운영 수집기·판정기·worker는 변경하지 않았다.

## 가설과 통제

기존 최초 입력 필드는 유지하면서 B에 DOM 문맥 경계, 대상 태그/인용 여부, 앞뒤 원문, 잘림 여부를 구조적으로 추가했다. DOM 근접성을 동일 작성자나 같은 의도의 증명으로 표현하지 않는다. 프롬프트/출력 계약/모델/순서/최대16개 배치는 동일하다. 이 실험은 문맥 표현 방식 전체의 효과이며 필드 이름 하나의 인과 효과를 분리한 것은 아니다.

두 번째 비교는 같은 의미 판정 결과를 기존 코드 관찰 모듈과 통합하는 것이다. A+관찰/B+관찰을 함께 계산하며 추가 API 호출은 없다. 의미 판정·검토 상태·이유를 그대로 유지하는 것을 assertion으로 확인한다. 이는 LLM의 기법 출력을 제거해 의미 전용으로 호출하는 실험이 아니다. 숫자 치환 및 부분 스타일 귀속 문제를 새로 해결하지 않는다.

## 자료 및 수집 검증

기존76개는 이미 관찰한 회귀 자료다. 개발32/확인32개는 실제 HTML로 구성하고 운영 Playwright 수집기로 저장했다. 각 분할은 광고16/정상12/근거 부족4개이고4종 기법별8개다. 예방 인용, 예방 설명 옆 별도 광고, 다른 댓글의 예방 설명 옆 광고, 다른 댓글의 광고 옆 정상 안내, 문맥 의존 링크, 근거 부족 링크, 직접 광고, 정상 안내를 포함한다.

개발/확인 사이 원문을 분리했으며 예방 설명은 각4종, 서비스 문구도 각4종으로 구성했다. article/section, blockquote/일반 요소, comment/listitem 경계, 제목/본문/링크, 분할span, 조상 투명·화면 밖 위치를 바꿨다. 정답은 HTML과 판정 입력에 포함하지 않는다.

64/64 대상의 selector·원문과 관찰 근거의 문자 범위를 검증했다. 독립 관찰 모듈의 기법 정답은 개발32/32·확인32/32였다. 이는 이 자료에서의 수집·관찰 검사이며 의미 판정 성능이나 모든 기법 변형의 일반화를 뜻하지 않는다. 최종 수집 자료는 `.runtime/context-ownership-data-v2`다. v1은 모델 호출 전 자료 검토에서 예방 문구 반복을 발견해 보완한 이전 버전이며 원본 생성기와 수집 자료를 보존했다. 모델 결과를 보고 자료를 수정한 것이 아니다.

자료 한계: 동일 제작자의 소규모 합성 세트이고8상황의4변형은 서로 독립 표본이 아니다. 반사실 대조를 위해 일부 내용이 반복된다. 새 세트에는 모호한 숫자 치환·부분 스타일 귀속·동적 댓글·iframe 변형이 없어 해당 범위의 일반화를 증명하지 않는다. 이 검사에는 대상 위치만 선별했으므로 모든 메뉴/주변 설명의 오탐이나25분 전체 사이트 탐지 성능으로 확대 해석하지 않는다. 근거 부족은 정상으로 합치지 않고 별도 검토 정확도로 평가한다.

### 의미 판정과 일반화 범위

- 세 자료에서 B가 두 기준선에 공통으로 잡힌 광고를 잃은 위치는0개다. 기존 누락1개와 새 개발/확인의 문맥 의존 광고 링크 각4개를 탐지했다. 링크 문구 자체에 서비스 이름이 없어도 주변 설명을 활용하는 효과가 이번 두 새 표현/구조에서 확인됐다.
- 기존 예방 인용 오탐은7/6→1개로 줄었지만 새 개발·확인의 예방 인용은 각각4개 모두 오탐했다. 해당 설명은 실제 수집돼 B 입력에도 포함됐고 quote/문맥 경계도 기록됐다. 따라서 이8개는 미수집보다는 전달된 문맥을 판정에 적용하지 못한 문제로 분류한다. 인용 의도 판단의 일반화 개선은 확인되지 않았다.

## 채택 판단

**문맥 구조화안 B 및 B+코드 관찰 모두 운영 미채택. 기존 운영 기준선 유지.**

회귀·개발의 의미 관문은 통과했으므로 사전 계획대로 확인32개를 호출했다. 확인에서는 정상 검토0→4개로 관문을 실패했다. B 단독은 기법 관문도 실패했으며 코드 관찰로 기법을 복구해도 빈 근거에 따른 정상 검토는 남는다. 관찰 미확정 범위도 전체 통합의 검증 한계다. 비용은 각 분할에서 기준선 대비 토큰·지연20% 한도를 넘지 않았으나 그것만으로 채택하지 않는다.

따라서25분 유료 종단 비교와 운영 연결로 확대하지 않았다. 같은 문구를 겨냥한 프롬프트 반복 수정·예외 규칙·빈 근거 보호 규칙 해제도 하지 않았다. 두 새 분할은 이제 결과를 관찰한 진단 자료이며 후속 작업에서 새 홀드아웃으로 취급하면 안 된다.

이번에 확인된 후속 원인은 문맥을 못 모은 문제와 구분되는 **예방 인용 설명의 적용 실패**, **의미 판단에 따라 관찰 결과까지 바뀌는 결합**, **빈 근거 출력 계약 실패**다. 이 원인들은 기록하되 현재 실패한 변경 위에 보정 단계를 더 붙이지 않는다.

검증: 실제 브라우저64대상 원문/위치/관찰 검사, 입력·프롬프트 보존 및 근거 부족 별도 집계 self-check, 요청 body/응답/usage/지표의 독립 재집계를 통과했다. 새 자료와실험만 추가했으므로 운영 전체/웹 빌드를 반복하지 않았으며 운영 소스 해시는 실행 전후 동일했다. 커밋·push·추가 유료 호출은 하지 않았다.
