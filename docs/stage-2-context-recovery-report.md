# 2단계 문맥 보완 후속 검증 — 기본 채택 보류

검증일: 2026-09-22. **문맥 의존 광고의 누락을 줄이는 보완 경로를 구현했지만, 정상 오탐·불확실성 처리·순서 변경 안정성이 채택 기준을 통과하지 못했다.** 기존 웹 worker와 `isolated` 비교 기준을 유지한다. 새 `contextual` 경로는 미채택 실험 코드이며 3단계는 진행하지 않았다.

## 변경한 부분

최초 문구 판정뿐 아니라 서비스 확인 이후에도 정상으로 조기 종료될 수 있었다. 따라서 마지막 음성 판정 중 명시적인 인용으로 확정되지 않은 후보에 문맥 보완 기회를 주었다. 특정 문구·case_id·URL·정답 라벨을 조건으로 삼지 않았다.

보완 분기의 순서는 다음과 같다.

1. **대상과 문맥을 분리해 읽기**: `target_text`와 앞뒤 참고 문맥을 다른 필드로 전달한다. 원문·위치는 수집 결과에 보존한다.
2. **문구 자체의 역할 확인**: 새 광고 또는 불확실 판정은 주변 문구를 가리고 이용 안내인지 독립적인 문서 정보인지 확인한다. 요소 종류·링크 소유 여부는 보조 자료로 제공하며 태그별 일괄 제외 규칙은 없다.
3. **서비스 성격 확인**: 이용을 권한다는 사실만으로 불법광고가 되지 않도록 불법 서비스·정상 서비스·제안 없음·근거 부족을 별도로 확인한다. 문맥의 불확실성이 정상 서비스 확인으로 해소되더라도 역할 자체의 불확실성은 남긴다.
4. **검증된 결과 통합**: 후보 ID·근거 위치·누락/중복을 검사한다. 독립 정보로 정정할 때 최종 인용 근거도 해당 대상 원문으로 돌리고 이전 제안은 별도 필드로 보존한다.

추론은 보완 문맥·역할 단계에만 HCX-007 `low`를 사용했다. 기존 단계와 서비스 성격 확인은 `none`이다. HCX는 추론과 Structured Outputs를 함께 사용할 수 없어, 추론 응답은 로컬에서 엄격하게 검사하고 형식 오류가 나면 `none`+Structured Outputs로 **한 번만** 재요청한다. 실패를 정상 판정으로 바꾸지 않는다. [Naver Cloud 추론 API 문서](https://api.ncloud-docs.com/docs/clovastudio-chatcompletionsv3-thinking)

이는 기존 프롬프트만 바꾼 동등 비용 비교가 아니다. 입력 계약·추론 설정·추가 단계의 효과를 합친 후보 구조 비교다. temperature 0, seed 42, 기본 배치 16, 보완/역할 배치 4, 기본 출력 한도 3,072토큰, 추론 출력 한도 5,120토큰을 사용했다. 순차 실행이며 실제 runner의 전체 호출 상한 300회·1시간 제한을 유지했다.

## 정확도 결과

아래 수치는 **선별한 텍스트 후보의 광고 의도 판정**이다. 전체 사이트 탐색 F1이나 대회 필수 4종 기법의 URL·location·technique 단위 F1이 아니다.

| 자료 | 비교 기준 TP/FP/FN | 보완 후 TP/FP/FN | 보완 정밀도 | 보완 재현율 | F1 변화 |
|---|---:|---:|---:|---:|---:|
| 진단 63개 | 9 / 0 / 16 | 24 / 0 / 1 | 100% | 96% | 52.94% → 97.96% |
| 기존 회귀 306개 | 119 / 0 / 1 | 120 / 2 / 0 | 98.36% | 100% | 99.58% → 99.17% |
| 새 합성 26개, 최초 실행 | 2 / 0 / 8 | 10 / 0 / 0 | 100% | 100% | 33.33% → 100% |
| 같은 26개, 순서·배치 변경 | 2 / 0 / 8 | 10 / 1 / 0 | 90.91% | 100% | 33.33% → 95.24% |

진단 63개와 새 26개에는 각각 **정답을 확정할 근거가 없어 검토 상태를 기대한 2개**가 있다. 이 2개는 이진 F1 분모에서 제외하고 별도의 계약 검사로 평가했다. 따라서 각각 이진 평가 대상은 61개·24개다. 순서 변경 실행은 새로운 26개가 추가된 것이 아니다.

| 자료 | 정상 후보의 불필요한 검토 | 불확실 후보를 잘못 정상 확정 |
|---|---:|---:|
| 진단 63개 | 0 | 2 / 2 |
| 회귀 306개 | 3 | 해당 표본 없음 |
| 새 26개 최초 실행 | 1 | 2 / 2 |
| 새 26개 순서 변경 | 1 | 2 / 2 |

**모든 최종 검사의 `passed`는 false다.** 새 표본 최초 실행의 이진 F1 100%만으로 통과했다고 해석하면 안 된다.

과거 306개 결과는 TP 120 / FP 0 / FN 0이었다. 이번 동일 구조 재실행에서는 서비스 확인에서 기존 광고 1개가 누락됐다. 위 표의 비교 기준은 이번 실행 안에서 기록한 보완 전 결과다. 보완 후 기존 광고 120개를 모두 탐지했으나 정상 오탐 2개와 불필요한 검토 3개가 발생했다. 기존 정상 성능을 유지한 개선으로 채택할 수 없다.

## 해결된 범위와 남은 오류

- **누락 복구:** 진단 자료에서 문맥을 읽지 않아 놓쳤던 광고 16개 중 15개를 복구했다. 새 표본의 문맥 의존 광고 8개도 두 실행 모두 복구했다.
- **근거 혼동:** 회귀 자료의 `시민 의견`, `관련 링크`가 주변 카지노/베팅 광고 때문에 광고로 바뀌었다. 표제와 실제 광고 문구의 귀속 구분이 아직 부족하다.
- **새로운 누락:** 진단 자료의 광고성 `이용 안내 보기`는 역할 확인 단계가 h3를 독립 정보로 해석하여 누락했다. 태그만으로 제외하지 말라는 지시가 있어도 모델이 그 단서에 과도하게 의존했다.
- **표기와 의도 혼동:** 교육 문구에 붙은 `CASINO`를 서비스 성격의 근거로 삼아 정상 3개를 검토 대상으로 남겼다. 관찰된 문자와 서비스 이용 의도를 충분히 분리하지 못했다.
- **불확실성 누락:** 서비스가 특정되지 않은 결제·접수 문구를 일반적인 정상 거래로 가정했다. 정상 서비스라는 긍정적 근거를 요구하는 계약이 모델 출력에서 지켜지지 않았다.
- **실행 변동:** 새 표본의 `검토 순서`는 최초 실행에서 검토, 순서 변경 실행에서 광고가 됐다. `등록 부서: 문화지원팀`은 순서 변경 실행에서 불필요한 검토가 됐다. 이 두 실행만으로 배치 효과와 모델 자체의 변동을 분리할 수는 없다.

특정 문구를 예외 처리하거나 제목·메뉴 전체를 제외하지 않았다. 새 표본의 실패를 확인한 뒤에는 판정 코드를 다시 조정하지 않았다.

## 검증 방식과 비용

- 진단 63개는 기존 실패 28개, 이번 개발에 사용한 합성 32개, 기존 회귀에서 확인한 3개를 합친 자료다. 독립 홀드아웃이 아니다.
- 306개는 기존 수집 스냅샷을 사용했다. 웹을 다시 수집한 시험이 아니다. 기본 단계의 44회 호출은 실제 재실행했고, 후속 실험에서는 완료된 기본 결과를 재사용했다. 현재 코드로 결과를 정확하게 재구성하고 요청 시스템 프롬프트와 호출 성공 여부를 확인했다.
- 진단·회귀 최종 결과는 고정한 기본 결과에 바뀐 보완 단계의 실제 호출 결과를 합친 **단계별 재검증**이다. 새 전체 연속 실행 시간으로 보고하지 않는다.
- 새 26개는 새 문구·DOM 조합을 브라우저로 수집한 48개 후보 중 사전에 정한 26개다. 광고 10, 정상 14, 근거 부족 2개이며 iframe·동적 삽입을 포함한다. 정답은 채점에만 사용했다.
- 새 표본 최초 모델 호출 전에 판정 소스와 입력을 해시로 고정했다. 두 실행 모두 전 단계를 실제 호출했고 저장 응답을 재사용하지 않았다. 두 실행 사이에 코드를 변경하지 않았다. 실제 공공 웹사이트 홀드아웃이 아닌 작은 합성 표본이다.

| 실행 | 호출 | 토큰 | 판정 실행 경과 시간 |
|---|---:|---:|---:|
| 306개 기본 단계 | 44 | 131,474 | 473.48초 |
| 306개 최종 구성 | 78* | 209,854* | 전체 연속 측정 없음 |
| 새 26개 최초, 기본 단계 | 5 | 7,279 | 53.43초 |
| 새 26개 최초, 보완 포함 | 16 | 보고된 27,667 + 미보고 시도 1회 | 318.23초 |
| 새 26개 순서 변경, 기본 단계 | 5 | 7,272 | 27.70초 |
| 새 26개 순서 변경, 보완 포함 | 15 | 27,747 | 157.23초 |

\* 306개는 각 구성 단계의 호출·토큰을 합친 값이다. 기본 44회에 보완 34회가 추가되는 구성이다. 추가 단계별 시간은 문맥 398.67초, 역할 59.08초, 서비스 확인 11.42초였다. 이들을 하나의 새 연속 실행 시간으로 취급하지 않는다.

새 표본 최초 실행은 실패한 네트워크 요청 70.31초와 재시도 대기 60초를 포함한다. 순서 변경 실행은 네트워크 실패 없이도 기본 27.70초에서 전체 157.23초로 늘었다. 정상 후보를 다시 읽는 비용이 주요 병목이다.

폐기한 비교안까지 포함한 이번 작업의 실제 호출은 **429회**, 제공자가 보고한 토큰 합은 **913,110**이다. 사용량이 보고되지 않은 시도 3회가 있어 전체 토큰과 원화 과금액은 확정하지 않았다. 재사용 결과를 실제 호출에 중복 합산하지 않았다.

## 코드와 재현

- `agent/experiments/run.cjs`: 기존 `isolated`와 미채택 `contextual` 경로를 구분한다.
- `contextualize.cjs`, `rescue-contract.cjs`, `role-contract.cjs`, `domain-contract.cjs`: 음성 종료 보완·역할·서비스 확인과 통합을 담당한다.
- `agent/src/core/llm.cjs`: 명시적으로 지정한 실험 계약에서만 추론을 허용한다. 기본 worker의 HCX `none` 설정은 유지한다. 형식 복구·호출 상한·취소·실패 저장을 유지한다.
- `score-intent.cjs`: 검토 상태와 이진 F1을 분리하고 미완료 실행·라벨/후보 누락을 검사한다.

```powershell
# 실제 유료 HCX 호출. 기존 결과 디렉터리는 덮어쓰지 않는다.
node agent/experiments/run.cjs contextual evidence.json NEW_OUTPUT_DIR
# 채점은 네트워크 호출이 없다.
node agent/experiments/score-intent.cjs NEW_OUTPUT_DIR labels.json
npm.cmd test --prefix agent
```

`npm.cmd test --prefix agent`는 자모 보존, 브라우저 수집, 판정 계약, 근거 귀속, 불확실 처리, 형식 재요청, 호출 제한·취소 검사를 통과했다. 별도의 네트워크 없는 runner 검사로 보완 분기와 실패 저장도 확인했다. **코드 검사 통과와 모델 정확도 기준 통과는 별개다.**

근거는 `.runtime/stage2-routing/`에 보존했다. 주요 파일은 `source-final.json`, `summary.json`, `diagnostic-final-combined/`, `panel-final/`, `panel-v12/replay-verification.json`, `fresh-v11/`, `fresh-original/`, `fresh-reordered/`다. 단계별 원래 요청·응답은 각 구성 실행 폴더에 남아 있다. API 키와 모델의 내부 추론 내용은 기록하지 않았다.

## 판단

문맥 의존 광고를 후속 판단에서 배제하면 안 된다는 방향은 확인했다. 그러나 현재 보완 분기는 근거 귀속과 불확실성 계약이 안정적이지 않고 지연도 크다. **기본 구조로 채택하거나 일반화 성능 개선이 완료됐다고 선언하지 않는다.** 다음 2단계 작업은 모델이 생성한 역할/불법성 라벨을 그대로 신뢰하는 부분과 대상에 귀속되는 근거의 검증 방법을 우선 검토해야 한다. 새 표본 26개도 이제 오류를 관찰한 진단 자료이며 이후에는 새 홀드아웃이 필요하다. 3단계·웹 기본 경로 전환·커밋·push는 시행하지 않았다.
