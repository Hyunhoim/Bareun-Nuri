# HCX 처리량 Goal 결과 및 운영 채택 (2026-10-01)

## 결론

**완료 결과의 페이지별 독립 반영 + 전체 결과 재출력 묶음 처리만 운영 채택했다.** HCX-007 none/12후보/출력512/동시3/공유58k TPM/61초 창/1초 발송 간격/FIFO/수집5/SRPT8·aging8/25분을 유지한다. AntiSpoof 모델·직렬 CPU 처리·프롬프트·근거·후보선별은 변경하지 않았다. 운영 변경은 `agent/src/core/bounded-scan.cjs` 한 파일이다.

큰 폭의 모델 속도 개선이나 의미 일반화 개선을 달성한 것은 아니다. 동일25분 실측에서 판정량 +1.57%, 전체 광고 정탐 +2.06%, 광고 의도 F1 +0.44%p로 제한적이지만 양의 효과가 있었다. 기존 정탐2손실·정밀도0.55%p하락과 응답 변동을 숨기지 않는다. 같은 응답 재생은 모든 판정과 기법을 보존했고, 실제 공통 요청387개·근거4189개가 완전히 같았다.

## 실험 범위와 조건

사전 계획 `hcx-throughput-goal-plan.md`를 따랐다. 독립 진단은 병렬로 진행했고 유료 조건은 동일 계정의 제한 간섭을 막기 위해 순차 실행했다. 무거운 CPU 재생은 실제25분과 겹치지 않았다. 제공사 테스트 API 관측 한도60k TPM/60RPM, 로컬58k예약을 유지했다. 한도를 늘린 실험이 아니다.

Phase1 v1.2의2240정답(광고1120/정상1120) 전체를 분모로 사용했다. 미방문·미수집·미판정 광고는FN이다. 정답 위치 밖 양성은 별도 목록으로 남겼으며 전체 실사이트 정밀도를 뜻하지 않는다. 이미 관찰한 동일 제작자 합성자료이므로 새 홀드아웃이나 실제기관 일반화 검증이 아니다. Phase2평가/학습0, 새로운 학습0, 평가문구 맞춤 수정0이다.

## 정확도 차이의 원인

공통387요청은 설정을 포함해 본문 전체가 같고, 수집근거4189개 및 코드관찰 결과 차이0이다. 실제공통판정3899개중 publication_act/광고/검토상태49개가 달랐다(정답 없는 요소와 정상간 역할변경 포함).

- **마감까지 추가 처리한 범위:** 광고10개 증가, 정상오탐4개 증가.
- **불완전응답의 반복 변동:** 광고9개 회복·2개 손실. 정상오탐3개 추가, 기존오탐3개는 미판정으로 바뀜(오탐 해결로 주장하지 않음).
- **양쪽 모두 판정한 동일 입력:** 광고정탐 손실0이나 정상12개가 이번에는 광고로 바뀜. 코드가 입력을 바꾼 것이 확인되지는 않았지만, 무작위 서비스 변동과 타이밍 효과를 엄밀히 분리한 실험은 아니다.

격리 묶음은 기존5/후보4이며 공통3,기존만2,후보만1이다. 순감소만 보고 불완전응답 문제가 해결됐다고 주장하지 않는다. 기존정탐2손실은 후보에서 새로ID누락된 같은1묶음에 속한다. 미확인 전송은 없고 기존 격리 계약대로 보존했다.

공통 요청의 응답을 기준선 값으로 고정하고 후보의 완료범위만 적용한 **사후 진단 계산**은TP836/FP336/FN284·F1 72.95%다. 이는 새 실측이 아니며, 관측+17TP 가운데 처리범위로 설명되는 이득이+10임을 보여준다. 저장재생의 의미·기법 일치와 함께 해석한다.

사전기준(전체TP/F1증가·정밀도하락1%p이내·저장/재개안전성)을 통과했다. HCX 의미 정확도가 개선됐다고 주장하지 않으며, 공통입력 오탐 변동과 격리는 남은 병목이다.

## 저장·자원 및 동작

전체 결과 기록량은34.04%,저장소read횟수는32.57%감소했다. 반대로 즉시확정과스케줄복원 기록으로 checkpoint기록량430.77→501.81MB(+16.49%)다. 필수 안전저장을 줄여 얻은 성과가 아니다. 관측 Node최대RSS710.14→628.56MB이나 단일실행GC변동을 포함하므로 메모리개선 보장으로 보지 않는다.

후보는 즉시 요청outcome/checkpoint를 저장한다. 같은페이지는 앞묶음부터 확정하고, 다음3요청은 기존 고정wave 순서로 준비한다. 전체result/diagnostics파일은 wave완료·종료 시 갱신하며 느린wave중에는 최대5초 타이머로 갱신한다(이벤트루프가동 가능한 경우). 기존 웹UI는 활성파일읽기를피하고 이벤트진행수치를 사용한다. UI를 새로 실시간목록화한 변경은 아니다.

운영서명은 `bounded-evidence-v5-independent-publish5`다. 이전서명 체크포인트를 자동이행하거나 미확인요청을재호출하지 않는다. 기존결과·실험원본을 보존했다. 라이브서버 재시작/배포/push는 하지 않았다. 다음 새작업부터 새worker코드가 사용된다.
