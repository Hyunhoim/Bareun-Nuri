# CANINE-S + Unicode 기법 분류 비교

2026-09-30. **CANINE-S+표준 근거로 기존 특화 분류기를 교체할 근거는 없었다. 기존 KLUE+표준 근거가 더 유망했지만 운영 채택하지 않는다.** HCX 광고 의도와 기존 기법 코드는 변경하지 않았다. 새 API 호출0.

## 무엇을 비교했나

기존 최초 KLUE 기법 특화 모델을 동결 기준선으로 두고, KLUE+Unicode, CANINE-S 원문, CANINE-S+Unicode를 비교했다. 새 조건은 동일 기존 학습320개(40어휘 그룹), 개발96개, seed42/batch8/FP32/전체학습/lr2e-5/weight decay .01/최대3epoch. 개발 macro F1 → 모호 오확정 → 빠른 epoch 순으로 선택했다. 선택 epoch는 KLUE+Unicode1, CANINE 두 조건3이다. GPU는 RTX4060 Laptop, CPU 추론은8threads/batch8이다. 기존과 신규 모두 substitution/literal/uncertain 3분류다.

CANINE-S는132,085,251개 파라미터, KLUE는110,620,419개다. 문자 입력이라고 더 작은 모델은 아니다. 동일 설정 제한 비교이며 모델별 최적 학습률/대규모 데이터 탐색은 하지 않았다. 이번 실패를 CANINE의 절대 성능 한계로 해석하지 않는다.

Unicode16.0 공식 confusables6355대응을 원문 token에 적용해 NFD skeleton과 위치별 코드포인트 대응을 문맥 끝에 보조 입력으로 제공했다. 정답 복원문은 주지 않았고, 표준에 없는 대응을 추가하지 않았다. `0→O`, `m→rn`, 키릴 `а→a`는 있지만 ASCII `4→A`, `8→B`는 이 표에 없다. skeleton은 복원 정답도, 위장 의도의 증거도 아니다. 본 실험은 bidi 등을 포함한 완전한 UTS39 보안 검증기 구현이 아니다.

**기존 운영 코드도 같은 Unicode16.0 SHA의 제한된 문자표를 이미 썼다.** 이번 추가 요인은 전체 표에서 얻은 보조 근거를 모델에도 제공하는 것이며 Unicode 최초 도입이 아니다. 17.0 고정 경로는404라16.0으로 고정했으며 최신판이라고 주장하지 않는다.

공식 자료: [Unicode16.0 대응표](https://www.unicode.org/Public/security/16.0.0/confusables.txt), [UTS39](https://unicode.org/reports/tr39/), [CANINE-S 모델](https://huggingface.co/google/canine-s), [Transformers4.57.3 CANINE 문서](https://github.com/huggingface/transformers/blob/v4.57.3/docs/source/en/model_doc/canine.md).

## 실제 저장 HCX 판정에 연결한 주 결과

개발96/과거 final96의 **동일 실제 HCX 의도 결과**를 고정했다. HCX 양성은32/36개이며, 이 대상만 기법 결과를 반영한다. 코드가 확정한 기법은 보존한다. 운영 outputResult로 URL/위치/HOMOGLYPH를 내보내 정답과 비교했다. 아래는 광고 의도 F1이나 전체4종 F1이 아닌 **HCX 의도+닮은꼴 기법 결합 결과**다. 새 FIFO/25분/웹 수집 실행은 아니다.

CANINE+Unicode는 기존48정탐을 유지했으나 기법 오확정9→20으로 증가했다. **HCX 양성만 넘겨도 실제 문자치환과 광고 안의 정상 표기를 구분하지 못하는 문제가 남는다.** 비광고 영역의 기법 오탐만으로 탈락시킨 결과가 아니다.

KLUE+Unicode는 기존48정탐을 유지하며9개 오확정을 없앴다. 단 개발 자료는 체크포인트 선택에 사용했으므로 합산100%를 독립 일반화 성능으로 주장하지 않는다. 과거 final은 이번 모델 선택에 사용하지 않았지만 프로젝트에서 이미 분석한 회귀자료다.

## 지연과 실제 수집 범위

아래는 개발/과거 final에서 코드 확정12개를 제외한 **각84개 전체 후보 진단**이다. CPU 워밍업 후 원래/역순/원래3회 중앙값이며 tokenization+추론 포함, 모델 로딩·수집·HCX 시간 제외다. HCX 양성만 실행하는 실제 범위의 시간은 별도로 `gated-timing.json`에 기록한다. 네 모델의 실행 순서는 고정되어 장비 부하 차이까지 완전히 통제한 교차실험은 아니다.

KLUE+Unicode는 보조 입력이 늘면서 전체84개 측정에서2.07~2.15배, HCX양성만에서는2.18~2.38배 소요됐다. CPU약2배라는 사전 제한에는 미달이다. 이 차이만으로 연구가치가 없다고 판단하지는 않지만, 결과를 본 뒤 제한을 바꾸거나 운영 채택으로 소급하지 않는다. 절대 추가시간은 이68개에서 중앙값합 약1.91초이며, HCX 시간/모델 상주 로딩/25분 전체 탐지량 영향은 이번에 측정하지 않았다.

실제/복제본 저장80구간은 기존21처리/59보호, KLUE+Unicode20/60, CANINE20/60, CANINE+Unicode19/61이다. 동일512입력길이 보호를 사용했지만 KLUE는 서브워드, CANINE는 문자 단위여서 물리적 본문 허용량은 다르다. CANINE 본체의 최대 길이2048까지 확대하지 않은 보수적인 비교다. 경고가 난 긴 입력은 모델에 전달하지 않았으며 잘린 추론을 정답으로 취급하지 않았다. 긴 문맥 구조 변경 효과와 모델 효과를 섞지 않았다.

정답 알려진 주입기법2개 중 기존/KLUE+Unicode/CANINE+Unicode는1개 확정, CANINE 원문은2개 확정이다. `B3T`는 앞의 세 모델에서 uncertain, `V1D30`는 모두 치환이다. 2개만으로 순위를 뒤집지 않는다. 나머지 미라벨 실사이트 구간을 정상으로 간주해 정밀도를 계산하지 않았다. 모델마다 처리범위가 달라 이80개 지연은 직접 우열 비교하지 않는다.

## 판단과 한계

- **CANINE-S+Unicode 미채택:** HCX 양성 연결에서도 오확정 증가, 기존112개 치환2개 손실, 모호 오확정 증가. 문자 단위 입력의 기대가 이번 학습조건에서 성능으로 이어지지 않았다.
- **KLUE+Unicode 연구 후보 보존:** 기법 정탐을 보존하며 오확정을 줄인 신호는 분명하다. 그러나 긴 수집입력/B3T가 해결되지 않았고 정상 보류 증가·CPU 증가·독립검증 부재가 남는다. 새 모델을 더 찾기보다 이 보조 근거의 기여를 독립 자료에서 검증할 가치가 있다.
- 같은 생성자의320학습/반복형식, train deposit/final depositary 관련 어휘 한계 유지. KLUE+Unicode는 epoch1 개발macro100%→epoch2 71.11%로 회귀했다. 형식 과적합 우려를 작업 중 즉시 보고했다. 오류 문장을 재학습하거나 새최종을 점수 맞출 때까지 생성하지 않았다.
- 사전 확대 조건은 세 후보 모두 미통과. 이번 비교를 종료하고 **기존 운영 HCX+코드를 유지**한다. 새 독립평가 및25분 운영 검증은 실시하지 않았고 운영승격도 없다.
