# FIFO·Bandit 실제 판정 및 경로 연속 탐색 비교

2026-09-23. A·B 실제 판정과 최종 검사를 완료했다. **Bandit은 유망한 비교 후보로 남기되 기본 채택은 보류하고, 이번 경로 연속 탐색안은 미채택한다.** 운영 FIFO·수집기·프롬프트는 변경하지 않았다.

## 고정 조건

- 기존 v4의 dev-101(127페이지), confirmation-201(135페이지)을 각각 50페이지 예산으로 비교했다. 사이트당 광고 24·정상 168개 정답 위치다. 미방문 광고도 FN이다.
- 실제 운영 수집기로 전체 262페이지/2,316후보를 먼저 수집했다. 각 사이트의 정답 192개가 모두 정확한 원문·위치로 수집됐다. 수집 시간은 153.82초와 163.21초였다.
- 이후 모든 정책은 동일한 증거 캐시를 사용했다. 스케줄러에는 방문한 페이지의 정보만 전달했다. 가상 호스트→loopback 주소 변경 전후의 FIFO/Bandit 순서를 확인했다.
- HCX-007, temperature 0, reasoning none, seed 42, 출력 상한 3072, 배치 16, 순차 호출, 동일 TPM 설정과 프롬프트를 유지했다. 조건마다 실제 API를 새로 호출하고 마지막 잔여 배치도 판정했다.
- 측정 시간은 캐시에서 정책을 실행하고 실제 판정한 시간이다. 실제 기관의 HTTP·브라우저 탐색을 포함하는 종단 지연으로 해석하지 않는다.
- 각 조건의 completed는 예정한 50페이지 후보 판정을 마쳤다는 뜻이다. 사이트 전체 탐색 완료를 의미하지 않는다.
- 개발 FIFO→Bandit, 확인 Bandit→FIFO 순서로 실행했다. 기존 자료를 사용한 단회 진단이며 새 홀드아웃 또는 통계적 일반화 검증이 아니다.

## A. 탐색 정책만 변경

### 의미 판정

| 자료 | 정책 | TP/FP/FN | 정밀도 | 재현율 | F1 |
|---|---|---|---:|---:|---:|
| 개발 | FIFO | 8/5/16 | 61.54% | 33.33% | 43.24% |
| 개발 | Bandit | 8/0/16 | 100% | 33.33% | 50.00% |
| 확인 | FIFO | 8/1/16 | 88.89% | 33.33% | 48.48% |
| 확인 | Bandit | 8/0/16 | 100% | 33.33% | 50.00% |
| 합산 | FIFO | 16/6/32 | 72.73% | 33.33% | 45.71% |
| 합산 | Bandit | 16/0/32 | 100% | 33.33% | 50.00% |

### 요소×기법 최종 판정과 비용

| 자료 | 정책 | TP/FP/FN | 최종 F1 | 호출 | 토큰 | 판정 시간 |
|---|---|---|---:|---:|---:|---:|
| 개발 | FIFO | 7/5/17 | 38.89% | 28 | 180,015 | 440.66초 |
| 개발 | Bandit | 8/0/16 | 50.00% | 27 | 177,475 | 424.12초 |
| 확인 | FIFO | 8/1/16 | 48.48% | 29 | 189,120 | 458.65초 |
| 확인 | Bandit | 8/0/16 | 50.00% | 29 | 188,308 | 456.51초 |
| 합산 | FIFO | 15/6/33 | 43.48% | 57 | 369,135 | 899.31초 |
| 합산 | Bandit | 16/0/32 | 50.00% | 56 | 365,783 | 880.63초 |

Bandit은 합산 최종 F1 +6.52%p, 토큰 -0.91%, 판정 시간 -2.08%다. 두 조건이 방문한 광고는 모두 각 사이트 8개이고 방문 광고의 의미 판정은 모두 맞았다. 사이트 전체 FN은 대부분 미방문으로 발생한다. 단, 두 정책이 방문한 광고의 집합이 같다는 뜻은 아니다.

### 개선과 손실을 분리

1. 개발 Bandit은 FIFO가 찾은 **일반 안내 광고 1개를 미방문**했고, 이용자 게시판 광고 1개를 새로 찾았다. 기존 정탐 위치 보존 관문을 실패했다. 확인에는 기존 정탐 손실이 없었다.
2. FIFO의 정상 오탐 6개는 Bandit도 방문했다. 개발의 5개는 후보 입력이 완전히 같았고 배치가 달랐으며, Bandit이 예방 인용 등으로 정상 확정했다. 확인의 1개도 정상 확정됐다. 검토로 돌려 FP를 숨긴 것은 아니지만, 이 변화가 배치 구성 때문인지 모델 변동 때문인지 단회 비교로 분리할 수 없다.
3. 개발 FIFO의 광고 1개는 의미 판정은 맞았지만 기법이 누락됐다. Bandit 조건에서는 기법도 맞았다. 따라서 최종 TP 1개 증가는 추가 광고 URL 발견만으로 설명되지 않는다.
4. needs_review 후보는 개발 FIFO 42/Bandit 38, 확인 FIFO 39/Bandit 67이다. 합산 **81→105개**로 검토 부담이 늘었다. 정답 정상 위치의 검토는 합산 5→10개이며 나머지는 메뉴 등 정답 표시 밖 후보다.
5. 정답 표시 밖의 확정 양성은 없었다. 보수적으로 이들을 FP로 넣는 별도 지표도 현재 표와 같다. 방문 페이지의 정답 텍스트 수집 누락은 없었다.

**A 판단:** 사전 관문 중 F1/정밀도/FP/비용은 통과했지만 기존 정탐 보존을 실패했다. Bandit의 수치상 이득은 인정하되 기본 운영 정책 채택은 보류한다. FIFO가 더 우수하다는 결론은 아니다. 순수한 탐색 개선과 판정 변동을 구분해야 한다.

## B. 제한된 경로 연속 탐색

기존 Bandit은 수정하지 않고 `navigation-path.cjs`에 분리했다. 매 10회 중 첫 슬롯에 가장 오래된 content_scope=false 대기 URL을 선택하고, 뒤의 2슬롯은 직전 페이지가 상세 본문이 아닌 경우 새로 발견한 링크를 이어 간다. 없으면 원래 선택으로 복귀한다. 매 5번째 FIFO는 유지한다. 특정 깊이·문구·URL·정답을 점수에 쓰지 않는다.

### 오프라인 결과

기존 6사이트 × 5순서, 다음 표는 분할별 15회 평균이다.

| 자료 | 예산 | 전체 광고 도달 변화 | 깊은 광고 도달 변화 |
|---|---:|---:|---:|
| 개발 | 20 | -1.39%p | 0%p |
| 개발 | 50 | -1.67%p | +4.17%p |
| 개발 | 100 | +1.39%p | +20.83%p |
| 확인 | 20 | -0.83%p | 0%p |
| 확인 | 50 | 0%p | 0%p |
| 확인 | 100 | -1.11%p | +11.67%p |

50요청의 깊은 광고 +5%p 기준을 어느 분할에서도 충족하지 못했다. 큰 예산에서 일부 깊은 영역 이득이 있지만 전체 광고 도달의 일관된 개선은 아니다. 결과를 보고 비율을 변경하지 않았다.

- 원래 4정책의 전체 방문 기록 120회 재현.
- 연속 탐색을 끈 구현이 기존 Bandit 30회 전체 순서와 일치.
- 20/50/100 요청 접두부 90개 일치, 전체 방문 집합 보존.
- 폭·깊이·순환·공유 링크·정상 막다른 경로를 달리한 3구조 × 5순서의 기능 검사 15회 통과. 이 검사는 새 광고 정확도 홀드아웃이 아니다.

### 실제 HCX 결과

| 자료 | 의미 TP/FP/FN | 의미 F1 | 최종 TP/FP/FN | 최종 F1 | 호출 | 토큰 | 판정 시간 |
|---|---|---:|---|---:|---:|---:|---:|
| 개발 | 8/1/16 | 48.48% | 7/1/17 | 43.75% | 28 | 179,624 | 428.22초 |
| 확인 | 10/1/14 | 57.14% | 10/1/14 | 57.14% | 28 | 182,694 | 441.31초 |
| 합산 | 18/2/30 | 52.94% | 17/2/31 | 50.75% | 56 | 362,318 | 869.53초 |

합산 의미 정밀도/재현율은 90.00%/37.50%, 최종 기법 정밀도/재현율은 89.47%/35.42%다. Bandit 대비 합산 최종 F1은 +0.75%p, 토큰 -0.95%, 시간 -1.26%다. needs_review는 개발 47·확인 41, 합산 88개다. 정답 정상 위치의 검토는 8+6=14개다. 정답 밖 확정 양성과 방문 페이지의 정답 수집 누락은 없었다.

- 개발에서는 같은 광고 8개를 방문했고 의미 정탐 위치는 보존했다. 그러나 이미 방문하던 정상 관리자 영역에서 오탐 1개가 생겼고 기존 JAMO 기법 정탐 1개를 잃었다. 최종 F1은 50.00%→43.75%로 하락했다.
- 확인에서는 이용자 게시판의 광고 2개를 추가 방문·탐지했다. 추가 방문한 정상 이용자 글에서도 오탐 1개가 생겼다. 기존 의미·기법 정탐은 보존했다.
- 두 사이트 모두 깊은 광고 도달은 여전히 0/8이다. 확인의 추가 탐지는 깊은 영역 해결의 증거가 아니다.

**B 판단:** 합산 이득은 있지만 개발 비회귀, 정밀도, 기존 기법 정탐 보존, 합산 +2%p, 오프라인 깊은 영역 +5%p 기준을 실패했다. 이번 구현은 미채택하며 비율을 조정해 같은 자료에 다시 맞추지 않는다.

## 최종 검증과 판단

6개 조건 모두 완료했고 169회 호출은 전부 HTTP 200, 확인된 사용량은 1,097,236토큰이다. 고정 소스·입력 manifest 27개 항목과 별도 채점/경로 소스 해시가 일치했다. 공통 프롬프트·추론 설정도 일치했다. 공통 후보의 모델 입력은 다음 비교에서 모두 동일했다.

| 비교 | 자료 | 동일 입력 후보 | 판정 signature 변화 | 광고 확정 여부 변화 |
|---|---|---:|---:|---:|
| FIFO→Bandit | 개발 | 373 | 58 | 5 |
| FIFO→Bandit | 확인 | 421 | 79 | 1 |
| Bandit→경로 연속 | 개발 | 421 | 59 | 1 |
| Bandit→경로 연속 | 확인 | 390 | 87 | 0 |

signature는 광고·검토·기법·관찰 기법의 조합이며 설명 문구 차이는 제외했다. 이 변화 수를 모두 오판 수로 해석하지 않는다. 후보 하나의 입력이 같아도 함께 보내는 후보와 배치 순서는 달라진다. 따라서 배치 영향과 모델 자체 변동을 분리한 증거는 아니다.

현재 근거로 **운영 FIFO 유지, Bandit 채택 보류, 경로 연속안 미채택**이 타당하다. FIFO의 우월성을 입증한 것이 아니라 사전 안전성 조건을 만족하는 대체안이 아직 없다는 뜻이다. 다음 유료 실험을 한다면 새 알고리즘을 더 쌓기보다, 동일 요청 본문 반복과 배치 구성만 변경한 대조를 제한된 표본에서 비교해 판정 변동을 먼저 분리할 가치가 있다. 이후 구조가 다른 미사용 사이트에서 고정된 정책을 확인한다. 이번 자료로 그룹·경로 비율을 재조정하는 실험은 권하지 않는다.

사용자가 제안한 입력 URL 범위 제한은 탐색 순서와 별개의 변경이다. 게시판 URL 입력 시 해당 게시판의 목록·상세·댓글·페이지 이동을 유지하고 메인/타 게시판 이탈을 막는 방향은 타당하다. 다만 `/board/list?board=free`와 `/board/view?board=free&id=123`처럼 상세 경로가 달라질 수 있으므로 pathname 접두부만으로 제한하지 않는다. 현재 수집기는 기본적으로 첫 경로 구간을 범위로 사용하며 게시판의 의미적 경계를 보장하지 않는다. 동일 정규 URL 재방문은 막지만 무한히 다른 쿼리 URL까지 해결한 것은 아니다. 이번에는 범위를 바꾸지 않았고 별도 검증 대상으로 남겼다.

## 통신 장애와 재실행

v1 첫 조건은 32/436후보 뒤 ECONNRESET, 제한적 재시도에서 ENOTFOUND로 중단됐다. 2회 성공의 12,280토큰을 확인했고, 응답 없는 2시도는 20,356토큰의 예약량을 예산에 남겼다. 서버 처리·실제 청구 여부는 미확인이다.

DNS와 TCP 443 복구 확인 뒤 `navigation-live-recovery.md`를 먼저 기록하고, v1을 보존한 채 v2에서 동일 조건 전체를 새로 실행했다. 일부 응답을 재사용하지 않았다. 실패·복구 비용은 성공 조건의 비교 시간과 구분하며 전체 사용량에 포함한다. v1 첫 32개와 v2 첫 32개는 동일 요청 본문이며 판정 signature 변화가 없었지만, 이 작은 부분 검사는 전체 모델 안정성을 입증하지 않는다.

v1 포함 전체 시도는 173회, 확인된 사용량은 1,109,516토큰이다. 응답 없는 2시도의 예약량을 포함한 예산 집계는 1,129,872토큰으로 사전 상한 내다. 이는 정확한 청구 토큰이나 원화 금액이 아니다.

예정한 최종 채점 외에 개발의 완성된 조건을 중간 점검하여 오류를 사용자에게 알렸다. 이는 계획의 ‘모든 실행 종료 후 채점’ 표현과 다른 모니터링 순서다. 정답이 스케줄러·모델 입력에 들어가거나 정책/채택 기준을 수정하는 데 사용되지는 않았다. 정책 B의 규칙은 실행 전 계획대로 고정하고 A 쌍 결과 확인 전에 소스 해시도 기록했다.

## 한계와 재현

262페이지는 같은 제작자의 기존 합성 자료이며, 사이트당 광고 문구·DOM 변형의 다양성은 제한적이다. 3개 구조 기능 검사와 링크 순서 변경을 실사이트 일반화 검증으로 해석하지 않는다. 결과에 맞춰 경로 비율·그룹·문구 점수를 조정하면 과적합 위험이 있다. 2·3단계 의미·기법 미해결 문제도 그대로 남는다.

```powershell
node agent/experiments/navigation-live.cjs prepare .runtime/navigation-live-new
node agent/experiments/navigation-live.cjs a .runtime/navigation-live-new
node agent/experiments/navigation-path.test.cjs .runtime/navigation-path-offline-new
node agent/experiments/navigation-live.cjs b .runtime/navigation-live-new
node agent/experiments/navigation-live-score.cjs .runtime/navigation-live-new fifo bandit
node agent/experiments/navigation-live-score.cjs .runtime/navigation-live-new bandit bandit-path
```

`a`, `b`는 실제 API를 호출한다. 원본 증거·실패 기록은 `.runtime/navigation-live-v1`, 완성 비교와 사용량은 `.runtime/navigation-live-v2`, 경로 오프라인 기록은 `.runtime/navigation-path-offline-v1`에 저장했다.

이번 실행의 사전 해시를 포함한 최종 검사는 `node agent/experiments/navigation-live-audit.cjs .runtime/navigation-live-v2`로 재현한다. 새 실행에서는 채점·경로 소스의 사전 해시 기록도 별도로 준비해야 한다.
