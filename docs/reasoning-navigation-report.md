## 탐색 비교 — FIFO 유지

고정한 문맥 Bandit과 FIFO를 기존 8개 합성 사이트 × 링크 순서5개 × 정책2개로 총80회 비교했다. 대형 사이트의 786개 HTML에서 출처 링크 문맥을 다시 추출했고 과거 저장 링크·detail·본문 fingerprint가 동일함을 검증했다. 타깃 페이지 문맥이나 정답을 링크에 미리 전달하지 않았다. 80회 직렬화 재개 순서와 240회 예산 접두부 검사, 전체 방문 집합·중복 검사를 통과했다. HCX 호출0회다.

아래는 **광고 위치 도달률**이며 광고 판정 F1이 아니다. 각 분할은 같은24개 또는12개 광고 위치의 링크 순서를 반복한 평균이며 독립 정답 사례 수가 늘어난 것이 아니다.

| 확인 대형 / 100 | 63.06% | 71.39% | +8.33%p |

사이트별 링크순서 평균 도달률 비감소와 깊은 광고 도달 비감소는 통과했다. 그러나 주요 예산의 기존 FIFO 광고 위치 보존은 개발50페이지 15회 중1회(손실1), 확인50페이지 15회 중10회(반복 합산 손실20, 최대3), 소형18페이지 10회 중1회(손실2)에서 실패했다. 확인 분할50페이지 평균 증가폭도 사전 +5%p 기준보다 낮다. 따라서 추가 유료 판정 관문은 **미통과**다. 소수점 이진 표현상 개발 증가폭은0.04999999999999999이나 수학적으로5%p이며, 확인 분할과 위치 보존 실패로 결론은 동일하다.

### 깊은 영역과 발견 병목

대형50페이지에서 깊은 광고 도달률은 개발0→0%, 확인0→3.33%다. 100페이지에서는 개발5.83→15.83%, 확인0→35.83%로 개선되어 깊은 발견 효과가 전혀 없다고 할 수는 없다. 다만 작은 예산에서는 충분하지 않다.

50페이지에서 미방문 광고 중 발견 후 대기는 개발 평균4.40→0.80개, 확인5.20→2.00개로 줄었다. 반면 주소 자체를 아직 발견하지 못한 광고는 개발12.00→14.40개, 확인12.47→14.67개로 늘었다. 이미 보이는 유망 링크를 먼저 방문하면서 일부 다른 영역의 경유 페이지가 늦어지는 상충관계다. 단순한 선택 계산 속도 문제가 아니다.

CPU 스케줄러 시간은 대형 전체 순회 평균 FIFO 약7~9ms, 문맥 Bandit 약108~120ms다. 이는 브라우저/네트워크/LLM을 뺀 오프라인 비용이며 실무 종단 지연으로 해석하지 않는다.

### 기존 결과와 종합

과거 소형2사이트 실제 HCX 비교에서 문맥 Bandit의 합산 F1은58.82%, FIFO40.00%였으며 수치 관문은 통과했다. 그러나 해당 자료는 광고24페이지 전부detail=true, 비광고31페이지 전부false로 보상 구조와 정답이 완전히 일치했다. 이번 대형 자료는 사이트당 정상72페이지도detail=true여서 이 상관관계가 약하지만, 광고는 여전히24페이지 모두detail=true다. 비detail 광고까지 포함한 새로운 일반화 검증은 아니다.

이번 확인 분할도 과거에 분석한 합성 자료다. `confirmation`이라는 이름을 새 홀드아웃의 증거로 사용하지 않는다. 평균 도달 이득은 확인됐지만 보존 관문과 확대 효과 관문이 실패했으므로 **운영 FIFO 유지, 문맥 Bandit은 실험 후보 보존**으로 결정한다. FIFO가 모든 목표에 최적이라는 결론은 아니다. 가중치 조정·상위 탐색 구조 추가·결과 맞춤 튜닝은 하지 않았다.

## 추론 비교 — 운영 채택 보류, 효과 미확인

단일 대상30개(광고12·정상16·근거부족2), none/medium 각3회. 양쪽 provider Structured Outputs를 끄고 기존 direct3분류 계약·동일 JSON 지시·로컬 검증을 사용한다. 초기 v1의429를 성능 비교에서 제외하고 전체 예약량을61초 유지하도록 실행 제어만 보정했다. v1 원본과 실패/비용을 별도 보존한다. v2의 출력 형식 오류도 실패로 보존하며 복구 호출을 하지 않는다.

v2는29시도/HTTP200 26개를 받았으며 마지막3시도는 fetch failed로 응답 상태·usage를 확인하지 못했다. 이3개를 광고 판정 오답이라고 보지 않는다. 사후 DNS 해석과TCP443 연결은 성공했지만, 당시 Node fetch 실패의 원인은 확인하지 못했다. 미확인 요청을 자동 재호출하지 않았다. 사전 연속 실패 중단 규칙을 지키고 다른 강도/프롬프트로 재탐색하지 않았다.

아래 표는 **양쪽 HTTP200을 받은 첫13개 동일 사례(광고7·정상6)의 최초 응답**만 집계했다. 운영 전체 F1이나30개 전체 성적이 아니다. 미시도 사례를 FN으로 세거나 아직 없는 반복 결과를 안정성0%로 해석하지 않는다. 최종 부분 집계는 `paired-audit.json`을 기준으로 한다. `reasoning-summary.json`은 완주 관문을 포함한 원시 실행 요약이며 미완주 행의 수치를 전체 성능으로 인용하지 않는다.

medium의4건은 완결 JSON 코드 블록 뒤에 추가 설명을 붙였다. 기존 로컬 검증은 응답 전체가JSON 또는JSON 코드 블록일 때만 허용한다. 광고2건과 정상2건이 이 계약에서 실패했으며, 성공적으로 검증된9건은 정답이었다. 따라서 위 FN2를 모델의 광고 의도 이해 실패라고 단정하지 않는다. 형식 복구 호출과 임의 JSON 발췌를 적용해 성공으로 바꾸지 않았다. 내용과 형식을 모두 요구하는 현재 설정 묶음의 연동 실패다.

같은13쌍에서 medium은 토큰 약2.15배, 순수 응답시간 약10.59배다. 추론 토큰을 포함한 실제usage이며 개별 thinkingContent는 저장하지 않았다. 요청 순서·TPM 대기가 조건별로 비대칭이므로 대기 포함 시간을 모델의 순수 지연 비교로 사용하지 않는다. v2 전체 경과는442.26초, 공통 대기 합계는별도 budget/paired-audit에 보존했다.

첫 반복의 앞부분에서 끝나 예방 인용·메타데이터 귀속·근거 부족 2개는 공통 응답 평가에 포함되지 못했다. 기존 직접 광고 정탐 4개의 보존, 동일 사례 3회 판정 변경률, 새 자료 일반화도 미검증이다. 단일 대상 direct 계약이 운영 프롬프트와 다르므로 none의 부분 100%를 운영 성능으로 주장하지 않는다. low/high와 다른 모델은 이번 비교 대상이 아니다.

**채택 판단:** medium의 개선 효과를 확정할 수 없으며 현재 엄격한 출력 계약·지연 관문도 통과하지 못했다. none을 유지한다. 조건부 후속인 새 자료·FIFO 16개 배치·동일 시간 예산 실험은 선행 관문 미통과로 시행하지 않았다. 효과 없음과 검증 미완료는 구분한다.
