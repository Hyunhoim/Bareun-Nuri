# 수집 동시2/3/4/5 비교 사전 계획

2026-09-30. 사용자 요청으로 동시3~5를 비교한다. 기존 동시2도 새로 측정하며 이전 수치와 새 수치를 직접 섞지 않는다. API0/외부 기관 요청0/운영 변경0. Katana/Crawlee는 추가 실행하지 않는다.

- 가설: context 동시 수 증가가 대기를 겹쳐 속도를 더 높일 수 있으나 CPU·메모리 경쟁, DOM 준비 지연, 근거 누락이 생길 수 있다. 최고 숫자를 기본값으로 정하지 않는다.
- 기준선 fifo2, 후보 fifo3/4/5. 기존 수집기·원문·문맥·스타일·좌표·iframe·기법 관찰·대기조건·FIFO dispatch/반영 순서를 고정한다.
- 각 조건을 **새 Node 프로세스**에서 실행해 이전 조건의 heap/GC 잔존을 줄인다. 브라우저 시작/종료와 근거 파일 저장을 포함한다. 프로세스 실행 준비와 자원 측정기 종료 시간은 따로 기록한다. 이전 실험과 프로세스 구성 차이가 있으므로 속도·RAM은 이번 기준선과 비교한다.
- 고정 URL: 기존 합성27페이지, 동작8페이지, 부산 실제 DOM 복제본20페이지. 4조건×3자료×3회=36실행. 실행당600초 안전 상한.
- 탐색: 기존 mixed-0/1, 동일20초·최대40페이지. 4조건×2사이트×3회=24실행. 도중 모든 URL을 수집하면 조기 완료한다. 조건 순서는 자료/회차에 따라 순환하며 사전 고정한다.
- 비교60실행과 mixed-1 전체28페이지의 동시2 참조 수집1회를 별도로 수행한다(총61). 참조 수집은 속도 통계에 섞지 않으며20초 이후 새로 도달한 페이지의 근거 대조에 사용한다. 전체1시간 안전 상한. 원래 클릭·6초 지연 댓글 미수집은 별도 기록한다. 합성/기존 회귀이며 새 독립 홀드아웃으로 보고하지 않는다.
- 후속 후보 기준: 고정 URL 근거 손실/변형0·신규실패0, 각 자료3회 중2회 이상 동시2보다 빠름, 자료군별 중앙값 합10% 이상 단축, 자료별 중앙값5% 초과 악화 없음. 20초에서 기존 광고 위치 손실0. 새로운 페이지의 근거도 고정 URL 전체 수집 결과와 대조한다.
- 여러 후보가 통과하면 중앙값 합이 최저인 후보 대비5% 이내인 **가장 작은 동시 수**를 후속 후보로 권고한다. 결과에 맞춰 기준/대기조건을 바꾸지 않는다. 근거 회귀는 즉시 알리고 채택 근거로 사용하지 않는다.
- working-set 합은 공유 메모리 중복 가능성을 명시한다. 새 프로세스의 본 수집기·브라우저·측정기만 포함하고 부모 fixture 서버는 제외한다. CPU 누적 생존 프로세스 표본을 총CPU 비용으로 변환하지 않는다.
- 원본·방문/취소·대기·메모리·소스 해시를 저장한다. 운영 저장/재개·실사이트·25분 HCX 종단 검증 없이 기본 동시 수를 변경하지 않는다.
