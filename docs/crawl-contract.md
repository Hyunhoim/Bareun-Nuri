원문·위치·문맥·관찰 근거는 불변 페이지 파일에, 판정은 완료 배치 파일에 저장한다. 체크포인트는 파일 해시·진행 위치·탐색 대기열·요청 상태를 보존하며 판정용 근거 캐시는 최대2페이지다. 동시 수집 중 snapshot 최대5개는 별도이며, 수집 시작 전 판정 캐시를 비우고 저장 후 snapshot 참조를 놓는다. 대기 URL이 없어도 미판정 페이지가 남으면 재개 대상이다. 현재 코드/설정과 다른 체크포인트 및 미확인 전송의 재개를 거부할 때 기존 결과·구간 파일은 변경하지 않는다. 기존 파일 자동 이행이나 미확인 요청 재전송은 하지 않는다. 새 저장·배분의 실험 결과와 한계는 `goal-throughput-report.md`를 따른다. 이전의 미판정16개 시작 기준은 과거 실행 구조다.

DOM·스타일·문자의 관찰 근거는 원래 요소에 저장하고 장문 구간의 의미 판정을 합친 뒤 통합한다. 관찰만으로 광고 의도를 바꾸지 않는다. 숫자 치환·부분 스타일·구형 근거의 미확정은 별도 검토에 남긴다. Mock은 기존 계약을 유지한다. 코드·계약이 달라진 과거 체크포인트를 자동 이행하지 않는다. 채택 근거·오탐·시간/호출 증가·대형 사이트 한계는 `semantic-search-report.md`를 따른다. 아래 과거 비교의16개 요청 설정은 현재 운영값이 아니다.

## 실험 운영 고정 규칙 (2026-09-25 사용자 확정)

아래 구분은 앞으로의 개선 작업에 필수 적용한다. 구체적인 자료·예산·채택 기준은 실행 전에 정하며 결과를 본 뒤 완화하지 않는다. 진단 실험을 매번 25분으로 자를 필요는 없지만, 최종 운영 채택은 반드시 25분 제출 조건의 비교를 통과해야 한다. 개별 사례 정확도가 높아져도 지연 증가로 전체 정탐 수가 줄면 그 정확도 상승만으로 채택하지 않는다.

- 원인 진단: 동일한 소규모 페이지/저장 근거를 끝까지 비교한다. 수집 수정은 동일 URL·DOM 대상의 원문/위치/문맥/스타일 보존, 판정 수정은 동일 저장 입력의 정밀도·재현율·F1을 측정한다. 시간·호출·토큰 상한은 사전 고정하고, 상한으로 미완주하면 전체 완료 성능으로 보고하지 않는다. 기존 최대 1시간은 진단용 안전 상한일 뿐 기본 실행 목표가 아니다.
- 제출 모의: 유망한 변경만 동일 사이트·FIFO·모델 설정의 25분 구간으로 비교한다. 누적 후보 수로 조기 종료하지 않고, 실제 30분 이내 결과 저장·종료를 검증한다. 전체 정답 기준에서 미방문·미판정 광고도 FN에 포함하며 완료 판정 수, 정탐/오탐, 미검사 범위, 호출/토큰/시간/메모리를 함께 보고한다.
- 재개 검증: 먼저 로컬/Mock의 짧은 제한으로 저장·종료·재개를 강제해 연속 실행과 작업 순서·결과·중복 호출을 비교한다. 이어서 실제 25분 경계 동작을 확인한다. 실제 LLM 재호출의 판정 변동과 실행 제어 오류는 구분한다. 첫 구간 점수와 재개 후 누적 점수는 별도로 보고한다.
- 기존 자료는 회귀·진단용으로 사용하고 별도 평가 자료와 구분한다. 한 번에 하나의 변경만 비교하며, 제출 방식의 변경 자체를 수집/의미 판정 일반화 개선으로 주장하지 않는다.

## 변경 전 고정한 얕은 비교 (과거 실험 기록)

- 기존 2사이트 50페이지 실제 실험은 과거 근거로 유지한다. 기존 Bandit은 정탐 위치 1개 손실, 경로 연속은 정상 오탐과 기법 회귀로 미채택이었다.
- 새 혼합 구조 2개를 코드와 함께 고정하고 각 24~36페이지, 같은 페이지 예산 12로 FIFO/Bandit/Bandit+경로 연속을 비교한다. 게시판 밖 글·별도 경로 상세·댓글·동일/외부/중첩 프레임·순환 및 페이지 이동을 포함한다. 정답은 탐색기·LLM에 전달하지 않는다.
- 운영 수집기로 증거를 고정한 뒤 같은 실행기에서 실제 HCX-007을 조건별 새 호출한다. 온도 0, seed 42, reasoning none, 16개 배치, 출력 3072, 순차·TPM 52000. 마지막 잔여 배치도 판정한다. 페이지별 브라우저 수집 시간과 캐시 기반 정책+실제 판정 시간을 분리한다.
- 실행 순서는 첫 사이트 FIFO→Bandit→경로, 두 번째 경로→Bandit→FIFO. 조건당 20시도/600초, 전체 120시도/800,000토큰(미응답 요청은 예약 포함). 형식/네트워크 자동 재시도는 기존 제한 내만 허용하고 실험 실패 시 반복 재실행하지 않는다.
- 각 사이트 전체 정답을 분모로 미방문 FN을 포함한다. 의미 P/R/F1, 위치×기법 F1, 기존 정탐 손실, 깊은 영역·프레임 도달, 정답 밖 양성(보수적 FP), 검토 수·호출·토큰·시간을 비교한다.
- 채택: 각 사이트 의미/최종 F1 비감소, 정밀도 하락 2%p 이내, FP 증가 최대 1, 기존 의미·기법 정탐 손실 0, 합산 최종 F1 +2%p, 합산 토큰/시간 증가 15% 이내. 구조 계약 검사를 모두 통과해야 한다. 복수 통과 시 최종 F1, 정밀도, 지연, 단순성 순으로 판단한다. 미통과하면 FIFO를 채택 기준선으로 유지한다. 사후 기준 완화·가중치 튜닝은 하지 않는다.
- 새 사이트도 동일 제작자의 합성 진단이다. 내용 재사용·구조 유사성·단회 모델 변동을 공개하며 실사이트 일반화나 독립 홀드아웃 성능으로 주장하지 않는다.

### 호출 예산 후속 채택 (2026-09-25)

## 현재 판정 실행 계약 (2026-10-01)

사용자 지시로 HCX 최대12후보 묶음을 최대3요청 동시에 실행한다. 공유58k TPM·1초 발송 간격·25분 예산을 적용하며 AntiSpoof는 직렬이다. 요청별 상태와 완료 결과를 저장하고 기존 순서대로 반영한다. 확정 저장 결과는 재사용하되 미확인 전송은 자동 재호출하지 않는다. 백엔드는 prepared/rejected/durable 요청만 남은 wave의 재개를 허용하고 worker가 서명·무결성·저장 근거를 추가 검증한다. 과거 순차 및 실험용 서명의 자동 이행은 거부한다. 아래 순차 판정 설명은 당시 기록이다. `parallel3-adoption-latency.md` 및 `phase1-parallel25-report.md` 참고.
