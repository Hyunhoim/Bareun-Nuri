# HCX-007 의미 판정 개선 탐색 — 2026-09-25

사용자는 병렬·점진 실험과 F1 중심의 실용적 채택 판단을 요청했다. 과거의 모든 지표 동시 통과/기존 광고 손실 0/비용 증가 20% 절대 관문은 이번 비교에 그대로 적용하지 않는다. 변경 기준은 결과를 보기 전에 이 문서에 고정한다.

## 원인과 비교

- 관측: 대상에 속한 예방 설명을 전달해도 인용을 광고로 판정했다. 원문 응답 감사에서는 근거 부족 후보에 다른 후보의 광고 문장이 전이된 사례도 있다.
- 가설: 문맥의 발화 귀속을 적용하지 못함, 중복된 스타일·주변 입력에 의한 주의 분산, 배치 간 근거 혼동. 어느 것도 단일 원인으로 확정하지 않는다.
- 첫 라운드: 운영 O, 직전 의미 전용 S, S+귀속 지침(scope), scope+간결한 순서 문맥(compact), compact+별도 대조 예시(contrast), S의 배치4(S4). 기본 배치16·HCX-007 none·온도0·seed42·출력3072는 고정한다.
- 개발 자료: 이미 관찰한64개. 최고의 단순 후보 1개만 새80개 독립 작성 합성 자료와 기존76개에서 확인한다. 새 자료 작성자는 후보 프롬프트와 개발 오류 문구를 보지 않는다. 동일 프로젝트의 합성 자료이므로 실사이트 일반화까지 증명하지 않는다.
- 필요하면 선별된 프롬프트의 배치4를 한 번만 추가 비교한다. 더 작은 배치, 복수 투표, 재판정 단계는 관측된 오염/변동 개선 이득이 비용을 정당화할 때만 후속 후보로 둔다. 새 평가 결과를 보고 같은 자료에 맞춘 문구 수정은 하지 않는다.

## F1 중심 선택

1. 광고/정상 확정 라벨의 F1·정밀도·재현율을 주 지표로 한다. 근거 부족 라벨은 별도3분류 지표로 보고 이진 F1 분모에서 제외한다. 보류된 광고는 FN이며 정상 보류는 오탐 감소와 별도로 보고한다.
2. 개발 F1 순위로 후보를 선별한다. 1%p 이내 차이면 적은 호출·토큰, 단순한 계약을 우선한다. 의미 F1 개선이 없으면 배치4 원인 분리를 한 번 확인한 뒤 중단한다.
3. 새로운80개는 두 번(정순/고정 섞기) 실행한다. 평균 F1 개선 ≥3%p, 두 실행 모두 개선 방향, 기존76개 F1 감소 ≤2%p를 의미 판정 채택 근거로 삼는다. 기존 TP 손실·FP 증감·불확실 판단·분류별 성능은 숨기지 않는다. 손실 0을 절대 조건으로 두지 않는다.
4. 비용/지연은 의미 개선과 함께 비교한다. 비용2배 초과 후보는 더 단순한 후보 대비 추가 이득이 명확하지 않으면 제외한다. 2배 이하도 자동 채택하지 않는다. 병렬 경쟁 대기는 모델 지연으로 혼용하지 않고 HTTP 서비스 시간과 공유 큐 대기를 분리한다.
5. 유망한 의미 후보는 같은 FIFO/수집기/25분 상한의 실제 수집→판정으로 비교한다. 조기 완료는 그대로 종료한다. 전체 정답 기준 미수집·미판정도 FN으로 집계한다. 기법 관찰은 별도 지표이며 의미 개선으로 덮지 않는다. 최종 운영 연결은 입출력·근거·재개 계약을 보존한 경우에만 한다.

## 예산과 보존

- 선별: 최대40요청/650,000예약토큰/1시간. 후속 확인: 최대80요청/850,000예약토큰/1시간. 후속확인시작전선택후보가4개배치임에따라새80개2회50요청+기존76개24요청=74요청을완주할수있게60요청초안을보정했다. 모델응답/채택기준을보고바꾼예산이아니다. 운영 비교는 선행 결과 후 별도 수량·소스·입력 해시를 고정한다. 상한은 실행 목표가 아니다.
- 준비·자료 작성·감사는 병렬화하고, 실제 HCX 요청은 최대2개 및 공통48,000 TPM 예약으로 제한한다. 후보 간 부하 경쟁 때문에 공유 실행 벽시계를 단일 운영 지연으로 표시하지 않는다.
- 요청·원본 응답·부분 결과·해시 보존. 미확인 전송 자동 재시도 금지. 출력 계약 실패는 실패로 기록하고 점수가 없는 조건을 성공으로 취급하지 않는다. 키는 로그에 기록하지 않는다.
- 새로 관찰한 자료는 다음 라운드부터 진단 자료다. 즉석 반복은 개발 자료에서만 하고, 프롬프트 수정은 새 독립 검증을 요구한다.

## 방법 선정의 외부 근거

문맥 위치에 따라 정보 활용 성능이 달라진다는 연구는 입력 정리 실험의 근거이며 HCX-007 개선을 보장하지 않는다: [Lost in the Middle](https://arxiv.org/abs/2307.03172). 간결하고 필요한 문맥/예시를 구성하는 접근은 [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)도 설명한다. 모델·과제가 다르므로 이번 실제 비교로 검증한다. RAG·파인튜닝·무제한 자기반성은 현재 병목과 독립 정답 데이터 규모상 우선 시행하지 않는다.
