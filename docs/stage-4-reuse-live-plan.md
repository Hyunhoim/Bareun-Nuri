# 4단계 반복 판정 절감 — 제한적 실제 호출 비교

2026-09-23. 유료 호출 전에 고정한다. 전체 3824개에서 보수적 중복 503개(13.15%), 재배치 시 요청 절감 상한 31/239(12.97%)를 확인했다. 원문만의 중복 86.01%는 재사용 근거로 사용하지 않는다. 기존 배치 그대로 재사용은 0회다.

## 입력과 조건

파일럿은 전체 스냅샷의 첫 192개(최초 탐색 순서), 광고/정상×4개 단일 기법별 node_id 정렬 첫 6개씩 최대 48개, 문맥 진단 28개로 구성한다. 이미 포함된 ID는 중복 추가하지 않는다. 기법 표본은 전체 스냅샷 순서를 유지한다. 라벨은 오프라인 선택·채점용이며 모델 입력·재사용 키에 추가하지 않는다. 기존 자료이므로 독립 홀드아웃이 아니다. 문맥 진단의 관찰은 기존 observeTechniques가 생성하는 legacy/missing evidence 상태로 기록하며 정상 스타일이라고 추정하지 않는다.

현재 worker와 같은 기본 createSession, 후보 16개, HCX-007, thinking none, temperature 0, seed42, maxCompletionTokens3072, 순차 실행을 사용한다. 기본 prompt/schema와 수집 근거는 변경하지 않는다. `baseline` → `reuse` → `baseline-repeat` 각 1회. baseline-repeat는 모델의 기존 변동을 구분하기 위한 대조이며 성공 사례를 고르기 위한 반복이 아니다.

reuse는 첫 출현 대표만 원래 순서로 16개씩 판정하고, 검증된 응답을 각 원래 node_id에 귀속한다. 최종 URL·선택자·원문은 원래 후보에서 가져온다. 보류도 그대로 보존한다. 실행 간 캐시는 없다. 요청 실패/누락/잘못된 출력은 성공 응답으로 저장하지 않는다.

## 관문과 예산

- 원래 후보 완전성, 위치·원문 보존, 다른 문맥/스타일 병합 0, 기존 양성 손실·정상 오탐 증가·보류 손실 0.
- 라벨 부분의 광고 의도 F1, 정상 오탐·보류와 기법 정확도·최종 요소×기법을 별도 기록한다. 미라벨 부분을 정상 정답으로 가정하지 않는다.
- 전체 후보의 의미/검토/관찰 기법 signature를 비교한다(reason 문장 표현 차이는 별도 기록). 기준선 반복에서도 판정이 흔들리면 독립적으로 재사용의 안전성을 확정하지 않고 통합 채택을 보류한다.
- 실제 요청 수와 토큰이 모두 감소해야 한다. 시간은 실제 측정하되 일회 측정/429 영향을 분리한다. 전체 사이트의 31회 절감을 이미 달성한 것으로 보고하지 않는다.
- 전체 64시도·400,000토큰 예산, 실행별 1시간. 429는 사용량 미제공을 0토큰으로 간주하지 않고 예약량을 예산에 반영한다. 다른 성공 응답의 usage 누락은 중단한다. 예산/형식/서비스 오류가 지속되면 해당 비교를 미완료로 보고하고 추가 튜닝하지 않는다.
- 진단 파일럿만으로 독립 실사이트 일반화나 기본 worker 통합 완료를 주장하지 않는다. 실패하면 실험 경로 미채택으로 종료하고 병렬화로 확대하지 않는다. 모두 통과하면 다음 검증에 사용할 후보안으로 보고하며, 기본 worker 적용에는 넓은 범위의 별도 검증이 필요하다.

2·3단계의 알려진 오류는 고치지 않는다. 그 오류를 정상으로 다시 라벨링하거나 숫자 치환 미확정을 숨기지 않는다.
