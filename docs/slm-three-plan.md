# 세 한국어 SLM CPU 기준선 비교

2026-09-29 사용자 요청. 추가학습 없이 EXAONE4 1.2B/Kanana2 3B/Bllossom3B의 Q4_K_M을 비교한다. 운영모듈/기존모델 변경, 유료API, 최종봉인 평가 접근은 없다. 다운로드는 고정revision/크기/SHA256을 검사하고 CPU판정은 순차 실행한다.

자료: 관찰 개발 new40+broad120+ownership44=204와 사용자가 검수한 정상17개. 기존 KLUE와 대상/주변문맥 내용은 같고, 입력 한도는4096토큰으로 이번 모델별 토크나이저에서 확인한다. 기존KLUE는512토큰 제한이므로 순수모델효과와 입력길이효과가 섞일 수 있음을 보고한다. 17개는 이진 오탐만 집계한다. 근거부족은 기존계약대로 이진F1에서 제외하고 광고확정/보류를 별도 집계한다.

CPU8threads, 한후보씩, temperature0/seed42, 비추론, 출력32토큰, 동일한국어지시/JSON스키마, 캐시재사용없음, 문맥자동잘림없음. 모델별공식chat template만 다르다. 사전고정 상한1시간/요청120초, 시작확인용 합성일반문장1회는 성능집계제외. 각모델221개 후 각개발패널 첫4개를 역순재측정하여12개 변동을 참고보고한다. 미완주는 완료성능으로 보고하지 않는다. 출력/통신실패를 정상판정으로 대체하지 않는다.

보고: 모델별TP/FP/FN/F1, 패널별손익, 근거부족, 실제정상오탐, 실패율, 입력토큰/총시간/중앙값/p95/입력처리와생성속도, 프로세스메모리, 시작시간. 현판정병목에 유망한가를 판단하되 관찰자료1회로 운영승격하지 않는다. HCX 신규호출없이 기존KLUE같은패널 측정치를비교하며 HCX직접우월성주장은하지않는다. 양자화/프롬프트/런타임을포함한시스템평가이며미양자화원본의성능한계로해석하지않는다.

실행 연결 수정 기록: v1은Windows한글절대경로의템플릿읽기실패로0판정. v2는EXAONE시작확인에서지시문누락의심(prompt36토큰)/스키마미적용을발견하여중단했다. 일부진행한Kanana도조건이불완전하므로최종순위에서제외한다. 모델성능수정이아닌공통전송결함수정으로, 공식Jinja를Transformers에서미리렌더링하고전체지시문/대상/문맥포함을assert한다. v3에서공통 /completion과동일GBNF정수라벨제약으로세모델을처음부터비교한다. EXAONE시작확인prompt284토큰과응답에반환된실제prompt로지시문보존을확인했다. 프롬프트의분류규칙/평가문구는변경하지않았다. 잘린출력과입력은계속오류로처리한다. 원로그는보존한다.

추가 연결 감사: v3 종료 후 원응답 prompt 전수검사에서 Kanana에 BOS 자동추가, Bllossom에 BOS 중복을 확인했다. v3 점수는 최종 비교에서 제외한다. v4는 llama.cpp의 공식 --override-kv로 tokenizer.ggml.add_bos_token/add_eos_token을 false로 지정한다. 이미 공식 Jinja가 생성한 문자열을 그대로 사용하고 매 응답마다 raw.prompt === rendered prompt를 assert한다. 세 모델 모두 다시 측정하며 분류 지시문/입력/라벨/양자화/생성 설정은 바꾸지 않는다.
