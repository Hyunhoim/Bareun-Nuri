# 숫자 치환 후보 힌트 제거 N — 사전 제한 실험

## 질문과 범위

원문을 읽는 능력보다 서버가 제시한 가능한 복원 문자열이 기법 확정을 유도하는지 진단한다. 이미 관찰한 개발56개에서 한 차례 비교한다. 과거 후보 제거 실험의 자유 출력 계약 실패와 달리, 이번에는 검증된 compact 3분류 출력과 단일 후보 요청을 유지한다. 파인튜닝·운영 코드 변경·새로운 단어 예외는 없다. 실패한 R/M/마스킹 지시는 누적하지 않는다.

## 고정 기준선과 변경 요인

- 기준선 S: `.runtime/digit-role-pilot-v1/00-dev-S`, `03-dev-S`의 원래/역순 결과를 재사용한다. 원요청112개, 원응답, 저장 판정, 당시 소스 해시와 전체 완료 감사 기록을 실행 전에 다시 검증한다.
- N: 동일 개발 입력·대상 ID·원문·소속 문맥·원표기 `unchanged`를 유지한다. 모델 입력에서 `readings`, `source_ids`, `readings_truncated`만 뺀다. 출력은 기존 `classification=substitution/literal/uncertain`만 사용한다.
- S의 다음 두 지시만 삭제한다. “제공 readings는 검증된 단어가 아닌 문자 대응 가설이다.” 및 “readings_truncated가 true이거나 후보 중 근거 있는 읽기가 없으면 substitution으로 확정하지 않는다.” 다른 정의·판정 지시·스키마·검증기는 그대로다.

**입력 힌트와 그 힌트가 있어야 확정하도록 하는 지시를 함께 제거하므로 순수한 입력 필드 하나의 효과라고 해석하지 않는다.** N은 복원 문자열을 출력하지 않아 정확한 문자 대응·복원 성공을 검증하지 않는다. 정답은 요청에 전달하지 않는다.

## 실행과 종료

- 자료: `.runtime/digit-generalization-data-v1/dev-inputs.json`의56개. 개발 정답은 사후 평가에만 사용한다.
- 순서: N 원래 순서56회, N 역순56회. 각 대상은 단독 요청이다. 기존 S의 해당 순서와 비교한다.
- HCX-007 / none / temperature0 / seed42 / 출력1024 / 로컬58k TPM / 최소1초 간격. 조건 시작 전61초 예약 소진 대기.
- 예정112회, 상한140회, 예약 상한1,000,000토큰, 전체1시간·조건10분. 사전 추정은202,036토큰이다.
- 자동 재시도·응답 수리 재호출·부분 실행 자동 재개는 하지 않는다. 실패 시 원본을 보존하고 전체 완료 점수로 보고하지 않는다.
- 신규 저장 위치: `.runtime/digit-nohint-pilot-v1`. 기존 결과는 덮어쓰지 않는다. 입력·계약·실행기·기준선 장부·계획 해시를 동결한다.

## 사전 후속 기준

원래/역순 각각에서 기준 S가 찾은 치환 정탐을 모두 보존하고, 정상 표기의 치환 오탐이 늘지 않으며, 두 조건 합산 모호 사례의 과확정이 감소해야 한다. strict F1·3분류 macro F1도 함께 보고한다. 통과할 때만 별도 v5 미사용 자료에서 **같은 시점의 S/N 쌍 비교**를 검토한다. 실패 결과에 맞춘 지시 수정·표현 예외·추가 개발 재측정은 하지 않는다.

## 보고 한계

기존 S는 저장 응답 재사용이므로 모델·시간 변동을 완전히 통제한 동시 비교가 아니다. 원래/역순 N의 요청 본문은 대상별로 같지만 실행 시점은 다르다. N의 실제 호출·토큰·시간과 재사용한 S 비용을 구분한다. 개발56개는 새로운 홀드아웃이 아니며, 이 실험만으로 운영 채택·25분 종단 개선·실사이트 일반화를 선언하지 않는다. 모든 정탐 보존·오탐·모호 과확정·순서 변화·추가 지연을 함께 보고한다.
