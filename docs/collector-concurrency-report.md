## 같은 URL 전체 수집

기존 createCollector, Playwright1.62.1, headless Edge를 사용했다. 작업당 브라우저 하나를 재사용하고 페이지별 독립 context를 동시에2/3/4/5개 열었다. 기존 대기·iframe·문맥·기법 관찰을 유지했다. 동시 수만 달리해 각 자료를3회씩 끝까지 수집했다.

| 자료 | 페이지 / 후보 | 동시2 | 동시3 | 동시4 | 동시5 |
|---|---:|---:|---:|---:|---:|
| mixed-0 합성 사이트 | 27 / 147 | 27.39초 | 19.57초 | 17.47초 | **16.53초** |
| 댓글·iframe·상태 격리 동작 | 8 / 22 | 10.23초 | 8.99초 | 7.70초 | **7.54초** |

| 자료군별 중앙값 합 | 55 / 3,712 | **70.03초** | **57.66초** | **50.89초** | **47.56초** |
| 동시2 대비 시간 감소 | | 기준 | 17.66% | 27.33% | **32.09%** |

합계는 세 자료군 중앙값의 합이며55페이지 연속 실행이나 전체 운영 시간은 아니다. 각 측정에는 브라우저 시작/종료와 근거 저장이 포함된다. 자원 측정기 종료 대기·Node 시작 준비는 별도 process_wall_ms로 보존했다.

후보별9쌍 모두 동시2보다 빨랐다. 고정 URL 수집 실패0, 기존 페이지 손실0. 합성 광고12개/정상12개 위치와 동작 검사의 기대 요소20개가 보존됐다. 실제 DOM 후보3,543개 전체를 정상/광고 정답으로 임의 분류하지 않았다.

5개가4개보다 중앙값 합 기준6.54% 짧았다. 역으로4개는 최저 시간인5개보다7.00% 길어, 사전에 정한 ‘최저 시간 대비5% 이내이면 더 작은 동시 수’ 규칙에 해당하지 않았다. 그래서5개를 선택했다.8페이지 동작 시험에서는4→5 이득이약2.04%에 그쳐 동시 수 증가의 이득이 자료마다 다름을 확인했다.

## 메모리와 근거 감사

각 측정은 **새 Node 프로세스**에서 시작했다. 이전 실행의 heap/GC 잔존을 줄이기 위해서이며, 부모의 로컬 자료 제공 서버는 측정 프로세스 트리에서 제외했다.

| 동시 수 | 고정 URL 실행 중 최대 working-set 합 |
|---|---:|
| 2 | 1,341MiB |
| 3 | 1,331MiB |
| 4 | 1,510MiB |
| 5 | 1,538MiB |

Node·브라우저·측정 PowerShell의 작업 메모리 합이다. 공유 페이지가 중복 계산될 수 있고1.5초 간격 표본이므로 물리 RAM 필요량이나 정확한 순간 최고치가 아니다. 3개가2개보다 작게 나온 값도 메모리 감소 효과로 주장하지 않는다. CPU 누적 생존 프로세스 표본은 보존했지만 종료된 프로세스가 있어 총CPU 비용으로 환산하지 않았다.

저장된 완료 페이지1,247개·후보 관측47,755건을 다시 읽어 재집계했다. 이 중 전체 수집 참조와 비교한1,054페이지·후보 관측36,469건에서 전체 근거 차이0, 후보 손실/추가/내용 변경0이었다. 후보ID 중복0, 관측 실패0. 반복 관측을 독립 사례 수로 부풀리지 않는다.

대조 범위는 제목·원문·정규화문·귀속 문맥·스타일·좌표·링크·프레임 경로·기법 관찰이다. 수집 시각/대기 시간은 제외하고 이슈 목록 순서만 정렬했다. 고정 URL 기준선 반복의 근거도 같았다. 동작 검사의 원래 클릭 후 댓글·6초 지연 댓글 미수집은 남아 있으며 해결됐다고 주장하지 않는다.

사전 관문(근거 보존·실패0·자료별 반복 속도·합계10% 개선·자료별 악화5% 이내·탐색 광고 위치 보존)은3/4/5 모두 통과했다. 저장 원본 감사, FIFO/출처/쿼리/동시3~5/예산 취소 자체검사, 이전1/2/Katana 집계 재현을 통과했다. 관련 운영8파일과 실험/계획7파일의 전후 SHA256은 같았고 로컬 서버5개 포트의 종료를 확인했다.

## 중단 실행과 해석 범위

최초 `.runtime/collector-concurrency-v1`은31개 실행 저장 후 PC 대기로 중단됐다. System 로그의 Kernel-Power506/507에05:56:09 KST Lid 대기 진입,06:44:14 KST 키보드 입력 복귀가 확인된다. 해당 `fixed-behavior-2-fifo3`은630초 보호 타이머로 종료됐다. 이를 수집기 성능 실패나 유효 지연으로 집계하지 않았다. 원본·중단 기록·전원 이벤트를 보존했다.

같은 소스·계획을 `.runtime/collector-concurrency-v2`에서 전부 재실행했으며, **이 보고서의 수치는 v2만 사용했다.** 61실행 소요는약24분46초지만 독립 실행의 합계이며 ‘25분 제출 종단 검증’이 아니다. 중단 전보다 재실행의 절대 시간이 길었다. 현재 PC의 배경 부하·전원 조건을 엄격히 통제한 하드웨어 벤치마크가 아니므로 반복 순서 순환과 같은 실행군 기준선으로 비교했다. 속도 차이를 병렬화만의 정밀한 인과 추정으로 확대하지 않는다.

현재 실험 실행기는 FIFO로 최대N개를 한 묶음씩 수집하고 묶음 전체가 끝나면 순서대로 반영한다. 완료 즉시 빈 슬롯을 채우는 스케줄러나 운영 bounded-scan의 저장/재개 경로를 구현·검증한 결과가 아니다. 실제 DOM 복제본은 원격 네트워크·원래 JavaScript·요청 제한을 재현하지 않는다. 합성 두 사이트도 기존 관찰/회귀 자료이며 새 독립 홀드아웃이 아니다.

따라서 **이번 범위에서는5개가 유망하지만 모든 사이트의 최적값으로 확정하지 않는다.** 운영 채택에는 실제 사이트의 동일 조건 수집, 동시 취소/저장/재개, 같은25분 HCX12묶음 조건에서 전체 정탐·오탐·미판정 광고·자원 사용 검증이 남는다. 운영 FIFO 동시1과 HCX 설정은 유지했다. Crawlee/Katana 추가 실행이나 판정모델 변경은 없었다.
