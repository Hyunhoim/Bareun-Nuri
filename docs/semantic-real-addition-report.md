# 실제 수집 문맥 추가 실험 결과

2026-09-30. **RTX4060에서 3모델 × 기존/추가 자료의 6조건 학습과 CPU 회귀 비교를 완료했다. 세 추가군 모두 사전 기준에 미달해 운영에 채택하지 않는다.** KcELECTRA는 실제 광고 일부와 기존 누락을 복구하면서 기존 정탐을 보존했지만 정상 오탐이 증가했다. KLUE는 정탐 손실, KoELECTRA는 큰 정상 오탐 증가가 남는다. HCX 대체 Goal은 미완료다.

## 같은 조건과 데이터

기존956행과 실제 수집 문맥22개를 추가한978행을 비교했다. 모두 순정 pretrained 모델에서512토큰/embedding 및 하위8층 동결/FP32/seed42/lr1e-5/3epoch/가족별 균형 손실로 학습했다. 기존 `semantic-encoder.py`의 학습 루프를 재사용하고 동일 개발 검증 rank로 선택했다. 모델·학습률·임계값을 결과에 맞춰 바꾸지 않았다. 추가군22개는 광고9·정상13,15그룹이다. 광고9개는3캠페인에 속하고 새 광고 캠페인은1개뿐이다. 기존67가족은80가족이 됐다.

추가 후보31개 중 근거 부족4개, 확정형 라벨이지만512토큰 또는 수집 문맥 잘림이 있는5개는 제외했다. 관찰31개는 훈련하지 않았고, 추가분의 관찰 사이트 중첩·정규화 동일 입력·토큰 입력의 상충 라벨을 검사했다. 대상과 실제 수집 문맥을 그대로 사용했다. 동일 캠페인은 기존 family에 합쳐 가중치를 중복 부여하지 않았다.

사용자 전체 열람 진술과 AI 개별 라벨 작성을 구분했다. AI 주석을 사람 확정 정답으로 승격하지 않았다. 개발 자료와 주석 작성자 편향, 소수 실제 사이트·캠페인, 이미 관찰한 평가라는 한계가 있다. 새 독립 홀드아웃이 아니다.

정상 가족 가중치 비중은55.87%→61.79%로 변했다. 자료 추가에는 문맥 보강과 라벨 구성 변화, 학습 순서·업데이트 수 변화가 포함된다. 효과를 단순히 실제 문맥의 우월성이나 모델 구조의 특성으로 분리해 주장하지 않는다.

## 개발 검증과 선택

| 모델 | 선택 epoch 기존→추가 | 개발 TP/FP/FN 기존→추가 | 개발 F1 기존→추가 |
| --- | --- | --- | --- |
| KLUE | 2→3 | 17/2/3→16/0/4 | 87.18→88.89% |
| KcELECTRA | 3→2 | 18/2/2→19/3/1 | 90.00→90.48% |
| KoELECTRA | 3→2 | 16/1/4→14/3/6 | 86.49→75.68% |

기본 개발50개 중 확정형40개의 수치다. 별도 표기변형40개는 원문과 동일 토큰이 되는 기존 한계를 유지하므로 독립 시험으로 합산하지 않는다. Kc·Ko 추가군의 정상FP3은 기존FP<=2 기준을 실패했다. Kc의3epoch은FP2지만, 실패 후 선택자를 바꾸지 않고 사전 rank의2epoch을 유지했다. Ko는 훈련 loss가 감소하는2→3epoch에도 개발F1이75.68→72.73%로 하락해 과적합 우려가 남는다.

세 대조군의 개발90개 hard 판정은 이전 동일 조건 실행과 일치했다. Kc·Ko는 가중치 해시도 같았다. KLUE는 가중치 해시는 다르고 최대 개발 확률 차이1.073e-6이 있었으므로 가중치까지 완전 재현됐다고 쓰지 않는다. 이번 비교의 대조군은 이번 실행에서 다시 동결한 모델이다. 과거 Kc 연구 후보는 전체층 학습이었으므로 이번 freeze8 대조군과 혼동하지 않는다.

## 실제 관찰 자료

잘림 없는 공통23개는 AI 라벨 기준 광고10·정상6·근거 부족7이다. 아래 F1은 이 중 확정형16개에 대한 것으로, 전체 사이트 정확도가 아니다.

| 모델 | TP/FP/FN 기존→추가 | F1 기존→추가 |
| --- | --- | --- |
| KLUE | 4/0/6→4/0/6 | 57.14→57.14% |
| KcELECTRA | 0/0/10→3/0/7 | 0.00→46.15% |
| KoELECTRA | 2/1/8→2/1/8 | 30.77→30.77% |
| HCX 원래·역순 저장 응답 | 두 순서 모두10/0/0 | 두 순서 모두100.00% |

전체31개는 광고11·정상13·근거 부족7이다. 분류기들은8개를 입력 보호로 보류한다(광고1·정상7). 이를 포함한 광고FN은 추가군 KLUE7/Kc8/Ko9이며 F1은53.33/42.86/28.57%다. 긴 입력을 잘라 계산한 raw 판정을 완전한 문맥 판정으로 채택하지 않았다. HCX는 전체 광고11개를 두 순서에서 모두 찾았지만 근거 부족7개 중 원래 순서1개·역순2개를 광고로 확정했다. HCX100% 수치는 근거 부족을 제외한 작은 확정형 자료의 값이다.

고정 .2~.8 보류 진단에서 Kc 추가군은 광고11개 중9개를 보류한다(입력 보호1개 포함). 그러나 근거 부족7개는 모두 정상으로 확정한다. 이진 확률은 근거 충분성 점수가 아니며 확률 기반 안전한 보류가 확보됐다고 주장하지 않는다. 이번 결과로 정상 제외 필터를 만들지 않았다.

## 기존 문맥·표기 회귀

문맥204개는 확정형167개(광고64·정상103)와 근거 부족37개다. 표현2000개는 광고1000·정상1000이다. 둘 다 기존 관찰/합성 회귀이며 기법·위치 검출 성능이 아니다.

| 모델 | 문맥204 TP/FP/FN 기존→추가 | 문맥 F1 | 기존 정탐 손실 |
| --- | --- | --- | ---: |
| KLUE | 53/7/11→47/2/17 | 85.48→83.19% | 6 |
| KcELECTRA | 62/3/2→64/8/0 | 96.12→94.12% | 0 |
| KoELECTRA | 42/8/22→50/16/14 | 73.68→76.92% | 0 |

같은 입력의 과거 HCX 묶음12는63/0/1·F1 99.21%다. 저장 HCX 판정 파일이 원래 감사 해시와 일치함을 재확인했으며 추가 호출은 없다. Kc 추가군은 HCX가 놓친 광고도 찾지만 정상8개 오탐이 있어 HCX보다 낫다고 정리하지 않는다. 근거 부족37개를 광고로 확정한 수는 KLUE20→15/Kc11→17/Ko29→33이다.

| 모델 | 표현2000 TP/FP/FN 기존→추가 | 표현 F1 | 기존 정탐 손실 |
| --- | --- | --- | ---: |
| KLUE | 972/61/28→928/17/72 | 95.62→95.42% | 44 |
| KcELECTRA | 792/28/208→931/78/69 | 87.03→92.68% | 0 |
| KoELECTRA | 975/181/25→996/375/4 | 90.45→84.02% | 0 |

Kc의 누락 복구와 기존 정탐 보존은 확인된 이득이다. 동시에 문맥FP3→8,표현FP28→78이라는 악화를 보존한다. Ko의 높은 재현율은 정상 오탐181→375 증가를 상쇄한 채택 근거가 아니다. KLUE는 FP 감소에도 정탐 손실이 있어 제외한다. 세 모델 모두 사전 조건을 충족하지 못했고, 같은 관찰 자료에 맞춘 재학습·임계값 변경 없이 이번 비교를 종료한다.

## 자원과 실행 검증

RTX4060에서 학습 시간 합336.59초다(다운로드·모델 준비·CPU 검증을 포함한 전체 경과시간 아님). CPU 계획은 학습 전 GPU 재인식으로 대체했고 실제 CPU 학습은 하지 않았다. 샌드박스 밖 Windows 장치 상태와 CUDA 연산을 확인한 뒤 GPU 실행 권한을 사용했으며 드라이버 재설치는 없었다.

| 추가군 실제31개 CPU FP32 | 추론 초 | 모델 로딩 초 | 토큰화 초 | 프로세스 RSS MiB |
| --- | ---: | ---: | ---: | ---: |
| KLUE | 5.87 | 0.20 | 0.034 | 1073 |
| KcELECTRA | 6.29 | 0.22 | 0.035 | 1358 |
| KoELECTRA | 6.41 | 0.18 | 0.036 | 1357 |

각각 별도 CPU 프로세스/8threads/batch8/워밍업 후 단회 측정이다. RSS는 해당 프로세스의 측정값이지 브라우저까지 포함한 운영 RAM이나 최소 요구량이 아니다. CPU는512 초과2개를 잘라 추론 후 보류하며 수집 문맥 잘림도 별도 보류한다. HCX 과거31개 처리11.82/11.67초는 전체 입력·네트워크/예약 대기 포함으로, 동일 처리 범위의 종단 가속률 비교가 아니다. 새25분 제출 조건 실행은 없었다.

학습6가중치,18epoch,개발24회 장부,선택 CPU/GPU hard 판정 일치,원본/입력/가중치 해시와 회귀 예측을 감사했다. 신규 유료API0·운영 변경0이다. 기존 모델과 원문은 덮어쓰지 않았다.

근거는 `.runtime/semantic-real-addition-gpu-v1/manifest.json`, `training-audit.json`, `evaluation-contract.json`, `comparison.json`, 각 `control/`·`addition/`의 모델/원예측/시간·메모리 기록이다. 계획은 `semantic-real-addition-plan.md`, 실행은 `local-benchmark/semantic-real-addition.py`, 평가·감사는 `semantic-real-addition-eval.py`와 `semantic-reviewed-score.py`다. 준비 시 각 arm에 부모 manifest의 바이트 동일 사본을 배치한 뒤 기존 trainer를 호출했다. CPU 준비 원본은 별도 `.runtime/semantic-real-addition-v1`에 보존했다.

## 남은 Goal

Kc 추가군은 연구 후보로 보존하되 운영 승격하지 않는다. 유망성의 범위는 이번 소규모 실제 광고3개 회복과 기존 회귀 정탐 보존이다. 사람 독립 검증·실제 도박 외 양성 유형·미방문/미수집 영역·전체 사이트 recall·25분 종단 채택 근거는 여전히 미달이다. 같은 실패 문구를 더 학습시키거나 합성 점수만 높이는 것으로 이 공백을 대체하지 않는다. 다음 개발에서는 실제 광고 자료의 형식과 대상 귀속·라벨 기준을 점검하고, 정상 보존을 함께 다뤄야 한다.
