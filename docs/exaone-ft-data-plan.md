## 목표

광고 정탐을 유지하며 예방 인용·피해 문의·다른 작성자 문맥으로 인한 오탐을 줄인다. 의미 판정과 HOMOGLYPH/JAMO/TRANSPARENT/OFFSCREEN 관찰을 분리한다. 숫자 치환의 의미 해석 성공을 기법 확정 성공으로 간주하지 않는다. 수집·위치·스타일 근거는 기존 코드의 역할로 유지한다.

## 계획 비율 (제작 전에 고정하고 필요 시 이유와 함께 변경)

독립 상황 기준 초기 훈련 목표는 약1,000개다. 개수보다 검수와 출처 다양성을 우선하며 아직 생성 완료한 수가 아니다. 실제 권유40%, 예방·교육·보도15%, 피해문의·일반정상·합법권유30%, 근거부족15%를 출발점으로 삼는다. 이는 실사이트 출현율 추정이 아닌 학습 설계다. 피해 문의는 기존 공통 계약의 라벨2로 고정하고 과거 Nuri의 라벨1 오류를 승계하지 않는다.

4종 단독 변형은 각15%, 일반표기30%, 복합변형10%를 목표로 한다. 각 기법 안에도 광고/정상/근거부족을 배치한다. 같은 원문의 변형·정상 대조·복원 쌍은 같은 group_id에 묶고 독립 사례로 부풀리지 않는다. 검증은 기술별 균형 자료와 정상 비중이 큰 운영 근사 자료를 별도로 보고한다.

## 보강할 관계

- 같은 짧은 CTA라도 해당 글의 실제 권유/합법적 신청/피해 신고/다른 작성자 광고/근거 미수집으로 정답이 달라지는 대조.
- 정상 서두 뒤 실제 거래, 인용 모양의 판매, 예방 설명 옆 별개 실제 광고.
- 제목·본문의 목적 차이, 본문과 댓글의 작성자 차이, 작성자 소개·링크·짧은 댓글.

- 투명/화면밖은 HTML·CSS와 위치를 가진 페이지로 만든 뒤 실제 브라우저 수집으로 확인한다. 스타일 이름이나 정답 태그를 의미 모델 입력의 지름길로 전달하지 않는다.
- 관찰이 충분해도 불법 여부·귀속이 불명확하면 보류. 반대로 실제 소속 문맥이 명확한 짧은 권유를 일괄 보류하지 않는다.

## 입력과 검수

현재 review-draft의 문맥은 설계용 설명으로 실제 수집 입력이 아니다. 이 설명을 그대로 최종 학습 입력으로 쓰지 않는다. 실제 게시글/댓글 경계로 HTML에 구현하거나 검수된 실제 문맥을 사용하고, 운영 수집기 결과만 모델 입력으로 사용한다. 원문·정규화 보조읽기·관찰 기법·위치를 따로 보존한다. 수작업 완전 복원 정답이나 라벨 근거는 모델 입력에 넣지 않는다.

review-draft24개는4개 상황 계열의 의미 계약 확인용이며 최종 훈련/검증/평가 분할이 아니다. 제안 라벨과 사람 검수 라벨을 분리하고 실제 원문 근거를 확인한다. 모델 출력은 정답 검수에서 숨긴다. 검수 완료 전 학습용 messages를 export하지 않는다. 이번 네 계열만 증식해1,000개를 채우지 않는다.

## 분할과 누출

새 훈련/개발검증/최종평가는 출처·사이트·작성자·문장/상황 계열 단위로 변형 생성 전에 분리한다. 단순 문장 무작위 분할은 금지한다. 훈련 목표1,000개와 별개로 검증/최종평가 각약250개 독립 상황 확보를 목표로 하되 현재는 미생성이다. 이미 분석한221개와 기존 평가 자료는 회귀 진단 전용이며 학습하지 않는다. 봉인 최종평가의 문구를 읽어 새 자료를 설계하지 않는다. 가까운 표현 검사는 허용된 개발/과거 학습 자료에서 수행하고, 봉인 세트와의 중복 감사는 내용을 공개하지 않는 별도 절차로 진행한다.

현재24개는 같은 CTA를 반복한 의도 대조 초안이라 다양성이 부족하다. 대상만/문맥만/관계 표기만으로 정답이 예측되는지, 특정 말투·영문 코드·HTML 태그가 라벨과 결합하는지 점검한다. 숫자 치환·스타일 변형은 독립 학습량 증가로 계산하지 않는다. 사람이 검수한 실제 문맥이 부족하면 합성 학습이라는 한계를 표시하고 운영 일반화를 주장하지 않는다.
