# Nuri1.0 정상 제외 필터 진단 결과

2026-09-29. 기존 A를 Nuri1.0으로 명명했다. 체크포인트 변경/재학습 없이 Nuri1.0과 D를 CPU 8스레드·배치8로 비교했다. **이번 필터는 둘 다 운영 미채택**이다. D는 개발 자료에서 유망했으나 다른 문맥 자료에서는 거의 제외하지 못했다. HCX 운영은 유지한다.

## 조건과 결과

사전 계획: `docs/nuri10-filter-plan.md`. 이미 관찰한 2,000개에서 광고 손실0 조건 중 정상 제외가 최대인 고정 격자 조건을 선택하고, 선택 파일을 저장한 뒤 기존221개에 그대로 적용했다. 모델 argmax가 일반정보이며 광고 점수가 낮고 일반정보 점수가 높은 경우만 제외한다. 인용/보류로 예측한 후보와512토큰 초과 입력은 통과한다. 정답 라벨을 필터 함수에 전달하지 않는다.

| 지표 | Nuri1.0 | D |
|---|---:|---:|
| 선택 광고 점수 상한 t (미만) | 0.001 | 0.0001 |
| 선택 일반정보 점수 하한 q | 0.999 | 0.9 |
| 개발 광고 통과 | 1,000/1,000 | 1,000/1,000 |
| 개발 정상 제외 | 25/1,000 (2.5%) | 335/1,000 (33.5%) |
| 개발 전체 후보 제외 | 1.25% | 16.75% |
| 확인 광고 통과 | 64/64 | 64/64 |
| 확인 정상 제외 | 0/120 | 2/120 (1.67%) |
| 확인 전체 후보 제외 | 0/221 | 2/221 (0.90%) |
| 확인 근거 부족 제외 | 0/37 | 0/37 |
| 개발 CPU 추론 | 42.09초 | 42.41초 |
| 확인 CPU 추론 | 7.98초 | 8.10초 |

로딩 약0.05~0.23초, 토큰화 약0.06~0.28초는 표의 추론 시간과 별도다. 확인 입력4개는512토큰을 초과해 모두 통과했다. 긴 입력 길이 측정 시 토크나이저 경고가 발생했지만 실제 모델 입력은512로 제한하여 실행 오류는 없었다. 단회 CPU 시간이며 다른 장비의 속도를 보장하지 않는다.

개발 기법별 각250광고는 두 모델 모두 통과했다. 정상250개 중 제외 수는 HOMOGLYPH/JAMO/TRANSPARENT/OFFSCREEN 순서로 Nuri1.0은5/6/5/9, D는80/90/81/84다. 이는 해당 표현이 들어간 후보를 통과시킨 결과이며 기법 판정 정확도가 아니다.

## 왜 더 느슨하게 제외하지 않았나

q=0.9로 비교하면 다음 절충이 관찰됐다. 아래 조건은 선택 기준을 바꿔 채택한 것이 아니라 사전 격자의 진단 결과다.

| 모델 | 광고 점수 상한 t | 정상 제외 /1,000 | 잘못 제외한 광고 /1,000 |
|---|---:|---:|---:|
| Nuri1.0 | 0.001 | 554 | 5 |
| Nuri1.0 | 0.01 | 730 | 30 |
| D | 0.001 | 821 | 18 |
| D | 0.01 | 881 | 69 |

최종 분류에서 Nuri1.0이 놓친143광고 중139개, D의202개 중200개가 일반정보 예측이었다. 누락 광고의 광고 점수 최솟값은 각각0.00061488, 0.00013130이었다. **실제 광고에도 매우 낮은 광고 점수를 줄 수 있다.** softmax를 보정된 실제 확률로 해석하면 안 된다. 특히 D의 선택 임계값0.0001과 관찰된 누락 최솟값은 가까워, 개발 손실0만으로 미사용 문맥에서의 안전성을 주장할 수 없다.

## HCX 연결 영향과 한계

221개 저장 HCX 판정을 재생해 제외 후보를 정상으로 대체했을 때, 두 필터 모두 기존 HCX 정탐 손실0이며 의미 이진 F1은 단일91.43%, 12개묶음99.21% 그대로였다. **실제 필터 후 재묶음 호출 결과가 아니다.** D는 정상2개 중 인용1개를 일반정보로 대체하므로4분류 결과까지 완전 보존한 것은 아니다. 근거 부족37개는 이진F1 분모에서 제외한 기존 계약을 유지했다.

D가221개에서2개만 줄이면서 CPU 추론8.10초를 추가하므로 실용적인 속도 개선 근거가 부족하다. 과거 HCX12묶음의37.16초와 비교해도 무시하기 어려운 추가 비용이지만, 이번에는 실제 연결 실행을 하지 않아 총 지연 증가량을 확정하지 않는다. 후보 제외율을 API 요청/토큰/비용 절감률로 바꿔 주장하지 않는다.

2,000개는500개 원형 계열에 걸친 자료이며 독립2,000시나리오가 아니다. 확인221개도 이미 관찰한 의미 진단/사람 검수 자료다. 개발에서 확인으로 정상 제외율이 급감한 것은 점수 분포와 문맥 차이에 대한 취약성을 보여주며, 같은 자료에서 임계값을 더 맞추면 과적합 우려가 있다. 새 홀드아웃 일반화, 실제 사이트 전체 정상 분포,25분 종단 효과는 미검증이다.

## 결정과 검증

- Nuri1.0: 개발 정상 제외2.5%로 사전 확대 기준10% 미달. 확대하지 않는다.
- D: 개발에서는 기준 충족하지만 확인 전체 후보 제외0.90%로 처리량 개선 근거 부족. 운영 승격/유료 연결 실험을 하지 않는다.
- 다음 검증을 한다면 임계값 반복 조정보다 실제 수집 후보 중 반복 안내·메뉴·정상 본문의 분포를 고정해 제외 효과가 있는지 확인하는 편이 합리적이다. 해당 후보를 이름이나 태그만으로 제외한다는 뜻은 아니다.

이전 저장 예측과 새 argmax는 모델별2,000개 모두 일치했다. 확률 합·고유ID·선택 후 확인·잘림 통과·제외 수 재집계·소스 및 체크포인트 해시 보존 검사를 통과했다. 운영 파일 변경, 학습, API 호출, push는 없다.
