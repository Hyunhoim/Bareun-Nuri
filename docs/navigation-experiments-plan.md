# 탐색 정책 / Sitemap 발견 경로: 사전 실험 계획

2026-09-23. 사용자 승인 범위의 두 실험을 분리한다. 이번 실행은 로컬 HTML을 실제 브라우저에서 읽은 스냅샷의 오프라인 탐색 비교다. 추가 HCX 호출 없이 정책 효과를 먼저 확인한다. 도달률을 탐지 F1로 부르지 않는다. 운영 수집기·프롬프트·worker는 변경하지 않는다.

## 자료와 잠금

기존 test-set-v3의 dev/confirmation 각 40페이지는 회귀·진단용이다. 새 test-set-v4는 개발 3개 사이트(seed 101/102/103), 확인 3개(seed 201/202/203)다. 개발은 메뉴에서 목록으로 펼쳐지는 구조, 확인은 공유 경유 메뉴·교차 링크·더 깊은 경로로 만든다. 각 사이트에는 정상 전용 게시판 2개, 이용자 게시판 2개, 안내/공지 각 1개, 깊은 이용자 영역 2개와 영역별 상세 12개를 둔다. 링크 문구·DOM 템플릿·광고 배치를 달리한다. 과제의 제목/본문/댓글, 4가지 위장 표현과 정상 예방 인용을 포함한다.

같은 제작자의 합성 자료이며 독립 실사이트 홀드아웃이 아니다. 코드/사이트/정답을 첫 성능 집계 전에 manifest로 고정하고 개발 결과를 본 뒤 확인 정책을 바꾸지 않는다. 기존 점수에 맞춘 가중치 조정은 하지 않는다. 정답 파일은 평가기만 읽으며 스케줄러의 인수에 들어가지 않는다. 정책이 볼 수 있는 정보는 시작 URL과 방문한 응답의 링크·구조적 문서 신호뿐이다.

## 실험 A: 정책

- FIFO: 기존 최초 발견 순서. 우선순위: priority.cjs 점수, 매 4번째 FIFO 그대로.
- 영역별 하이브리드: 최초 시작 페이지에서 발견한 가지를 영역으로 삼고 하위 링크에 상속한다. 다중 부모는 최초 귀속을 유지한다. 5회 주기에서 집중 3회/발견 1회/오래된 URL 1회. 집중은 점수가 양수인 후보가 있는 영역 중 가장 적게 방문한 영역을 고르고 그 안의 최고 점수 URL을 선택한다. 발견은 내용 링크 밖의 탐색 링크가 있는 영역 중 가장 적게 방문한 영역을 고른다. 동률은 최초 발견 순서. 해당 풀이 비면 전체 대기열로 대체한다. 정답 영역을 사용하지 않는다.
- 경량 Bandit: id/class/URL을 제외한 DOM 태그·role 경로의 끝 5단계 + 내용 링크 여부로 링크를 그룹화한다. 그룹별 UCB(mean reward + sqrt(2 log(t+1)/visits)), 미방문 그룹 우선. 동률과 그룹 내부는 최초 발견 순서. 5번째 선택마다 전역 FIFO를 유지한다. 보상은 방문한 페이지에 구조적으로 상세 본문/댓글이 있고 동일 본문 지문을 이미 보지 않았으면 1, 아니면 0. 광고 판정과 정답을 보상으로 사용하지 않는다. 논문 전체 재현이 아닌 경량 가설 검증이다.

시작 페이지 요청도 예산에 포함한다. 20/50/100 HTTP 요청 지점(기존 40페이지는 20/40까지만)과 모든 페이지 완료를 비교한다. 실제 페이지가 없어 404가 나도 요청을 소비한다. 링크 순서를 원래/seed 11/23/37/51로 바꾼 5회 반복을 모든 정책에 동일 적용한다. 정답은 전체 사이트 분모이며 미방문은 도달 실패다. 첫 광고 요청 순번, 영역별 재현율, FIFO가 도달한 광고의 손실/추가, 방문 페이지/본문/바이트, 스케줄러 시간, 전체 완료 집합 보존을 기록한다.

새 정책의 후속 실제 LLM 평가 진입 기준: 개발과 확인 각각에서 20요청 평균 도달률 비감소, 20/50/100 중 두 지점 이상 평균 +5%p, 어느 사이트/예산에서도 5회 평균 -5%p 초과 회귀 없음. 알려진 광고 위치 하나도 잃지 말라는 기준은 탐색 예산의 범위 교환을 막으므로 별도 손실 지표로 보고한다. 대신 안내·공지·깊은 영역의 체계적 누락과 개별 회귀를 숨기지 않는다. 이 기준은 본 실험용으로 실행 전에 고정한다.

## 실험 B: 발견 경로

FIFO 대 FIFO+Sitemap만 비교한다. 동일 사이트에 없음/충분함/불완전/오래됨의 4조건을 만든다. 각 사이트에서 같은 스냅샷을 양쪽에 제공한다. 없음은 robots에 선언 없음. 나머지는 robots → sitemap index → 2개 URL set으로 구성하고, 충분함은 전체 URL, 불완전은 광고와 무관한 해시로 약 절반, 오래됨은 약 1/4 기존 URL + 존재하지 않는 URL을 포함한다. index 순서와 URL 순서도 5개 반복에서 동일하게 바꾼다.

보강은 시작 페이지를 읽고 robots 및 XML을 읽은 뒤, HTML에서 발견한 FIFO와 Sitemap FIFO를 1:1 교차 선택한다(첫 슬롯은 HTML). 중복 방문하지 않는다. 한쪽이 비면 다른 쪽을 처리한다. XML 목록은 방문 완료로 세지 않으며 본문을 검사할 페이지 목록에만 추가한다. 기존 링크 탐색을 유지한다. robots/XML/404 요청과 바이트를 총예산에 포함한다. XML 오류·범위 밖 URL·중복·다른 호스트는 검증/거부한다. 메타데이터 한도 4요청, 각 1MB, URL 총 5,000개. robots에 선언이 없으면 무제한 경로 추측을 하지 않는다.

충분함/불완전 조건의 후속 진입: 각각 두 새 분할에서 20요청 비감소, 두 예산 이상 평균 +5%p, 사이트별 평균 회귀 -5%p 이내. 없음/오래됨의 회귀도 반드시 보고한다. 유효 조건만 통과하면 조건부 후보일 뿐 기본 활성화로 채택하지 않는다.

## 안전성과 한계

정책 순서가 gold 변경에 불변인지, 숨은 자식에 조기 접근하지 않는지, 기존 FIFO/priority와 일치하는지, URL 중복·범위·완료 집합을 검사한다. HTML/댓글/분할 텍스트와 Sitemap XML은 Playwright의 DOM 파서로 읽어 fixture 객체를 그대로 특징으로 주입하지 않는다. 스냅샷 저장은 전체 그래프를 알지만 정책 모듈은 콜백으로 방문한 응답만 받는다.

요청 수는 재생 모델의 HTTP 문서 요청 수다. 브라우저의 CSS/이미지 등 모든 하위 요청이나 실제 네트워크 시간을 재현하지 않는다. 실제 HTML 읽기/파싱 시간과 스케줄러 CPU 시간은 따로 기록한다. 판정 호출/토큰은 0이며 현재 단계에서는 정밀도/F1을 산출하지 않는다. 방문 광고를 실제 HCX가 모두 탐지한다고 가정하지 않는다.

정상 게시판의 상세 문서 보상이 광고 희소성과 어긋날 수 있고, 합성 DOM의 반복성이 Bandit에 유리할 수 있다. 이를 반례로 포함해 과적합 우려를 보고한다. 미통과면 같은 자료를 보고 보상·비율을 재조정하지 않고 종료한다. 통과는 다음 실제 LLM 평가의 후보 선정이며 운영 채택이 아니다.
