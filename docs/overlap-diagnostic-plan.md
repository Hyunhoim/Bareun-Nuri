# 제한적 수집·판정 중첩 사전 진단

2026-09-26. 운영 C와 FIFO/SRPT8/aging8/배치4/512를 유지한다. API 호출·운영 수정 없이 저장된 `.runtime/jamo-context-live-c-v1`를 분석한다.

가설: API 응답 또는 사용량 제한 대기 동안 다음 FIFO 페이지 하나를 수집하면 같은 판정 입력·순서를 유지하며 시간이 줄어든다.

공통 사전 계획은 `docs/c-throughput-three-plan.md`다. 최초 파일 점검에서 수집 합계가 약34초임을 관측한 뒤 이 세부 진단을 작성했다. 따라서 이 문서를 수치 결과를 보기 전에 고정한 독립적인 채택 기준으로 부르지 않는다. 전체 수집 시간에서 최초 페이지를 뺀 절대 절감 상한과, 배치 순서·방문 집합을 보존하는 스케줄 재생의 실제 중첩 기회를 구한다. 시간 상한과 복잡도 대비 실용적 이득을 판단하며 다른 수집 비중의 사이트를 배제하지 않는다.

보수적 후보는 현재 active8를 넘지 않는 슬롯에서만 다음 FIFO 페이지 1개를 미리 수집한다. 결과의 페이지 admission, 링크 등록, 판정 후보 선택은 기존 순서에서만 수행한다. 준비 결과는 디스크에 저장해야 하며 실제 로딩 최대2페이지·미확인 요청 재전송 금지·취소 후 자원 정리·원체크포인트 보존을 요구한다. 관문 미통과 시 이러한 복잡한 비동기 변경은 구현하지 않는다.

출력은 시간 상한 및 동일 스케줄 재생 검증이다. API F1·실제 중첩 지연·새 사이트 일반화·동시 브라우저 안정성을 측정했다고 주장하지 않는다. 추가 시간 측정을 위해 기존 API를 재호출하지 않는다.
