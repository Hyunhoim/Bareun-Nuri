# 바른누리 사용설명서

## 결과 파일 위치 · 심사 시 확인

**결과 원본:** `01_실행/state/jobs/<작업 ID>/artifacts/result.json`

- **결과 JSON 저장**을 누르면 같은 결과를 브라우저 다운로드 폴더에 `result.json`으로 저장합니다. 같은 이름의 파일이 있으면 브라우저가 번호를 붙일 수 있습니다.
- 작업 ID는 `01_실행/state/jobs`의 각 폴더 안 `job.json`에 있습니다. 검사 URL과 시작 시각을 대조하면 해당 결과 폴더를 찾을 수 있습니다.
- 재개 후 원본은 누적 결과로 갱신됩니다. 첫 구간 결과는 **첫 구간 결과 저장** 또는 `artifacts/segments/0001/result.json`에서 확인합니다.
- 추가 유형은 구현하지 않아 **`result_extra.json`은 생성하지 않습니다.** `coverage.json`·`diagnostics.json`은 검사 범위·검토 항목을 위한 보조 기록입니다.

## 1. 실행하기

1. **제출 폴더 전체**를 쓰기 가능한 Windows 로컬 폴더에 복사합니다. ZIP으로 받았다면 먼저 압축을 풉니다.
2. `01_실행/바른누리_실행기.exe`를 더블클릭합니다. 실행기와 기본 웹브라우저의 검사 화면이 열립니다.
3. 왼쪽 **API 키 관리**에서 OpenAI API 키를 추가합니다.
4. 검사할 URL을 입력하고 **검사 시작**을 누릅니다.

Java·Node.js·Python·수집용 Chromium·AntiSpoof 모델이 포함되어 있습니다. 일반 실행에는 별도 개발 도구 설치나 모델 다운로드가 필요하지 않습니다. EXE만 따로 옮기면 실행되지 않습니다.

|항목|사용 환경|
|---|---|
|운영체제|Windows 11 x64|
|로컬 기법 모델|CPU 실행, GPU 불필요|
|화면|기본 웹브라우저, 로컬 주소 `127.0.0.1`|
|광고 의도 API|OpenAI Responses API, 모델 `gpt-6-luna`|
|API 키 변수|`OPENAI_API_KEY`|
|외부 연결|검사 대상 웹사이트와 OpenAI API에 접속 가능한 인터넷|

API 키에는 해당 모델의 호출 권한과 사용 가능한 API 잔액이 필요합니다. API 비용은 키를 발급한 계정에 부과됩니다. ChatGPT·Codex 구독과 API 결제는 별개입니다. Windows 기본 .NET Framework 4.x를 사용하며 ARM·macOS·Linux용 패키지는 아닙니다.

## 2. API 키 등록·교체

**API 키 관리**에서 키를 추가하거나 삭제합니다. 화면에는 키 일부만 표시됩니다. 등록 성공은 파일 저장 완료를 뜻하며 제공사의 인증 성공을 뜻하지 않습니다.

파일로 설정할 때는 실행기를 종료한 뒤 `01_실행/config/.env`에서 다음 항목을 수정합니다. 화면과 파일은 같은 키 저장소를 사용합니다.

```dotenv
OPENAI_API_KEY=발급받은_API_키
BROWSER_CHANNEL=chromium
```

키 교체 후 재빌드·재컴파일은 필요하지 않습니다. 진행 중에는 키 변경이 잠기며 다음 검사 또는 안전하게 재개 가능한 작업부터 변경된 키를 사용합니다. 제출본의 키는 비어 있습니다. **폴더를 다른 사람에게 전달하기 전에는 키를 삭제하세요.** 키 파일은 사용자 PC에 저장되므로 공유 폴더 보관은 피하는 것을 권합니다.

## 3. 검사·일시 중지·재개

**페이지 수집 → 광고 의도 판단 → 기법 판정 → 결과 저장** 순서로 진행합니다. 같은 출처의 연결 페이지를 FIFO로 탐색하고, 방문 페이지의 본문·제목·댓글·접근 가능한 iframe을 수집합니다. 외부 사이트로 이동하는 일반 링크는 제외 기록을 남기고 삽입 iframe은 별도로 검사합니다.

모니터와 그래프에서 수집·판정·발견 현황을 확인합니다. **시간 막대는 현재 구간 경과 시간**, 판정 완료율은 **수집 후보 기준**이며 사이트 전체 완료율은 아닙니다.

|상황|동작·선택|
|---|---|
|25분 도달|새 작업을 멈추고 진행 중인 작업과 결과를 저장합니다. 저장 완료까지 시간이 추가될 수 있습니다. **이어서 검사**는 새 25분 구간을 시작합니다.|
|사용자 일시 중지|**저장 후 일시 중지**를 누릅니다. 진행 중인 작업을 저장한 뒤 멈춥니다. 재개 시 같은 구간의 남은 시간을 사용하며 대기 시간은 차감하지 않습니다.|
|중단 후 종료|모니터 안의 **여기서 종료**를 누릅니다. 저장 결과를 보존하고 해당 작업의 재개를 종료합니다.|
|프로그램 종료|실행기 창의 **프로그램 종료**를 누릅니다. 브라우저 탭만 닫으면 검사는 계속됩니다.|

완료된 판정은 재개 시 재사용합니다. 응답 수신 여부를 확인할 수 없는 API 요청이나 코드·모델이 달라진 기록은 자동 재개하지 않습니다. 확정된 불완전 응답은 일반 검사가 끝난 뒤 작은 묶음으로 한 번만 복구를 시도하며, 실패하면 미판정으로 남깁니다.

한 번에 검사 작업 하나를 실행합니다. 구간당 최대 **200페이지·600 API 호출**이며 누적 후보 수 제한은 없습니다. 페이지당 수집 한도·메모리 보호와 로그인·접근 제한·늦게 로딩되는 댓글 등의 제약은 별도로 존재합니다. **검사 범위와 미처리 내역**에서 대기·제외·수집 실패·미판정을 확인하세요. 부분 결과가 사이트 전체의 정상 판정을 뜻하지 않습니다. 재개·다시 검사에는 API 비용이 추가될 수 있습니다.

## 4. 결과 확인·이력 관리

검사 구간이 끝나면 **탐지 결과**에서 항목을 선택하여 원문·URL·요소 위치·기법을 확인합니다. 검색과 기법 필터로 결과를 좁힐 수 있습니다. 같은 위치에 여러 기법이 확인되면 기법별로 별도 항목을 표시합니다.

**결과 JSON 저장**으로 내려받은 파일은 다음 구조입니다. 광고가 없어도 `findings`는 빈 배열로 포함됩니다.

|JSON 필드|내용|
|---|---|
|`meta.topic`|`TOPIC`|
|`meta.entry_url`|입력한 진입 URL|
|`meta.started_at`, `meta.finished_at`|검사 시작·구간 종료 시각, ISO 8601|
|`meta.elapsed_sec`|최초 시작부터 결과 저장 시점까지 경과 시간(초). 재개 전 대기 시간도 포함|
|`meta.tool_version`|프로그램 버전|
|`findings[].id`|파일 안에서 고유한 항목 ID|
|`findings[].url`, `location`|광고가 있는 페이지와 요소 위치. iframe 내부는 ` >>> `로 연결|
|`findings[].is_violation`|검출 항목의 광고 판정, `true`|
|`findings[].evidence_text`|정규화 전 원문|
|`findings[].technique`|`HOMOGLYPH`·`JAMO`·`TRANSPARENT`·`OFFSCREEN` 중 하나|

결과는 UTF-8(BOM 없음) JSON입니다. 한 요소에 여러 기법이 있으면 기법별 객체를 생성합니다. 광고 의도나 기법 근거가 부족한 항목은 **검토 필요** 또는 미처리 내역에 남으며 검출 목록에 임의로 채우지 않습니다.

**검사 이력**에서 당일·최근 7일·최근 30일·모두 보기를 선택하고 이전 결과를 열 수 있습니다. 기간은 이 PC의 날짜와 검사 시작 시각 기준입니다. 이력 삭제 시 해당 결과·근거·재개 기록도 삭제됩니다. 진행 중인 검사는 삭제할 수 없습니다. 내부 기록을 직접 편집하면 무결성 검사 또는 재개가 실패할 수 있습니다.

## 5. 문제 해결

|문제|확인할 내용|
|---|---|
|화면이 열리지 않음|실행기의 **검사 화면 열기**를 누르거나 표시된 주소를 브라우저에 입력합니다. 재실행하면 기존 실행기의 화면을 엽니다.|
|실행기 시작 실패|압축 해제·폴더 전체 복사·쓰기 권한을 확인합니다. `01_실행/logs/backend.log`에 상세 기록이 있습니다.|
|Windows 게시자 안내|코드 서명 인증서가 없는 실행 파일입니다. 본인이 받은 제출본과 경로를 확인합니다.|
|API 키 미등록·인증 실패|키 저장 여부, 유효성·모델 접근 권한·API 잔액을 확인합니다.|
|네트워크 오류|인터넷, 프록시·방화벽, 대상 사이트와 `api.openai.com` 접속 상태를 확인합니다.|
|요청량 제한|계정의 API 한도를 확인합니다. 제공사가 낮은 한도를 반환하면 프로그램이 요청 예산을 하향합니다.|
|부분 완료·미판정|검사 범위와 중단 이유를 확인합니다. 안전한 재개가 가능하면 **이어서 검사**를 선택합니다.|
|다시 검사 필요|오류 카드의 **다시 검사하기**는 기존 이력을 보존하고 처음부터 새 검사를 시작합니다.|

오류는 검사 모니터 아래 안내와 오류 기록에 표시됩니다. 강제 종료·전원 차단은 미확인 요청을 남길 수 있으므로 실행기의 종료 버튼을 사용하세요.

## 6. 제출 폴더 구성

```text
Bareun-Nuri 제출/
├─ 사용설명서.md
├─ 01_실행/
│  ├─ 바른누리_실행기.exe
│  ├─ app/                 # 화면 포함 백엔드·Agent·모델·외부 구성요소 고지
│  ├─ runtime/             # Java·Node.js·Python CPU·Chromium
│  ├─ config/.env          # API 키
│  ├─ state/jobs/          # 실행 후 생성되는 검사 이력·결과·중단 기록
│  └─ logs/                # 실행 후 생성되는 로그
├─ 02_소스코드/
│  ├─ README.md            # 소스 구성·실행·빌드·검증 방법
│  ├─ frontend/
│  ├─ backend/
│  ├─ agent/
│  ├─ scripts/
│  └─ licenses/            # 외부 구성요소 고지
└─ 03_신청서류/            # 신청서·서약서·동의서·기획서
```

가중치는 `01_실행/app/agent/models`에 한 벌만 제공합니다. 학습자료와 개발 실험 기록은 실행물에 포함하지 않습니다. 재빌드는 `02_소스코드/README.md`, 외부 구성요소 출처·이용 조건은 `01_실행/app/licenses` 및 각 런타임의 LICENSE·NOTICE·legal·dist-info에서 확인합니다.
