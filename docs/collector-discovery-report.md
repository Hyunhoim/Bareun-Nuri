# 동시 수집 2개 및 Katana 비교 결과

> 2026-09-30 후속 측정 주의: [동시5/10/15/20 보고서](collector-concurrency-high-report.md)에서 구형 PID 기반 자원 측정기의 집계 오염 가능성이 발견됐다. 아래 메모리 값은 원관측으로 보존하며 확정된 자원 비교값으로 사용하지 않는다. 속도/근거 결과와 분리한다.

2026-09-30. **기존 수집기의 동시 2개는 후속 검증 후보로 유지한다. Katana 사전 탐색 후 순차 수집 방식은 이번 조건에서 미채택한다. 운영은 변경하지 않았다.**

사전 계획: [collector-discovery-plan.md](collector-discovery-plan.md). 36개 로컬 실행을 완료했다. HCX 호출0, 외부 공공기관 요청0, 운영 소스 변경0이다. 수집 성능 진단이며 광고 의미 F1이나 25분 제출 종단 성능 비교가 아니다.

## 같은 URL 전체 수집

기존 createCollector/Playwright 1.62.1/headless Edge를 그대로 사용했다. 작업당 브라우저 하나, URL마다 독립 context, 기존 최소1초·최대5초 안정화, 원문·문맥·스타일·좌표·iframe·기법 관찰을 유지했다. 동시성만1→2로 바꾸고 FIFO dispatch 순서로 결과를 반영했다. AB/BA/AB 세 쌍을 비교했다.

| 자료 | 페이지 / 후보 | 동시1 중앙값 | 동시2 중앙값 | 시간 감소 |
|---|---:|---:|---:|---:|
| 기존 mixed-0 합성 사이트 | 27 / 147 | 35.97초 | 21.48초 | 40.27% |
| 댓글·iframe·상태 격리 동작 검사 | 8 / 22 | 12.57초 | 7.97초 | 36.61% |
| 부산 실제 DOM 복제본 | 20 / 3,543 | 36.87초 | 22.40초 | 39.26% |
| 자료군별 중앙값 합 | 55 / 3,712 | **85.41초** | **51.84초** | **39.30%** |

합계 행은 자료군별 중앙값의 합이며, 하나의55페이지 연속 실행 시간이나 운영 전체 속도 개선율이 아니다. 브라우저 시작/종료·페이지 근거 저장을 포함하고 별도 측정기 종료 대기는 제외했다.

- 9쌍 모두 동시2가 빨랐다. 신규 수집 실패0, 누락된 기존 근거0.
- 고정 URL 실험은330회 페이지 수집·22,272개 후보 관측이다. 고유 후보 수를 반복 수만큼 부풀린 학습/검증 표본이 아니다.
- 제목·원문·정규화문·귀속 문맥·스타일·좌표·링크·프레임 경로·기법 관찰을 URL별로 대조했다. 수집 시각/대기 시간만 비교에서 제외했고, 이슈 목록의 순서만 정렬했다.
- 합성 사이트의 광고12개/정상12개 위치가 매번 보존됐다. 동작 검사의 기대 요소20개도 보존됐다. 원래 존재하는 클릭 후 댓글·6초 지연 댓글 미수집은 그대로이며 해결됐다고 주장하지 않는다.
- 실제 DOM 복제본 원문 전체에 정상/광고 라벨을 임의 부여하지 않았다. 3,543개 후보의 근거 보존을 확인한 결과다. 원격 네트워크와 원래 JavaScript/iframe 동작을 재현하는 자료는 아니다.

동시1의 자료군별 구간 합 중앙값은 안정화60.19초, 탐색 이동3.27초, 추출8.74초, 페이지 생성7.49초였다. 대기를 겹치는 것이 유리하다는 가설과 일치한다. 병렬 조건의 구간 시간 합은 벽시간과 달라 속도 계산에 사용하지 않았다. 실제 기관 웹사이트의 현재 병목 비율은 이번 로컬 재생으로 확정하지 않는다.

## 20초 탐색 + 근거 수집

두 기존 합성 사이트에서 조건마다 같은 시작 URL·동일 출처·20초·최대40개 브라우저 페이지를 적용했다. 세 조건을 순환 순서로3회씩 실행했다. 아래는 각3회 중앙값이다. 광고 위치는 전체 사이트의12개를 분모로 두었으며, 판정한 광고가 아니라 정답 원문과 위치까지 수집한 광고다.

| 사이트 | 방식 | 수집 완료 페이지 | 수집 후보 | 광고 위치 / 12 | 정상 통제 위치 | 전체 HTTP 요청 |
|---|---|---:|---:|---:|---:|---:|
| mixed-0 | FIFO 동시1 | 15 | 87 | 5 | 5 | 18 |
| mixed-0 | FIFO 동시2 | **24** | **133** | **10** | **10** | 29 |
| mixed-0 | Katana → 동시1 | 8 | 54 | 1 | 1 | 40 |
| mixed-1 | FIFO 동시1 | 15 | 85 | 5 | 5 | 16 |
| mixed-1 | FIFO 동시2 | **24** | **128** | **10** | **10** | 28 |
| mixed-1 | Katana → 동시1 | 8 | 54 | 1 | 1 | 41 |

mixed-0 동시1은14/15/15페이지, Katana 광고 위치는0/1/1개였다. 다른 표의 핵심 페이지/광고 수는3회 동일했다. 20초까지 저장된 근거만 집계하고, 중단된 수집21건은 미완료로 남겼다. 브라우저 종료까지 총벽시간은 약20.49~20.57초였다. 종료 여유에 추가 수집을 하지 않았다.

Katana는 공식 v1.7.0 Windows 배포본이다. 압축파일 SHA256 `8d9632f95dfeae3bd6847971dbf6bef18f395056236fe7e43499d46b9789d278`을 공식 릴리스 digest와 대조했다. standard HTTP/breadth-first/depth20/동시2/5요청초/80페이지·8초 상한/재시도0/동일 출처 scope를 사용했다. 자동 폼 제출·클릭·headless·JS 추가 파싱·경로 추측은 사용하지 않았다. 쿼리 값은 보존하고 본문 중복 필터를 해제했다.

HTTP 탐색이 끝난 뒤 결과 URL을 FIFO에 넣고 기존 브라우저로 수집했다. 브라우저가 추가 발견한 링크도 큐에 넣었다. Katana 사전 탐색8.13~8.15초와 추가 요청도 공통20초에 포함했다. Katana가 발견한29/30주소에는 별도 프레임 문서 주소가 포함되므로, 이를 일반 페이지 발견 재현율로 직접 비교하지 않는다.

**실패 원인 해석:** 사전 탐색이 브라우저 수집 예산을 소비했고, Katana 반환 순서가 기존 DOM anchor 순서와 달라 정보·목록·경유 페이지가 앞에 배치됐다. 둘의 단독 인과효과를 분리하지 않았다. HTTP 주소를 많이 얻은 것이 광고 원문 수집량 증가로 이어지지 않았다.

이 결론은 **사전 탐색 완료 후 브라우저 수집하는 이번 구성**에 한정한다. URL 발견과 브라우저 수집을 동시에 진행하는 구성, JS 엔드포인트가 많은 사이트, Katana headless는 실행하지 않았다. 이 실패를 Katana 일반 성능의 열위로 확대하지 않으며, 결과를 보고 설정을 계속 바꾸는 추가 실험은 하지 않았다.

## 자원·경계·감사

- 고정 URL 실행의 프로세스 하위 트리 최대 working-set 합: 동시1 **1,347MiB**, 동시2 **1,507MiB**. Node·브라우저·측정 PowerShell을 포함하며 공유 페이지가 중복 계산될 수 있다. 한 Node 프로세스에서 조건을 순환했으므로 GC·이전 실행의 잔존 메모리 영향도 있다. 순수 물리 메모리 증가량이나 배포 시 필요 RAM으로 해석하지 않는다. CPU는 살아 있는 프로세스의 누적값을 표본 저장했으며 종료된 프로세스 때문에 단순 차분으로 총CPU 사용량을 만들지 않았다.
- 실제 요청 로그에서 로컬 fixture의 GET/동일 출처 및 허용 프레임 출처 경계를 확인했다. 일반 외부 링크 요청0. 일반 인터넷 대상 리다이렉트·SSRF 안전성을 이번 Katana 진단으로 검증했다고 주장하지 않는다.
- 저장 원본611개 페이지·23,890개 후보 관측을 다시 읽었다. 비교 가능한 공통 후보 관측11,957개의 내용 차이0, 공통 페이지의 전체 근거 차이0, 후보ID 중복0. 정답은 사후 위치 대조에만 사용했다.
- 고정 URL의 사전 속도/보존 기준은 전부 통과했다. Katana는 광고 위치 보존과 완료 페이지 증가 기준에 실패했다. 사후 기준 변경은 없다.
- 운영 관련8파일 및 실행기·계획 파일의 전후 SHA256이 같았다. 운영에 연결하거나 기존 체크포인트를 바꾸지 않았다.
- FIFO 순서·출처·쿼리·시간 초과 취소 자체검사, 원본 재집계·해시 감사를 통과했다. 동시 수집의 운영 저장/재개 및25분 HCX 연동은 미검증이다.
- Graphify는 관련 최신 소스만 별도 복제하여 정적으로 갱신하고 실제 코드로 확인했다. Graphify LLM 입력/출력 토큰0. Katana 실행 환경 점검 중 설정 경로 실패·제한 환경에서 요청0이 발생한 준비 실행은 성능 표에서 제외했다. 연결이 확인된 동일 호스트 환경으로 모든 본 비교 조건을 맞췄다.

## 결정과 파일

기존 수집기의 동시2를 유망한 후속 후보로 보존한다. 다음 채택 검증은 실제 사이트의 동일 입력·자원·수집 누락 확인, 운영 스케줄러의 저장/취소/재개 검증, 같은25분 HCX 조건의 최종 정탐·오탐 비교가 필요하다. 이번39.30%를 전체 운영 가속으로 표시하지 않는다. Crawlee 도입은 이번 비교에 필요하지 않았고 실행하지 않았다. 운영 FIFO·동시1·HCX12묶음은 그대로다.

- 실행기: `agent/experiments/collector-discovery-run.cjs`
- 저장 원본 감사: `agent/experiments/collector-discovery-audit.cjs`
- 결과: `.runtime/collector-discovery-v1/summary.json`
- 원본 재검증: `.runtime/collector-discovery-v1/independent-audit.json`
- 설정/소스: `.runtime/collector-discovery-v1/manifest.json`, `source-after.json`
- 각 조건 디렉터리: `page-*.json`, `result.json`, `timings.json`, `resources.json`, Katana 조건의 `katana.jsonl`·`discovery.json`

재검증: `node agent/experiments/collector-discovery-audit.cjs .runtime/collector-discovery-v1` (API0/브라우저0). 원본을 덮어쓰지 않고 새 실험은 다른 출력 디렉터리를 사용한다.
