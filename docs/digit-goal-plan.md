# 숫자 치환 문맥·누락 개선 Goal 실험 계획

2026-09-26. 목표는 기존 정탐 보존, 문맥 혼동과 치환 누락 감소, 운영에 맞는 채택이다. 한 후보가 실패하면 원래 기준선으로 돌아가 별개의 공통 원인 가설을 시험하며 결과 맞춤 예외는 쌓지 않는다. 운영 적용은 독립 자료와 운영12배치·25분 종단 검증 뒤 결정한다. 위험한 무한 유료 반복 대신 단계별 예산·가설·진입 기준을 고정한다.

## 1차 병렬 가설 파일럿

- R: D의 원문·읽기후보·프롬프트·출력을 그대로 유지하고 같은 토큰의 상충 문맥을 요청에서 분리한다. 슬롯별 순환으로 각 대상의 묶음 내 위치를 보존하고 후보 집합/호출 수/배치4를 유지한다. 실행 순서와 동료만 바뀐다. 일반화된 토큰 비교만 사용하며 정답·역할·단어 목록을 보지 않는다. 실험의 사이트간 혼합을 그대로 운영에 가져오지 않는다.
- K: D와 완전히 같은 입력/묶음/읽기후보를 사용하고 classification만 출력한다. 읽기 선택과 자유 인용의 출력 계약을 함께 제거한다. 완전복원 F 입력이 아니라 D 입력이다. 복원 정답은 미측정이며 점수0이나100으로 취급하지 않는다.
- 대조: 직전 digit-complete-live-v1 D의 두 순서를 재사용해 API 낭비를 줄인다. 기존 두 실제 실험에서 D의 동일 요청 변동도 측정했다. 이는 선별용 역사적 대조이며 최종 효과 판단에는 신선한 동시기 대조가 필수다. 시간·비용은 이번 방법만 먼저 측정하고 과거 지연 대비 인과를 주장하지 않는다.

자료는 기존112개 진단자료이며 새 홀드아웃이 아니다. 분할별 R/K 원래 순서·K/R 역순으로 총8조건112요청. HCX007 none/temp0/seed42/출력1024/배치4/58k/순차API, 조건 전61초 분리. 1차 최대160요청/예약80만토큰/1시간, 조건10분. 자동형식복구/재시도 없음. 미확인통신/429/한도변화/소스변화는 전체종료, 확인된HTTP200형식실패는조건실패로보존한다. 자료제작·방법구현·운영검토는 병렬이다.

유망성 판단은 두 분할의 치환 정탐과 대조 정탐 위치 보존, 정상 오탐·모호 과도확정,3분류macroF1,順序변동을 함께 본다. 정탐 손실0을 우선하고, 누락 감소와 문맥 혼동 감소가 어느 지표에서 실제 관측됐는지 분리한다. 작은 평균변동 하나로 후보를 버리거나 채택하지 않으며 원시 손익을 보고한다. K는 인용을 출력하지 않으므로 인용오류0을 혼동해결로 주장하지 않고 대조 문맥의 정답과 독립 평가로 판단한다.

## 후속 진입

독립 작업자가 새 단어 계열·실제 템플릿·사이트를 분리한 자료를 먼저 봉인한다. 모델 수정 담당자는 해당 평가 결과를 보기 전에 후보를 고정한다. 긍정 해석뿐 아니라 숫자 일부를 원래 규격/수량으로 보존해야 하는 표기도 넣는다. 1차에서 유망하면 동시기 D/후보 비교로 검증한다. 미흡하면 같은 실패 문구를 튜닝하지 않고 단일 대상 판정 또는 더 명확한 입력 귀속 등 다른 가설을 별도 계획 후 한정 비교한다.

운영 광고의 의미 판정과 숫자 기법 판정은 다른 경로다. 기법실험 승리를 광고F1개선으로 주장하지 않는다. 운영 연결은 저장/재개·미확인요청 거부·기존관찰·원문위치 계약을 보존해야 한다. 다음 단계의 구체 호출 예산과 채택 기준은 실행 전에 추가 문서로 고정한다.
