# 자모 근거 검증의 자동 구간 통합 진단

2026-09-30. 앞선 후처리 단독 결과를 실제 운영 자동구간추출·CPU모델·기법 통합에 연결했다. 결론은 **근거 검증 단독 운영 채택 보류**다. 순수자모 오귀속은 줄지만, 옆 숫자치환을 모델이 미확정으로 남기면 최종 후보의 H 탐지가 사라진다. 앞선 '추가 정탐 손실0'은 수동 지정 구간 평가 범위의 결과였으며 자동 구간 합집합까지 확장할 수 없다.

## 검증한 계약

실험 후처리는 모델의 H 증거 중 자모만으로 구성된 구간을 미확정으로 옮긴다. 원래 모델 확률·라벨을 감사용으로 보존한다. 코드 증거는 건드리지 않으며 광고 의도·J 증거·다른 문자 혼합 구간은 유지한다. 운영 소스는 변경하지 않았다.

실제 패키지 CPU모델로 9후보/14구간을 처리했다. emoji의 UTF-16 위치, NFD/공백자모/전각영문/붙어쓴 혼합표기, 정상 의도 제외를 확인했다. 코드 확정 보존, 다른 구간 H 보존, 저장 결과 재개 시 재판정0, 정책 서명 변경 거부를 검사했다. 3개 H 근거를 미확정으로 변경했다. 모델 시작을 포함한 1회 추론6.828초, 후처리0.666ms이며 반복 CPU 지연평가나 종단 속도 개선 수치는 아니다.

최초 저장재개 검사에서 테스트 대역이 4개 요청에 9개 응답을 반환해 실패했다. 운영 12묶음을 명시하고 요청 ID에 맞춰 응답하도록 테스트 대역을 수정한 뒤 새 디렉터리에서 통과했다. 기존 실패 체크포인트를 변조/재개하지 않았다. 이는 실험 대역 오류이며 운영 결함으로 보고하지 않는다.

## 자동구간 108후보 진단

기존 관찰 진단자료에서 일반영문 옆 자모54개와 숫자치환 옆 자모54개를 가져왔다. 기존 수동 target 표시를 제거한 원문에 운영 `queries`를 적용했다. 각 후보를 실제 CPU모델이 자모·영문 두 구간으로 판정하고 운영 `integrateObservations`로 합쳤다. 광고 의도는 통제된 true이며 실제 HCX 호출이나 실제 게시물 광고 평가가 아니다. 자료는 이미 관찰한 합성 진단이므로 독립 일반화 평가도 아니다.

|후보 단위 관찰|기존|후처리|
|---|---:|---:|
|일반영문 옆 자모54: H 확정|1|0|
|숫자치환 옆 자모54: H 확정|23|0|
|J 확정(전체108)|108|108|

23개의 원래 H 근거는 모두 자모에 잘못 귀속되어 있었다. 후처리는 이를 올바르게 보류했지만, 숫자치환 구간 자체의 미확정은 복구하지 못했다. 따라서 '오귀속23개 해결'만 보고 기법 성능 개선으로 채택하면 안 된다. 생성 설계상 H가 있는 후보54개의 H 확정은 오히려23→0으로 감소했다. **잘못된 근거의 탐지 유지와 정확한 근거로의 교정을 구분해야 한다.** 이는 광고 의도 누락23개라는 뜻은 아니다.

자동구간 실행은108후보/216구간27.60초(시작 포함1회), API0. 코드/모델/프롬프트 불변이며 추가 학습·최종860접근·25분 제출 검증0이다.

## 판단과 다음 실험

독립 자모 검증은 연구용 진단으로 보존하되 단독 운영 승격은 중단한다. 목표는 자모 근거를 지우는 것에서 끝나지 않고 실제 치환 구간에서 H 근거를 회복하는 것이다. 앞선 구간대조 보강모델을 동일 자동구간에서 확인해 학습 효과가 실제 입력 계약에서도 나타나는지 우선 비교한다. 개발·회귀의 정탐 손실 문제는 그대로 남으므로 자동구간 결과 하나만으로 승격하지 않는다. 이후 Unicode 보조근거의 자모정규화/기타문자대응 구분은 별도 요인으로 실험할 수 있다. 결과를 보고 기존 진단 문구를 학습시키지 않는다.
