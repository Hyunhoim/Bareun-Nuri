# 0·1순위 실행 계획 — 2026-09-25

사용자 승인 범위: 제출 실행 계약 구현과 수집 근거 전달 개선의 독립 검증. FIFO/브라우저 재사용/HCX-007 none/최대16개 순차 배치를 유지한다. 새 탐색 정책·동적 클릭·모델 교체는 하지 않는다.

## 0순위

- 기본 검사 구간25분, 누적 후보 수 제한 없음(0으로 명시), 구간당 페이지/호출 보호 한도는 별도 표시. 각 구간마다 새 작업은 마감 이후 시작하지 않는다. 진행 중 요청 정리/체크포인트/브라우저 종료를 포함해 첫 실행30분 이내로 검증한다.
- 기존 core checkpoint를 재사용해 웹 이어서 검사/여기서 종료를 연결한다. 구간별 결과/시간, 최초 시작부터 경과시간, 누적 실행시간을 분리한다. 같은 작업 재개는 완료 판정·FIFO 순서·범위를 보존한다.
- 전송 전 대기와 전송 후 미확인을 구분한다. 미확인 전송은 재개를 막고 자동 재호출하지 않는다. 전송 실패의 추측성 자동 재시도를 제거한다.
- 후보 상한 해제와 자원 무제한을 혼동하지 않는다. 메모리 보호 중단/미판정·대기 상태를 남기고 페이지당 추출 상한은 별도 범위 한계로 표시한다. 이번에는 저장 계층 전체를 재설계하지 않는다.
- 검증: 짧은 마감/대기/전송 중/완료/실패·강제 중단 재개, 기존 Agent·수집기 회귀, React→Spring→worker Mock 흐름, 실제1500초 마감(LLM 비용 없는 제어된 입력)과30분 내 저장·종료. 판정 프롬프트와 배치 동일성 유지.

## 1순위

관측: 수집된 context_evidence/ancestors가 운영 입력에 빠진다. 가설: 근거를 대상/참고 문맥으로 나눠 전달하면 인용·귀속 및 조상 은닉 판정이 나아질 수 있다. 과거 유사 시도에서 오탐/보류 회귀가 있었으므로 개선을 전제하지 않는다.

- 운영 입력은 고정하고 실험용 initialEvidence만 확장한다. 문맥만 추가한 조건, 조상 스타일만 추가한 조건을 각각 기본값과 비교한다. 의미 프롬프트·출력 계약·모델·순서·배치는 유지한다. 두 효과가 혼합된 새 기본값을 바로 만들지 않는다.
- 알려진 stage4 파일럿의 라벨76개를 원래 순서로 사용한다. 기존 관찰 자료이므로 회귀 진단이다. 기본A1→문맥B→스타일C→기본A2를 실행하고 코드/입력/라벨을 실행 전 동결한다. 조건별 원본 근거 동일성, 대상 ID·라벨 비전달을 검사한다.
- 사전 관문: 두 기본 실행이 공통으로 확정한 광고 손실0, 각 기본 대비 정상 FP 증가0, 의미F1 비감소, 기법 평가 대상의 정답 일치 비감소. 문맥 조건은 FN 또는 FP 최소1건 감소, 스타일 조건은 기법 정답 최소1건 증가가 필요하다. 토큰/시간 증가는 더 느린 기본 대비20% 이내. 실패 시 해당 안은 미채택하고 같은 문구로 재조정하지 않는다.
- 통과한 안만 별도 자료 및25분 제출 조건으로 확대한다. 그 전에는 일반화 개선/운영 채택을 주장하지 않는다. 이전 실패 사례 맞춤 예외를 추가하지 않는다.
- 유료 진단 상한: 최초4조건 합계32시도/400,000 예약 포함 토큰/1시간. 응답 불명·형식 복구 실패 시 중단하며 미확인 요청 자동 재실행 금지. 추가 확대는 별도 계획과 남은 예산을 확정한 뒤 수행한다. 키는 환경파일에서만 읽고 출력하지 않는다.
