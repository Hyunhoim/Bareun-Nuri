## 조건과 해석 범위

기존 공공기관 DOM 복제본의 원문·문맥·스타일을 그대로 수집했다. 소형은 목록과 첫3상세, 중형은 목록과10상세, 대형은 이전에 수집한20페이지다. 광고 정답에 따라 페이지를 고르지 않았다. 자연 탐색 난이도와 작업량을 분리하려고 해당 URL 목록을 고정해 제공했다. 따라서 홈페이지에서 게시판을 찾는 성능이나 심사 자료의 규모를 예측하는 실험이 아니다. 같은 관찰 복제본을 재사용한 진단이며 새 홀드아웃이 아니다.

## 발견한 병목과 수정의 효과

소형은 모든 후보를 검사해도 광고2개를 놓쳤다. 실제 입력에 거래 설명이 있는 짧은 링크와 띄어쓰기 없는 판매 명사구의 의미 판정 실패다. 대형의 누락10개는 미판정7개·의미 오류3개이며 광고28위치는 모두 수집됐다.

중형 C는197번째 HTTP200/stop 응답에서 실패했다. 완전한 decisions JSON 뒤에 설명 문장이 붙어 JSON.parse가 거부했고,889.60초에 남은 작업이 중단됐다. 시간 한도 실패가 아니다. 원본 실패 기록은 보존하고 자동 재호출하지 않았다.

응답 처리 개선은 선두의 완전한 JSON 객체 하나와 일반 설명 꼬리를 구분한다. 앞 설명, 추가JSON/배열/코드블록, 중복키, 잘린JSON, 잘못된 후보ID/필드는 계속 거부한다. 모델의 분류값을 추론·수정하거나 정상으로 대체하지 않는다. 기존 HTTP/finish 검증·스키마 검증·원응답 저장도 유지한다.

별도 새 중형 실행은1,156.40초에1,113원문/1,127작업/통제64위치를 모두 판정했다. **TP18→25, FP2→4, FN10→3, F1 75.00→87.72%**이며 요소×기법 F1은70.00→82.61%다. 기존18정탐은 모두 유지됐고 미판정 광고7개가 모두 추가 탐지됐다. 의미 누락3은 그대로다.

공통197개 요청 본문과 문제197번째 원응답이 완전히 같다. 기존 코드는 이 응답에서 실패했지만 수정안은3개 판정을 검증·저장하고 추가91호출을 이어갔다. 새 실행에서 설명 꼬리 처리는1회 발생했다. 공통 판정 통제 위치의 이진 변화0이다. 따라서 중단 해소는 처리 수정의 효과이며, 모델 의미 능력 개선이 아니다. 오프라인1,713원응답 재생에서도6,766기존 판정이 모두 일치했고 실패3판정만 추가로 해석했다(API0).

정상 오탐 증가2개는 기존 미판정이던 예방 인용 제목과 예방 안내문에서 발생했다. 같은 입력의 정답→오답 회귀는 아니지만 최종 정밀도 저하에 포함했다. 정답 밖 양성은8→9개로, 추가1개는 실제 광고 설명 문단이다. 기존 작성자 오탐1은 그대로 남는다. 이를 공통 정상으로 사후 추가하면 수정 중형 F1은86.21%다. 중첩 광고 부모4개를 별도 정탐으로 가산하지 않으며 전체 사이트 정밀도로 부르지 않는다.

## 운영 반영과 검증

- `agent/src/core/json-envelope.cjs`: 단일 완전 JSON과 설명 꼬리 구분, 모호한 출력 거부.
- `agent/src/core/llm.cjs`: 응답 포장만 처리하고 기존 스키마·후보 귀속 검증 유지.
- `agent/src/worker.cjs`: 새 모듈을 코드 서명에 포함. 옛 코드·실패 체크포인트 자동 이행 금지.
- `npm run test:response`: 네트워크stub으로 의미 보존·잘림·ID/스키마·중복·추가JSON·자동재시도 금지 확인.

실제 worker의 설명 꼬리 응답을 포함한 중단·재개, 이전 구간·원문 보존, 옛 서명/미확인 요청 거부와 기존 Agent 계약 검사를 통과했다. `.runtime/bounded-worker-check-1790370620113/result.json` 참고. 실제 비교와 소스 감사를 마친 뒤 반영했다. 원래 중형 실패 실행을 수정한 것이 아니라 별도 새 실행에서 검증했다. 추가 유료 확대와 push는 하지 않았다.

실험 navigation 목록을 바꾼 snapshot의 기존 snapshot_sha256는 원래 collector 출력 해시다. `scale-summary.cjs`가 원래 navigation을 복원해 이 해시를 확인하고 별도 derived_fixture_hash를 기록한다. 체크포인트/저장 파일 해시는 변경된 실제 파일을 검증한다. 원본 측정 파일을 덮어쓰지 않았다.

운영 반영 후 실제 운영 createSession으로 새 중형까지 포함한2,001원응답을 다시 검증했고7,893기존 판정이 모두 일치했다. 원래 실패3개만 추가 해석됐으며 새 유료 호출은0이다. `.runtime/envelope-operating-audit-v1.json`과 `.runtime/semantic-adoption-check-1790370907298/check-result.json`을 참고한다. 후자는 운영 C의1,845실제 요청 대상·동결 실험 전체 요청 일치, 장문·관찰·재개·미확인 전송 거부도 확인했다.

## 최종 판단

1. **형식 오류로 전체 검사가 멈추는 문제는 이번에 수정·채택했다.** 유효한 판정을 그대로 보존하는 신뢰성 개선이다.
2. **작은·중간 규모는 의미 판정 오류를 다음 우선순위로 둔다.** 중형까지 완주했으므로 처리량 확대만으로 남은 의미 누락3·통제 오탐4·작성자 오탐을 해결할 수 없다.
3. **대형 처리량은 별도 과제로 유지한다.** 현재25분에는 원문의 약절반만 판정했다. 부분결과/재개를 유지하고 정상 후보 일괄제외나 신호 기반 삭제로 정확도를 희생하지 않는다. 이번 형식 수정이 대형 시간 병목을 해결한 것은 아니다.

심사 자료가 작을 것이라고 예측하지 않는다. 같은 실패 문구에 맞춘 반복 프롬프트 조정은 과적합 위험이 있어 시행하지 않았다. 준비한 scoped-input 문맥 제거안은 신뢰성 병목을 우선 해결하면서 유료 실행 전에 보류했다(API0). 원문·문맥 삭제는 운영에 적용하지 않았다.
