# 수집·판정 대기 중첩 진단

2026-09-26. **현재 자료에서는 운영 미채택, 비동기 구현·유료 확대 없이 종료를 권고한다.** 실제 실행 속도를 개선했다고 주장하는 결과가 아니라, 이미 관측한 C 실행에서 숨길 수 있는 수집 시간의 상한을 계산한 진단이다.

## 측정

입력은 `.runtime/jamo-context-live-c-v1`의 25분 실행이다. 수집20페이지/판정467요청을 기록 그대로 사용했다.

| 구간 또는 가정 | 시간 |
|---|---:|
| 전체 페이지 수집 | 33.599초 |
| 최초페이지를 제외한 수집 전체 | 31.792초 |
| 각 수집을 직전 API 호출 대기 하나에만 겹친 상한 | 25.895초 |
| active8를 늘리지 않는 슬롯이 있는 경우만 겹친 상한 | 11.416초 |
| API 실제 응답 대기 합 | 955.691초 |
| API 사용량 제한 등 큐 대기 합 | 446.322초 |

31.792초는 25분의2.119%, 보수적인11.416초는0.761%다. 수집 시작점의 다음 URL이 이미 알려져 있고, 동시 실행해도 수집 비용과 API 대기 길이가 바뀌지 않는 낙관적 가정이다. API 할당량 대기가 지배하면 수집을 빨리 끝내도 다음 전송이 빨라지지 않아 실제 절감은 더 작을 수 있다. 이후의 새 방문·미관측 API 시간을 추측하여 F1을 산출하지 않았다.

운영 admission은 한 판정 차례당 다음 FIFO 페이지1개를 추가하되 미완료 active8까지만 허용한다. 활성8개가 찬 동안에는 후보 판정을 계속해야 다음 수집 슬롯이 열린다. API 대기 전체446초를 수집 단축분으로 볼 수 없다. 준비 snapshot을 별도로 들고9번째 페이지를 숨기는 것은 이번 제한적 중첩과 다른 메모리 변경이다.

## 검증과 변경 위험

실제 work 길이와 각 요청 크기로 SRPT8/aging8를 재생해467회 선택 페이지, 요청 배치의 모든ID와 내부 순서,20페이지 admission 순서, 마지막 offset과 active 순서를 원본과 대조했다. 모두 일치했다. 실행 스크립트와 운영 bounded core, 세부 계획, 입력 SHA256을 `.runtime/overlap-diagnostic-v1`에 보존했다. 이는 기존 스케줄 재현 검사이며 새로운 비동기 실행의 취소·재개 검사가 아니다.

실제 구현에는 다음을 추가 검증해야 한다. 현재 판정 데이터와 collector 결과가 함께 있을 때 최대2페이지 로딩을 지키고, 결과를 디스크에 먼저 저장하며, 다음 기존 admission 시점까지 링크와 후보 선택에 반영하지 않아야 한다. 취소 시 pending 수집을 정리하고 미전송/미확인 API 상태를 분리해야 한다. 준비 snapshot의 무결성·재개 일치도 필요하다. 이 비용에 비해 해당 자료의 절감 상한이 작으므로 운영 복잡도를 추가하지 않았다.

## 한계

- API0, 브라우저0, 운영 소스 변경0. 새 F1 측정이나 정확도 동일성의 실제 모델 검증은 아니다.
- 초기 수집 합계를 확인한 뒤 세부 진단 계획을 작성했으므로 결과 전 수치 채택 관문을 소급 주장하지 않는다. 판단 기준은 공통 사전 계획의 효과 대비 위험이다.
- 로컬 실제DOM 복제본이며 이미 관찰한 회귀 자료다. 느린 실사이트에서는 수집 비중이 달라질 수 있다.
- 실행: `node agent/experiments/overlap-diagnostic.cjs`.

## 후속 서비스 기회 산술 진단

별도 페이지 순서 진단의 미판정7개 순번을 사용했다. 과거467요청의 평균 API 경과시간(사용량 대기 포함)은3.002초, 전체 벽시간/요청은3.213초다. active8보존11.416초를 이 평균으로 나누면3.80 또는3.55요청, 완전한 슬롯으로는약3회다. 절대상한31.792초는10.59 또는9.90요청, 약9~10회에 해당한다. **미래 API 시간이 같다는 보장은 없고 실제 추가 호출 수의 상한도 아니다.**

기존 순서에서 가장 가까운 미판정 광고도 해당 페이지에4회 추가 판정 기회를 줘야 도달한다. 나머지는5/6/9/10/15/15회다. 따라서 평균 처리량의 보수적3회 시나리오에서는 새로 해당7개에 도달하지 못한다. 이것을 중첩의 실제 TP 개선0 증명으로 해석하지 않는다.

새 수집을 완전히 막고 현재20페이지만 기존 SRPT8/aging8로 계속 판정하는 인위적인 보조 시나리오에서는 첫 미판정 광고까지28슬롯, 나머지37/47/54/77/83/83슬롯이다. 실제 운영은 완주페이지가 생기면 다음 FIFO 페이지를 admission하므로 이 순서도 미래 운영 예측이 아니다. 미래 snapshot이 없어 추가 광고나 F1은 계산하지 않았다.

실행: `node agent/experiments/overlap-slots.cjs`. 결과: `.runtime/overlap-diagnostic-v1/slots.json`.
