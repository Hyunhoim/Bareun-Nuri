# 수집 동시성 및 Katana 비교 사전 계획

2026-09-30. 사용자가 동시 수집 1/2 및 Katana URL 발견 후 기존 수집 비교를 승인했다. 운영 코드·HCX·기법 판정은 변경하지 않는다. API 호출 0, 외부 기관 대상 요청 0인 로컬 진단이다.

## 가설과 고정 조건

- 대기 중심 수집에서는 독립 context 2개의 로딩을 겹치면 동일 근거를 더 빨리 수집할 수 있다. 기존 createCollector를 그대로 사용한다.
- Katana HTTP 발견은 브라우저에서 링크를 발견할 때보다 빠를 수 있으나 HTTP 추가 비용, 동적 링크 누락, 발견 순서 차이로 최종 근거 수집량이 줄 수도 있다.
- Playwright 1.62.1/headless Edge, 원래 viewport/요청 경계/원문·문맥·스타일·좌표/iframe/최소1초·최대5초 안정화/observeTechniques=true를 고정한다. 후보를 유형·신호·라벨로 제외하지 않는다.
- FIFO 큐의 결과 반영은 dispatch 순서로 고정한다. 완료 순서에 따라 방문 우선순위를 바꾸지 않는다. 원래 쿼리를 보존하며 동일 출처 전체 경로를 탐색한다.

## A: 동일 URL 전체 수집

기존 mixed-0 전체 27페이지, 기존 behavior 8페이지, 저장된 부산 실제 DOM 복제본의 사전 고정 20페이지를 동시1/동시2로 비교한다. 3쌍, AB/BA/AB. 페이지당1만 후보·전체 실행당600초 상한. 기존 자료는 회귀자료이고 새 독립 홀드아웃이 아니다. 부산 원문 전체에 광고/정상 정답을 임의 부여하지 않는다.

원문·정규화·문맥·스타일·좌표·링크·프레임·기법관찰의 동일성을 URL별로 비교한다. 수집 시각/소요시간만 제외한다. 알려진 클릭/6초 지연 미수집은 별도 보고한다. 브라우저 시작/종료 및 근거 파일 저장까지 벽시간에 포함한다. 구간 합산시간은 병렬 실행 벽시간과 구분한다.

확대 판단: 각 자료에서 3쌍 중2쌍 이상 빠름, 전체 중앙값 합10% 이상 감소, 기존 근거 손실0, 신규실패0. 미달이어도 결과를 보존한다. 통과는 운영 채택이 아니다.

## B: 같은 시간 안에 탐색 + 근거 수집

mixed-0/mixed-1에서 20초 공통 예산, 조건마다 최대40개 브라우저 페이지, 3회 순환 순서로 비교한다.

1. 기존 FIFO + 동시1
2. 기존 FIFO + 동시2
3. Katana standard HTTP 발견 + 기존 수집 동시1

Katana v1.7.0 공식 Windows 배포본 SHA256을 검증한다. breadth-first/depth20/동시2/초당5요청/최대80HTTP페이지/최대8초/재시도0/자동폼·클릭·headless·경로추측 없음. 동일 출처 scope, 쿼리 무시/유사URL 필터 사용 안 함, 출력 본문 중복 필터 해제. Katana 발견 과정의 시간·요청도 20초 예산에 포함한다. 발견 URL은 원문 주소 그대로 기존 브라우저 수집기로 전달하며 이후 브라우저가 발견한 링크도 같은 FIFO 큐에 추가한다. 일반 외부 링크는 수집하지 않는다.

이 두 유한 fixture에는 외부 리다이렉트/폼 제출 경로가 없고 외부 프레임은 기존 브라우저 수집기의 경계로만 검사한다. Katana의 일반 실사이트 리다이렉트/SSRF 경계는 이 실험으로 검증했다고 주장하지 않는다.

20초 안에 근거 수집이 완료된 페이지/후보/통제 광고 위치, 미방문/미완료, 추가 요청, 정상 위치 보존을 집계한다. 정답은 실행 순서·선별에 사용하지 않고 사후 평가한다. 이는 광고 의미 F1 또는 제출 종단 F1이 아니다. HTTP만 읽은 페이지는 검사 완료에 포함하지 않는다.

Katana 후보 유지 기준: 두 사이트 각각 완료 광고 위치 수가 FIFO1보다 감소하지 않고, 전체 평균 완료 페이지10% 이상 증가, 공통 수집 근거 손실0, 경계 위반0. 동시2 대비 결과도 별도 보고한다. 실패하면 튜닝 없이 종료한다.

## 실행·감사

총 로컬 진단 안전 상한1시간, 유료API0. 실제 OS 프로세스 하위 트리의 working-set 합/CPU를 가능한 범위에서 표본 측정하고 합산 working-set이 물리적 전용 메모리와 같지 않음을 표시한다. 프레임워크 설치는 .runtime 안의 실험 바이너리만 사용한다. 운영 소스의 전후 해시를 대조하고 다른 작업의 변경과 구분한다.

원응답/스냅샷/방문순서/시간/실패를 새 디렉터리에 저장한다. 시행 후 기준 완화·실패 문구 맞춤 수정은 하지 않는다. 유망해도 새 실사이트 진단 및 동일25분 HCX 운영 검증 전에는 운영에 연결하지 않는다. Crawlee 도입은 이번 비교의 필수 조건이 아니며 별도 실행하지 않는다.
