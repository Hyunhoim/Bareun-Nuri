# 숫자 치환 대안 1 → 2 순차 검증 계획

2026-09-23. 유료 호출 전에 고정한다. 기존 기본 의미 판정·관찰기·worker와 이전 실험 파일은 변경하지 않는다.

## 비교

가설 1: 제공된 복원 목록이 정상 식별자와 모호 표현의 과도한 확정을 유도했을 수 있다.
가설 2: 여러 후보를 한 요청에 담으면 문맥 귀속이 흔들릴 수 있다. 둘 다 아직 원인으로 입증되지 않았다.

- control: 읽기 후보 제공, 배치 4.
- no-readings: 읽기 후보만 미제공, 배치 4 (1순위).
- single: control과 같은 입력·프롬프트, 배치 1 (2순위). 미채택 1순위 위에 쌓지 않는다.

세 조건은 동일한 자유 문자열 reading 출력 계약을 사용한다. 목록이 없는 조건에 r0 같은 불투명 키 선택을 요구할 수 없기 때문이다. 따라서 과거 enum 방식의 저장 결과는 참고이며, 새 control을 실제 호출한다. 세 조건의 SYSTEM·JUDGE·JSON schema는 같다. no-readings는 입력의 readings와 readings_truncated 필드만 제거한다. classification/reason을 유지하며 substitution일 때 복원 문자열, 나머지는 none을 출력한다. 복원은 기존 숫자 대응 후보와 비교해 검증하고 기존 r키로 변환해 동일 채점기를 재사용한다. 형식·대응 오류는 기존 어댑터의 1회 복구를 거치며, 계속 실패하면 실행 실패로 기록한다. 이를 미확정/정상 정답으로 바꾸지 않는다.

## 자료·설정·순서

기존 dev 44와 evaluation 44를 모두 진단 자료로 재사용한다. 각각 치환 16, 실제 식별자 20, 모호 표기 8, 광고/예방 22쌍이다. 새로운 홀드아웃이 아니다. 같은 원문·위치·순서를 사용한다.

control 두 분할 → no-readings 두 분할 → single 두 분할 순서로 각각 한 번 실행한다. 중간 결과에 따라 프롬프트·판정·라벨을 수정하지 않는다. 1순위 실패여도 2순위는 독립적으로 실행한다.

HCX-007 / thinking none / temperature 0 / seed 42 / maxCompletionTokens 2048 / 순차 실행 / 실행별 1시간. 예정 기본 호출은 22 + 22 + 88 = 132회. 복구·후속 확인 포함 전체 상한 220회·250,000토큰. 사용량 누락, 지속 API/계약 오류, 한도 도달 시 중단하고 미검증으로 보고한다. 동일 SDK·간격/TPM 제한을 사용한다. 지연은 단계 총경과·호출 수·토큰을 보고하고 단일 측정의 변동성을 명시한다.

## 사전 관문과 종료

각 분할에서 치환 TP >= 14/16, 실제 식별자 오탐 0 및 literal 20/20, 모호 표기 uncertain 8/8, 쌍 분류 불일치 0, 치환 확정의 잘못된 복원 0을 모두 충족해야 한다. 새 control이 맞힌 치환도 사례 대응으로 유지해야 한다. 정상 광고 의도·다른 기법·원문 위치 보존은 자동 검사한다. 모두 uncertain으로 보내는 결과는 통과하지 못한다.

두 분할 관문을 통과한 조건만 새 단어 계열의 합성 44개 평가로 확대한다(동일 작성자 합성이라는 한계 명시). 통과 후 역순 확인과 기존 306개 저장 의미 판정에 대한 관찰 통합 회귀를 수행해야 채택 검토 가능하다. 새 자료와 라벨은 호출 전에 고정하고 모델에 전달하지 않는다. 진단 단계에서 두 대안 모두 실패하면 즉시 pass: 새 평가/306개 확대/추가 프롬프트 조정 없이 기본 경로를 유지한다.

최종 기준 충족 대안이 하나면 그것만 적용 후보로 삼는다. 둘 다 충족하면 정확도·검토 계약 보존을 우선하고 추가 호출·토큰·지연이 작은 안을 택한다. 실제 사이트 일반화나 광고 F1 개선을 기법 진단 점수로 주장하지 않는다. 원인 가설은 조건 간 효과와 별개로 보고한다. 자유 출력 변경과 과거 결과 비교, 시간·순서에 따른 모델 변동을 인과 증거로 과장하지 않는다.
