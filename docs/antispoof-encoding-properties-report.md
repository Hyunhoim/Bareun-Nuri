# 라벨 없는 인코딩 구조 검증

2026-09-30. 광고문구/정답/기존실패문장을 사용하지 않고 ASCII, 현대자모, 호환자모, 확장자모, 전각, 그리스, 키릴, 결합문자, 형식문자의9군을 사용했다. 길이1/4/8/16/32/64/128 × 반복/다양 × 고정seed3 =378조건이다. 전각 숫자·문자 등은 형태검사이며 실제게시글 분포나 광고 정확도를 대표하지 않는다.

기존 typed와 이미동결된 indexed 표현의 정보/길이만 검사했다. 추가 형식조정/학습/모델추론/API는 없다. 직접 대응 복원 assert는 indexed가 각표기를 직렬화할 때 실행된다.

| 결과 | typed | indexed |
|---|---:|---:|
| 문자단독+근거 입력 충돌 그룹 | 6 | 0 |
| 378조건 중512초과 | 109 | 60 |
| 현대자모 최초 관찰512초과 길이 | 16 | 32 |
| 호환자모 최초 관찰512초과 길이 | 16 | 32 |
| 전각 최초 관찰512초과 길이 | 16 | 32 |

초과109→60은 회복54개와 새초과5개의 합성결과다. 처음초과길이는표본과구성에따른관측값이며모든16문자가초과한다는보장이아니다. indexed는문자구별에필요한정보는보존하지만원래근거가거의없던문자에는코드포인트정보를추가하므로항상더짧아질수없다. 알려진44개새초과만을해결하는예외는넣지않았다.

이 결과는 기존문구를고치지않아도직렬화병목이재현됨을보여준다. 그러나성능개선/운영채택근거는아니다. 짧은표기에서발생하는문맥오확정·역할일반화실패를512초과로설명하지않는다. 현재typed후보의이득과미해결범위를분리한다.

다음설계는긴문자근거를본문과같은한문자열로계속확장하기보다문자식별정보와문맥정보를별도로처리할필요가있는지검토하는것이합리적이다. 이는새구조의가설이며빠르거나정확하다는결론이아니다. 기존운영을교체하지않는다. 동일합성학습·개발반복이누적되어과적합위험이있으므로새구조승격에는독립적인표기역할검수와운영조건검증이필수다.
