# HCX payload audit (API 0)

운영 최대12후보/출력512와 판정 내용은 고정한다. 가설은 출력 상한448 또는384가 예약 부담을 줄이되 기존 완전 응답을 담을 수 있는가다. 저장 completion_tokens와 실제 스키마 검증으로 위험을 먼저 검사한다. 저장 응답이 낮은 상한에 들어간다고 새 생성 결과가 같다는 뜻은 아니다.

Phase1 실제 실행 전체와 기존 동시성 반복 실험을 감사한다. 서로 중복되는 실험은 독립 사례로 합산하지 않고 자료군별 표시한다. 응답을 인위적으로 잘라서 실제 API의 새 출력을 모사하지 않는다. 정상 완전 응답 중 상한 초과가 하나라도 있으면 해당 전역 축소안은 이번 단계에서 제외한다. 통과하더라도 별도 제한된 실호출/25분 비교 전에는 운영 채택하지 않는다.

입력 공용표의 기존516요청 가역성 재생을 재사용한다. 내용 삭제나 프롬프트 변경은 실행하지 않는다. 같은 관찰 세트에서 임계값을 세밀하게 맞추지 않으며 Phase2 및 새 최종 자료는 읽지 않는다. 이 감사는 회귀와 용량 진단이고 일반화 향상 증명이 아니다.
