# Nuri1.0 / D 실제 수집 후보 필터 비교

2026-09-29. **Nuri1.0은 필터 확대 실험을 중단하고, D는 조건부 후속 후보로 유지한다. 운영 적용은 아직 하지 않는다.** D는 앞선221개 의미 중심 자료와 달리 실제 수집 후보에서 유의미한 후보 감소를 보였다. 정답이 확인된 광고의 손실은 없지만 전체 제외분의 독립 정답과 실제 순지연 개선은 미확인이다.

## 고정 조건

기존 v1 임계값(Nuri1.0: 광고점수<0.001·일반정보점수>=0.999, D: 광고점수<0.0001·일반정보점수>=0.9)을 그대로 사용했다. 일반정보 argmax만 제외하고512토큰 초과는 통과시켰다. 재학습/새 임계값 선택/HCX 호출0이다. 기존 contract.initialEvidence + scoped context 직렬화와 CPU8스레드·배치8을 재사용했다. 코드·입력·원본·체크포인트 해시를 보존했다.

저장된 실제 공공사이트8페이지1,636후보(부산 시민생각·연제 체육시설 자유게시판·소비자 포털·부산 공지·대전 시험FAQ 등)와 부산 DOM 복제본20페이지3,543후보를 사용했다. 대상 길이/기법 신호/태그로 후보를 선별하지 않았다. URL+위치 중복만 제거했다. 새 실시간 크롤링이나 새 홀드아웃은 아니다.

## 정확도와 비용 해석

**실제 제외120개 중119개, 복제본 제외552개 중545개는 독립 정답 미상이다.** 이를 모두 정상으로 집계하거나 정상 제외 정확도100%라고 보고하지 않는다. 알려진 광고28개 전부 통과는 긍정적인 진단이나 실제 사이트의 미라벨 광고 손실이 없었다는 증거가 아니다. 사람 검수17개는 이전221개 실험에도 포함됐으므로 새 확인 자료가 아니다. 알려진 복제본 역시 이전 관찰 자료다.

전체 후보가 줄어든 비율은 비용·지연 절감률이 아니다. 짧은 메뉴가 주로 빠지면 입력 토큰 절감은 작을 수 있고, 페이지별12개 묶음의 요청 수가 같은 경우도 있다. D CPU 처리166초를 상쇄할 실제 HCX 응답/예약 대기 절감이 있어야 속도 이득이다. 수집은 그대로 수행하므로 수집 시간 절감도 주장하지 않는다. 새로운 묶음의 의미 판정 변화와25분 종단 결과는 측정하지 않았다.
