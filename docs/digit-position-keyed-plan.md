# 숫자 위치별 P2 — 출력 계약 보완 후 제한 진단

2026-09-26. 기존 P는 3회 호출·1,476토큰 후 종료했다. 세 번째 응답은 HTTP200/stop이지만 숫자 위치2개에 선택5개를 반환했다. 배열 길이를 고정하지 못한 계약 오류이며 전체 의미 정확도는 미측정이다. 원본 `.runtime/digit-position-pilot-v1`과 코드는 보존한다. 두 성공 사례만 점수로 보고하거나 잘못된 배열을 잘라 해석하지 않는다.

## 변경과 검증

P2는 P의 숫자별 의미 정의·원문·문맥·문자 대응·코드 통합을 유지한다. 출력 배열만 `marks` 객체로 바꾸고 원위치/원숫자에서 만든 `p인덱스_숫자` 키를 모두 필수로 지정한다. 각 키의 enum은 해당 숫자에 허용된 문자/keep/unknown뿐이다. 시스템 지시의 출력 형식 한 문장과 입력의 `source_ids`만 이를 위해 바꾼다. `source_ids`는 기존 API 도우미가 후보별 스키마를 만드는 메타데이터다. 실제 모델 입력에도 포함되며 숨겨진 정보라고 주장하지 않는다. 평가 정답은 포함하지 않는다.

운영 llm/core는 수정하지 않는다. 실험 파일 `digit-position-keyed.cjs`가 기존 P와 일반 문자 대응 함수를 재사용한다. 키 순서에 의존하지 않고 코드에서 원위치 순서로 정렬해 복원한다. 누락/추가/중복 ID, 위치 키 불일치, 허용되지 않은 문자, UTF-16 오프셋, 일부 미확정과 완전 복원을 API0 검사한다. 같은 의미를 더 잘 이해한다고 가정하지 않고, 출력 계약 안정성과 의미 성능을 각각 확인한다.

## 실행과 사전 관문

- 관찰 자료 v4 전체48개를 원래 순서로 새로 실행한다. 실패 요청만 재시도하지 않는다. 미확인 요청은 없었으며 원래 P를 재개하지 않는다.
- S는 기존 5차의 검증된48개 응답 두 회차를 재사용한다. 소스·원요청·원응답을 다시 검사한다. 동시기 비교가 아니라 구조 진단이다.
- HCX-007 none/temperature0/seed42/출력1024/58k TPM/최소1초간격, 시작 전61초 분리.48회 예정,60회 상한, 예약94,310토큰(상한100만), 전체1시간·조건10분.
- 새 위치 `.runtime/digit-position-keyed-pilot-v1`. 원요청·응답·설정·자료·계획·소스를 동결한다. 자동 재시도나 응답 수정은 하지 않는다.
- P와 동일하게 strict F1>S, 정상 식별자 FP≤S, 모호 과확정≤S, 혼합 TP>9/12, 양성 정확 복원≥20/24가 진단 확대 관문이다. 대소문자를 접은 읽기 일치와 원문 비숫자 보존을 구분한다. 개별 S 정탐 손실을 보고하되 미채택 S의 모든 위치 보존을 운영의 정탐 보존과 혼동하지 않는다.
- 첫 관문 통과 시에만 같은 코드·계획·입력·설정의 역순48회를 별도 `.runtime/digit-position-keyed-reverse-v1`에 실행한다. 첫 실행 해시와 설정을 검사하며 예시·지시·정답 예외를 추가하지 않는다. 두 순서 통과 시에만 새 독립 평가를 설계한다.
- 실패하면 이 구조를 확대하지 않는다. 실제 운영 채택에는 기존 운영 광고 정탐·다른 기법·최종 탐지 F1·25분 처리량·저장/재개 검증이 별도로 필요하다.

## 해석 한계

기존 P 전체 점수가 없으므로 P 대비 의미 F1 개선으로 보고하지 않는다. 고정 속성으로 바꿔도 모델이 내용상 잘못 선택할 수 있다. 관찰한 합성 v4에 대한 진단이며, 의미 추론 강화나 실제 사이트 일반화 증명은 아니다. P·P2 비용과 실패를 모두 보존한다.
