# 숫자 치환 Goal 3차: 봉인 자료에서 요청 분리 확인

2026-09-26. 운영 채택 전의 제한된 일반화 확인이다. 기존 개발56개에서 S 단일 대상은 원래/역순 모두 TP24, 정상 FP0을 보존했지만 모호12개 중7/8개를 과도 확정했다. 이 약점은 해결된 것으로 취급하지 않는다. C/G/S 2차 완료 및 감사 후 실행한다.

가설은 다른 대상과의 배치 간섭을 제거하면 새로운 단어·문맥에서도 기존 치환 정탐을 보존하면서 순서에 따른 누락을 줄인다는 것이다. 모호성까지 해결한다는 가설은 아니다. S/C 계약과 복원 후보는 수정하지 않는다. 단어 예외·정답 기반 후보 선택·실패 뒤 프롬프트 재조정은 하지 않는다.

자료는 이미 독립 봉인된 `.runtime/digit-holdout-v3/inputs.json`의72개 전부다. 정답은 별도파일로 유지한다. 조건은 C4 원래, S1 원래, S1 역순, C4 역순이다. 동일 HCX007 none/temp0/seed42/출력1024/58k TPM, 순차 요청과 조건 전61초 분리를 사용한다. 총180요청, 최대220요청/예약100만토큰/1시간이며 조건당10분이다. 미확인 요청·429·입력/소스/제공자 한도 변경시 종료하고 자동 재호출하지 않는다. 모든 원요청·응답을 저장한다.

평가는 치환 TP/정상 FP/FN/F1, 3분류 macro F1, 모호 과도 확정, 각 반복의 C 정탐 위치 손실/추가, 순서 변경률, 동일 요청 반복 안정성, 호출·토큰·시간이다. 복원 문자열을 출력하지 않으므로 복원 정확도를 주장하지 않는다. 부분 숫자를 보존해야 하는8개는 별도 분석한다. 모호 사례를 F1 분모에서 분리한 기법 F1만으로 채택하지 않고, 모호 사례를 포함한 치환 정밀도도 보고한다.

다음 운영 검증으로 진입하려면 두 반복에서 C 정탐을 보존하고 누락/정상 오탐 또는 변동을 줄이는 근거가 있어야 한다. 모호 과도 확정이 악화하면 일반 채택하지 않으며 추가 기법 관찰을 확정하는 안전성을 별도 검증해야 한다. 효과가 없으면 해당 후보는 미채택한다. 이 시험의 실패 표현에 맞춰 같은 자료에서 수정하지 않는다. 운영 광고 의미 판정/512토큰/12개 배치/최종 기법 통합/25분 검사 결과는 이 시험으로 보장하지 않는다.

자료는 합성이고 같은 제작자의 구조적 편향이 남으며 일부 규격의 의미계열은 기존자료와 관련된다. 현재까지 미사용 평가이나 결과를 연 이후에는 새 홀드아웃으로 재사용하지 않는다. 보조 광고 라벨의 범위는 운영과 다르므로 이번 기법 평가에만 정답을 사용한다.
