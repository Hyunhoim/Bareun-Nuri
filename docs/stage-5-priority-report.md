# 5단계 페이지 우선순위: 초기 도달 이득, 독립 실험 종료·미채택

2026-09-23. 고정한 기존 Pipeline에서 페이지 순서만 비교했다. 기존 합성 사이트의 초기 광고 위치 도달은 증가했지만 사전 효과 관문은 통과하지 못했다. 운영 적용·HCX 호출·가중치 재조정 없이 종료한다. 2·3단계의 의미·관찰 오류, 4단계 미채택은 그대로다.

## 구현과 기준선

`agent/experiments/priority.cjs`는 방문한 페이지에서 발견한 링크만 대기열에 추가한다. 링크 문구·URL 토큰·주변 DOM으로 점수를 정하고 동점은 발견 순서로 방문한다. 네 번에 한 번은 가장 오래 대기한 URL을 선택한다. 낮은 점수 페이지도 제외하지 않는다. 목적지의 미방문 본문·링크·정답은 점수에 접근할 수 없다. URL 정규화와 범위 검증은 운영 collect의 함수를 재사용한다.

`priority-capture.cjs`는 별도의 loopback 테스트 서버를 실행하고 기존 readDocument/settlePage로 링크를 다시 기록한다. 서버와 브라우저는 종료했다. `priority-score.cjs`에서만 정답을 읽고 도달 여부를 채점한다. 운영 worker/collect/llm/output에는 연결하지 않았다.

136개 소스·계획·입력 파일의 해시를 측정 전에 고정했고 이후 일치를 검증했다. Graphify의 기존 소스 그래프와 운영 소스 네 파일이 같은 것을 확인한 뒤 collect/settlePage/run 흐름을 조회하고 실제 코드로 교차 확인했다. 그래프 CLI의 레거시 노드 ID 경고가 있어 그래프만으로 결론을 내리지 않았다.

## 자료와 무결성

- 기존 자료: 홈페이지 1, 게시판 목록 10, 상세 90 = **101페이지**, 후보 **3,824개**, 기록 링크 **1,207개**(중복·외부 포함).
- 정답 대상: 광고 120개, 정상 180개 = 300개. 정답 대상 밖의 후보를 정상 정답으로 가정하지 않았다.
- 전체 후보의 원문·selector·프레임 경로·순서가 기존 저장본과 일치했다. 스타일을 다시 측정해 전체 일치를 주장한 것은 아니다. 이번 비교는 원래 후보 증거를 수정하지 않는 링크 순서 실험이다.
- FIFO 재생 순서가 기존 전체 수집 페이지 순서와 완전히 일치했다. 두 정책의 최종 방문 집합과 후보 수가 같다. 순환·중복·외부 범위·인증정보 포함 URL·미기록 목적지·아직 발견하지 않은 하위 링크를 검사했다.
- 페이지 재기록에 151.22초가 걸렸다. 이는 A/B 지연 비교나 운영 전체 실행 시간이 아니다.

## 결과: 탐지 성공이 아닌 정답 위치 도달

분모는 전체 광고 정답 120개다. 방문한 부분집합만 분모로 삼지 않았다.

| 방문 예산 | FIFO 광고 위치 | 우선순위 광고 위치 | 광고 도달률 변화 | 누적 후보 FIFO → 우선순위 | 정상 정답 도달 FIFO → 우선순위 |
|---|---:|---:|---:|---:|---:|
| 10페이지 | 8 (6.67%) | 11 (9.17%) | +2.50%p | 524 → 479 | 11 → 13 |
| 25페이지 | 21 (17.50%) | 27 (22.50%) | +5.00%p | 1,309 → 1,175 | 33 → 42 |
| 50페이지 | 58 (48.33%) | 58 (48.33%) | 0 | 2,141 → 2,141 | 79 → 79 |
| 전체 101페이지 | 120 (100%) | 120 (100%) | 0 | 3,824 → 3,824 | 180 → 180 |

첫 광고 정답을 포함한 페이지는 7번째에서 5번째로 앞당겨졌다. 관측된 전체 1~101페이지 곡선에서 전체 광고 위치 도달 수 감소는 없었다. 사전 지정한 10/25/50 예산의 기법별·위치별 도달률 감소도 없었다.

| 광고 위치 유형 | 10페이지 도달률 차이 | 25페이지 도달률 차이 | 50페이지 차이 |
|---|---:|---:|---:|
| 제목 | +6.25%p | +12.50%p | 0 |
| 본문 | 0 | +6.25%p | 0 |
| 댓글 | 0 | +8.33%p | 0 |
| 작성자·서명 (각각) | +12.50%p | 0 | 0 |
| 답글·링크·첨부파일 (각각) | 0 | 0 | 0 |

25페이지에서 HOMOGLYPH·TRANSPARENT는 각각 +7.50%p, JAMO +2.50%p, OFFSCREEN 0이었다. 이는 **해당 기법이 있는 광고 위치에 도달한 비율**이며 기법 판정 정확도가 아니다. 정상 정답 도달 증가 역시 오탐 증가라는 뜻이 아니다.

## 왜 확대하지 않는가

사전 기준은 10/25/50 중 두 지점 이상에서 광고 도달률 +5%p, 전체 감소 없음, 유형별 손실 5%p 이하, 최종 집합 보존이었다. +5%p를 달성한 지점은 25페이지 하나라 효과 관문을 실패했다. 결과를 보고 기준을 낮추지 않았다. 이 기준은 이번 후속 실험의 실익을 정하기 위한 사전 관문이며 모든 사이트의 보편적인 최적 기준은 아니다.

또한 현재 자료는 게시판 중심이며, 미사용 실사이트 홀드아웃이 아니다. 선택 점수는 홈페이지 0점 1개, 1점 9개, 3점 1개, 4점 90개였다. 대부분의 상세 페이지가 같은 점수여서 다양한 공공 사이트 페이지 유형 간 효과를 평가하기 어렵다. 해당 자료에 맞춰 점수·문구·경로 예외를 추가하면 과적합 우려가 있다. 이 우려는 실행 중 사용자에게 보고했다.

작은 기능·반례 그래프에서는 다음을 확인했다. 이는 별도 일반화 성능 수치가 아니다.

| 구성 | FIFO의 광고 페이지 순번 | 우선순위의 순번 |
|---|---:|---:|
| 게시판에 광고 | 3 | 2 |
| 게시판은 정상, 일반 안내에 광고 | 2 | 4 |
| 불투명 URL·정보 없는 링크 | 3 | 3 |

오래 대기한 URL을 방문하는 규칙은 영구적인 소외를 막지만 모든 시간·페이지 예산에서 광고 재현율을 보존하지는 않는다. 게시판 밖 광고와 정상 게시판이 포함된 대표성 있는 별도 사이트 자료가 필요하다.

## 실무 연결의 한계

현재 worker는 **전체 수집 후** LLM 판정을 시작한다. 페이지 한도를 넘으면 실패하며 부분 결과를 완성된 검사처럼 반환하지 않는다. 따라서 이번 순서 변경만으로 제한 시간 내 확정 탐지가 빨라지는 것은 아니다. 수집과 판정의 점진 실행이나 부분 결과 계약을 바꾸는 일은 별도 변경이다.

HCX 요청 **0회**, API 토큰 **0개**다. F1·정밀도·실제 탐지 지연·호출 절감은 측정하지 않았다. 페이지 예산이 같아도 후보 수가 달라 LLM 비용이 같다고 해석할 수 없다. 모델 자체 변동과 배치 순서 영향도 이번에 해결·검증하지 않았다. 기존 탐지 코드가 그대로라는 사실과 실제 호출로 회귀 없음을 입증했다는 주장을 구분한다.

## 검증과 재현

`npm.cmd test --prefix agent` 전체 통과, `git diff --check` 통과. 새로운 `priority.test.cjs`를 기존 테스트 명령에 추가했다. 외부 의존성 추가·커밋·push는 없다.

프로젝트 루트에서 재실행한다. 출력 디렉터리는 기존 결과를 덮어쓰지 않도록 새 경로를 사용한다. 캡처는 별도 로컬 포트 8786을 사용한다.

```powershell
node agent/experiments/priority.test.cjs
node agent/experiments/priority-capture.cjs .runtime/stage3-observation/collected-panel-v2.json .runtime/stage5-priority-new
node agent/experiments/priority-score.cjs .runtime/stage5-priority-new test-set-v2/private/ground_truth.json
```

Git 제외된 `.runtime/stage5-priority/`의 `manifest.json`, `graph.json`, `capture.json`, `comparison.json`에 고정 해시·원본 링크·완전한 방문 순서·예산별/기법별/위치별 지표가 있다. 캡처 입력도 로컬 Git 제외 자료이므로 이 코드만 복사한 새 checkout에서 과거 실험이 자동 재현되는 것은 아니다.

현재 결론은 **좁은 순서 실험은 완료했지만 운영에는 미채택**이다. 후속 검증을 하려면 같은 게시판 자료의 가중치를 재조정하기보다 혼합된 페이지 유형의 별도 평가 자료와 실제 운영의 부분 진행 요구를 먼저 갖추는 편이 타당하다.
