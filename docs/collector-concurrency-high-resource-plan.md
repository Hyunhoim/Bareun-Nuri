# 동시5/10/15/20 메모리 재측정 보충 계획

본 비교61회 종료 후 생성. `.runtime/collector-concurrency-high-v1`의 탐색 기준선5 일부에서 작업 메모리 합5,272/5,417MiB, 실행약15초 중 CPU 누적1,518/1,552초 표본이 관측됐다. 기존 PID/부모PID만의 트리 탐색이 재사용된 PID와 과거 부모 관계를 구분하지 못하는 집계 오염 가능성을 확인했다. 원인 확정 전 기존 메모리 수치를 확정 근거로 사용하지 않는다. 속도·수집 근거 파일은 보존한다.

- 자원 측정기만 수정: 자식 생성 시각 >= 살아 있는 부모 생성 시각, Get-Process 시작 시각과 CIM 생성 시각 일치를 검증한다. 집계된 PID/이름/생성 시각/부모PID/작업 메모리/CPU와 오래된 부모 관계 제외를 저장한다. 실제 수집 코드·대기·동시 수·FIFO 계약은 유지한다.
- 기존 실제 DOM 복제20페이지, 동시5/10/15/20, 각3회=12실행. 순환 순서와 매 실행 새 프로세스,600초 수집/630초 프로세스/전체1시간 안전 상한은 같다. API0/외부기관0/운영변경0.
- 이 보충 실행은 메모리 근거를 재측정하는 진단이다. 최초61회의 속도 순위/사전 관문을 바꾸거나 유리한 새 속도를 골라 섞지 않는다. 보충 소요 시간은 원자료에만 보존한다.
- 모든20페이지/3,543후보 보존 및 조건별 원본 근거 일치를 확인하고, 프로세스 생성 관계·합계·제외 PID를 독립 재집계한다. 오래된 관계 제외가 실제 관측되면 집계 결함의 재현으로 기록하되 과거 이상치의 정확한 프로세스를 소급 식별했다고 주장하지 않는다.
- 공유 메모리 중복/표본 간 순간 피크 누락/이미 종료된 부모의 자손 누락은 여전히 가능하다. 물리 메모리 필요량으로 해석하지 않는다. 기존2~5보고서의 메모리도 구형 측정기의 관측으로 한계를 덧붙이며 원값은 수정하지 않는다.

보충 첫 시도 `high-memory-v1`은 PowerShell5.1의 해시테이블 Measure-Object 집계 오류로 중단/미측정 처리했다. PSCustomObject로 바꾸고 실제 PowerShell5.1 한 표본의 PID·생성 시각·작업 메모리 합계를 확인한 뒤 전체12회를 새 디렉터리에서 실행한다. 오류 시도의 속도·메모리 값은 최종 비교에 섞지 않는다.

실행: `node agent/experiments/collector-concurrency-run.cjs resources .runtime/collector-concurrency-high-memory-v2 5,10,15,20 docs/collector-concurrency-high-resource-plan.md`
