# HCX-007 광고 의도 일반화 개선 실험

**최종 후보 act4를 운영에 채택했다.** 별도 합성72개 두 순서의 평균 의미 F1은69.01%→83.21%, 실제 FIFO 종단의 전체 확정604개 위치 F1은76.09%→80.00%였다. 기존 정탐 손실과 신규 오탐은 남으며, 종단 시간은12.87% 늘었다. 모든 병목을 해결했다는 결론은 아니다.

## 문제와 접근

기존 판정기는 광고 문구가 예방·교육·보도에 인용된 경우에도 광고로 판단하고, 주변 문맥에 의해 의미가 결정되는 링크를 놓쳤다. 이번에는 특정 단어를 예외 처리하지 않고, **표시된 대상이 그 문맥에서 수행하는 게시 행위**를 판단하도록 과제를 정리했다. 대상 원문과 소속 문맥을 순서대로 표시하고 광고 의도와 DOM·스타일 관찰을 분리했다.

사용자 요청에 따라 F1을 주 지표로 삼았다. 기존 정탐 하나의 손실이나 비용 증가만으로 즉시 탈락시키는 종전 관문을 그대로 적용하지 않았다. 다만 유효한 출력, 근거·위치 보존, 미완료 표시, 미확인 API 요청의 재호출 금지는 유지했다. 실제 호출은 공통 TPM 예산 안에서 최대2개로 제한했고, 자료 작성·계약 구현·감사는 별도 에이전트가 병렬로 수행했다.

## 첫 별도 평가에서 발견한 실패

독립 작성80개(광고32·정상40·모호8)에서 운영 O는 정순 F1 66.67%, 섞기65.71%였다. 필수 참조를 요구한 passageJson4는52개/36개 처리 후 중단했다. HTTP/JSON 오류나 허구 출처가 아니라, 판단불가2개·일반정보1개에서 evidence_ids가 비어 있던 것이 원인이었다. 이 분류들은 입력 문맥과 합치했으므로 의미 이해 실패로 집계하지 않는다. 전체 완료 F1도 부여하지 않는다.

이를 계기로 문구나 정답을 바꾸지 않고 출력 출처 선택 작업을 분리했다. 이미 정의해 둔 act/reference를 같은4개 배치로 비교했고, F1이 같아 토큰이 적은act4를 선택했다. 새80은 이제 진단 자료로 취급한다. 추가로 후보 프롬프트와 실패 문구를 보지 않은 작성자가 새72개를 준비했다.

act4의 표시 이유는 모델이 고른 분류와 실제 대상 원문을 코드가 조합한 요약이다. 모델의 자유 설명이나 문맥 출처 선택 성공으로 표시하지 않는다. 근거 없는 추정 문장을 만들어 빈 설명을 채우지 않는다.

저장된 근거의 판정 비교는 다음과 같다. 모든 조건은 완주했고, 실패한 첫 후보의 응답을 새 계약으로 재해석하여 점수를 만들지 않았다.

새72개는 후보를 고정한 뒤 처음 판정했다. 평균 F1은69.01%→83.21%이며 두 순서 모두 개선됐다. 새72개는 같은 프로젝트의 다른 작성자가 만든 합성 자료로, 다른72개를 두 번 측정한144개 독립 표본이 아니다. 프롬프트가 주로 명시한 도박·불법성인물뿐 아니라 기타 명시적 불법 서비스도 포함해 의미 전이를 시험했으므로 서비스 범주별 재현율을 별도 기록한다.

모집요강 원문은 불법광고를 “도박·성인물 등”으로 예시한다. 이번 혼합 자료의 범위를 도박만의 성능과 혼용하지 않는다. 새72개에서 도박8개는 두 순서 모두6/8→8/8, 기타24개는18/24→21/24 및19/24→20/24였다. **근거 부족8개는 두 방식·두 순서 모두 정상으로 답했다.** 후보의 순서별 의미 판정 변화는4/72개, 운영은3/72개였다. 후보는 정순 기존 정탐 손실0·추가5, 섞기 손실1·추가4이며 신규 오탐은 없었다.

관찰한80개에서는 정순 기존 정탐 손실0/추가 탐지6, 섞기 손실1/추가 탐지6이었다. 두 순서 간 의미 판정은8/80개 달랐다. 토큰은 약18%, API 서비스 시간은 약40~45% 줄었으나 호출은5→20회였다. 공유 실험 큐 대기는 단일 운영 지연과 다르다.

기존76개에서는 **기존 오탐6개를 없앤 대신 다른 정상6개에 신규 오탐**이 발생했다. 여기에는 정상 링크, 작성자·조회수·게시일·분류 등 주변 광고와 역할이 다른 요소가 포함된다. 주변 문맥을 더 많이 활용하면서 대상 자체의 역할을 잘못 해석하는 문제는 남는다. 특정 태그나 단어를 일괄 제외하는 예외로 덮지 않았다. 기존 광고 손실0, 누락1개 회복, 토큰17.12%/서비스 시간49.15% 감소를 확인했다.

기법 관찰 정답48/48 및 최종 기법 F1 100%는 기존76개 중 기법 라벨이 있는48개 한정이다. 나머지28개에 발생한 신규 오탐을 감추는 지표로 사용하지 않는다. 관찰 미확정은 구형 근거28개와 visibility/clipping4개를 합쳐32개다.

## 실제 FIFO 종단 비교

같은25분/200페이지/300호출 상한에서 기준선→후보를 순차 실행했다. 두 조건 모두81페이지·615개 요소를 수집·판정하고 조기 완료했다. 방문 순서, 원문·위치·문맥, 수집 집합은 같고 누락·미판정·미확인 요청은 없었다. 후보는 코드 관찰 수집, 체크포인트와 출력 통합 비용까지 포함했다.

모델 호출 전에 기존80개 외535개 위치도 별도 작성자가 정답을 고정했다. 전체615개 중 광고43·정상561·근거 부족11이며, 이진 F1의 분모는604개다. 535개에는 반복 메뉴와 목록 링크가 많이 포함되므로615개의 독립 문장에 대한 일반화 증거로 해석하지 않는다.

토큰은16.73% 줄고 API 응답 서비스 시간도 줄었지만, 호출 증가와 요청 예산 대기 때문에 **전체 시간은95.821초,12.87% 늘었다.** 속도 개선으로 보고하지 않는다. 둘 다25분 전에 끝나 이번 사이트에서는 미방문 손실이 없었으나,300호출 보호 한도에서 요청당4개는 약1,200개 작업 항목을 처리한다. 이전16개는 약4,800개였으므로 대형 사이트의 첫 구간 도달·판정량은 별도 위험이다. 재개는 지원하지만 첫25분 손실을 없앤다는 뜻이 아니다. 상한을 몰래 늘려 이번 점수를 만들지 않았다.

사전 기준인 지정 대상 F1·정탐 증가와 전체 확정 위치 F1 비악화, 기법·출력 계약을 통과했다. 기존 정탐의 완전 보존을 절대 조건으로 적용하지 않고 **전체 F1과 실제25분 내 완료를 근거로 채택**했다. 새72개 확인과 종단 회귀 결과를 구분하며 이번 사이트의80개를 새 홀드아웃으로 재명명하지 않는다.

원본 감사: `.runtime/semantic-e2e-act4-v1/independent-audit.json`. 소스38개 해시,615개 정답의 일대일 대응, 요청/응답/체크포인트, 의미 불변인 관찰 통합, 실제 출력과 오프라인 재통합 일치를 독립 검사했다. 후보의 `score.json`은 관찰 통합 전 의미 전용 중간 점수이므로 최종 기법 성능은 이 독립 감사와 `result.json`을 사용한다.

## 운영 반영 및 검증

`agent/src/core/judgment.cjs`에 고정한 판정 계약을 두고 `worker.cjs`, `request-budget.cjs`, `scan.cjs`에 연결했다. 수집 후 판정 시작 기준16개는 유지하며 실제 HCX 요청은 최대4개씩 순차 전송한다. 모델은 게시 행위만 고르고, 코드가 광고·정상·보류로 매핑한다. 관찰 근거를 원래 요소 단위로 보존하고 장문 구간을 합친 후 기법을 통합한다. Mock은 기존 연결 검증 계약을 유지한다.

숫자 치환·부분 스타일 등 미확정 관찰은 별도 검토 기록으로 남기며 광고 의도를 바꾸지 않는다. 새 코드·계약과 다른 과거 체크포인트는 자동 이행하지 않는다. 실험 계약 파일 이름 충돌로 과거 검사가 실패한 문제는 새 factory를 `semantic-intent-contract.cjs`로 분리하고 보존된 옛 `intent-contract.cjs` 원본을 바이트 그대로 복구해 해결했다. 참조 경로만 조정했으며 과거 archive와 운영 판정 프롬프트는 바꾸지 않았다.

다음 검증을 완료했다. 추가 유료 요청은 없었다.

- `npm.cmd test --prefix agent`: 기존17개 연결 검사 통과.

## 사용량

실패·부분 실험을 포함한 이번 전체 실제 사용량은 **499시도,498개 HTTP200,429 응답1개,확인된1,293,158토큰**이다. 확정 응답2개의 재사용은 중복 비용에서 제외했다. usage가 없는429의 실제 토큰은 미확인이며 예약 토큰을 실사용으로 부르지 않는다. 원화 비용은 청구서를 확인하지 않았으므로 환산하지 않았다. 상세 감사는 `.runtime/semantic-total-usage-with-e2e.json`에 있다. 후속 검증은 저장 응답·Mock을 사용해 유료 호출을 추가하지 않는다.

## 한계

- 모든 새 자료는 통제된 합성 자료다. 실제 공공기관의 광고 유병률과 전체 사이트 F1은 알 수 없다.
- 반복 실행은 서로 다른 독립 사례 수를 늘리지 않는다. 같은 자료의 순서 민감성을 확인하는 용도다.
- 코드 관찰의 숫자 치환·일부 스타일·구형 저장 자료의 근거 누락은 별도 문제다. 의미 F1 상승으로 해결됐다고 표시하지 않는다.
- 모호한 입력을 정상으로 확정하는 문제는 개발 자료에서 남았다. 이진 F1에서 제외된 보류 성능을 숨기지 않는다.
- 실험마다 요청·응답·소스 해시·부분 결과를 보존했다. 429가 발생한 초기 실행은 기록하고 확정된 응답만 정확한 요청 본문 일치 검증 후 재사용했다.
