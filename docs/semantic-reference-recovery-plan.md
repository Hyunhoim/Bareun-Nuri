# 근거 선택 계약의 독립 수정 비교

첫 새80 평가에서 passageJson4는 두 순서 모두 Invalid evidence reference로 중단했다. 기존64 F1 100%를 운영 채택 근거로 확대하지 않는다. 새80은 이제 관찰한 진단 자료다. 이전 개발 탐색은 종료했고, 별도 평가에서 새로 발견된 출력 계약 취약성에 한정하여 이 추가 계획을 고정한다.

문구·분류 기준·입력·모델은 수정하지 않는다. 이미 구현된 act와 reference를 모두 4개 배치로 실행하여 출처 선택 제거와 선택적 출처 선택을 비교한다. 필수 출처 버전과 비교한 단일 변경 요인은 출력 출처 요구다. 잘못된 출처, 후보 ID, 분류 enum은 계속 거부한다. 코드가 의미 판정을 정상으로 바꾸거나 미확정 출력에서 광고를 추측하지 않는다.

1. 기존64에서 act4/reference4, 최대32호출/300,000예약토큰/1시간. F1 우선, 동률이면 더 단순하고 낮은 비용인 방식 선택. 완주하지 못한 조건은 제외. 이전 기준선 F1 75%보다 3%p 이상 개선하지 않으면 종료한다.
2. 선택 후보를 이미 관찰한80 정순/섞기 두 번과 기존76에서 검증한다. 이전 O 응답은 동일 저장 입력의 참고 기준이며, 독립 확인에서는 동시 새 O를 실행한다. 후보80×2의40호출과 기존76의O5+후보19호출을 합쳐 최대64호출/650,000예약토큰. 완료 F1을 사용하고 확인80 양순서 F1 이득, 기존76 F1 하락2%p 이내를 본다.
3. 별도 작성자에게 후보 프롬프트/실패 문구를 주지 않고 새72개를 작성하게 했다. 선택 확정 이후 O와 후보를 정순/섞기 각2회 실행한다. 평균 F1 이득3%p 및 양순서 개선을 재확인한다. 최대46호출/600,000예약토큰. 이 자료의 점수를 보고 추가 프롬프트 수정하지 않는다.
4. 통과하면 FIFO 25분 실제 수집/전체 후보 판정 비교로 운영 적용을 검증한다. 원문·위치·재개·출력검증은 필수다. 불확실 판정 미해결과 코드로 만든 근거 설명은 명시한다. 같은 제작자의 합성 자료만으로 실제 공공사이트 일반화나 전체사이트 F1을 주장하지 않는다.

완료된 실패 응답을 새 계약으로 재해석하여 채택 점수를 만들지 않는다. 유료 요청은 하나의 공유 계정 예산 조정기로만 병렬 처리하며 미확인 요청은 자동 재시도하지 않는다.
