# HCX 동시2·3·4·5 비교 결과와 채택 판단

2026-10-01. **현재는 동시2를 후속 운영 통합 후보로 유지한다. 동시3은 유망하지만 반복 검증이 미완료되어 새 승자로 확정하지 않는다.** 운영 소스 변경 및25분 종단 비교는 하지 않았다.

## 실제 실행과 중단

이전 실험과 같은24요청/238후보를 유지했다. 동일 HCX-007/none/512/12묶음/58k 공유예약/61초창/1초발송간격이다. 각 조건 사이61초 냉각을 두었다. 정답 위치는 광고50/정상45의95개이며 나머지143개는 미라벨이다. 기존에 관찰한 Phase1 회귀자료로, 새 독립 일반화 평가가 아니다.

사전 계획은2→3→4→5→5→4→3→2의192호출이었다. 첫 동시5 조건의 요청index20/source448에서 `fetch failed`가 발생해 응답을 받지 못했다. 이미 전송 상태로 기록돼 서버 처리 여부는 미확인이다. 사전 오류 중단 규칙과 AGENTS.md의 미확인 API 요청 자동재호출 금지에 따라 **96요청 시도/95응답으로 중단했고 두 번째 반복은 실행하지 않았다.** 실패 요청은 다시 보내거나 정상으로 채우지 않았다.

동시5가 실패 원인이라고 단정할 수 없다. 제공사 제한 HTTP429 응답을 받은 것이 아니며, 실행기는 당시 fetch 오류의 세부 cause까지 기록하지 않았다. 따라서 네트워크·서버·클라이언트 원인은 구분되지 않는다. 동시2보다 통계적으로 불안정하다고 입증된 것도 아니다.

전체516개 과거 service 시간을 고정한 모사에서는 준비간격을 포함한 완료시간이 동시2/3/4/5 각각1951.911/1924.428/1912.156/1902.844초였다. 2→5도약2.51%의 차이에 그친다. 이 계산은 실제 응답시간·페이지 수집 의존성·CPU 경합이 달라질 수 있는 투영이다. 짧은24요청의 실측 이득이 전체 운영에서도 유지된다고 가정하지 않기 위한 보조자료이며 실측을 대체하지 않는다.

## 최종 판단

- **동시2: 기존 유망 후보 유지.** 이전 ABBA 실제 비교에서 순차대비19.9% 단축과95위치 F1 유지가 두 번 관측됐고, 이번82.649초도 이전81.543/81.632초와 비슷하다. 아직 운영 채택 완료는 아니다.
- **동시3: 추가 검증할 가치가 가장 큰 상위 후보.** 첫 실행은4와1초 차이지만 두 반복 조건을 충족하지 못했으므로 사전5%선택 규칙을 통과했다고 소급하지 않는다.
- **동시4: 3보다 추가 이득이 작아 우선하지 않는다.** 안정성 열세를 입증했다는 뜻은 아니다.
- **동시5: 이번 실행에서 미채택.** 미확인 요청이 발생해 완주하지 못했으며, 통신 실패를5개 동시성의 필연적 결과로 일반화하지 않는다.

따라서 현재 운영을 숫자만 바꿔 교체하지 않는다. 단일 inflight 및 격리요청번호 귀속 문제를 먼저 해결하고 동시2를 실제25분 조건에서 검증하는 선택이 가장 근거가 많다. 3으로 확대할 최종 근거는 아직 부족하다. 역순 반복의 미실행을 숨기거나 실패 요청을 제외한 새 평가로 성공을 만들지 않는다.
