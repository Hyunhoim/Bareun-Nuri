# Qwen CPU vs HCX 기존 평가셋 비교 사전 계획

2026-09-28. 기존 `.runtime/throughput-hypotheses-v1/inputs.json`의 137개 전체(광고60/정상65/근거부족12)를 비교한다. 새 홀드아웃·크롤링·25분 전체사이트 실험이 아닌 저장 근거 판정 비교다. 운영 코드는 바꾸지 않는다.

HCX-007 none과 공개 Qwen3.5-2B Q4_K_M CPU8스레드/추론off를 동일 system/user 메시지, 동일 후보·묶음, temperature0, seed42, 출력512로 비교한다. 각 순서에서 12개 묶음 11개+5개 묶음1개, 정순/역순 반복. 모델 토크나이저는 달라 토큰 수는 같지 않다.

HCX정순→Qwen정순→Qwen역순→HCX역순. 각 조건은 요청을 순차 실행하며 HCX는 운영 58k TPM 제한을 적용한다. Qwen은 CPU 전용 빌드/장치none/GPU layers0, prompt cache off, context16384. 모델 시작시간·요청 합계·API 서비스/제한 대기·RAM을 분리한다. HCX와 Qwen은 동시에 실행하지 않는다.

총 HCX24회/예약250,000토큰 이내, Qwen24회, 총1시간 안전상한. 응답이 확인되지 않은 외부 호출은 재시도하지 않고 중단한다. 확정 HTTP200 형식 오류는 원본을 저장하고 다음 배치를 진행한다. 형식 수선을 위한 추가 모델 호출은 하지 않는다.

주 지표는 운영 parseEnvelope+judgment 계약 그대로 평가한다. 실패 배치는 미판정으로 기록하며 그 안의 광고도 누락으로 계산한다. 정상 미판정을 정상 정답으로 계산하지 않고 별도 수량을 보고한다. 정밀도·재현율·F1·유효판정률·근거부족 양성/보류를 보고한다.

참고 지표는 문자열 분류값 `"이용권유"`를 `{publication_act:"이용권유"}`로 감싸는 무손실 형식 변환만 허용한다. 두 모델에 동일 적용한다. ID누락/추가/중복, enum외 값, JSON잘림은 복구하지 않는다. 참고 지표는 현재 운영 호환 성능과 구분하며 운영 변경 근거로 자동 채택하지 않는다.
