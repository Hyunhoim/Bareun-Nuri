# 4단계 독립 검증 계획

2026-09-23. 2·3단계 미해결 문제를 유지한 상태에서, 채택된 웹 Pipeline의 반복 판정 절감만 먼저 검증한다. 프롬프트·광고 의미 계약·기법 판정은 바꾸지 않는다.

## 미해결 사항과 기준선

- 2단계: 문맥 의존 광고 누락, 예방 인용/주변 근거 귀속, 불확실성·순서 안정성이 아직 해결되지 않았다. 미채택 contextual/attributed/direct 경로는 사용하지 않는다.
- 3단계: 관찰 모듈은 독립 검증 상태이며 전체 통합은 미채택이다. 숫자 치환 미확정·식별자 오탐·복원 및 출력 계약 오류가 남았다. 새 digit 실험 경로도 사용하지 않는다.
- 기준선은 **현재 agent/src/worker.cjs의 기본 createSession → 후보 16개 순차 decide → outputResult**다. isolated 저장 의미 판정의 F1이나 3단계 저장 응답 통합의 96.77%를 현재 worker의 정확도라고 가져오지 않는다.
- 현재 소스·저장 입력의 해시를 고정한다. 기본 worker는 독립 관문 통과 전 수정하지 않는다.

## 가설과 첫 측정

같은 원문뿐 아니라 문맥·스타일·링크·판정 설정까지 동일한 후보가 반복된다면 호출을 줄일 수 있다. 우선 기존 전체 사이트 스냅샷(101페이지/3824후보), 306개 패널, 28개 문맥 진단을 분석한다. 기존 자료는 회귀·성능 측정용이며 신규 홀드아웃이 아니다.

원문만 같은 비율과 보수적으로 재사용 가능한 비율을 분리한다. 후보 재사용 키는 node_id/url/location/selector 같은 출력 위치를 제외한 **수집 후보의 나머지 모든 근거**를 포함한다. 원문·정규화문·제목·근접 문맥·구조화 문맥·자기/조상 스타일과 좌표·링크·프레임 경로를 삭제하거나 느슨하게 정규화하지 않는다. 판정 설정과 source hash는 실행 범위에서 고정하고 다른 실행의 응답은 재사용하지 않는다. 추가 관찰 sidecar가 있으면 그 관찰 근거도 위치 식별값 외에는 일치해야 한다. 알 수 없는 새 근거 필드도 기본적으로 키에 포함한다.

현재 모델의 입력만 같은 것과 수집한 전체 근거가 같은 것은 다르다. 특히 현재 모델이 보지 않는 조상 스타일/구조화 문맥을 버려서 중복률을 높이지 않는다. DOM 위치는 각 후보별로 보존하며 판정의 ID만 올바르게 다시 귀속해야 한다.

기존 배치 16개 구성을 그대로 두고 **전체 순서 있는 배치가 일치하는 경우**와, 후보 단위로 제거해 배치 구성이 바뀌는 경우를 구분한다. 후자는 모델 결과가 바뀔 수 있으므로 동일성이 보장된 것으로 취급하지 않는다.

## 관문과 종료

1. 실제 절감 가능한 후보와 요청 수를 먼저 계산한다. 보수적인 후보 일치가 전체 입력의 5% 미만이거나 예상 요청 절감이 5% 미만이면, 이 자료에서 결과 캐시/재배치 구현 및 유료 정확도 실험을 하지 않는다. 느슨한 키로 기준을 맞추지 않고 실익 부족으로 보고한다.
2. 절감 여지가 있으면 실험 경로에서만 결과 재사용을 구현한다. 정상·광고·보류 결과는 그대로 유지하며 API 실패/누락/형식 오류를 정상 응답으로 캐시하지 않는다. 위치 매핑·완전성·비슷하지만 다른 문맥/스타일 차단을 자동 검증한다. 같은 원문의 광고/예방 쌍, 스타일·링크·프레임 차이, 같은 대상이 다른 배치 이웃에 놓이는 경우를 포함한다.
3. 정답과 별도로 입력·출력 계약 보존을 확인한다. 기존 양성 유지, 정상 오탐 증가 없음, 보류 손실 없음, 위치/근거 혼동 0을 요구한다. F1·관찰 기법·호출/토큰/시간을 분리한다. API/판정 실패는 정상으로 간주하지 않는다. 기존 반복 응답이 서로 모순되면 재사용의 안전성 근거로 삼지 않는다.
4. 유료 검증이 필요할 때는 호출 전에 비교 입력·라벨·소스·예산·종료 조건을 별도로 고정한다. 중복 통계나 mock만으로 실제 F1 개선을 주장하지 않는다.
5. 병렬화는 재사용의 안전성·실익과 API 예산/429 처리에 대한 별도 검증 이후만 비교한다. 이번 최소 검증에서 재사용 관문이 미달하면 병렬화·5단계까지 자동 확대하지 않는다. 현재 limiter의 429/사용량 문제를 숨기지 않는다.

별도 사례에 맞춘 키 완화나 프롬프트 튜닝은 하지 않는다. 결과가 미달이면 기본 경로를 유지하고 구현을 추가하지 않는 것도 유효한 종료다. 새로운 사이트에서 중복 구조가 다르면 그때 같은 보수적 기준으로 다시 측정할 수 있다.
