# Bandit 경로 재개 실험 결과 — 2026-09-23

경로를 기억해 이어가는 수정안을 실험 전용으로 구현했다. 일부 깊은 영역에 더 일찍 도달했으나 기존 광고 위치 방문이 감소해 **미채택**한다. 운영 FIFO, 수집·판정·출력 계약은 변경하지 않았다. HCX 호출·토큰 사용은 0이다.

## 구현과 검증 범위

`agent/experiments/frontier-corridor.cjs`는 기존 Bandit 또는 문맥 Bandit의 선택기를 감싼다. 방문 페이지에서 현재 대기 중인 서로 다른 다음 목적지가 하나뿐이면 그 경로를 기억하고, 매5회 중4번째 방문에서 이어간다. 매5번째 FIFO와 나머지 기준선 선택은 유지한다. 경로 전용 슬롯은 최대20%이며 한 경로가4슬롯을 사용하면 뒤로 돌려 다른 경로에도 기회를 준다. 경로 상태는 체크포인트에 남는다.

갈림길·막다른 길·읽기 실패에서는 해당 경로 재개를 끝낸다. URL 후보 자체는 기준선 대기열에서 제외하지 않는다. 미래 페이지, 정답, URL 문자열이나 특정 태그에 따른 예외는 사용하지 않는다. 이미 진입한 단일 연결 경로의 진행을 돕는 방식이며, 입구 발견과 분기 선택까지 해결하는 알고리즘은 아니다.

사전 기준은 `frontier-corridor-plan.md`에 고정했다. 기존127/135페이지 사이트6개와 혼합27/28페이지 사이트2개를 각각 링크 순서5개로 비교해 총180개 전체 방문 순서를 생성했다. 사이트 수와 링크 순서 반복 수를 독립 표본 수로 혼용하지 않는다. 예산20/50/100 및12/18/24에서 광고가 있는 위치까지 방문했는지 계산했다. **광고 위치 도달률이며 실제 판정 F1·정밀도가 아니다.**

## 큰 사이트: 50페이지 예산

각 분할은3사이트×5순서다. 사이트당 광고24개, 이 중 깊은 영역8개다. 표는 평균 도달률이다.

|자료|정책|전체 광고 위치 도달|깊은 광고 위치 도달|
|---|---|---:|---:|
|개발|Bandit|35.56%|0%|
|개발|Bandit+경로 재개|33.61%|24.17%|
|확인|Bandit|31.94%|0%|
|확인|Bandit+경로 재개|30.00%|0%|

개발 자료에서 깊은 영역 개선은 있었으나 전체 도달은 두 분할 모두1.94%p 낮아졌다. 기준선이 방문하던 광고 위치 손실은 실행당 평균 개발2.47개, 확인0.87개다. 새로 얻은 위치를 상쇄해 순감소만 보고 손실을 숨기지 않았다.

첫 깊은 광고 방문 순번은 전체 순서 기준 평균 개발98.13→34.53, 확인104.80→76.60으로 앞당겨졌다. 하지만 확인 자료에서는50페이지 예산 안의 개선이 없었다. 사전 조건인 두 분할 각각 깊은 도달+10%p, 전체 도달 비감소, 기존 광고 위치 보존을 통과하지 못했다.

실제 동작 예로 dev-101의 원래 링크 순서에서는20번째 안내 페이지 이후24·29·34번째에 경로를 이어가고42번째에 깊은 광고를 방문했다. 경로 기억이 작동하는 사례이지만 전체 성능 개선을 증명하지는 않는다.

## 혼합 사이트: 문맥 Bandit에 연결

2사이트×5순서 평균이다. 사이트당 광고12개, 깊은 광고2개다.

|페이지 예산|문맥 Bandit 전체 도달|경로 재개 추가 전체 도달|문맥 Bandit 깊은 도달|경로 재개 추가 깊은 도달|
|---:|---:|---:|---:|---:|
|12|43.33%|41.67%|0%|0%|
|18|68.33%|65.83%|0%|15%|
|24|83.33%|91.67%|0%|55%|

24페이지에서는 개선됐지만12·18페이지의 회귀가 있다. 기준선 광고 위치 손실도 실행당 평균0.3/0.6/0.1개여서24페이지의 평균 증가만으로 보존을 주장할 수 없다. 첫 깊은 광고 순번은 평균25.70→21.90이다. 이 연결 방식도 사전 관문 미통과다.

참고로 같은 혼합 자료의 기존 Bandit에 연결했을 때12/18/24의 전체 도달25.83/48.33/80.00%, 깊은 도달40/80/100%는 기존 Bandit과 같았다. 효과는 기준선과 연결 구조에 따라 다르다. 이전 실제 HCX 실험은 원래 링크 순서만 사용했으므로 이번5순서 평균과 F1을 직접 비교하지 않는다.

## 병목과 일반화 한계

- 관측: 개발 자료에서는 경로 재개가 깊은 목적지 방문을 앞당겼다. 그러나 같은 예산에서 안내·이용자 글·관리자 영역의 기존 광고 위치 일부가 밀렸다. 깊은 탐색은 무료 추가 탐색이 아니라 방문 예산 재배분이다.
- 관측: 확인 자료의50페이지 내 재개 슬롯은 navigation71회 외에 user25/normal_board17/guide14/admin8회에도 사용됐다. 이는15개 반복 실행의 합계이며 독립 페이지 수나 정상·광고 판정 수가 아니다. 남은 링크 하나라는 조건은 깊은 메뉴만을 구별하지 않는다.
- 한계/가설: 입구 선택이 늦거나 갈림길이 많은 구조에서는 현재 재개 조건만으로 개선을 보장할 수 없다. 확인 자료의 실패 원인을 한 가지로 확정하지 않는다.
- 과적합 우려: 이미 분석한 합성 자료이고 분할별 연결 구조가 유사하다. 혼합 자료에도 상세 본문 자격과 광고 라벨의 결합 및 본문 반복 편향이 남는다. 실제 보상은 새로운 상세 본문 여부라 라벨과 완전히 같지는 않지만 일반화 근거로는 부족하다. 구조 검사 통과를 새 정확도 홀드아웃으로 부르지 않는다.

결론은 구현 가능성과 일부 도달 효과 확인, 운영 채택 실패다. 결과에 맞춰 슬롯·회전 횟수를 조정하거나 유료 판정으로 확대하지 않는다. 독립된 다양한 연결 구조에서 전체 도달 보존을 먼저 입증하기 전에는 이 실험 코드를 기본 경로에 연결하지 않는다.

## 검증과 재현

```powershell
node agent/experiments/frontier-corridor.test.cjs
node agent/experiments/frontier-corridor-run.cjs .runtime/frontier-corridor-new-run
```

출력 경로는 새 디렉터리를 지정해야 한다. 저장 스냅샷·정답 자료가 필요하다. 실행 중 네트워크 호출은 차단된다.

- 구조10실행, 실제 core 체크포인트 재개2조건 통과: 단일 경로·넓은 경로·분기·순환·실패·슬롯 상한·회전·중복/잘못된 링크·JSON 직렬화.
- 과거 순서 일치106건, 예산 접두부 일치150건, 전체 도달 페이지 집합 보존, 직렬화 후 방문 순서 일치 통과.
- 원본 기록: `.runtime/frontier-corridor-v1/{manifest,runs,rows,summary,diagnostic}.json`. manifest는 실행 코드·입력 해시다. diagnostic의 shortest_route_posthoc는 사후 전체 그래프의 최단 경로이며 실제 발견 경로로 해석하지 않는다.
- 브라우저/API 종단 지연·광고 판정 회귀·F1은 이번에 측정하지 않았다. 오프라인 스케줄러 시간은 실제 검사 시간 개선 근거가 아니다.
