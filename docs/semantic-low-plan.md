# 출력 방식과 짧은 추론의 분리 진단

문맥이 입력에 있어도 none 조건에서 같은 의미 오류가 반복되어, 기존 프롬프트를 더 조정하기 전에 출력 방식과 짧은 추론을 분리한다. [HCX 공식 문서](https://api.ncloud-docs.com/docs/en/clovastudio-chatcompletionsv3-thinking)에 따라 추론과 structured outputs는 동시에 요청하지 않는다. Context7에는 직접 HTTP API 문서가 없어 공식 자료를 사용했다. 과거 medium의 형식 실패를 의미 능력 하락으로 해석하지 않는다.

- 첫32개(기존 개발 자료; 광고16/정상12/근거부족4), 동일 게시행위 계약, 배치4.
- 조건: native structured+none / prompt JSON+none / prompt JSON+low. 공통 출력 상한8192, 온도0,seed42, 같은 local검증, 형식 자동수정·추출보정·재시도 없음.
- 최대24요청/400,000예약토큰/1시간, 공통48kTPM/최대2병렬. 데이터나 문구를 결과에 맞춰 수정하지 않는다.
- 출력실패는 해당 조건 실패이며 성공한 일부만 전체 F1로 보고하지 않는다. 세 조건의 요청·응답을 그대로 보존한다.
- F1이 기존 가장 좋은 의미 전용 후보보다3%p 이상 개선되면64개로 확대(별도24요청/400k 상한, 이미확인한응답불필요재호출없음)하거나 새80개 확인으로 넘어갈 수 있다. 그렇지 않으면 더 높은추론/투표/자기반성 호출을 추가하지 않는다.
- 비용과 지연이 늘더라도 사전20% 절대상한으로 잘라내지 않고 오류 감소 규모와 함께 판단한다. 최종25분 정탐 손익은 별도로 확인한다.
