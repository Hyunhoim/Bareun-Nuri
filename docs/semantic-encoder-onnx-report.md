# 동결 분류기 ONNX/INT8 변환 비교

2026-09-29. **3모델×2형식 실행과25,782개 출력 감사를 완료했다. ONNX FP32는 판정을 보존했지만 속도 감소6~12%로 사전20% 기준에 미달했다. INT8은 약70% 빨라졌으나 세 모델 모두 판정 보존 기준을 탈락했다.** 운영 HCX 및 학습 가중치는 변경하지 않았다. Goal은 미완료/진행 중이다.

## 질문과 비교 범위

앞선12조건에서 동결한 KLUE-f8-512, Kc-full-512, Ko-f8-512를 같은 입력/0.5임계값으로 변환했다. FP32 변환의 수치 보존과 INT8의 손실을 분리한다. 모델마다 동결 층 조건이 다르므로 양자화 결과 차이를 아키텍처 자체의 우열로 해석하지 않는다.

PyTorch2.6.0+cu124, ONNX1.17.0, ORT1.23.2 CPUExecutionProvider,8threads/batch8/512토큰이다. INT8은 상수 weight를 사용하는 MatMul74개에 per-channel QInt8 동적 양자화를 적용했다. 모든 가중치가 INT8인 것은 아니므로 파일이 FP32의 정확히1/4이 되지는 않는다. 토크나이저·NFC·대상/문맥 직렬화·잘림 보류는 유지했다.

패널은 개발90, 기존 HCX 비교204, 기존 기법별 회귀2000, 실제 미라벨2003이다. 모델당4297개,3모델×2형식이다. 개발90에는 원문과 변형이 함께 있고 기존 패널은 관찰 자료다. 합산 행 수를 독립적인 의미 사례 수로 부풀리지 않는다. 실제2003은 DOM 요소이며 사람 정답이 없어 실제F1을 계산하지 않는다.

사전 계획: [semantic-encoder-onnx-plan.md](semantic-encoder-onnx-plan.md). FP32는 hard 판정 변경0/저장 확률 최대오차1e-4 이하, INT8은 각 라벨 패널의 기존정탐손실0·새오탐0 및 실제raw판정변경0을 요구했다. 결과를 보고 기준이나 임계값을 바꾸지 않았다.

## 실행 조건과 한계

각 export/형식 추론을 별도 프로세스로 순차 실행했다. 실제 입력 추론 시간은 워밍업 뒤2003개1회이며 토큰화·모델 로딩을 별도 기록했다. 이전 turn의 PyTorch와 실행 시점·다른 프로세스 부하가 다르므로 시간 차이의 반복 실험/인과적 추정은 아니다. 속도 후보 기준은 이전 측정 대비20% 이상 감소다.

메모리는 프로세스 peak working set이다. 공통 Python/transformers/PyTorch import,2/17/512토큰 동적 shape 검사,4개 패널이 포함돼 순수 최소 ORT 런타임 메모리가 아니다. 이전 PyTorch의 실제2003만 검사한 프로세스와 메모리를 엄밀한 동등 조건으로 비교하지 않는다. 모델 파일 크기에는 토크나이저/런타임 패키지가 포함되지 않는다.

KLUE의 보조 symbolic shape inference는 `Min(514, sequence)` 오류로 실패했다. 이 단계만 생략한 뒤 ONNX checker/shape inference와 실제 길이·batch 실행을 통과시켰다. 이는 예측 결과를 보기 전의 변환 호환성 수정이다. 의존성은 `.runtime/semantic-onnx-deps`에만 설치했다.

실제 수집2003개, 순수 추론 초다. PyTorch는 이전 turn의 같은 저장 입력 결과다.

ONNX FP32는 모델당4297개 전체 hard 판정 변경0이고 저장 확률 최대오차는 KLUE7.27e-6/Kc1.03e-5/Ko1.19e-5다. 이전 PyTorch 대비 추론 시간 감소는6.4%/12.3%/11.5%로 사전20% 속도 기준에 미달한다. FP32 변환본은 수치 보존이 확인된 연구용 산출물이며 운영 채택이나 의미 성능 개선은 아니다.

INT8의 실제raw판정 변경은 KLUE7/Kc24/Ko678개다. 기존 수집/토큰 잘림 보류는 전부 같고, 이를 적용한 확정 판정 변경은7/24/654개다. 미라벨이므로 이를 실제 정답 개선/악화 수로 주장하지 않는다. 고정.2~.8 진단 보류까지 고려한 출력 변화는17/38/957개로, 원본의 보류 정책을 단순 승계해도 판정은 보존되지 않는다.

동일한 ONNX 검사 범위의 최고 작업 메모리는 FP32→INT8에서 KLUE1328.6→1038.6MiB, Kc1389.8→1106.1MiB, Ko1337.7→1055.6MiB다. 메모리와 크기의 감소를 인정하되 정확도 손실과 상쇄해 채택하지 않는다.

## 확인한 회귀

KLUE INT8은 개발 판정이 같아도 HCX 관찰 비교에서 기존 정탐2개를 잃고1개를 회복했다. 기존2000에서는 정탐1개를 잃고4개를 회복했으며, 새 정상오탐6개와 기존오탐해소8개가 함께 생겼다. 총F1이 일부 좋아지는 것과 기존 탐지를 보존하는 것은 다르다.

Kc INT8은 HCX 관찰 비교에서 TP62→6, 기존2000에서 TP923→49로 크게 회귀했다. 같은 모델의 ONNX FP32는 기존 판정을 보존했다. 이번 양자화 조건의 심각한 수치/판정 손실이며 Kc 원본 모델이나 ELECTRA 전체가 부적합하다는 증거는 아니다. 세부 원인을 양자화 범위·연산 커널·미세조정 민감성 중 하나로 확정하지 않는다.

Ko INT8은 HCX 관찰 비교에서 기존 정탐 손실0/누락20개 회복과 함께 새 오탐23개가 발생했다. 기존2000에서도 FN25→0이지만 새 오탐420개/기존오탐해소3개가 함께 발생해 FP181→598로 증가했다. 재현율 상승만으로 개선이라고 판단하지 않는다.

|HCX 비교204 중 이진167|KLUE|85.48%|84.55%|2|0|
|동일|Kc|91.85%|17.14%|56|0|
|동일|Ko|73.68%|78.98%|0|23|

HCX204에는 근거부족37개가 있어 표의 의미F1은 이진167개만 포함한다. 개발90은 원문/변형80이진+10근거부족이고, INT8에서 KLUE 판정변경0, Kc44, Ko20이다. 개발 이진 정탐손실은0/32/0, 새오탐0/0/11이다. 이는 추가 독립 사례가 아니라 기존 개발 자료의 회귀다.

## 감사와 재현

`local-benchmark/semantic-encoder-onnx.py`의 모델별 `export`, `fp32`, `int8` 명령으로 생성했다. 이미 완료된 결과는 덮어쓰지 않는다. `local-benchmark/semantic-encoder-onnx-audit.py`가3개 원본 가중치·변환본 해시,4개 패널의 동결 입력/정답,24개 예측 파일의 ID/유한 확률/임계값/변경목록/기존정탐손실/새오탐/지표/실수집보류를 재계산해 통과했다. 스크립트 컴파일 및 이번4개 소스/문서 범위의 diff whitespace 검사도 통과했다.

근거는 `.runtime/semantic-encoder-onnx-v1/audit.json`과 각모델/형식의 `report.json`, `completed.json`, 원예측 JSON이다. 런타임 추가 학습·운영 변경·API 호출은0이다. 전체 저장소에는 다른 작업의 변경이 있어 저장소 전체 검사를 이번 변경의 통과 근거로 사용하지 않았다.

## 남은 목표

빠른 형식 변환만으로 HCX 대체 품질을 확보한 것은 아니다. 실제31개 블라인드 사람 검수는 여전히 미완료이며, 새 실제 입력에 대한 HCX 직접 비교 및25분 종단 채택 검증도 없다. 기존12조건의 의미 판정 회귀·근거부족 처리 한계를 그대로 인정한다. 운영은 HCX를 유지하고 이번 자료는 배포 형식 선택용 관찰/회귀 증거로 보존한다. 추가 학습0/API호출0이다.
