# 2단계 단일 대상 직접 판정 실험 계획

실험 전 등록: 2026-09-22. 기존 실패안 `contextual`·`attributed`에 단계를 추가하지 않는다. 기본 worker와 `isolated`는 변경하지 않는다.

## 관측과 가설

관측: 여러 의미 필드의 조합, 문맥 판정 뒤 별도 역할 판정, 근거 위치 제한을 사용해도 정상 요소로의 근거 전이·근거 부족의 정상 확정·반복 변동이 남았다. 앞선 단일 후보 시도 역시 다른 계약을 사용했으므로 현재 가설의 검증으로 간주하지 않는다.

가설: 여러 중간 의미 분류를 조합하기보다 하나의 대상에 대한 근거 기반 3분류를 직접 요구하고 다른 후보를 요청에서 분리하면, 문맥 의존 광고를 복구하면서 근거 전이와 불필요한 추론을 줄일 수 있다. 이는 아직 확인되지 않은 가설이다.

## 고정 조건

- 기준선: 저장된 `isolated` 기본 판정. 실험 대상은 음성 종료 중 확정된 인용을 제외한 후보이며 기준선의 광고 판정은 보존한다.
- 변경안: 대상 표시가 있는 순서 보존 문맥을 읽고 광고·정상·근거 부족 중 하나를 직접 판정한다. HTML 태그나 스타일로 역할을 추측하도록 요구하지 않는다. 근거는 후보 내부 위치를 선택하고 코드가 원문을 복원한다.
- HCX-007, 추론 none, temperature 0, seed 42, 출력 한도 3,072토큰. 단일 후보 조건과 배치 4 조건에서 프롬프트·입력 내용·모델·추론 설정·통합 규칙을 동일하게 유지한다. 서로 다른 후보를 같은 요청에 넣는지의 효과만 두 조건 간 비교한다.
- 기존 실패안과 비교할 때는 계약·입력 표현·추론 설정이 함께 달라졌음을 명시한다. 개선을 특정 요인 하나의 효과라고 주장하지 않는다.
- 실제 호출은 순차 실행한다. 각 실행은 기본 단계 포함 300회·1시간 이내로 제한하고 호출·토큰·추가 경과 시간을 기록한다. 요청을 공유하는 세션 간 동시 실행은 하지 않는다.
- 프롬프트와 판정 코드를 최초 호출 전 해시로 고정한다. 실패 사례를 보고 문구나 예외를 추가하지 않는다. 구현 오류가 있으면 별도 결함으로 기록하며 수정 후 새로운 실행으로 구분한다.

## 평가와 종료 기준

1. 진단 63개: 광고 25개, 정상 36개, 근거 부족 2개. 기존 자료이므로 회귀·진단 검사다. 같은 기본 응답에 실제 단일 후보 보완과 배치 4 보완을 각각 적용한다.
2. 단일 후보 변경안의 진단 통과 조건: 광고 25개 탐지, 정상 오탐 0개·불필요한 검토 0개, 근거 부족 2개 모두 검토. 기본 광고 판정이 변하지 않아야 한다. 배치 4는 원인 비교용이며 더 좋은 결과만 골라 채택하지 않는다.
3. 진단을 통과한 경우에만 기존 306개 회귀 검사로 확대한다. 광고 120개 유지, 정상 오탐·불필요한 검토 0개를 요구한다. 마지막 미채택안의 악화된 지표를 허용 기준으로 삼지 않는다.
4. 두 관문을 통과한 경우 새 문구·HTML 조합을 사전에 라벨링·고정하고 전체 실제 호출로 원래 순서, 역순, 같은 순서 반복을 평가한다. 기존 26개·32개는 새 평가로 사용하지 않는다. 표본 수와 허용 범위는 그 평가의 최초 호출 전에 기록한다.
5. 불확실 항목을 이진 F1에서 제외하더라도 별도 검토 계약에 반드시 포함한다. 검토 처리로 오탐을 숨기지 않는다. 실제 광고·검토 여부의 반복 변동이 남으면 안정성 통과를 주장하지 않는다.
6. 진단 또는 회귀 관문이 실패하면 이 변경안을 미채택하고 이번 실험을 종료한다. 프롬프트를 다시 조정하거나 다른 검토 단계를 덧붙여 통과시키지 않는다. 실패 근거·비용을 보고하고 기본 구현을 유지한다. 3단계 자동 진입은 하지 않는다.

과적합 위험: 같은 진단 자료를 여러 번 분석한 이력이 있다. 새로운 예시를 프롬프트에 넣지 않으며, 개발 자료의 통과만으로 일반화 개선을 주장하지 않는다.
