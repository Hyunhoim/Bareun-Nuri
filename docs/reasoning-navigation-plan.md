# 추론 설정과 탐색 정책의 분리 검증 — 2026-09-23

## 고정 기준과 가설

운영은 FIFO + 재사용 브라우저 + HCX-007 none, 최대16개 순차 배치를 유지한다. 이번에는 추론 모드가 동일 근거의 판정 오류를 줄이는지 먼저 검증한다. 추론을 켜면 개선된다는 가정은 하지 않는다. 기존 실험용 direct 3분류 계약을 재사용하는 **단일 대상 진단**이며 운영 프롬프트/구조 변경 효과로 해석하지 않는다.

## 1. 제한된 추론 비교

- 저장 자료 `.runtime/stage2-direct/single63/evidence.json` 및 `.runtime/stage2-routing/diagnostic-labels.json`. 기존 순서의 context-dependent, context-pair-normal, direct-ad, quotation, metadata-next-to-ad, insufficient 유형 전부 선택: 광고12, 정상16, 근거부족2, 합계30. 기존 대상 단독 판정의 광고 누락8개와 정탐4개를 포함한다. 이는 과거 실패 자료를 재사용한 진단이며 새 홀드아웃이 아니다.
- 같은 입력/기존 direct 계약/최종 JSON 스키마, 단일 대상. node_id는 호출마다 `1`로 가린다. 라벨·이전 응답은 모델에 보내지 않는다. 대상별 source_ids는 실제 전달되는 문맥과 일치시킨다.
- none 대 medium, 각3회. medium은 추론 모드 존재 효과를 볼 한 조건이며 low/high 최적화나 모델 능력 상한을 주장하지 않는다. temperature0, seed42, maxCompletionTokens10240 공통. 두 조건 모두 provider Structured Outputs 없이 동일 JSON 지시와 로컬 검증을 사용한다. 동일한 JSON fence 처리. 형식 복구/전송 재시도는 하지 않고 최초 응답 실패를 기록한다.
- 매 반복·사례에서 none/medium 실행 순서를 교차한다. 순차 실행, 전체 공통 세션 속도 제한. 실제 요청·응답 최종 content·usage·queue/service 시간을 저장한다. 내부 thinkingContent와 키는 저장하지 않는다. 출력 잘림은 형식 실패와 별도로 기록한다.
- 최대200시도/예약 포함600,000토큰/1시간. 개별 응답180초. 연속 형식·통신 실패3회, 401/403, 예산 소진 시 중단하며 부분 결과로 표시한다. 중단된 미확인 요청은 자동 재호출하지 않는다. 유효한 완주 쌍이 없으면 추론 효과는 미확인이다.
- 이진 광고 P/R/F1(광고의 보류도 FN), 정상 오탐, 정상 불필요 보류, 근거부족 보류 성공, 예방 인용/정상 메타데이터 귀속, 3분류 정답률, 사례별3회 판정 변경률, 전체 토큰/순수 API 지연/대기 포함 지연을 보고한다. 반복 응답은 독립 사례90개로 과장하지 않는다.
- 후속 진입: 매 반복 기존 none 정탐 손실0, FP 증가0, 정상 보류 증가0, 근거부족 정답 비감소, 전체 3분류 정확도 +5%p 이상, 2회 이상에서 판정 정확도 개선, 변경률 비증가, 형식 실패/잘림0. 비용·지연은 각각 none의4배 이내. 실패 시 프롬프트 조정/다른 강도 재탐색 없이 이번 추론안 미채택.

## 2. 조건부 FIFO 운영 확인

1단계 통과 시 코드/입력 계약을 고정한 추가 문구·문맥/구조의 별도 자료에서 확인한 후 운영의 실제 근거/16개 배치·FIFO에 적용하여 비교한다. none은 운영 Structured Outputs 그대로, medium은 JSON 지시/검증으로 이 단계는 배포 설정 묶음 비교임을 명시한다. 기존 정탐 손실0·FP 증가0·의미/최종 F1 비감소, 비용/전체 시간 증가30% 이내, 동일 시간 예산에서 최종 탐지 재현율 비감소를 모두 만족해야 운영 채택한다. 실제 수집 시간을 포함하거나 별도로 측정한 수집 시간을 결합한 추정임을 명시한다. 1단계 실패 시 유료 후속은 생략한다.

## 3. FIFO 대 문맥 Bandit

판정 조건을 유지하고 기존 문맥 정책은 수정하지 않는다. 6개 기존 대형 혼합 사이트와 2개 소형 혼합 사이트, 링크 순서5개에서 FIFO 대 문맥 Bandit의 전체 방문 순서를 새로 실행한다. 대형20/50/100, 소형12/18/24 요청 예산. scheduler에는 방문한 페이지 정보/출처 링크 문맥만 제공하고 정답은 실행 후 채점한다.

기존 대형 자료의 링크 문맥이 부족하면 실제 HTML에서 inspectContext를 추출하여 보강한다. 타깃 페이지의 정보를 링크에 미리 넣지 않는다. 전체 방문 집합·중복·예산 접두부·직렬화/재개 순서를 검증한다. 광고 전체 정답을 분모로 하고 미발견/발견후대기, 깊은 광고 도달, 기존 FIFO 도달 위치 손실, 정상 방문 비율, 스케줄러 CPU 시간을 각각 보고한다. API가 없으면 F1/종단 시간이라고 부르지 않는다.

기존 자료의 detail과 광고 상관 편향을 명시한다. 모든 사이트/예산에서 링크순서 평균 도달률 비감소, 주요 예산(대형50/소형18)의 각 실행에서 FIFO 광고 위치 손실0, 개발/확인 각각 주요 예산 평균 +5%p, 깊은 광고 도달 비감소, 전체 집합·재개 동일성이 유료 후속 진입 조건이다. 관문 실패 시 추가 유료 판정 없이 FIFO 유지, 과거 실제 판정 실험과 합쳐 이유를 보고한다. 통과 시 detail이 정상에도 나타나고 비detail에도 광고가 있는 별도 구조 확인 및 동일 예산 실제 HCX 비교를 사전 등록한 뒤 시행한다. 최종 채택은 기존 crawl-contract의 F1/정탐보존/비용 관문도 충족해야 한다.

어느 단계도 결과를 보고 관문을 완화하거나 실패 사례에 맞춰 수정하지 않는다. 실험 실패는 모델/알고리즘의 일반적 불가능 증명이 아니다. 원화 비용은 실제 계정 과금 단가가 확인되지 않으면 토큰과 상대 비용으로만 보고한다.

## 실행 보정 기록 (v1 초기 통신 검사 후)

v1에서 실제 응답 totalTokens로 TPM 예약을 조기에 해제하자 6번째 요청에 HTTP429가 발생했다. 첫 실행은 성능 비교에서 제외하고 기록을 남긴다. 모델 판정 내용/라벨별 성적은 이 보정의 근거로 사용하지 않았다. v2는 61초 동안 요청의 전체 예약량(입력 추정+최대 출력)을 유지하며, 429는 즉시 중단한다. 기존 결과를 덮어쓰거나 미확인 요청을 자동 재호출하지 않고 새 실행 폴더에서 동일 계획을 수행한다. 입력·출력 계약·모델 설정·평가 관문은 유지한다.
