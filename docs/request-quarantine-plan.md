# 요청 단위 불완전 응답 격리 — 사전 채택 계획

2026-09-30. 목표는 확정 HTTP 응답의 일부 ID 누락 때문에 전체 작업이 중단되는 문제를 줄이는 것이다. 광고 의미 판정·FIFO·묶음12·출력512·none·58k는 유지한다.

1. HTTP 성공/정상 종료/완전 JSON/요청 ID의 유효한 비어 있지 않은 부분집합만 격리한다. 잘림·전송 불명·중복키·알 수 없는 ID·잘못된 값은 실패를 유지한다. 원응답·요청ID·반환 판정·미반환ID를 불변 저장한다. 묶음 전체는 미판정이며 자동 재호출하지 않는다.
2. offset은 다음 시도할 위치, judged_work_items는 실제 저장 판정 수로 분리한다. 페이지 끝에 도달해도 격리가 있으면 complete=false. 선택 큐에서는 제거하되 coverage에 미판정으로 남긴다. 같은 페이지 다음 묶음도 처리한다. 재개 시 범위·ID·중복·해시를 검증한다. split 후보의 일부 구간만 판정됐다고 전체를 정상 처리하지 않는다.
3. 연구 경로에서 오프라인 장애주입/정상결과일치/예산중단재개/변조·옛서명거부를 먼저 검증한다. 운영 소스는 승격 전까지 불변이다.
4. 실제 수집+HCX+AntiSpoof의 새 25분/600호출/200페이지 Phase1 실행을 연구 코드로 진행한다. 희귀 오류에 의존하지 않도록 20번째 정상 HTTP 응답의 마지막 ID 하나를 실험용으로 제거한다(원응답 별도 보존). 원래 실패160요청의 체크포인트는 재개하지 않는다. 주입 여부와 자연 오류를 구분하고, 같은 저장 응답을 기준선에 재생해 기준선은 해당 오류에서 멈추는지 비교한다. 이 비교는 장애 조건의 복원력 검증이며 자연 오류 발생률·독립 의미 일반화의 증명이 아니다.
5. 채택 조건: 정상 응답 판정 불변, 격리 위치 누락/가짜 정상/중복 전송0, 동일 페이지와 이후 페이지 진행, 재개 보존, 기준선 중단 지점 대비 25분 내 전체 정탐 증가 및 공통 완료 판정 보존. 추가 처리 영역의 오탐은 별도로 보고한다. 실제 실행이 다른 결함으로 실패하거나 계약 검증 실패 시 승격하지 않는다.
6. 통과 시 검증한 연구 소스를 운영 반영하고 worker/화면의 판정수·미판정 안내를 일치시킨다. 새 코드 서명으로 옛 체크포인트 자동 이행을 거부한다. 별도 승인 없는 격리 요청 재판정 기능은 추가하지 않는다. 연구 기록과 기존 결과는 보존한다.
