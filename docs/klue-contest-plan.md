# 4종 합성 사이트 분류모델 봉인 평가

2026-09-28. 새 test-set-contest-v1을 처음 판정한다. 재학습, 임계값 조정, 실패 문구 보정, HCX 유료 호출은 하지 않는다. Ponytail 원칙으로 기존 수집기·문맥 직렬화·KLUE 추론 함수를 재사용한다.

## 고정 조건

- 이전 보강 KLUE: `.runtime/klue-refinement-v1/model`.
- 개선 후보: `.runtime/klue-cycle3-v1/frozen8/model` (8천 학습, 하위8층 고정, 선택 epoch1).
- 실제 운영 createCollector로 상세250 URL을 직접 지정해 수집한다. FIFO URL 발견 경쟁이나25분 종단 실험이 아니다. 브라우저 작업당 재사용, 기본 안정화 대기, 페이지당 최대1000후보, iframe 포함, 동일 근거 한 번 저장.
- 정답의 URL·선택자는 수집된 지정 대상을 평가에 대응시키는 데만 사용한다. 빠진 대상을 gold 문구로 대신 판정하거나 정답 복원을 주입하지 않는다. 미수집은 별도 집계하며 전체광고 기준 FN에 포함한다.
- 입력은 기존 KLUE 평가와 같은 `contract().initialEvidence(c).normalized_text` + `klue-context.cjs` 문맥, 모델 입력 NFC, 최대512토큰. 서버 자모 보조 읽기 포함 여부도 두 모델 동일하다.
- CPU8threads/batch8/argmax, 순서 고정. 워밍업은 과거 관찰 개발 자료8개만 사용한다. 새 자료는 모델별 단1회. 추론은 최대30분 안전 상한이며 전체 작업 1시간 상한을 둔다.
- 모델/소스/데이터 해시 고정, 시작마커 배타 생성. 예측을 저장한 후 이진 정답으로 채점한다. 데이터/모델을 바꿔 재평가하지 않는다.

## 보고 기준

주지표: 전체 광고1000/정상1000 기준 TP/FP/FN·정밀도·재현율·F1·정상오탐률. 보류는 광고에서 FN이며 정상에서 별도 검토부담으로 보고한다. 수집된 대상만의 의미 성능도 병기한다. 유형·세부 변형·배치 위치·문맥 계열별로 분해한다. 같은 원문4변형의 짝 일관성과 기존 정탐 손실/획득을 보고한다.

기법 정확도는 코드 관찰의 별도 지표다. 의미양성에 코드의 확정 기법을 결합한 지정위치×기법 성능도 별도 계산하며 이를 제출 종단 성능이라고 부르지 않는다. 공통 입력 길이·잘림·로드/토큰화/순수 CPU 추론시간을 보고한다. 단회 시간 비교이므로 작은 차이의 인과효과를 주장하지 않는다.

후보 유망 기준은 전체광고 F1이 기준선보다2%p 이상 높고 TP가 줄지 않으며 FP가 늘지 않는 것이다. 통과해도25분 운영 채택 또는 HCX 우위 증거가 아니다. 실패하면 그대로 보고하고 이번 세트에 맞춰 다시 학습하지 않는다. 이진 정답이므로4분류 macro F1을 일반화 성능으로 제시하지 않는다.

250개 광고 원문×4/250개 정상 원문×4이며500개 의미그룹·50개계열이다. 영어접두어/같은제작자/도박편중/합성정답 편향을 유지해 공개한다. 새 평가 이후에는 관찰 자료다.
