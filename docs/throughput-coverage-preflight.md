# 유료 종단 실행 전 도달 가능성 점검

2026-09-25. 2×2 판정 진단 실행 중, 종단 후보의 실제 의미 결과를 보기 전에 추가한 API0 안전 점검이다. throughput-plan.md의 네 조건·입력·정답·프롬프트·채택 기준은 변경하지 않는다.

페이지 분산은 FIFO 방문 순서를 바꾸지 않지만 새 페이지의 앞4개를 우선 처리하고 이전 페이지의 나머지 작업을 순환한다. 따라서 페이지 뒤쪽에 있는 광고는 수집해도300호출 안에 판정 차례가 오지 않을 수 있다. 이 경우 유료25분의 재현율 개선을 기대할 근거가 없으므로 먼저 실제로컬복제본 collector와 동일 스케줄러를 사용해 모의 판정으로 실행한다.

- dev 게시판 진입, FIFO200시도/300모의호출/1500초/누적후보0/메모리768MiB, 브라우저 재사용, 같은 최대4개 요청 묶음과 선택 규칙.
- 모의 판정은 모두 일반정보를 반환한다. 정답을 스케줄러/판정기에 주지 않는다. HCX0회이며 의미F1/속도개선 측정으로 해석하지 않는다.
- 전체 위치의 수집/판정차례 도달과 메모리·저장·수집 실패를 관찰한다. 모의판정 자체의TP0은 유료모델TP0의 증거가 아니다.
- 시간/메모리 등으로 중단한 모의실행은300호출 도달 불가능성의 수학적 증명이 아니다. 그러나 광고 수집 후 판정 대기가 주요원인인지 진단하는 근거로 보고한다.
- 전체300호출까지 마치고 광고 판정 대상이0이면 동일 저장수집·스케줄에서 유료모델만 바꿔 광고를 찾을수는없다. 추가유료확대 대신 그 한계를 보고하며, 분산규칙을 정답 위치에 맞춰 변경하지 않는다.
