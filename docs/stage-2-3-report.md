# 2단계 검증 결과 및 3단계 진입 판단

이 문서는 앞선 미채택 실험의 기록이다. 후속 개선과 현재 진입 판단은 [2단계 일반화 검증 보고서](stage-2-generalization-report.md)에 있다.

검증일: 2026-09-22. **2단계 개선안을 구현하고 HCX-007로 검증했으나 오류가 남았다. 3단계는 시행하지 않았다.** 기본 웹 실행에는 기존 판정기를 유지하고 새 판정 계약은 `agent/experiments/`에 분리했다. F1 상승만으로 재현율 하락과 근거 귀속 오류를 통과시키지 않았다.

## 적용한 수집 개선과 실험한 판정 개선

- 문맥 범위를 DOM 의미 요소, 분기하는 블록, 반복되는 독립 항목으로 구분한다. 특정 사이트의 클래스명·URL·정답 ID는 사용하지 않는다.
- 중첩 래퍼를 지나 같은 범위의 설명을 보존하되 다른 댓글, 제목과 작성자 필드 사이의 설명 혼입을 줄인다. 앞뒤 최대 3개 요소, 주변 요소별 600자를 제공하고 잘림 여부를 기록한다.
- 실험 판정기는 대상과 앞뒤 문맥을 구분하고, 현재 게시자의 제시 목적을 `solicitation / quotation / ordinary / uncertain`으로 판단한다.
- 후보별 근거 위치 enum을 사용한다. 선택된 위치의 실제 문자열은 코드가 복사한다. 근거 문장을 모델이 생성하게 했던 안은 입력과 다른 인용을 만들어 폐기했다.
- 의도 전용 실험에서는 스타일 입력과 기법 출력까지 제거하여 의미 판단 자체를 진단했다. 이것은 3단계 완성품이나 대회 결과 생성기가 아니다.

기본 수집 결과에는 `context_evidence`를 추가했다. 기본 판정기의 API 입력·응답 계약은 기존과 동일하다. 실험 계약은 worker에서 사용하지 않는다. 문구 예외 처리, 제목/댓글 검사 생략, 정답 라벨 참조는 추가하지 않았다.

## 검증 범위와 조건

전체 고도화 사이트를 다시 수집했다: 101개 상위 문서(진입점 + 하위 100페이지), 3,824개 후보, 수집 135.71초. 이전 수집과 모든 후보의 ID·원문·정규화문·URL·위치·기법 힌트·직접 이웃·페이지 제목·링크·frame 경로·own_style가 동일하다. 기존 300개 정답 위치가 보존되었다. 수집 회귀 검사에서 깊은 래퍼, 독립 댓글, 목록, 작성자/제목 분리도 통과했다.

실제 모델 비교는 **300개 정답 요소 + 과거 오탐 위치 6개 = 306개 후보를 선별한 회귀 패널**이다. 전체 3,824개 후보를 HCX로 재검사한 결과가 아니며 전체 사이트 F1로 보고하면 안 된다. 정답은 오프라인 선별·채점에만 사용하고 모델 입력에 넣지 않았다.

모델 조건: HCX-007, temperature 0, reasoning none, seed 42, 출력 한도 3,072토큰, 16개씩 순차 판정, 분당 토큰 예산 52,000. 각 전체 패널 실험은 20회 호출이었다. 진단용 1개/4개 묶음 검사는 별도 기록하고 주 비교에 합치지 않았다. API 시간은 단일 측정값이며 반복 지연 벤치마크가 아니다.

## 결과

완료된 중간 버전의 대회 형식 채점(위치 × 기법 단위, 정답 160쌍):

| 지표 | 기존 1단계 판정기 | 2단계 혼합 판정 v6 |
|---|---:|---:|
| TP / FP / FN | 156 / 40 / 4 | 152 / 9 / 8 |
| 정밀도 | 79.59% | 94.41% |
| 재현율 | 97.50% | 95.00% |
| F1 | 87.64% | 94.70% |
| 판정 시간 | 329.79초 | 491.59초 |
| 토큰 | 138,818 | 199,228 |

오탐은 줄었지만 누락은 증가했다. 시간은 49.1%, 토큰은 43.5% 증가했다. **v6는 채택하지 않았다.** 이 수치는 최종 문맥 범위 수정 전의 중간 버전이며, 수정 후 혼합 판정기의 전체 성능으로 대체해 해석하지 않는다.

최종 문맥 범위 + 의도 전용 실험의 원시 의미 판정(기법 채점 아님):

| 지표 | 기존 1단계 판정기 | 최종 의도 전용 실험 |
|---|---:|---:|
| 300개 중 정상 오판 | 42 | 0 |
| 300개 중 광고 누락 | 1 | 4 |
| 추가 정상 위치 6개 중 광고 판정 | 0 | 2 |
| 300개 중 검토 보류 | 6 | 0 |
| 판정 시간 | 329.79초 | 397.11초 |
| 토큰 | 138,818 | 139,775 |

위 표는 보류 여부와 별개로 모델의 광고 의도 판단을 비교한다. 첫 표는 보류를 제외하고 실제 출력된 위치·기법을 채점하므로 오류 개수가 서로 다르다. 의도 전용 실험에는 기법 출력이 없어 대회 F1을 계산하지 않았다. 시간은 기존보다 20.4%, 토큰은 0.7% 증가했으며, v6와는 문맥 범위도 달라 스타일 제거 하나의 인과 효과로 단정하지 않는다.

별도 합성 문맥 변형 32개와 추가 변형 16개에서는 최종 의도 오류·보류가 모두 0건이었다. 직접 권유/예방 인용, 이웃 경고와 독립 광고, 광고 옆 정상 메타데이터, 설명의 앞뒤 위치, 다른 표현과 DOM 래퍼를 포함한다. 그러나 기존 패널에는 오류가 남았다. 이 자료는 개발 중 반복 사용한 합성 회귀 자료이며 실제 웹사이트의 미공개 홀드아웃 일반화 성능을 증명하지 않는다.

## 남은 오류와 원인 구분

관찰된 사실:

1. 실제 가입·결제·이용 권유 4건(`advanced-043 / 087 / 088 / 102`)을 인용으로 판단했다. 일부는 근거로 `서명`이나 `답글`이라는 항목명을 골랐는데도 설명에 “신고된 광고 인용”을 만들어 넣었다.
2. `시민 의견`, `관련 링크` 두 정상 위치를 주변 광고의 내용으로 판단했다. 첫 사례는 같은 범위의 다른 요소를 실제 근거로 선택했고, 두 번째는 자체 항목명을 선택한 뒤 다른 광고 내용을 설명했다.
3. 유효한 근거 위치를 강제하면 존재하지 않는 위치·다른 후보의 ID 참조는 차단된다. 하지만 근거의 의미와 판정이 일치하는지는 해결되지 않는다.
4. 혼합 판정에서는 정상 인용과 실제 권유를 구분한 뒤에도 기법 관찰 값이 일관되지 않았다. 이 문제는 3단계에서 다룰 대상이지만 선행 의미 오류가 해소되지 않았다.

가설과 한계:

- 여러 후보를 한 요청으로 처리할 때 의미가 옮겨 붙는 현상이 의심된다. 단독 사례 검사는 통과했지만 표본이 적어 원인 확정은 아니다. 4개 묶음 혼합 검사에서도 오류가 남았으므로 단순 묶음 축소를 해결책으로 채택하지 않았다.
- DOM 범위는 작성 주체나 의미적 귀속의 정답이 아니다. 정상 메타데이터와 광고가 같은 범위에 있을 수 있어, 목표 문구가 실제로 무엇을 말하는지와 주변 문구의 역할을 별도로 검증해야 한다.
- 기법 정보 제거는 일부 간섭을 줄였을 가능성이 있지만, 신규 누락과 추가 위치 오판이 남아 전체 일반화 개선 완료로 선언할 수 없다.

다음 2단계 검증의 우선순위는 **대상 문구의 의미와 선택한 근거가 판정을 실제로 뒷받침하는지 검증하는 것**이다. 동일 후보를 단독/혼합/순서 변경 조건에서 비교해 배치 간섭을 구분하고, 독립 재검증이 필요하다면 오류 감소와 추가 호출 비용을 함께 측정한다. 특정 항목명이나 알려진 실패 ID를 예외로 처리하지 않는다.

## 코드·실행 검증 및 산출물

- `npm.cmd test --prefix agent`: 자모 보존, 기존 판정 계약, DOM 수집/문맥 범위, 실험 근거 귀속/스키마 검사 통과. 외부 API를 호출하지 않는다.
- 저장된 실제 응답 60회(기존·혼합·의도 전용 각각 20회)를 공통 전송 코드로 재생했다. 모든 API 요청 본문과 918개 판정 결과가 실험 당시와 동일했다. 네트워크 재호출 없이 코드 분리 후의 계약 보존을 확인했다.
- `node scripts/verify-web.cjs`: React → Spring Boot → Node → 결과 다운로드, 1시간 한도, 취소/실패, 재시작 후 기록, 모바일 UI 검사 통과. 이 웹 검사는 mock이며 HCX 정확도 검사는 위의 실제 호출 실험과 구분한다.
- 최종 기본 버전은 `0.3.5-web.0`. 3단계 관찰기 통합, 캐시, 병렬화, 페이지 우선순위는 적용하지 않았다.
